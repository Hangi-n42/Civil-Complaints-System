# 검색 평가 관련성 채점 루브릭 v3 (답변 재사용 안전성 프레임)

> 민원 유사검색(RAG) 정답지(qrels)의 (쿼리, 후보) 쌍을 0/1/2로 채점하는 LLM 기준.
> 두 차례 독립 AI 적대적 검증을 거쳐 확정. 졸업 발표 "평가 신뢰성" 자산.

## 1. 한 줄 요약

채점의 질문을 **"두 민원이 닮았는가(유사도)"에서 "이 선례를 답변에 넣어도 안전하게 재사용할 수 있는가(안전성)"로 전환**했다. 닮았더라도 결론이 반대거나 요건·제도·시점이 다르면 위험하므로 감점한다.

## 2. 구조 — 3축 채점 후 위험 플래그로 상한(cap)

- **핵심 3축(0/1/2)**: `issue`(1차 요구 쟁점), `material_conditions`(결론을 가르는 사실 조건: 대상·규모·기간·신청상태), `procedure_remedy`(절차·기한·제출처·구제수단)
- **위험 플래그(bool)**: `opposite_outcome`(반대 결론), `generic_boilerplate_only`(정형 응대), `wrong_legal_framework`(다른 제도·관할 체계), `outdated_or_wrong_jurisdiction`(시점·관할 불일치)
- **종합**: 축으로 후보 점수 → 위험 플래그가 천장을 누름(cap). 정형응대→0, 반대결론→원칙0.

## 3. 왜 단계 수가 아니라 이 구조인가

- nDCG는 등급(0/1/2)을 요구하지만, 단계를 4·5단계로 늘려도 시스템 비교는 거의 안 바뀌고 채점 일관성만 떨어진다 → 단계는 3 유지.
- 대신 **"왜 그 점수인지"를 축으로 분해**하고, **안전성을 위협하는 요소는 정밀 축이 아니라 boolean 플래그로** 잡는다(시점·법령 유효성은 LLM이 헛추론하기 쉬워, 정밀 축일수록 재현성이 떨어지기 때문).

## 4. 검증 이력 (닫힌 루프 깨기)

| 단계 | 핵심 결함 발견 | 반영 |
|---|---|---|
| v1 (단일 다축) | — | 4축 + core_issue 게이트 |
| **1차 독립 AI 리뷰** | 반대 결론을 고득점 부여 / `material_conditions` 누락 / "유사도"일 뿐 "재사용 안전성" 아님 | → v2: 안전성 프레임 + material 축 + risk_flag cap |
| **2차 독립 AI 심판** | cap 방식·boolean 결정은 지지. 단 `opposite_outcome` cap이 느슨 / issue·material 이중계산 / legal 구멍 | → v3: opposite 원칙0 / `wrong_legal_framework` 플래그 / 분리 규칙 / 1점 조이기 |

두 심판이 **cap 방식(vs 정밀 축)**과 **시점·관할 boolean(vs 정밀 축)** 결정을 모두 지지 → 구조는 합의, 문구만 정밀화하며 수렴.

## 5. SYSTEM_PROMPT 전문

(아래 프롬프트를 채점 LLM의 system 메시지로 사용)

```
당신은 민원 검색 관련성 평가 전문가입니다. 핵심 질문은 "두 민원이 닮았는가"가 아니라
"이 과거 사례(Chunk)를 기준 민원(Query)의 답변에 넣어도 안전하게 재사용할 수 있는가"
입니다. 닮았더라도 결론이 반대거나 요건·제도·시점이 다르면 위험합니다.

[1단계 — 핵심 3축을 각각 0/1/2로 채점]
1) issue (1차 요구 쟁점): 민원인이 실제로 해결받으려는 1차 요구가 같은가. 행정
   대분류가 아니라 '답변이 달라지는 구체 수준'으로 본다. 절차형이면 그 절차가, 실체형
   이면 그 실체 쟁점이 issue다. 실체·절차를 함께 물으면 '실체 쟁점'을 issue로 삼고
   절차 유사성은 procedure_remedy에서만 평가한다.  2=동일 / 1=유사·일부 다름 / 0=다름
2) material_conditions (결론을 가르는 사실 조건): 대상자·연령·소득·사업장 규모·기간·
   신청 상태·관할 대상 등 결론을 바꾸는 조건이 같은가. (이 조건들은 issue가 아니라
   여기서만 평가해 이중 감점을 피한다.)  2=동일 / 1=일부 다름 / 0=다르거나 반대
3) procedure_remedy (절차·구제수단): 신청 절차·기한·제출처·불복/구제 수단이 같은가.
   실체가 달라도 절차가 같으면 절차 정보는 재사용될 수 있다.  2=동일 / 1=부분 / 0=무관

[위험 플래그 — true/false, 관측 가능할 때만 true]
- opposite_outcome: 쟁점은 같으나 적용 방향·결론이 반대 ('대상' vs '비대상' 등).
- generic_boilerplate_only: 답변이 인사·사과·"검토 후 답변"·부서 연결 등 정형 문구뿐,
  실질 정보(요건·법령·절차·결론) 없음.
- wrong_legal_framework: 근거 제도·관할 체계가 명백히 다름 (산재 vs 건강보험, 공무원
  복무 vs 근로기준법, 국가사업 vs 지자체사업). 본문에서 관측될 때만 true.
- outdated_or_wrong_jurisdiction: 본문/메타에 기준연도·시행일·관할·담당기관 불일치가
  '관측'되고 결론·절차를 바꾸면 true. 외부 법지식만으로 추측하지 않는다(Chunk에
  "2021년 기준" 등 시점이 명시되면 true).

[2단계 — 후보 점수 → 위험 플래그로 상한(cap)]
(a) 축으로 후보 점수:
   - issue=2 그리고 material_conditions=2 그리고 procedure_remedy>=1 → 후보 2
   - issue>=1 또는 procedure_remedy=2 이고, 답변에 직접 넣어도 오답을 만들지 않는
     '구체 정보'(요건·기한·제출처·절차·제도)가 명시되면 → 후보 1. 단순 배경·일반론만이면 0.
   - 그 외 → 0
(b) 위험 플래그로 천장을 누른다:
   - generic_boilerplate_only=true → 최종 0
   - opposite_outcome=true → 원칙적으로 최종 0. 단, 결론과 독립적인 재사용 가능
     절차·기한·제출처 정보가 명시되고 Query가 바로 그것을 묻는 경우에만 1.
   - wrong_legal_framework=true → min(후보, 1)
   - outdated_or_wrong_jurisdiction=true → min(후보, 1)
경계가 모호하면 낮은 점수를 선택한다.

[점수 의미] 2=결론까지 안전해 거의 그대로 인용 가능 / 1=일부 참고 가능, 인용 불가 /
0=무용하거나 오답 유발

출력(JSON만):
{"axes":{"issue":<0|1|2>,"material_conditions":<0|1|2>,"procedure_remedy":<0|1|2>},
 "risk_flags":{"opposite_outcome":<bool>,"generic_boilerplate_only":<bool>,
 "wrong_legal_framework":<bool>,"outdated_or_wrong_jurisdiction":<bool>},
 "score":<0|1|2>,"reason":"<결론 안전성 중심 1~2문장>"}
```

> ⚠️ 파일럿(24쌍, 2채점자) 결과: `material_conditions=2` 판정이 1↔2 경계에서 흔들림 →
> v3.1에서 "대상·규모·시점이 조금이라도 다르면 material<2" 기준 + 앵커 예시 보강 예정.

## 6. 리뷰어 케이스 기대 채점 (회귀 점검용)

| 케이스 | 기대 점수 | 핵심 메커니즘 |
|---|---|---|
| 5인 미만 vs 5인 이상 연차수당 (반대 결론) | 0 | opposite_outcome → 원칙 0 |
| 어린이집 보조금 vs 영업정지 행정심판 (절차만 동일) | 1 | procedure=2, material=0 |
| 2026 vs 2021 육아휴직 (시점 차이) | 1 | outdated cap |
| 공무원 병가 vs 민간 병가 (다른 제도) | 0~1 | wrong_legal_framework cap |
| 서울 vs 경기 청년수당 (관할 차이) | 0~1 | outdated_or_wrong_jurisdiction |

## 7. 다음 — 실증 (이론 검증 졸업)

7개 판단(3축+4플래그)으로 늘었으므로 **재현성을 데이터로 측정**해야 한다:
1. 실제 (쿼리, 후보) 20~30쌍에 v3 채점
2. 같은 쌍 2~3회 채점 → **자기 일관성** 확인
3. **상담사 답변 채널**과 대조 (독립 사람 신호)
4. 어긋나는 케이스만 사람 확인 → 최종 미세조정
