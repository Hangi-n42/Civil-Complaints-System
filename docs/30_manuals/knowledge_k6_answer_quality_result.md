## 1. 왜 이 비교를 했는가

v6는 모델이 선택하지 않은 사실도 본문에 자동으로 추가했다. 필요한 정보가 화면에 있다는 사실과 질문에 정확히 답했다는 판단을 분리하기 위해, 동일한 수락 사실로 질문 요구 정리·선택·짧은 답변을 한 호출에 수행하는 두 후보를 구현했다. 정답 기준을 줄이거나 본문 누락을 상세 패널의 정보로 보충해 통과시키지 않았다.

- A: 기존 속성 묶음 추천 + 추천 밖 사실까지 정본으로 표시.
- B: 속성 묶음 + 질문 요구 + 근거 ID를 연결한 짧은 답변.
- C: B와 같은 지침/출력 + 출처별 같은 행/설명 문맥으로 묶은 입력.
- Qwen 추가 비교는 C 하나만 사용. EXAONE의 B는 A-5 메타데이터 범위 재해석·출처 혼합과 새 인과 설명을 만들었고, C는 B보다 짧으며 서류 경로에 HTML 태그를 쓰지 않았다. **C도 실패 후보이며 검증된 우월성은 아니다.** Qwen에 맞춘 프롬프트 수정은 하지 않았다.

공개 검색 요청에 모델/후보 선택 옵션을 추가하지 않았다. 후보 결과에는 `requirements`, `fact_details`, `answer_style=concise_grounded`가 있지만 **실제 검색 API 기본 동작은 A**다. 후보가 채택되지 않았으므로 본문/접힌 상세 화면으로의 전환도 적용하지 않았다. 실험 산출물을 운영 품질 개선으로 표현하지 않는다.

추가 라이브러리·평가 호출·재작성 루프·모델 자동 선택·캐시·그래프 DB 없음. 활성화나 원장 사실을 수정하지 않고 검색 실행 기록만 추가했다.

## 3. 비교 조건과 시간

기존 3건 × A/B/C를 먼저 실행한 뒤 추가 4건 × A/B/C를 실행했다. 프롬프트/예산 수정과 재실행은 없었다. EXAONE에 중요한 오류가 남아 같은 C로 Qwen 7건을 추가했다. 모두 temperature 0, 컨텍스트 16,384, 출력 1,536토큰, 프롬프트 상한 12,000자. B/C 실제 입력은 1,849~6,434자였다.

**28회 모두 모델 1회, JSON 정상 종료(`done_reason=stop`), 절단/형식 실패 0회.** Qwen 7회는 HTTP 전송 직전 요청 본문을 기록해 `think=false`와 동일 예산을 확인했다. 이는 출력 내용의 정확성 보장이 아니다.

| 방식 | 질문/호출 | 모델 시간 합계 | 전체 시간 합계 | 본문 평균 길이 |
|---|---:|---:|---:|---:|
| EXAONE A | 7 / 7 | 18.100초 | 24.540초 | 768.6자 |
| EXAONE B | 7 / 7 | 45.368초 | 51.044초 | 204.0자 |
| EXAONE C | 7 / 7 | 40.024초 | 45.607초 | 159.4자 |
| Qwen C | 7 / 7 | 31.005초 | 37.392초 | 132.4자 |
| 합계 | 28 / 28 | 134.497초 | 158.583초 | — |

길이는 `len(answer)`이며 공백/줄바꿈 포함, 별도 한계/인용/상세 패널 제외다. 한계 문장도 읽고 중복·정확성을 검수했다. 문장을 생성하는 B/C와 ID만 선택하는 A의 작업량이 다르고, 모델 로딩/프롬프트 캐시 영향을 분리하지 않은 1회씩의 실행이므로 일반 속도 순위로 해석하지 않는다.

- 질문마다 네 방식의 실제 선택 주장 집합 동일. B/C는 묶음 구조 외 사실/발췌/위치 내용이 동일함을 저장 입력으로 확인.
- 평가 정답·금지 기준은 생성 입력에 넣지 않음. 현재 프롬프트는 일반적인 비교/조건/방향 지침이며 과제 ID나 정답 숫자 분기 없음.
- EXAONE digest: `c7c4e3d1ca22fe9225f18b35eb719f67e2ca96a42e7fd17294a45b83ba8fbf03`.
- Qwen digest: `2a654d98e6fba55d452b7043684e9b57a947e393bbffa62485a7aac05ee4eefd`.

아래는 저장 출력과 고정 원문/판정 기준을 대조한 **AI 개발 검수**다. 현업 전문가 승인이나 통계적 정확도 측정이 아니다.

A는 좁은 조회에서도 모든 조회 사실을 펼쳤다. EXT-01은 431자, EXT-03은 1,178자로 질문하지 않은 속성까지 포함한다. EXT-04에서도 Q7 원문을 그대로 제시할 뿐 반대 방향 전제를 직접 구분하지 않는다. 기존 방식도 최종 목표를 충족했다고 보지 않는다.

구체적인 원출력:

- EXAONE B / EXT-02: “이 차이는 소수점 이하 조정이나 집계 범위의 미세한 차이로 인한 것으로 보입니다.” **원문 근거 없음.**
- EXAONE C / DEV-03: “PDF 자료: 국민임대 521세대, 영구임대 464세대 (총 985호)”. PDF 근거는 건설호수 985호·5개동이며 유형별 수치는 HTML 근거다.
- Qwen C / EXT-02: “5세대 차이 (1세대)”. 정수 차이와 동수 차이를 뒤섞은 출력이며 원문을 충실하게 요약하지 못했다.
- EXAONE B/C / EXT-04: “네, Q7의 설명에 따르면 …”. 뒤에 인용한 정방향 조건이 정확해도 질문의 반대 전제를 긍정한 문제는 해소되지 않는다.

**판정: 세 후보 모두 미채택.** 두 좁은 조회에서는 필요한 선택과 간결성이 실제로 개선됐다. 그러나 비교·인과·조건 방향에서 오류나 필수 정보 누락이 남아 전체 채택 조건을 통과하지 못했다. 이 결과로 Qwen 또는 EXAONE이 일반적으로 더 정확하다고 결론 내리지 않는다.

## 5. 확인 범위·재현·다음 작업

- 관련 자동 확인: `python -m pytest app/tests/unit/test_knowledge_search.py -q` → **21 passed**. 모델 의미 정확성 시험을 대체하지 않음.
- 새 후보를 기본 검색/화면에 연결하지 않아 새 답변 화면 검증·백엔드 재시작은 수행하지 않음. 기존 화면 검증을 새 후보의 통합 성공으로 재사용하지 않음.
- 로컬 원기록: `data/knowledge/pilot_v1/k6_quality_exaone_dev.jsonl`, `k6_quality_exaone_new.jsonl`, `k6_quality_qwen_c.jsonl`. 각 행에 요청/모델 digest/코드·평가 파일 해시/원프롬프트·해시/원출력/전체 응답/Run ID/시간 보존. 데이터 디렉터리는 Git 관리 대상이 아니므로 코드 복제만으로 해당 스냅샷·원기록을 재현할 수 없음.
- 비교 스크립트는 기존 출력 파일을 덮어쓰지 않는다. 새 파일을 지정해 실행하면 추가 호출이 발생하므로 재현은 필요할 때만 수행한다. 먼저 진행 중인 지식 실행을 마쳐야 한다.

```bash
.venv/bin/python scripts/compare_knowledge_k6_answers.py --split development --output data/knowledge/pilot_v1/example_dev.jsonl
.venv/bin/python scripts/compare_knowledge_k6_answers.py --split new_question_once --output data/knowledge/pilot_v1/example_new.jsonl
.venv/bin/python scripts/compare_knowledge_k6_answers.py --split all --variants C --model qwen3.5:4b --output data/knowledge/pilot_v1/example_qwen.jsonl
```

다음은 **실패한 비교/조건 답변의 출력 단위를 좁히는 작업**이 적절하다. 출처별 선택 사실을 수치·단위·시점이 고정된 짧은 비교 행으로 표시하고, 모델이 그 필드를 문장으로 다시 쓰며 출처를 섞지 않게 한다. 모든 사실을 다시 덧붙이는 방식은 피한다. 조건 질문은 ‘질문의 전제’와 ‘원문의 적용 방향’을 답변 항목으로 분리해, 정방향 원문 복사가 역방향 질문의 긍정 답변이 되지 않도록 한다. 이는 후속 설계 제안이며 효과는 아직 확인되지 않았다. 별도 심사/수정 모델 호출은 추가하지 않는다.

이번 추가 4문항도 이제 개발에 노출됐다. 후속 수정을 같은 7건으로만 성공 판정하지 말고, 변경한 실패 유형에 한정한 새 질문 소량을 먼저 고정해야 한다. K7은 K6 답변 품질 해결 이후다. **현재 사용자 결정이 필요한 사항 없음.** 계획의 중단 조건에 따라 이번에는 추가 튜닝·벤치마크를 확대하지 않았다.
