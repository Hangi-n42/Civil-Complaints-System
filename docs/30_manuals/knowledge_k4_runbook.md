## 구현 선택과 파일

## 실제 검토 결과

개발 검토의 결정자는 `codex-smoke`다. **AI 보조 원문 대조이며 현업 전문가 승인이나 독립 정답 평가가 아니다.**

- 전체 실행 `5d6dfb9b`의 명시 매핑 후보 108개를 검토 수락했다. 단지 6개와 공고 1개의 공식 ID, 공고→단지 관계 6개를 확인했다.
- HTML 설명의 총 985세대는 모델이 누락하여 기존 후보를 직접 수정했다. HTML 필드 521세대·CSV 990세대·설명 985세대를 출처/범위별 별도 주장으로 보존했다. 화면에서 985 후보의 범위 수정·저장 후 API 재조회 값도 일치했다.
- PDF 두 재확인 묶음의 이름·같은 행 주소를 CSV와 대조하여 **6개 별칭을 연결**했다. AI가 잘못 생성한 mention, 수량 근거 셀, 원문 값·단위, 월 형식을 수정하고 18개 사실(각 단지명·건설호수·최초입주월)을 검토 수락했다.
- 금산의 HTML 입주예정월 `2011-05`, PDF 최초입주월 `2011-06`, CSV 준공일 `2011-05-23`·입주지정시작일 `2011-05-26`이 별도 속성으로 유지된다. 월에 임의 날짜 01을 만들지 않았다.
- PDF 연결 해제 2건에서 각각 직접 의존 사실 3건만 proposed로 바뀌고 다른 후보 revision은 유지됐다. 원래 근거로 재연결 후 3건을 다시 수락했다.
- 최종 검토 대상 세 묶음 합계 **수락 134개**, 보류 178개다. 보류 중 108개는 PDF 재확인 때 중복 생성된 CSV 후보이며, 70개는 전체 실행의 미확정/오류 후보다. 최초·취소 실행의 초안은 비교 이력으로 별도 보존한다.
- 전체 실행 검토 후 검사 통과 117·오류 63·보류 70. PDF 두 묶음은 원문 수동 수정 후 오류 0, 수락 16/8개, 중복 CSV 보류 각 54개다. 이것은 수정 후 저장 검사 결과이며 모델 정답률이 아니다.
- 검토 후 전체 실행에서 참조하는 근거는 matched 101·unmatched 6개, PDF 두 묶음은 matched 67/59개다(묶음 간 중복 있음). 미일치 근거 후보는 보류했다. 문자열 위치 일치 자체는 의미 정확도를 보증하지 않는다.

로컬 상세 기록은 `data/knowledge/pilot_v1/k4_prepared.json`, `k4_execution_result.json`, `k4_review_smoke.json`, `k4_pdf_review_smoke.json`에 보존한다. 로컬 원문/원장은 Git 추적 대상이 아니다.

## 발견한 문제와 좁은 수정

1. **HTML 입력 범위:** 화면 기본값을 명시 필드·단지 설명 21개로 맞추고 선택/제외 수와 이유 표시. 전체 HTML 선택은 사용자가 명시할 때만 적용한다.
2. **PDF 슬롯 혼동:** 해당 단지표의 명시 헤더가 있을 때 출력 스키마를 3개 관련 슬롯으로 한정. 전체 스키마나 모델을 교체하지 않았다. 행 누락은 여전히 가능하다.
3. **근거·값 오류:** 값의 원문 문자열이 인용에 없는 경우, 조건/예외의 필드 근거가 없는 경우, 월 형식/정규화·날짜 메타데이터가 불일치하는 경우 수락 차단. 이 검사는 의미를 모두 검증하지 않는다.
4. **수정 경로:** 링크의 잘못된 원문명·근거 ID도 수정 가능하게 했다. 코드 없는 별칭의 원문명은 인용에 있어야 한다. 새 부분 근거가 없어도 고정 입력의 기존 K2 전체 블록 근거로 수정할 수 있다. 수정 전후는 결정 이력에 남긴다.
5. **구조가 잘못된 레코드:** 단위 전체를 버리지 않고 `invalid_records`에 원본/오류 보존. 잘림·JSON 오류는 단위 실패다. 성공 단위 재호출 없이 실패 단위부터 재개한다.

## 필요한 수준의 확인

- 추출 경계 5개, 저장/결정 경계 5개, 기존 K2 API 1개: **관련 테스트 총 11개 통과**. 추가 변경 뒤에는 영향을 받는 테스트만 다시 확인했다.
- 실제 LinkML 클래스 이름 대응, 한국어·반복/불일치 정렬, 고정 입력·성공 단위 재사용·중복 방지, 날짜/범위 보존, revision 충돌, 연결 해제·결정 이력 확인.
- 실제 모든 추출 Run 이후 기존 parse 포인터가 그대로인 것 확인.
- TypeScript·변경 화면 ESLint, pip check 통과. 브라우저에서 실행·범위 표시·저장 묶음 선택·수정 저장·PDF 이름/주소/행/열 조회 확인.
- 전체 12과제·기존 민원 전체 테스트·다중 모델 비교·Windows 실기는 실행하지 않았다.

## 실행과 다음 작업

Python 3.11.9 가상환경에서 `python -m pip install -r requirements.txt`. `.env`의 `KNOWLEDGE_ENABLED=true`, 상대 `KNOWLEDGE_DB_PATH`와 기존 `STRUCTURING_MODEL`/Ollama 설정을 사용한다. 공통 코드에 Mac 경로나 의존성은 추가하지 않았다. LangExtract 및 전이 의존성은 [재사용 기록](../third_party/knowledge_k3_reuse.md)을 따른다.

```sh
python scripts/prepare_knowledge_k4_schema.py
python -m uvicorn app.api.main:app --host 127.0.0.1 --port 8000
# 별도 터미널의 frontend 디렉터리
npm run dev
```

보충 스크립트는 기존 파일럿 원문과 K2/K3 로컬 원장이 준비되어 있어야 한다. 백엔드는 단일 프로세스만 사용한다. `http://127.0.0.1:3000/knowledge` → **개체·사실**에서 검토된 온톨로지, 기본 자료 범위와 CSV 등록부를 선택한다. 이미 저장된 결과는 재추출 없이 검토 묶음에서 확인할 수 있다.

다음은 **K5 검토된 지식 스냅샷·활성화·롤백**이다. 수락 후보만 선택하고 같은 필드의 재확인 중복 후보는 제외해야 한다. HTML 자유 서술 추출의 빈 값/슬롯 오류, PDF 행 누락과 근거 오연결은 별도 품질 잔여로 유지한다. `matched`·`accepted`·실행 succeeded를 운영 신뢰도나 자동 정확도로 승격하지 않는다. 현재 사용자 결정이 필요한 사항 없음. 이번 작업에서 커밋·푸시·GitHub 변경은 하지 않았다.
