# K3 온톨로지 초안 — 구현·실행 안내

기준일: 2026-09-27. K2 원장을 확장하며 실제 개체·사실 추출(K4), 활성 스냅샷(K5)은 구현 범위 밖이다.

## 구현과 선택 이유

- Ponytail 원칙으로 기존 SQLite·직렬 executor·Ollama 호출·원문 조회를 재사용. 별도 큐, 다중 에이전트 런타임, 외부 온톨로지 서버를 추가하지 않았다.
- 자료 분석 n회 → 설계 1회 → Qwen 반례 검토 1회 → 필요 시 수정 1회. 정상 n+2 또는 n+3 호출. 사람이 수정한 뒤 추가 AI 검토를 하지 않는다.
- 분석/설계는 `STRUCTURING_MODEL`, 반례 검토는 `CIVIL_LLM_RUBRIC_MODEL`과 `think=false`. 기존 민원 프롬프트·모델 역할은 변경하지 않는다.
- 원문·파싱 실행·블록·CQ·기준 버전을 Run에 고정. 실패·취소 재시도는 성공한 앞 단계 결과를 재사용한다. 실행 중 취소는 현재 모델 호출 종료 후 적용한다.
- K2의 parse 버전 갱신을 parse 작업에만 적용해 온톨로지 작업이 파싱 상태를 덮어쓰지 않게 했다.
- `ontology_versions`, `changesets`, `decisions`만 추가. LinkML 정본에 개념·속성·관계·근거·CQ를 보존하고 화면과 JSON Schema를 파생한다. 수정은 새 버전이며 원제안·결정 이력·ID는 보존한다.
- 후보 `proposed/accepted/deferred/rejected`, 온톨로지 `draft/reviewed`. reviewed는 사람 또는 시험 작업의 검토 결정 기록이며 운영 활성 상태가 아니다. 시험 확인의 actor는 실제 현업 담당자로 표기하지 않는다.

[재사용 출처·라이선스](../third_party/knowledge_k3_reuse.md). LinkML/runtime 1.11.1 직접 사용. LinkML의 전이 의존성 PyShexC가 chardet>=7.4.1을 요구하여 chardet 7.6.0과 이를 지원하는 requests 2.34.2를 함께 고정했다. 임의 다른 패키지 일괄 업그레이드는 하지 않았다.

## 실행·사용

K2와 동일한 Python 3.11.9 가상환경에서 `python -m pip install -r requirements.txt`. `.env`의 `KNOWLEDGE_ENABLED=true`와 상대 `KNOWLEDGE_DB_PATH`를 유지한다. 백엔드·프런트엔드 실행은 [K2 실행 안내](knowledge_k2_runbook.md)를 따른다.

1. `/knowledge` → **온톨로지 초안** 선택.
2. 파싱 완료 자료와 업무 질문(CQ) 선택·수정. 기본 자료는 최신 정정공고 HTML+CSV이고, CQ 초기값은 개발용 과제의 질문만 읽는다. 기대 판정·정답·새 확인용 과제는 읽지 않는다.
3. 생성 후 후보·근거·반례 의견 확인. 수락·수정 후 수락·보류·기각 가능. 속성·관계와 해당 개념은 함께 수락해야 한다.
4. 저장된 버전에서 LinkML·JSON Schema와 원제안·결정 이력 확인. 이후 작업의 기준은 reviewed 버전만 선택 가능.

API 접두사 `/api/v1/knowledge`: `POST /runs`의 kind=ontology에 `source_version_ids`, `cqs[{id,question}]`, 선택적 `base_ontology_version_id` 전달. 재시도는 kind와 `retry_of_run_id`만 전달. `GET /ontology-cqs`, `/ontologies`, `/ontologies/{id}`, `/candidates?changeset_id=...`, `POST /changes/{id}/decisions` 추가. 결정 요청은 expected_changeset_revision·actor·decisions를 받으며 오래된 revision은 409다.

## 실제 확인 중 발견·수정한 문제

- EXAONE이 근거 필드 이름을 바꾸고 CQ에 문서 ID를 반환: 고정 근거 타입·허용 CQ ID를 출력 스키마에 명시.
- 여러 표 셀의 내용을 하나의 인용으로 합성: 모델은 근거 ID를 선택하고 서버가 해당 고정 블록의 원문 인용을 붙이도록 변경. 사람이/API가 제공한 인용은 여전히 문자 일치 검사. 위치 일치는 의미 정확성 보증이 아니다.
- 같은 인용이 분석 관찰마다 반복되어 설계 입력 23,846자로 초과: 입력 내 동일 인용을 한 번만 제공. 관찰과 원문을 제외하거나 재요약하지 않고 동일 입력을 9,789자로 줄였다.
- 초안에서 코드·명칭을 별도 개념으로 생성하고 Qwen이 CQ의 집합 표현을 실제 명칭 불일치로 판단: 포함/제외 필드 필수화, 업무 대상 유형과 속성 구분 및 CQ 해석 지침 보완. 이는 모델 정확성 보증이 아니다.
- 속성/관계의 domain_id가 누락된 출력: 출력 스키마를 후보 종류별로 구분하고 참조 필드를 필수화. 없는 클래스 참조는 완료·수락으로 통과시키지 않는다.

초기 예산은 분석·검토 출력 2,048, 설계·수정 4,096토큰, 컨텍스트는 분석 16,384·후속 32,768이다. 분석 원문 4,000자/묶음, 후속 프롬프트 12,000자 상한. 상한 초과·잘린 출력은 실패로 표시한다. 문자 수는 정확한 토큰 수가 아니다. 자료 분석의 핵심 관찰 최대 12개/묶음은 초안용 선택이며 전체 사실 추출을 의미하지 않는다.

## 실제 확인 결과

최신 양산 정정공고 HTML `20796`과 관련 6개 단지 CSV, 개발 CQ `DEV-02/DEV-04`의 질문만 사용했다. 같은 공고군의 실패·발견 문제만 수정하여 다시 실행했으며 별도 사례나 평가 정답을 추가하지 않았다.

최종 실행 `93279f8fb0e8476f94754deed2db1500` / `ontology-v6`:

| 단계 | 호출 | 실측 모델 대기 |
|---|---:|---:|
| 자료 분석 | 3 | 61.993초 |
| 설계 | 1 | 53.502초 |
| Qwen 반례 검토 | 1 | 22.057초 |
| 수정 | 1 | 67.321초 |
| 합계 | **6** | **204.873초** |

실행 전체 경과 205.970초. 실제 Qwen 호출은 `think=false`, 응답 종료 이유는 모든 단계 `stop`이다. 출력·컨텍스트 예산은 초기값을 유지했다. 후보는 **개념 1·속성 8·관계 1, 총 10개**다.

초기 시행착오도 원장에 남겼다. v1(1회/36.521초), v2(1회/23.661초), v3(3회/49.997초), v5(4회/103.148초)는 실패, v4(6회/175.310초)는 구조상 완료됐지만 의미 문제가 있었다. 최종 v6까지 같은 자료 디버깅 총 **21회/593.510초** 모델 대기다. 이는 성능 비교나 독립 품질 평가가 아니다.

Mac 화면에서 원문 위치 확인 → 주택단지 정의 수정 후 수락 → 자기 참조 관계 보류 → 검토 버전 재조회를 수행했다. `actor=codex-smoke`로 2개 결정을 기록했고 현업 승인이 아님을 사유에 명시했다. 수정 후에도 `CONCEPT_001` ID가 유지되며 LinkML/JSON Schema의 정의가 일치했다. 검토 버전 `bcee923633524b28846dbe1d39cb6976`에는 시험 수락한 개념 1개만 있고 나머지 후보 9개는 미해결이다.

관련 자동 확인은 K2 6개와 K3 7개, 총 13개 통과. 파싱 포인터 보존, 실패/취소/재시작 후 성공 호출 재사용, 잘린 출력·없는 근거·인용 불일치·잘못된 참조 거부, 결정 충돌/ID/버전 보존, 기존 Ollama 문자열 반환을 확인했다. 프런트엔드 TypeScript·해당 파일 ESLint와 `pip check`도 통과했다.

### 의미 검토에서 남은 문제

- Qwen은 `C02748`을 숫자처럼 해석하고, 정상적인 date 타입도 문자열 변경 대상으로 지적했다. 반례 의견 자체가 정답이 아니다.
- 설계/수정 결과에 코드와 이름을 연결한다는 주택단지 자기 참조 관계가 남았다. UI 확인에서 보류했다.
- `임대유형`과 `주택유형`의 혼동, 월 단위 정보를 date로 정의한 제약, 날짜 역할 누락·재지정이 남았다. 구조·인용 검사를 통과해도 의미 정확성은 보장되지 않는다.
- 수정 후 AI 재검토를 추가하지 않았다. 화면에 수정 전 의견이라는 점을 표시하며 최종 해결 판단은 원문을 보는 검토 작업에 남긴다.

따라서 K3의 **초안 생성·검토 도구 동작**을 확인했으며 완성된 업무 온톨로지나 AI 평가 정확도를 입증한 결과는 아니다. K4 입력으로 사용하기 전 날짜·유형·관계 후보를 검토해야 한다.

## 남은 범위

Windows 실행·전체 12개 평가 과제·현업 사용자 효용·모든 문서의 의미 정확도는 미검증이다. 실제 처음 확인한 자료 범위를 넘어 성능이 입증됐다고 보고하지 않는다. 다음은 K4 공식 ID 연결·근거가 붙은 사실/관계 후보 구축이며, K3 검토 결과를 그대로 운영 활성 지식으로 사용하지 않는다.
