# K5 구현·공고군 확인 결과

- 기준일: 2026-09-28. [구현 계획](../05_plans/company_knowledge/k5_implementation_plan.md), [최소 계약](../05_plans/company_knowledge/contracts.md).
- 상태: **K5 기능 구현 및 현재 공고군 확인 완료**. Local/Global 검색·자동 정정 영향 분석은 후속 단계다.
- 진행 이유: K4 수락 139개를 과거 실험 후보와 구분해 고정하고, 사용 중단된 근거가 롤백으로 다시 사용되지 않게 하기 위해 기존 SQLite 원장에 스냅샷과 별도 상태 이력을 연결했다.
- Ponytail 적용: 신규 의존성·LLM 호출·작업 큐·그래프 DB·추가 승인 화면 없음. 기존 검토 API·LinkML·Next.js 재사용.

## 구현 내용

| 변경 파일 | 역할 |
|---|---|
| `app/knowledge/snapshots.py` | 명시적 다중 묶음 선택, 불변 복사, 활성화/롤백, 사용 상태, 상태를 적용한 조회·JSON/CSV |
| `repository.py`, `schemas.py`, knowledge router | snapshots/knowledge_state/availability_history/snapshot_events 4개 테이블, 요청 계약, 기존 성공/오류 봉투 |
| `extraction_store.py`, `service.py` | 수락 사실 수정·직접 연결 변경의 needs_review, 기존 blocked 유지, 감사 화면의 사용 제한 표시, 명시적 유효기간 입력 검사 |
| `KnowledgeSnapshots.tsx`, `/knowledge/page.tsx`, `KnowledgeExtraction.tsx` | 지식 버전 탭, 묶음/후보 선택, 활성화·롤백, 원문 블록/위치, 상태·이력, 내보내기, 기존 검토 화면의 제한 표시 |
| `app/tests/unit/test_knowledge_snapshots.py` | 선택/충돌·불변성·롤백 제한·수정 후 재검토·유효기간·다중 묶음/API·불완전 후보 회귀 확인 |

스냅샷은 원문 파일을 다시 복제하지 않으며, 선택한 연결·개체·주장·근거/위치·자료 버전·LinkML 정본을 저장한다. 현재 후보를 재조회해 과거 내용을 재구성하지 않는다. 신규 생성 때 선택 묶음 revision과 연결 revision을 대조한다. 생성과 활성화는 별도 동작이다.

사용 상태는 주장뿐 아니라 필드·주체/대상 연결·공식 개체 식별 근거와 그 자료 버전에 적용된다. 넓은 자료 중단을 개별 주장 allowed로 우회할 수 없다. 수락 사실을 수정하거나 연결을 바꾸면 직접 의존 주장은 needs_review가 되며, 재수락만으로 제한을 풀지 않는다. 후보/원문 감사 화면은 내용을 숨기지 않고 사용 제한을 표시한다.

조회·내보내기는 제한된 주장의 값을 제외하고 제외 ID·원인을 반환한다. JSON은 구조를, CSV는 주장별 값과 JSON 형식 근거 위치/출처를 보존한다. 원문 블록 전체·인용문은 파일에 포함하지 않고 기존 원문 화면에서 확인한다. 사용 상태와 이용허락·현업 정확성은 별개다.

`as_of`는 `valid_from`/`valid_to`로 명시된 일 단위 유효기간과 근거가 있을 때만 적용한다. 준공일/입주월을 유효기간으로 추정하지 않는다. 현재 공고군은 시점 판정이 `unverified`이며, 검토된 수량을 특정 업무일의 현행값으로 인증하지 않는다.

## 실제 공고군 1회 확인

입력은 [K5 선택 기록](../../configs/knowledge/pilot_v1/k5_review_selection.json)의 두 묶음/revision 4다. 새 추출·생성 없이 기존 수락 항목만 사용했다.

| 단계 | 실제 결과 |
|---|---|
| S1 생성 | `1baa816ee0fe474db6bc39c311defd6b`, 개체 7·연결 31·주장 103. 생성 직후 활성 ID는 null 유지 |
| S1 활성화 → S2 생성/활성화 | S2 `8fc330a1085f44b4813466e015fdd549`, 개체 7·연결 32·주장 107. parent=S1 |
| 화면에서 PDF 근거 중단 | 물금2 `452호`, 인쇄 4쪽/물리 2쪽 오른쪽, 표 2·행 1·열 3. 근거 `16d684702f6fc0ca8926e2ed9d9af833`를 blocked로 변경 |
| S2 조회/내보내기 | 주장 106·제외 1. JSON·CSV 각각 106행 확인 |
| 화면에서 S1 롤백 | 주장 102·제외 1. 중단한 근거의 제한 유지, status_revision=1 |
| 화면에서 재허용 후 S2 복원 | 시험 종료 사유로 allowed, status_revision=2. 주장 107·제외 0 및 JSON/CSV 각각 107행 확인 |

제외된 주장은 `7b884b73ce86122c79238615de2dd21b`다. 생성/활성화는 API로, 중단·롤백·제외 사유 조회·재허용·최종 복원은 브라우저 화면으로 확인했다. 마지막 상태는 **S2 활성, 시험 근거 allowed**, 활성화/롤백 이력 4건이다.

추가 LLM 호출은 **0회**다. 기존 Run 원장의 누적 호출 수 30이 확인 전후 동일하다. 상세 결과는 Git 제외 로컬 `data/knowledge/pilot_v1/k5_result.json`에 저장했다. 위 ID는 이 로컬 원장에 종속되므로 코드만 복제하면 같은 자료가 생기지 않는다.

## 관련 자동 확인·전문가 검수

- K5 관련 **7개**, 기존 K4 저장·검토 **5개** 통과. 후속 변경은 해당 K5 범위만 재확인했다.
- TypeScript 검사 및 변경 화면 ESLint 통과. 기존 전체 민원 테스트·12과제·추가 모델 실험은 반복하지 않았다.
- 백엔드/원장 전문가와 제품/프론트엔드 전문가 역할의 **독립 AI 에이전트 2개**가 코드 기반 검수했다. 외부 현업 전문가 승인과 구분한다.
- 반영: 유효기간 입력 형식/근거/순서 검사, CSV 출처·위치, 잘못된 후보 구조에서 감사 주석 오류 방지, 화면과 내보내기 필터 일치, 원문 블록 열람, 상태 조회 실패 시 다른 대상의 상태가 섞이지 않게 처리.
- 두 에이전트의 수정 재검수에서 잔여 중요 문제를 발견하지 못했다. 모든 오류가 없거나 운영 준비가 입증됐다는 뜻은 아니다.
- 설치된 Next.js의 안내된 로컬 docs 경로가 없어 [공식 use client 문서](https://nextjs.org/docs/app/api-reference/directives/use-client)를 확인했고 기존 클라이언트 컴포넌트 방식을 유지했다.

## 사용 방법·남은 범위

1. 기존 API/프론트엔드 실행 후 `/knowledge` → **지식 버전** 탭을 연다. 현재 로컬 화면은 `http://127.0.0.1:3000/knowledge`다.
2. 새 버전은 reviewed 온톨로지와 수락 묶음·후보를 선택한다. 필요한 주체/관계 대상 연결도 함께 선택하고 결정자·사유를 입력한다.
3. 만든 버전을 확인한 뒤 활성화한다. 이전 버전을 선택해 같은 버튼으로 되돌릴 수 있다.
4. 주장/근거/자료의 상태·사유를 확인하고 변경한다. 제외 목록의 사유 버튼으로 중단된 근거에 다시 접근할 수 있다.
5. 대상·기준일을 조회한 뒤 JSON/CSV를 내보낸다. 아직 조회하지 않은 필터 입력은 파일에 적용하지 않는다.

K5는 로컬 단일 운영자용이다. Mac에서 확인했으며 Windows 실기는 수행하지 않았다. 공통 코드에 Mac 절대 경로나 새 의존성은 넣지 않았다. 상태 이력은 현재 파일럿 규모에서 순차 조회하며 일반 변경 영향 전파는 없다. 자유 서술 추출의 완전성, 다른 PDF 양식, 현업 효용은 이번 확인 대상이 아니다.

다음 작업은 **K6 Local 검색**이다. 활성 스냅샷의 동일 사용 상태 필터를 재사용하여 개체·최대 2단계 관계·원문 근거를 검색과 답변에 연결한다. **현재 사용자 결정이 필요한 사항 없음.** 이번 작업에서는 커밋·푸시·GitHub 이슈 상태 변경을 하지 않았다.
