온톨로지는 LinkML 정본을 유지한다. LLM은 정규화된 값 대신 원문 문자열을 반환하므로, nullable 값 스키마를 그대로 복사하지 않고 검토된 정의의 안정 ID·대상·속성/관계 구분으로 작은 출력 계약을 만든다. 저장 단계의 타입·참조 검사는 유지한다. 다중값 속성의 신규 추출은 미지원으로 표시하며 기존 결과는 조회·검토할 수 있다. 다수 대상 관계는 개별 관계 사실로 유지한다.

숫자와 날짜는 코드가 변환하며 원문 없는 일 01을 만들지 않는다. 알려진 표의 주체/값 셀에만 같은 행 규칙을 적용하고 헤더·등록부는 구분한다. 한국어 접미사 때문에 LangExtract 토큰 정렬이 실패하더라도 **원문에 유일하게 존재하는 정확한 문자 구간**이면 그 위치를 사용한다. 반복·없는 인용을 유사 매칭으로 통과시키지는 않는다.

## 실제 화면 복구와 검증

- A5 재확인에는 자동 링크 1개·사실 4개가 있었다. 세 수량은 원문 대조와 저장 검사에서 확인됐다. 나머지 `국민임대, 영구임대 혼합단지`는 원문에 연속해서 없는 합성 표기라 수락할 수 없었다.
- 현재 검토된 정의에서 국민임대·영구임대는 **주택유형**이고, 임대유형은 CSV의 건설임대 등 별도 분류다. 이번 잔여는 주택유형 슬롯 자체가 틀린 사례로 보고하지 않는다.
- 브라우저에서 해당 합성 후보를 기각하고 원문 구간의 `국민임대`를 주택유형 수동 후보로 추가했다. 공식 링크·세 수량·수동 후보를 검토 수락하고 재조회했다. 결과는 수락 5·기각 1, 수동 추가 1, 결정 이력 7건. 원래 `units`와 호출 `metrics`가 그대로인 것을 확인했다.
- 결정자 `codex-smoke`는 AI 보조 개발 확인이다. 현업 승인·운영 활성화가 아니다. `국민임대` 1개 수동 추가는 복구 기능 확인이며 모든 유형의 수동 정리가 끝났다는 의미가 아니다.
- 관련 자동 확인 **17개 통과**: 기존 10개 + 신규 품질 5개 + 등록부 문맥 분리 1개 + 기존 API 1개. 새 인용 정렬 경계도 기존 검사에 포함했다. 실패한 새 검사에서 문자 길이 기대값 오기를 바로잡고 해당 범위만 재확인했다.
- TypeScript·변경 화면 ESLint 확인. 전체 민원 테스트·12과제·모델 비교·Windows 실기는 수행하지 않았다. 새 공통 코드에 Mac 절대 경로나 의존성은 추가하지 않았다.

상세 원장/출력은 로컬 `data/knowledge/pilot_v1/k4_quality_result.json`, `k4_quality_a5_result.json`, `k4_quality_review_result.json`에 보존한다. 비교 스크립트는 `--baseline-run <기존 실행 ID> --output <결과 JSON>`을 받는다. 새 실제 추출 Run을 만드는 명령이므로 조회 목적이면 저장 결과를 열면 된다.

## 남은 한계와 다음 작업

- 알려진 LH 단지표에만 결정적 매핑을 적용한다. 다른 PDF 양식·병합 구조는 미지원/검토 필요이며 범용 PDF 추출 품질을 입증하지 않았다.
- 단지 이미지 설명은 현재 원문에 맞춰 세대수·주택유형만 추출한다. 그 밖의 속성은 CSV/공식 HTML 필드 또는 다른 추출 범위를 사용해야 한다.
- 자유 서술의 범위 누락·합성 원문값 등 의미 오류는 남는다. 전체 비교의 동수 오류는 수락 검사에서 걸렸으며, 최종 축소 계약으로 모든 단지를 다시 확인하지 않았다. 설명 단위 반환이 모든 사실의 발견을 보장하지 않는다.
- 과거 현업 검토 시간이 없어 노동 절감률은 제시하지 않는다. 새 모델이나 자동 평가 루프를 추가할 근거도 이번 확인만으로 충분하지 않다.
- 다음은 [K5 구현 계획](../05_plans/company_knowledge/k5_implementation_plan.md)의 저장/API부터 구현하는 것이다. 두 묶음의 명시적 선택, 불변 스냅샷, 최신 사용 상태를 유지하는 롤백으로 연결한다. K5는 이번 작업에서 구현하지 않았다. **현재 사용자 결정이 필요한 사항 없음.**
