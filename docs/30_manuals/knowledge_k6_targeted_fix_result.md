> **후속 인도 결정(2026-09-29):** K6 구현을 인도하고 K7으로 진행한다. 정확하고 간결한 답변의 남은 문제는 [모델 교체 후 #516](https://github.com/Hangi-n42/Civil-Complaints-System/issues/516)으로 이관한다. 아래 실험·미채택 결과는 그대로 보존하며 당시 K7 보류 판단만 이 결정으로 대체한다.

- 2026-09-29. [계획](../05_plans/company_knowledge/k6_targeted_fix_plan.md)에 따른 D 후보 구현과 검수 완료. **세 문제 전체 해결은 미완료이며 D는 기본 검색에 채택하지 않음.**
- 출처/수치 재작성과 없는 원인을 자유 서술하는 경로는 좁혔다. 그러나 조건 방향 오판 및 있는 근거를 확인 불가로 답하는 회귀가 남았다. 기존 A, 민원 생성/평가 설정, 활성 지식 보존. 실험 당시에는 커밋/푸시하지 않았으며 이후 K6 구현 인도에 포함.

## 1. 구현 선택과 실제 변경

## 2. 실패를 포함한 실행 기록

처음 계획한 9개 고정 질문 외에 **실패 경로 수정/진단 16회**를 수행했다. 총 **25회**, 최종 9건의 모델 시간 합계 **20.562초**, 검색 전체 시간 합계 **27.893초**다. 빠른 응답을 정확성 성공으로 평가하지 않았다.

| 실행 | 호출 | 확인한 결과 |
|---|---:|---|
| D1 기존 7건 | 7 | 사실 정본화로 숫자 재작성은 막음. checks가 비어 판단 누락, 다른 단지 주택유형 대신 임대유형 선택 회귀 |
| D2 실패 4건 | 4 | 질문별 항목 필수화로 판단 생략 개선. 조건 역방향은 supported 오답. 원질문 재작성 1건은 발췌 검사에서 거절. 판단 근거가 본문에 과도하게 펼쳐짐 |
| D3 실패 3건 | 3 | 질문 q-ID 선택으로 원질문 재작성 제거. 판단 근거 자동 본문 추가 제거. 출처/인과 개선, 역방향 오판 유지 |
| 추론/endpoint 진단 | 5 | 동일 EXT-04 한 건만 비교. 아래 참조. 모두 채택하지 않음 |
| D3 나머지 기존 4건 + 신규 2건 | 6 | 최종 9건 구성. 정상 방향 신규 질문 성공, NEW-02 설명 요청의 확인불가 오판과 CHECK-01 설명 누락 발견 |
| 합계 | **25** | 20회 형식상 응답 반환, 5회 실행/형식 실패. 형식상 성공과 의미 정확성은 구분 |

최종 D3는 `qwen3.5:4b`, `/api/generate`, `think=false`, temperature 0, num_ctx 16,384, num_predict 1,536이다. 최초 3건과 나머지 6건 사이 답변 프롬프트/출력 계약은 바꾸지 않았다. 이후 전문가가 발견한 checks 개수 제한만 제거하고 자동 테스트로 확인했다. 이 제한 제거 후 모델 9건을 반복하지 않았다.

추론 진단은 동일한 조건 방향 질문에 한정했다.

- generate + think=true + 1,536: 최종 응답 빈 값, `done_reason=stop`, eval_count 62. 의미 오답으로 집계하지 않음.
- chat + think=false + 1,536: 여전히 잘못된 supported. endpoint 변경만으로 해결 안 됨.
- chat + think=true + 1,536 및 3,072: 모두 `done_reason=length`, 최종 답변 빈 값.
- chat + think=true + 3,072, 형식 강제 없이 스키마를 프롬프트에 제공: 역시 length/최종 답변 빈 값.

실측 절단 때문에 해당 진단에서만 출력 예산을 3,072로 늘렸다. 더 큰 예산/새 모델/반복 호출로 확대하지 않았다. **Ollama 형식 강제가 원인이라고 입증하지 못했고 추론 모드의 의미 품질도 비교할 수 없었다.** 생각 필드를 최종 답변으로 승격하지 않았다. 진단 중 추가한 공통 `GenerationService`의 chat 분기는 최종 코드에서 제거해 기존 민원 호출 계약을 그대로 유지했다.

로컬 Ollama 버전 0.34.3. 공식 [Thinking 문서](https://docs.ollama.com/capabilities/thinking)는 thinking과 최종 답변 필드를 구분하며, [Structured Outputs 문서](https://docs.ollama.com/capabilities/structured-outputs)는 생성 스키마와 응답 검증을 설명한다. 이 문서는 진단 방법의 참고이며 현재 로컬 실패의 원인을 입증하는 자료는 아니다.

24회 앱 경로의 모델 시간 합계 107.409초/전체 시간 합계 126.159초, 별도 HTTP 진단 1회는 요청 시간 40.058초. 총 요청 처리시간 합계는 166.217초이며 개발 작업 전체 소요시간이나 순수 모델 시간으로 해석하지 않는다.

## 4. 제3자 검수와 필요한 확인

독립 역할 에이전트 `k6_narrow_review`가 계획·코드·저장된 최종 9개 출력을 직접 검수했다. 원자료 대조를 수행한 AI 개발 검수이며 현업 사람의 승인이나 독립 모델 성능 평가가 아니다.

- 수치/출처 보존, 인과 추측 방지, 단순 조회/서류 관계의 개선 확인.
- EXT-04 역방향 오판, NEW-02 있는 근거에 대한 확인불가 오판, CHECK-01 본문 설명 누락 확인.
- D 미채택·A 유지에 동의. 추가 휴리스틱/자동 평가를 늘려 성공처럼 보이지 않게 할 것을 권고.
- 확정 코드 결함 1건: checks 최대 4개인데 질문 q-ID는 무제한 생성되어 질문이 5개면 정상 완료 불가능. **최대 4개 제한을 제거하고 5개 질문·미선택 사실 미표시 테스트로 수정 확인.**

관련 자동 확인: 검색/기존 Ollama 반환 계약 테스트 **29 passed**. 프런트 TypeScript·해당 컴포넌트 ESLint 통과. 전체 민원 테스트나 대규모 모델 비교는 수행하지 않았다. 기본 검색 전환이 없어 서버 재시작·새 D 화면의 실제 사용자 흐름 확인은 수행하지 않았으며, 타입/정적 확인을 브라우저 통합 성공으로 표현하지 않는다.

## 5. 재현 자료와 다음 작업

로컬 실행 기록은 `data/knowledge/pilot_v1/k6_targeted_*.jsonl`과 `k6_targeted_unconstrained_probe.json`이다. 최종 9건은 `k6_targeted_fix3.jsonl`의 3건 + `k6_targeted_final_remaining.jsonl`의 6건이다. 원프롬프트/원출력/요청 설정/Run ID/코드·설정 해시/HTTP 옵션/시간을 보존했다. 추론 내부 텍스트는 답변 기록으로 사용하지 않았다. 데이터 폴더는 Git 대상이 아니므로 저장소 복제만으로 로컬 스냅샷을 재현할 수 없다.

- **완료:** 세 오류를 겨냥한 출력 계약·정본 표시·실험 경로·화면 지원, 실패를 포함한 비교, 독립 검수, 검수 코드 결함 수정.
- **미완료:** 조건 방향의 신뢰성, 조회와 판단 구분의 회귀 해결. 따라서 실제 기본 검색에 D를 적용하지 않았고 K6 전체 완료/K7 착수로 표시하지 않는다.
- **다음:** 정본 선택/표시의 개선은 보존하되, 조회와 주장 판정 구분 및 조건의 선행/후행 관계를 다루는 방식을 다시 설계해야 한다. 같은 프롬프트 지시를 추가하는 것만으로 해결됐다는 근거는 없다. 전체 사실 자동 첨부나 무조건 확인 불가, 추가 judge 호출로 이 문제를 숨기지 않는다. 모델 변경이나 조건 구조화 중 어느 쪽이 유효한지는 이번 결과만으로 확정할 수 없다.
- **사용자 결정:** 현재 사용자 결정이 필요한 사항 없음. 이번 범위의 실행·검수는 종료하며, 채택 실패를 숨기기 위해 추가 예산/반복 실험을 확대하지 않았다.
