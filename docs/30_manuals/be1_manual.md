## 1. 문서 목적

이 문서는 BE1(팀장)의 실행 책임을 Week3~Week8 기준으로 명확히 고정한다.  
핵심은 데이터/구조화 품질과 KPI 관리가 검색/생성 품질로 연결되도록 팀의 기준선을 유지하는 것이다.

## 2. BE1 한 줄 정의

**BE1은 구조화 데이터 품질과 평가 체계를 소유하고, Week3 기준선(평가셋/메타데이터/KPI 리포트)을 고정하는 오너다.**

## 3. 현재 단계 진단 (2026-03-27)

- M1(W1~W2): 완료
	- ingest-structure-validate E2E 안정화
	- 샘플 50건+ 처리, 스키마 통과율 90% 기준 달성
- M2(W3~W4): 진행중
	- Week3 우선순위: 검색용 메타데이터 품질 보강 + 500건 평가셋 고정 + baseline 벤치마크
	- Week4 진입 게이트: 단일 RAG baseline 지표 확정(Recall@5, 4요소 F1, citation 정합성, latency)

## 4. BE1 최종 책임 범위

### 주 책임
- 구조화 데이터 계약 품질 유지(필드 누락/포맷 불일치 방지)
- 검색 메타데이터 품질 관리(region/category/date)
- 평가셋/정답셋 관리 및 버전 고정
- 구조화/검색/생성 KPI 산출 체계 운영
- 최종 보고서 및 발표 정량 근거 총괄

### 협업 책임
- BE2에 인덱싱 가능한 고품질 구조화 데이터 공급
- BE3에 검증 가능한 필드 규칙/오류 사례 전달
- FE에 화면 검증용 샘플 응답과 성공/실패 상태 사례 전달

### 담당 제외
- 벡터DB 내부 최적화 로직 주도(소유: BE2)
- `/qa` 생성 파이프라인 안정화 주도(소유: BE3)
- UI 컴포넌트 구현 주도(소유: FE)

## 9. BE1 핵심 리스크 관리

### 리스크 1: 구조화 품질 저하가 검색/생성까지 전파
- 징후: 검색 결과 관련성이 낮아지고 citation 신뢰도 하락
- 원인: 전처리 노이즈 및 필드 누락 방치
- 예방책: 주 2회 오류 샘플 리뷰와 규칙 회귀 테스트
- 대응책: 규칙 핫픽스 후 동일 평가셋 재측정
- 최악의 경우 폴백안: 고신뢰 카테고리 subset 기반 데모 시나리오 운영

### 리스크 2: 평가셋 품질 미고정으로 비교 불가
- 징후: 주차별 수치 비교가 의미 없어짐
- 원인: 케이스 구성/난이도 분포가 계속 변경됨
- 예방책: `evaluation_set.json` 버전 freeze 및 변경 승인 절차 적용
- 대응책: 변경 전/후 결과를 분리 보고
- 최악의 경우 폴백안: Week3 freeze 버전을 공식 비교셋으로 고정

### 리스크 3: 발표 직전 정량 근거 부족
- 징후: 슬라이드 수치 출처 추적 불가
- 원인: 로그-리포트-발표자료 연결 누락
- 예방책: 주간 KPI 테이블 누적 관리
- 대응책: 리포트 생성 스크립트 재실행 후 수치 재정렬
- 최악의 경우 폴백안: Gate A/B/C 핵심 지표만 우선 제시

## 10. 최종 완료 기준

- 구조화 품질을 필드 단위 수치로 재현할 수 있다.
- 평가셋/정답셋 버전이 고정되어 주차별 비교가 가능하다.
- 검색/생성팀이 사용할 데이터 계약이 일관되고 안정적이다.
- 발표 자료에서 데이터 품질 기여와 KPI 달성 근거가 명확하다.
