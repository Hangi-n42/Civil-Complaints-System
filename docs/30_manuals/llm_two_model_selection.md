# Gemma·Qwen 두 모델 역할 선정 및 실패 보완

2026-09-29. EXAONE을 유지하던 이전 비교와 달리, 이번 요구는 Gemma 4 31B와 Qwen 3.8 27B 두 후보 안에서 각 역할을 선택하는 것이다. 이전 평가를 폐기하거나 새 모델의 전체 우위를 전제하지 않는다.

## 비교 범위와 변경 이유

- 기존 생성·민원 구조화·민원 평가·K3 반례 검토 결과를 재사용한다. K3 분석·공개 K6 A·관련성 필터도 동일 저장 입력의 비교를 재사용한다.
- 기존에 실패한 K3 설계·수정, K4 추출, 피드백·재작성만 보완한 동일 프롬프트로 두 후보를 비교한다. 새 호출은 7입력×2모델로 시작한다.
- 피드백2입력: 일정 확약 오류와 실제 복합민원 저장 최종 답변. 재작성2입력: 일정 확약 제거와 같은 복합민원에 저장된 잘못된 피드백을 준 경우. 답변을 매번 생성해 입력을 바꾸지 않는다.
- K3 설계·수정은 기존 원문·관찰·후보·검토 의견을 고정하고, K4는 같은 A5 원문 블록을 사용한다. 사례별 기준과 실제 요청은 로컬 `data/model_role_comparison_20260929/two_model_followup/cases.json`에 실행 전에 저장했다.
- 핵심 사실 오류·필수 정보 누락·근거 연결·현재 출력 계약 준수를 비교한다. 단순한 분량 증가를 이득으로 세지 않는다. 두 후보 모두 실패하면 잔여 문제를 밝히고 상대적으로 나은 후보를 선택한다.

## 최소 보완

- 피드백: 점수·검토 의견을 사실로 간주하지 않고 원문과 대조. 근거 없는 부서·접수 경로·일정 보강 금지, 요청·의도와 완료·성과 구분.
- 재작성: 잘못된 피드백을 그대로 실행하지 않고 원문 우선. 과거 사례를 현재 이행 확약으로 바꾸지 않음. 요청 목록의 문자열 배열 계약 명시.
- K3: 정상 후보·근거 있는 CQ 필수 속성 보존, 같은 ID를 다른 날짜 역할에 재사용하지 않음. 분석·설계·수정을 각각 비교했지만 최종 선택이 모두 Gemma여서 기존 STRUCTURING_MODEL을 공유하고 모델을 실행 시작 시 고정.
- K4: raw_value는 원문 인용의 연속 부분 문자열, 여러 유형 합성 금지. 범위를 명시한 경우 scope_evidence도 명시.
- 새 K3/K4 실행과 직접 Ollama 호출에 비추론 모드 명시. 과거 recipe의 옵션 생략 값은 보존하되 변경된 recipe로 성공 산출물을 섞어 재시도하지 않음.
- 이전 두 모델의 K3 설계가180초를 초과했던 근거에 따라 설계 단계만360초 제한 적용. 출력·문맥 예산과 호출 횟수는 유지.

### 보완 전후

- K3 수정: Qwen은 ATTRIBUTE_006을 예정월에서 지정시작일로 바꾸고 예정월을 삭제했다. Gemma는006예정월/007최초월/008시작/009종료 의미를 보존했지만,002단지명에서 공식명을 제외하는 오류는 남았다. 자동 수락하지 않는 기존 후보 검토 흐름을 유지했다.
- K4 첫 보완: Qwen은 유형 합성값을 해소했으나 짧은 유형 단어가 원문에서 반복되어2개 인용 정렬 실패. Gemma는 수량3개와 혼합유형 설명1개가 통과했지만 유형값에 수량 설명이 붙었다.
- K4 두 번째 보완: 범주값과 인용문을 분리하고 인용에 주변 문장을 포함하도록 명시. 두 모델 모두 총985·국민521·영구464세대와 국민임대·영구임대의 고유5사실을 반환했고, 실제 어댑터·값 검사·인용 정렬 오류0. 같은 노출 사례 재확인이며 새 자료 전체 품질을 보장하지 않는다.
- 피드백: 원문 우선·요청/완료 구분·없는 정보 보강 금지 지시로 두 모델의 부서/일정 추가 요구 해소. 정상과 오류를 모두 포함한 대규모 검증은 하지 않았다.
- 재작성 첫 보완: 두 모델 모두 잘못된 피드백의 부서 예시를 따라 쓰는 문제 지속. Qwen은 일정 미확정에서 점검 미완료를 추론했고, Gemma는 신속 수리 확약과 과거 설치 추진 사실도 추가했다.
- 재작성 최종 보완: 입력 뒤에 한국어 최종 규칙을 배치해 피드백 예시를 사실로 복사하지 못하도록 명시. Gemma는2사례 목표 오류0, Qwen은1사례에 references 미지원 법령 유지. 이 법령은 원서비스의 별도 legal_citations에 확인 기록이 있으므로 **법 자체가 거짓이라는 판정이 아니라 고정 입력의 근거 범위 문제**다. Gemma가 법령을 제거한 것을 일반적으로 더 법적으로 정확하다는 주장으로 확대하지 않는다.

## 설정·코드

- 서비스 기본 모델과 `.env.example`, `configs/base.yaml`의 모델 표기를 두 모델 구성으로 갱신했다. 현재 앱은 환경변수를 읽으며 YAML을 런타임 모델 선택기로 사용하지 않는다.
- 로컬 `.env`도 동일 선택 적용. 생성·재작성·피드백 비교의 기존 로컬1536출력/8192문맥은 유지하고 신규 설치 예시에도 명시했다. 신규 설치의 코드 기본값도 검증된1536/8192로 맞췄다. 현재 로컬 실행의 출력·문맥 예산을 더 늘린 것은 아니다.
- 공통 HTTP timeout 기본값은 이전 실제 생성121초 초과 결과를 반영한180초. 설계만 `KNOWLEDGE_DESIGN_TIMEOUT=360`. 새 선택적 call timeout은 요청과 로그에 같은 값을 쓰며 서비스 객체를 바꾸지 않는다.
- K3/K4 recipe에 새 요청의 think=false를 기록. 과거 recipe의 미지정 think는 임의 변경하지 않는다. 기존 저장 결과·온톨로지·스냅샷·인덱스는 재생성하지 않았다.
- 직접 Ollama 경로와 K6에서도 비추론을 명시. 선택 기능은 비활성 상태를 유지한다.
- 모델 자동 선택기, 추가 수정 루프, 이중 모델 평가, 별도 큐·캐시·검증 플랫폼은 추가하지 않았다. Q0~Q7과 기존 인용·근거 검사는 유지했다.

설치·시작 방법은 [로컬 실행 문서](local_dev_runbook.md)를 따른다. 이전 EXAONE/Qwen4b 파일은 삭제하지 않았다. 실제 사용 모델2개와 디스크에 설치된 모델 개수는 다르다.

## 실제 서비스 확인

관련 자동 확인은 모델·recipe·재시도·파싱 상태·인용/저장 경계를 다루는 핵심26개가 통과했다(반복 실행 제외). 비활성 호출부의 비추론 옵션 변경과 관련된 verifier·인사이트 테스트15개도 통과했다. 전체 프로젝트 테스트나 이전12과제 평가는 반복하지 않았다. 독립 에이전트의 코드·원문 검수는 AI 개발 검수다.

선정 조합으로 기존 라우터를 ASGI에서 직접 호출하고 실제 검색·Ollama를 사용했다. 앱 시작 절차·브라우저 조작은 이 시험에 포함하지 않는다.

- 실제 검색→생성→평가→피드백→1회 재작성→재평가 1건: HTTP 200, **13호출·493.710초(8분14초)**. 필터1·생성1·초기 평가5·피드백1·재작성1·재평가4이며 Q2는 재사용했다. 비교20호출과 구분한다.
- 실제 요청 모두 `think=false`, 추론 출력 없음. Gemma→Qwen 피드백→Gemma 재작성 전환에서 모델 로드 시간은 각각12.253초·6.662초였다. 두 대형 모델 동시 상주를 전제로 하지 않았다.
- 네 요청을 모두 다뤘고 인용3개는 검색 원문과 일치했다. 구체 부서·접수 경로 창작은 없었으나, **현재 조치 약속과 근거 없는 ‘소관 부서가 상이’ 단정**이 남았다. 문의 안내·감사 문구도 반복됐다.
- Q3·Q4는 존재하는 구조화 citation을 두고 인라인 마커 부재를 이유로 낮게 평가했다. Q4의 별도 check는 `supported`여서 판단 이유가 모순된다. Q6는 반복을 놓쳤다. 실제 답변 결함과 평가 오탐을 구분해야 한다.
- 초기·최종 종합 점수는 모두3.55였다. 모델 점수는 정답이 아니며, 고정 비교와 검색 결과·초안이 달라 직접적인 전후 오류율 비교는 하지 않는다.
- 별도 법령 메타데이터의 `verified=true`와 피드백에 전달된 근거 범위는 구분했다. 법령 삭제를 법적 정확도 개선으로 세지 않았다.
- 독립 에이전트가 최종 답변·검색 원문·평가 결과를 대조했고 같은 한계를 확인했다. 이후 백엔드를 새 설정으로 재시작하고 `/health` 정상 응답을 확인했다.

- 형식 처리: 기존 일반 문의·감사 종결이 답변 끝에 중복되는 확인 사례만 제거했다. 본문 보존·종결 1회·재처리 동일성 테스트를 추가했다.
- 저장된 실제 실패 답변·검색 자료를 재사용했다. 첫4호출173.484초에서 재작성 후 네 요청을 보존하고 조치 약속·부서 상이 단정을 제거했으며, Q6도 기존 반복을 감지했다. 그러나 Q3 오탐과 Q4의 ‘확인 필요=조치 계획’ 오해는 남았다.
