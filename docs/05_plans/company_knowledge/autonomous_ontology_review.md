# 자율 탐색 온톨로지 구축 설계 검수 기록

- 작성일: 2026-09-30.
- 대상: [구현 계획](autonomous_ontology_plan.md), 첨부 문서, 현재 입력 도구·K2~K6 코드, 인용한 공식 문서·연구.
- 방법: 역할이 다른 전문가 페르소나 AI 에이전트 3개가 독립 조사 후 계획 초안을 검수. 아래 지적을 주 에이전트가 계획에 반영.
- 범위: 설계·코드 계약 검토. 구현 완료, 실제 모델 성능, 현업 전문가 승인 또는 사람 감독 효과를 확인한 결과가 아님.

## 1. 검수 역할과 판단

| 관점 | 확인 범위 | 판단 |
|---|---|---|
| 백엔드·온톨로지 저장 | 원장·파싱 포인터·후보 저장·버전·승인·K4 호환성 | 기존 저장소와 직렬 실행기 확장 가능. 버전 충돌과 불완전 후보 저장 계약 보완 필요 |
| 온톨로지 방법론·정보검색 | 전체 구조 조사·표본·반례·종료·공통 기반·오픈소스 | 방법 조합은 구현 가능. 역사 실행의 용어 계보 격리와 실제 분석 완료 기준 보완 필요 |
| 인간 감독·보안 | 검수 문맥·자동화 편향·누락 시험·도구 권한·자료 사용 중단 | 최종 검수 중심 흐름 적절. 오류 통과 지표와 교차 비교·중단 자료의 파생물 처리 보완 필요 |

세 에이전트 모두 전체 아키텍처를 다시 설계해야 할 차단급 결함은 없다고 판단. 이는 제한된 AI 설계 검수의 결론이며, 실행 결과를 보증하지 않음.

## 2. 지적과 반영

| 발견 사항 | 계획 반영 | 위치 |
|---|---|---|
| 현재 DB에 검토된 온톨로지 계보별 head가 없어 동시·순차 변경 충돌을 충분히 비교할 수 없음 | 작은 `ontology_heads` 테이블, 실행 기준·예상 head 검사, 결정·버전·head 원자 저장. 같은 changeset의 다음 결정에는 반환된 head 사용 | §8·13 |
| 입력 도구의 블록을 discovery Run에만 저장하면 기존 `latest_parse_run_id → units → blocks` 조회 계약과 불일치 | 등록·수입용 parse Run으로 기존 원장에 적재. discovery는 완료된 parse와 블록 대응을 고정 | §7.1 |
| 현재 전체 후보 검증 후 changeset을 만드는 흐름에서 불완전 후보 하나가 정상 산출물까지 막을 수 있음 | 원출력·정규화 후보·검증 결과를 정본 생성 전에 저장. 참조가 닫힌 수락 집합만 정본으로 발행 | §7.3 |
| 기존 v1 후보로 YAML을 재구성하면 새 is_a·annotation이 손실될 수 있음 | v2는 저장된 LinkML 정본에서 직접 SchemaView·JSON Schema 생성. v1 경로 유지 | §7.2·13 |
| 사람 수정 뒤 의존 단계 재계산이 자동 AI 재검토로 해석될 여지 | 근거·구조·diff·직접 영향·파생 스키마만 재계산. 명시적 재생성 요청은 새 Run | §8·10 |
| 역사 원문을 격리해도 현재 ontology registry에서 미래 지식이 유입될 수 있음 | 기준 version의 계보·scope/step 확인. lookup_term도 해당 계보와 실행 내 후보로 제한 | §3·8 |
| read 완료를 의미 분석 완료로 오인할 수 있음 | 구조 조사·원문 제공·분석 성공·쟁점 생성 분리. 필수 완료는 성공 산출물·입력 해시·원문 범위 저장 기준 | §6.5 |
| 필수 절/표 분석량이 제안된 호출 예산을 넘을 가능성 | 구조 조사 후 필수 분석량과 Builder/Critic 예산 산정. 초과 시 부분 완료 예상과 미처리 범위 표시 | §6.5 |
| ‘수정 없이 수락’만 세면 사람이 잘못 수정한 후 승인한 오류를 놓침 | 최종 승인 내용에 핵심 오류가 남은 카드 수를 오류 통과 분자로 사용 | §11.3 |
| UI 비교의 순서·카드 재노출에 따른 편향 | 고정 A/B 묶음과 두 검토자의 반대 UI 순서. 같은 사람에게 같은 카드 재노출 금지 | §11.3 |
| 빈 CQ 표시 확인만으로는 AI의 잘못된 충족 주장 반박을 시험하지 못함 | 명시적 공백 1개와 무관 후보로 충족했다고 주장한 공백 1개. 기준 CQ는 AI 출력과 별도 고정 | §11.3 |
| 자료 읽기를 막아도 저장된 요약·후보가 후속 입력·승인에 재사용될 수 있음 | 재개·후속 모델 입력·승인에서 기존 K5 상태 확인. 중단 출처 파생물 제외 또는 보류 | §9 |

백엔드 에이전트가 §7·13의 보완된 계약을 좁게 재검수하여 head 충돌 검사·불완전 후보 저장·v2 파생에서 추가 차단급 문제 없음을 확인. 추가로 같은 파일을 새 파서 recipe로 처리할 때 기존 source version의 parse 포인터도 갱신할 수 있어야 한다는 문구 모순을 발견하여 §7.1에 반영. 기존 실행의 고정 parse/block 참조는 유지.

## 3. 유지한 단순화

- 기존 SQLite·직렬 executor·Ollama·LinkML·후보 화면 재사용.
- 역할별 순차 작업으로 구현. 별도 멀티에이전트 서버·작업 큐·범용 DAG·승인 플랫폼 미도입.
- 모델이 읽을 입력 범위와 실행 권한을 서버에서 제한. 모든 단계마다 사람 승인을 요구하지 않음.
- 검수 수정 후 자동 AI 재평가·재수정 루프 미추가.
- 전체 자료의 구조 조사와 선택 원문의 의미 분석을 구분. 대표행 선택을 지식 완전성 보장으로 표현하지 않음.
- 실제 기능 경계와 오류 사례만 확인. 전체 민원 회귀·12과제 평가·다중 모델 비교를 착수 조건으로 만들지 않음.

## 4. 아직 확인하지 않은 것과 다음 작업

- 계획의 새 실행기·변경 모델·검수 화면은 미구현. 호출 수·소요 시간·누락률·검수 부담 감소는 미측정.
- 공통 패턴의 다른 회사 적용성과 실제 사람의 오류 발견 효과는 미검증.
- 다음 작업은 A1 입력 동결·parse 원장 연결. 기존 근거 ID로 원문을 재조회할 수 있어야 자율 탐색과 최종 검수가 같은 자료를 사용.
- 실제 검수자 시험은 A6에서 별도 수행. 검토자 미확보를 기능 개발의 차단 조건으로 삼지 않음.
- 현재 사용자 결정이 필요한 사항 없음. 확정된 LH 입력 범위와 현재 로컬 모델 설정으로 착수 가능.
