# K6 잔여 문제 분석과 보완 계획

- 작성: 2026-09-28. 대상: `feature/knowledge-local-search`의 미커밋 K6 구현.
- 입력: [초기 실측](../../30_manuals/knowledge_k6_runbook.md), 실제 `local-v4` 요청/응답·원장 스냅샷·검색 코드. 평가 정답을 제품 프롬프트에 넣지 않는다.
- 기록 범위: 2026-09-28의 분석/보완 및 정보 보존 확인. 2026-09-29 재검토에서 이를 원래 답변 목표의 완료로 보지 않기로 정정했다. 최신 작업은 [K6 답변 품질 개선 계획](k6_answer_quality_plan.md)을 따른다. 아래 §4는 당시 변경 이유를 보존한 기록이다.
- 목표: A-5 출처별 수치 혼합과 Q7 조건 누락을 출력 단계에서 보완하고, 선택 누락과 사실 보존을 구분해 확인한다. 기존 활성 버전·민원 기능·모델 설정 유지.

## 1. 확인한 원인

### 근본: 검토한 지식과 제공한 문장의 단위가 다름

수락된 지식은 주체·속성/관계·값·단위·범위·조건·날짜·근거를 갖춘 assertion이다. 기존 최종 응답은 이 assertion을 자유 문장 `text`로 다시 작성했다. 서버가 검증한 것은 ID의 존재와 출처 소속이며, 제공한 문장의 의미와 조건 완전성은 아니었다. 따라서 앞 단계에서 근거를 검토해도 마지막 문장에 다른 출처의 숫자를 넣거나 조건을 삭제할 수 있었다.

이는 이번 코드/실행으로 확인한 설계상의 틈이다. EXAONE의 한국어 능력·모델 크기·학습데이터가 직접 원인이라고 단정할 증거는 없다. 모델 교체만으로 해결된다고 판단하지 않는다.

### 거시: 구축 단계의 구조가 답변 단계에서 사라짐

- K3~K5는 수치와 범위를 분리해 저장했으나 K6가 다시 종합하면서 이를 병합했다. 온톨로지/관계의 효용이 사용자 답변까지 보존되지 않았다.
- 검색 입력은 필요한 사실을 모두 포함했다. 벡터 검색·그래프 DB·추가 자료 수집으로 이번 오류를 해결해야 한다는 근거가 없다.
- 기존 테스트는 상태·ID·호출 수 경계를 확인했다. 가짜 모델의 올바른 문장을 전제로 했으므로 실제 의미 오류를 입증하거나 방지하지 못한다.
- `answered`는 응답 생성 상태다. assertion 사용률도 조건별 완전성을 뜻하지 않는다. 이를 사용자가 의미 정확성 인증으로 오해하지 않게 화면/문서에서 구분한다.

### 미시: 실패별 직접 경로

| 사례 | 정본/입력 | 기존 최종 출력 | 검사에서 놓친 이유 |
|---|---|---|---|
| DEV-03 | HTML 521/464/985, PDF 985호·5개동, CSV 990세대·6동·주택유형 등 10개 주장 모두 포함 | HTML 인용 문장에 CSV 990 혼입, PDF 문장에 CSV 6동 혼입, CSV 시점 누락 | `source_ref`와 assertion ID가 맞으면 `s.text`를 그대로 채택. 같은 속성의 출처별 값 보존은 입력 단계에만 적용 |
| NEW-02 | 단일 설명 value에 이전 유형과 다음 청약 3유형 전부 존재 | 다음 유형 중 비분양전환 공공임대 삭제 | ID 1개는 사용됐으므로 coverage는 유지되지만 그 value의 일부 조건이 없어짐 |
| 공통 | 실제 source/claim 연결은 정합 | 자유 `limitations`도 새 사실 또는 잘못된 부재 판정 가능 | 인용 연결 검사만으로 자유 문장의 진실성 검증 불가 |

HTML 메타데이터의 521은 정본에서 '집계 범위 미확인'이고, 설명문 521은 '국민임대 세대'다. 두 레코드를 임의로 합치지 않는다. CSV 임대상가와 수량 차이 5의 인과관계도 추론하지 않는다. 실제 실패 기록은 출력 절단으로 종료되지 않았고 필요한 자료가 입력에 있었으므로 입력/출력 예산 증설을 우선하지 않는다.

## 2. 선택한 해결 방식

**LLM 1회는 질문에 관련된 주장 묶음 선택에 사용하고, 사실 본문은 서버가 정본에서 구성한다.** 자연스러운 자유 요약보다 원문 조건 보존을 우선하는 동작 변경이다. 단순 프롬프트 강화는 이미 반복 실패했으며, 별도 심사 모델·재작성 루프를 추가하는 것보다 원인을 직접 제거하는 변경이 작다.

1. 기존 범위/상태 필터·2단계 경로·BM25·입력 예산 유지. 같은 `(subject_id, predicate_id)`의 모든 허용 출처/범위별 사실을 한 선택 묶음으로 제공한다. 관계의 앞단 경로도 보존한다.
2. 모델 출력은 `selected_group_ids`와 `unanswered_question_ids`만 허용. 질문을 물음표/줄바꿈 기준의 원문 조각으로 나눠 q ID를 부여한다. 모델에 임의의 사실 문장·인용·한계 설명을 쓰게 하지 않는다. 질문의 일부만 미해결이어도 해당 조각을 미해결로 선택하도록 지시한다.
3. 선택 묶음의 경로 의존 관계와 같은 주체·속성의 사실을 함께 포함한다. 서버는 출처·자료 날짜·주체·속성·value/대상·unit·scope·conditions·exceptions·사실 날짜를 그대로 렌더한다. 긴 설명 value도 전체를 표시하며 합산·단위 환산·조건 재요약하지 않는다.
4. 반환 citations/paths/사용 assertion ID는 실제 표시한 사실과 경로에서 구성한다. 모델 입력에 사용한 전체 의존 ID는 기존처럼 상태 재확인 대상으로 유지한다.
5. 미선택 주장은 `coverage.not_selected_assertion_ids`로 예산 제외(`omitted_assertion_ids`)와 분리해 공개한다. 미선택이 있으면 부분 응답으로 표시하고 화면에서 미선택 수를 보여준다. 전부 자동 출력하거나 정확도 통과로 처리하지 않는다.
6. 한계는 서버 고정문으로만 구성한다. 미해결 q ID에는 질문 원문과 '선택된 검토 자료에서 답을 찾지 못함'을 표시하며 모델의 선택 결과임을 밝힌다. 서로 다른 범위/출처의 수치 비교는 그 비교만으로 차이 원인을 확인할 수 없음을 표시한다. 실제 인과 근거의 부재나 현실의 법적 자격까지 확정하지 않는다.
7. 빈 선택은 `insufficient`, 잘못된 ID·JSON·잘린 출력은 기존 실패 경로. 자동 재호출/전체 근거 대체 반환 없음. 외부 `answer/sentences/citations/paths/limitations` 계약 유지, 응답 방식은 `answer_style=reviewed_facts`로 명시.

묶음 선택 자체는 모델 판단이므로 필요한 속성을 놓치거나 무관한 것을 고를 수 있다. 수량 비교에서 유형·단위·범위 등 해석에 필요한 맥락도 선택하도록 일반 지침을 주되 시험 정답·과제별 분기는 넣지 않는다. 정본 오류·예산 밖 근거·미등록 별칭·새 질문의 완전성은 이 수정으로 보장하지 않는다.

## 3. 구현·확인 순서

1. 분석/계획을 독립 AI 전문가 2개 관점으로 검수. 핵심 보완: 같은 주체/속성의 비교값, 관계 경로, 미선택 범위, 자유 limitations 제거, 제품 동작 변경 명시.
2. `app/knowledge/search.py`에서 모델 출력과 정본 렌더 변경. UI에는 '검토된 사실·원문 조건'과 미선택 범위를 표시. 저장소/활성 지식은 변경하지 않음.
3. 관련 가짜 모델 테스트: 출처별 숫자/단위/범위 보존, 설명 조건 전체 보존, 선택/관계 의존과 미선택 구분, 미등록 ID/절단 실패, 기존 상태 변경 경계. 대규모 의미 판정기나 새 테스트 프레임워크 없음.
4. 기존 스냅샷·고정 질문으로 DEV-03/NEW-02 및 최종 버전 NEW-01을 각 1회. NEW-01은 브라우저 생성→인용 원문 열람까지 확인해 이전 미확인 UI 구간도 마무리한다. 실패할 때 해당 경로만 보완/재확인.
5. 두 전문가에게 변경 코드와 실제 출력을 다시 검수받고 원문 대조 결과·호출 수·시간·남는 한계를 기록. 자동 테스트 통과와 의미적 과제 통과, AI 검수와 현업 인간 승인을 구분한다.

과제별 통과 기준은 기존 고정 파일 그대로다. 단순 전체 근거 나열이나 잘못된 답변을 근거 부족으로 바꾼 것만으로 성공 처리하지 않는다. 새 모델/추출 실행·활성화·전체 12과제/민원 테스트·Windows 환경 확보는 이번 선행 조건이 아니다. 현재 사용자 결정이 필요한 사항 없음.


## 4. 첫 보완 결과에 따른 계획 수정과 최종 적용

첫 v5 실제 확인 2건에서 정본 렌더 자체는 수치 혼합·조건 삭제를 없앴다. 그러나 DEV-03에서 모델이 동수 2건을 선택하지 않았고, Q7 본문에는 답이 있는데 질문 일부를 미해결로 분류했다. 따라서 근거의 최종 표시 여부나 부재 판정도 같은 모델의 선택에 전적으로 맡기는 것은 불충분했다. 실패를 숨기거나 과제 기준을 바꾸지 않고 아래와 같이 보완 범위를 좁혔다. 두 전문가에게 원인/수정안을 다시 검토받았다.

- **모델 역할:** 허용된 근거 묶음 중 우선 볼 것을 추천. 출력은 `selected_group_ids` 하나만 사용. q 분할·`unanswered_question_ids` 제거.
- **서버 역할:** 추천 근거와 나머지 조회 맥락을 `sentences[].section=recommended|context`로 구분해 원문 필드 그대로 표시. 후자는 현재 필터·2단계·입력 예산을 이미 통과한 `chosen` 집합 안에서만 가져온다. 전체 스냅샷을 추가 조회하거나 조건을 다시 합성하지 않는다.
- **빈 추천:** 여전히 `insufficient`. 관련 근거를 전혀 찾지 못한 요청에 전부를 답변으로 대신 붙이지 않는다.
- **추적:** `recommended_assertion_ids`와 `context_assertion_ids`를 구분. 두 영역을 합한 실제 표시 주장이 `used_assertion_ids`, 인용·경로와 일치. 예산 제외·최신 상태 차단은 계속 `partial`/`stale` 처리. 추천 밖의 근거가 낮은 신뢰도라는 뜻은 아니다.
- **한계:** q별 부재 판정은 폐기. '제시한 검토 사실에 없는 현재 상태·개인별 적용 여부는 확인하지 않았다'와 수치 비교 자체의 인과 추정 한계만 고정문으로 표시한다. `answered`는 사실 표시가 끝났다는 상태이며 질문 완전성이나 정확성 인증이 아니다.
- **제품 범위 변경:** 자유 문장 종합답변에서 **사실 보존형 Local 검색**으로 좁혔다. 정보가 길어지고 사용자의 비교 부담이 늘 수 있다. 모델 추천 품질이 향상됐다는 주장이 아니라, 잘못된 추천/요약이 정본 사실을 삭제·변조하지 않도록 역할을 바꾼 것이다.

§2의 '미선택을 표시하지 않음/미해결 q 분류'는 폐기했다. 단순 전체 나열을 성공으로 간주하지 않고, 각 과제의 필요한 정보·적용 조건·원문 위치·관계 경로를 실제로 읽고 판정한다. 최종 v6 DEV-03에서는 추천 8개와 맥락 2개(동수)를 나눠 표시했고, Q7은 전체 조건을 그대로 제공했다. NEW-01은 실제 화면에서 같은 표 행의 발급기관 원문과 2단계 경로를 열어 확인했다. 최종 3건의 결과와 한계는 [실측 기록](../../30_manuals/knowledge_k6_runbook.md#6-k6-잔여-보완-최종-결과)을 따른다.
