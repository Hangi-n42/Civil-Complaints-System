## 1. v1.0→v1.1에서 추가·변경된 요구

| 구분 | v1.1에서 추가·명확화한 내용 | 구현에 미치는 영향 |
|---|---|---|
| P0 활용 기능 확대 | FR-11 Local 검색, FR-12 Global 종합 검색 추가. 구축·관리뿐 아니라 두 검색의 인용 답변까지 P0 산출물 | 단순 지식 조회·내보내기인 FR-09만으로 P0 완료 처리 불가 |
| Local 처리 | 검토된 ID·별칭으로 대상 연결 → 최대 2단계 관계와 관련 원문 조회 → 짧은 인용 답변 | 동명 대상 선택, 근거 부족 표시, 답변에 사용한 관계 경로 필요 |
| Global 처리 | 선택 범위의 사용 가능한 활성 주장 전체를 확인하고 주제별로 종합. 공통점과 개별 조건·차이·예외 구분 | 일부 top-k 결과만으로 전체 자료를 종합했다고 표시할 수 없음 |
| Global 입력 예산 | 들어가면 직접 종합, 초과하면 묶음별 요약 후 한 번 종합. 근거 ID·조건·예외 유지 | 무제한 요약 단계 대신 제한된 처리. 사용·제외 자료와 부분 처리 공개 |

| 검색 중 상태 변경 | 생성 전 사용 상태 확인, 응답 시 상태 변경 여부 확인. 영향을 받은 답변은 재조회 대상으로 표시 | 중간 요약도 스냅샷·범위와 연결하며 근거 사용 중단을 반영 |
| 검증 범위 제한 | 기존 ID·근거·상태 확인은 유지하되 질문마다 별도 LLM 평가·전문가 합의·사람 승인을 추가하지 않음 | 기존 민원 평가 루프를 새 지식 검색마다 붙이지 않음 |
| 평가 과제 배분 | 총 12개 과제 안에 Local 3건과 Global 3건 포함 | 별도 대규모 검색 벤치마크를 추가하지 않고 유형별 결과 보고 |
| 비교 공정성·채택 판단 | B1에도 같은 예산의 문서별 요약·종합 허용. 관계 자동화 효용과 두 검색의 제공 여부 분리 | B2 추가 효용이 없어도 B1 기반 Local/Global 제공 가능 |
| 구현 순서 | 한 공고군으로 구축→검토→활성화→Local, 다음으로 선택 자료 전체 Global, 이후 변경 관리 | 변경 관리 전체를 먼저 완성하는 순서는 사용하지 않음 |

자료 예산(문서 버전 최대 20개·CSV 1개), SQLite 우선, 사람의 지식 검토, 불변 스냅샷과 별도 사용 상태 이력, 민원 활용 P1은 유지된다. Local/Global이라는 기능명은 Microsoft GraphRAG 알고리즘이나 GRAG 논문 전체 재현을 요구하지 않는다.

기존 제3자 AI 검수 기록은 v1.0에 대한 것이다. PRD §16에 따라 이번 추가 범위까지 검수 완료된 것으로 해석하지 않는다.

### 1.1 v1.2 재사용 결정

기존 버전과 충돌하는 라이브러리를 일괄 제외하지 않는다. 필요한 버전을 조정하고 **공개 API 직접 호출 → 얇은 어댑터 → 필요한 자산 이식/방법 재구현** 순서로 적용한다. 상세 입력·출력과 변경 범위는 [구현 계획 §2~7](implementation.md)를 따른다.

| 적용 단계 | 사용할 자산 | 우리가 구현할 접점 |
|---|---|---|
| K1 | Ontology 101·LOT·CQ4OE의 질문 중심 방법 | 질문→필요 개념/관계→원문 과제표. 고정 평가 정답은 생성 입력에서 제외 |
| K2 | pdfplumber·python-hwpx 직접 사용 | 파서 결과→ParsedBlock/Evidence, PDF 좌표·HWPX 구역/표/셀. 관련 Pillow/Streamlit 등 버전 조정 |
| K3 | OntoGPT 작성 템플릿·validator 일부, AutoSchemaKG 개념화 지침 이식; LinkML 직접 사용 | LH용 후보/검토 데이터, 원장에 저장한 LinkML→JSON Schema, 기존 Ollama 호출 |
| K4 | LangExtract 정렬 API 직접 사용, OntoGPT grounding 방법 적용 | 발췌→문자 위치→원문 대조, LH 공식 ID/검토 별칭 연결. 별도 LLM 추출 호출 없음 |
| K5 | SQLite, SKOS/PROV/SSSOM/N-ary 모델링, 기존 Next.js | 검토·활성화·상태 이력·버전·근거. 온톨로지 정본과 파생 스키마 구분 |
| K6 | LightRAG의 개체/관계+텍스트 검색 방법, 기존 RRF/BM25/Chroma | SQLite 2단계 관계와 지식 Evidence 검색·필터·인용. 기존 stage 타입은 어댑터로 연결 |
| K7 | GraphRAG map/reduce 프롬프트 이식 | 활성 주장·원문 인용 입력, 공통점/차이/예외 출력. 순차 묶음 요약 후 한 번 종합 |
| K8 | DeepDiff·difflib 직접 사용, Graphiti의 시간 구분 | ID별 필드 변경·원문 diff→재검토 후보. 정정 결정과 사용 상태는 원장이 담당 |
| K9~10 | 누적 확인 결과와 기존 API/생성 경계 | 호환성/효용 결과, 별도 민원 지식 패널·assist |

Docling은 선정 PDF 파서가 필수 표를 복원하지 못한 경우의 대체 후보이며, RDF/SHACL·외부 검토 서버·전체 그래프 플랫폼은 해당 요구가 생길 때 사용한다. 지금 모든 후보를 설치하거나 여러 검색 엔진을 운영하지 않는다. v1.2 추가 범위에 대한 별도 제3자 검수는 아직 수행하지 않았다.

## 2. 구현할 전체 기능

P0는 **11개 기능 요구(FR-01~09·11~12)**, P1은 **FR-10**이다.

| 기능 묶음 | 구현 내용 | 요구사항 |
|---|---|---|
| 자료 등록·원문 보존 | CSV·HTML·텍스트 PDF·HWPX 등록, 출처·권리·해시·버전 기록, 동일 입력 중복 방지, 문단·페이지·표·셀 위치 추적 | FR-01·02 |
| AI 온톨로지 초안 | 자료 분석 → 개념·관계 설계 → 반례 검토를 고정 순서로 실행. 정의·포함/제외 기준·속성·허용 관계·근거 제안, 최대 1회 수정 후 사람 검토 | FR-03 |

| Global 종합 검색 | 선택 자료 범위의 활성 지식을 주제별 종합, 공통점·차이·예외와 원문 인용 제공, 사용·제외 범위 및 입력 제한 표시 | FR-12 |

| 민원 활용 예시 | 별도 지식 패널과 assist API. 회사 지식 출처와 민원 인용 구분, 기존 Search/QA·Q0~Q7 보존, 별도 지식 근거로 답변 보조 | FR-10, P1 |

공통 운영 기능은 단일 작업의 진행 상태·취소·실패 단위 재실행, 호출 수·시간·검토 결과 기록, 백업·복원, 한국어 화면이다. 네 화면은 **자료 목록 / 온톨로지·사실 검토 / 변경 검토 / 지식 조회**로 구성한다.

환경은 Python 3.11.9, Mac/Windows 네이티브, 로컬 Ollama이며 모델 설정은 기존 것을 재사용한다. 채택 도구에 필요한 라이브러리 버전 조정은 허용한다. 지식 모듈은 기존 민원 모듈과 독립된 경계를 사용하며 로컬 `.env`를 분리한다. P0는 단일 운영자의 loopback 실행이다.

전체 그래프 시각화, 대규모 크롤링, 스캔 OCR·구형 HWP, 전용 그래프 DB, 다중 에이전트 프레임워크, 자동 법률 판단, SSO·다중 테넌트는 이 일정의 구현 범위가 아니다.

## 3. 일정의 전제

- 아래 기간은 **개발자 1명과 AI 개발 지원, 업무일 기준의 계획 추정치**다. 기존 앱·모델 실행 환경이 준비되어 있고 PRD의 제한된 자료 예산을 사용한다고 가정한다.
- 각 마일스톤은 1~2일이며 필요한 API·화면·대표 사례 확인을 함께 포함한다. 구현은 순차 진행한다. 완료 기준을 만족하기 전 다음 단계의 전제가 갖춰졌다고 보지 않는다.
- 자료 이용 승인 대기, 실제 업무 검토자 섭외, 모델 다운로드, Windows 실행 환경 확보, 기관 배포 대기는 개발일 산정에서 제외하며 따로 기록한다.
- 파싱 손실·추출 품질·사람 검토량 때문에 넘치는 작업이 확인되면 해당 부분을 추가 1~2일 단위로 분리하고 잔여 일정을 갱신한다. 고정 날짜에 맞추기 위해 원문 근거·조건·예외 요구를 삭제하지 않는다.
- v1.2의 라이브러리 연동은 각 기능 단계에 포함한다. 버전 조정은 관련 직접·전이 의존성을 함께 다루며 실제 문제가 확인되면 추가 1~2일 단위로 산정한다. 재사용을 선택했다는 이유로 기존 추정 기간을 검증 없이 줄이지 않는다.
- 기존 PRD의 큰 단계 M0~M4는 유지한다. 아래 K 번호는 이를 실행 가능한 개발 단위로 나눈 것이다.

## 5. 측정과 완료 판단

1. K1에서 입력·기대 근거·판정 규칙을 고정한다. 개발용 6건과 새 확인용 6건이라는 구분은 Local/Global 유형 구분과 별개다. 새 자료를 튜닝에 사용하면 독립 확인으로 보고하지 않는다.
2. B0는 수작업, B1은 같은 파싱·공식 ID·메타데이터·diff·기본 RAG·동일 모델 요약과 수동 관계표, B2는 여기에 온톨로지·관계 후보·영향 탐색을 추가한 방식이다. Global에서 B1에도 동일 예산의 문서별 요약·종합을 허용한다.
3. 최초 구축·검토 시간은 해당 단계에서 기록한다. K9에서 기억으로 복원하지 않는다. 동일 원문에 대한 반복 작업의 순서·사전 노출도 기록한다.
4. 각 단계에서 바뀐 경로의 대표 사례를 확인하고 K9에서 기존 기록을 합친다. 새 실패가 없는데 전체 테스트나 이미 완료한 모든 사례를 반복하지 않는다. 별도 대규모 평가 플랫폼은 만들지 않는다.
5. 소표본에서 중대한 오병합·범위 오적용·구버전 확정 사용·없는 근거 통과가 없어야 P0 기술 조건을 통과한다. 전체 정확도를 입증했다고 표현하지 않는다.
6. PRD의 B2 확장 기준은 B1 대비 중대한 오류·영향 누락이 늘지 않고 고정 묶음의 총 사람 작업시간이 10% 이상 감소하는 것이다. 미충족/불공정 비교면 추가 효용 미확인으로 남기고 추가 관계 자동화 확장을 중단한다. 두 검색은 B1 기반으로 제공할 수 있다.
7. P1은 B2 채택 여부와 별개로 채택한 방식의 기술 통과 및 실제 민원 활용 과제 정의가 필요하다. Windows 환경이 없으면 Mac 결과만 확인으로 보고하고 Windows 검증은 미완료로 남긴다.

## 6. 구현 시작 시 지킬 경계

- `app/knowledge`, 별도 knowledge API와 화면을 중심으로 추가한다. 기존 민원 검색·생성·평가 계약과 현재 작업 트리 변경을 보존한다.
- SQLite·Pydantic·기존 Ollama 호출을 재사용하고 PRD에서 선택한 파서·LinkML·LangExtract·DeepDiff를 연결한다. OntoGPT/AutoSchemaKG/GraphRAG 자산은 정해진 부분만 이식하고 고정 commit·라이선스·수정 요지를 기록한다. 전체 OntoGPT나 전용 그래프 DB 설치를 선행 조건으로 두지 않는다.
- 기존 모델 설정을 사용하고 새 역할에는 해당 역할의 프롬프트를 사용한다. Qwen 반례 검토는 실제 호출의 `think=false`를 확인한다. 질의마다 별도 AI 채점 루프를 만들지 않는다.
- 코드에 Mac 사용자 경로를 넣지 않는다. 비밀·원문·DB·모델은 Git에 포함하지 않고 `.env.example`에 비밀 없는 설정 예시만 둔다.
- 시작점은 K1과 K2다. 첫 공고군에서 검토된 지식이 실제 답변까지 연결되는 데 필요한 구조부터 구현하고 이후 자료 범위를 넓힌다.

## K3 완료 기록 (2026-09-27)

온톨로지 순차 생성·반례 검토·최대 1회 수정, 실패 단계 재시도, 후보 편집/결정 이력, LinkML 정본·파생 JSON Schema를 구현했다. 같은 양산 HTML+6개 단지 CSV의 최종 실행은 6회 호출/205.970초 경과, 후보 10개다. Mac 화면 수정·보류·재조회를 확인했고 관련 자동 테스트 총 13개가 통과했다. [실측·시행착오·한계](../../30_manuals/knowledge_k3_runbook.md).

K3 완료는 도구 동작 범위다. Qwen 오지적과 날짜/유형/관계의 의미 문제는 남았으며 현업 검토·정확성 입증·K5 활성화는 아니다. 다음 K4에서는 검토된 개념/속성을 기준으로 공식 단지 ID, 범위·시점을 보존한 사실·관계 후보를 구축한다. 현재 사용자 결정이 필요한 사항 없음.

## K4 착수 준비 완료 (2026-09-27)

기존 K3 후보 10개를 원문 대조하여 수락 9·기각 1로 정리했다. 누락 정의 5개는 K4 첫 단계에서 최소 보충하며, 전체 온톨로지 완성으로 표시하지 않는다. [K4 구현 계획](k4_implementation_plan.md)에 저장·추출·연결·검토와 제한된 확인 범위를 확정했다. K4 코드는 미구현이며 예상 2일은 유지한다. 사용자 추가 결정은 없다.


## K4 기능 구현·제한된 통합 확인 (2026-09-28)

저장·추출·공식 코드/별칭 연결·사실/관계 수정·결정·연결 해제 기능을 구현했다. 첫 공고군 61개 블록의 기본 호출은 2회이며, 발견 오류 재확인·취소를 포함한 총 7회를 실행했다. 원문 대조 개발 검토로 단지 6개 별칭과 서로 다른 수량·날짜 속성을 보존했고 직접 의존 재검토를 확인했다. 관련 자동 확인 11개·화면 확인 통과. 모델만으로 누락 없이 올바르게 추출하지 못했으며 수동 수정이 필요했다. 따라서 기능 구현 완료와 자동 추출 품질 잔여를 구분한다. 상세 수치·실행 이력은 [K4 안내](../../30_manuals/knowledge_k4_runbook.md). 다음은 K5 활성 스냅샷이며 현재 사용자 추가 결정은 없다.
