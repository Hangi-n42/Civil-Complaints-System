# K6 재개선 계획 — 질문에 정확하고 간결하게 답하기

- 기준일: 2026-09-29. **후보 구현·EXAONE 21회·Qwen 7회 비교 완료. 세 후보 모두 채택 기준 미달, 기본 검색은 v6 유지.** [실제 결과와 다음 작업](../../30_manuals/knowledge_k6_answer_quality_result.md). 아래는 실행 전에 확정한 계획이며 ‘미실행/오늘’ 표현은 계획 작성 당시 기록이다.
- 기준: [PRD FR-11](../../00_overview/company_knowledge_prd.md#8-기능-요구사항), [직전 보완 기록](../../30_manuals/knowledge_k6_runbook.md#6-k6-잔여-보완-최종-결과), 현재 `app/knowledge/search.py`와 저장된 실제 응답.
- 결론: v6는 정보 손실을 막은 중간 단계다. **짧고 정확한 인용 답변이라는 원래 K6 목표는 미완료**이며 K7 착수보다 이 개선을 우선한다. 이전 완료/다음 단계 표기를 이 문서 기준으로 정정한다.

## 1. 재검토: 정보 보존으로 답변 정확성을 대신했는가

**A-5에서는 그렇다. 모든 사례가 장황해진 것은 아니다.** 저장된 `answer` 문자열을 Python `len()`으로 비교했다. 공백·줄바꿈·본문 내 출처명은 포함, 별도 limitations/citations 패널은 제외했다. 실제 읽기 시간이나 순수 설명문 길이를 측정한 값은 아니다.

| 과제 | v4 본문 | v6 본문 | 확인한 의미 |
|---|---:|---:|---|
| DEV-03 A-5 | 491자·문장 레코드 3개 | 1,474자·사실 레코드 10개 | 약 3배. 추천 8개에 서버가 동수 2개를 추가. 모델의 선택 개선 없이 정보 존재를 충족시킴 |
| NEW-02 Q7 | 369자·문장 레코드 3개 | 263자·설명 레코드 1개 | 원문 한 문장이 필요한 조건을 모두 담아, 전체 보존이 오히려 더 짧고 정확했음 |
| NEW-01 서류/기관 | 이번 길이 비교 대상 아님 | 297자·관계 레코드 2개 | 두 관계가 질문과 직접 대응. A-5와 같은 과잉 펼침이라고 단정할 근거 없음 |

A-5의 10개 사실이 모두 불필요하다는 뜻은 아니다. 기존 DEV-03-C2는 PDF/CSV 동수·유형·시점을 명시적으로 요구하므로 그 정보를 삭제해 간결성 점수를 올려서는 안 된다. 길이 증가에는 필요한 동수뿐 아니라 출처명/날짜 반복, HTML 521 메타데이터와 설명문의 별도 표시도 포함된다. 평가를 ‘필수 답변 사실 / 범위 해석에 필요한 맥락 / 선택적 참고’로 실행 전에 구분하고, 필수 정보는 출처별 짧은 행으로 압축해야 한다. 이 구분은 기존 실패를 사후 통과로 바꾸지 않는다.

v4의 짧은 답은 오류가 있으므로 길이가 짧다는 이유로 우월하지 않다. 문제는 다음 두 가지를 구분하지 않은 평가/완료 판단이었다.

1. **근거 회수·보존:** 화면 어딘가에 필요한 정보가 있는가? v6에서 개선됐다.
2. **질문에 대한 답변:** 무엇을 비교/판정/설명해야 하는지 파악하고 필요한 정보만 선택해 정확히 답했는가? v6는 본문 합성을 없앴으므로 이 능력의 개선을 입증하지 못했다.

현재 코드는 추천이 하나라도 있으면 나머지 `chosen`을 모두 `context`로 본문에 넣고, 추천 여부와 무관하게 전체를 `used_assertion_ids`로 집계한다. 따라서 ‘표시한 정보의 coverage’를 ‘정확히 고른 정보의 coverage’로 읽으면 개선을 과대평가하게 된다. 본문에 반복되는 출처명·범위 미확인 메타데이터와 중복 숫자는 사용자가 비교해야 한다. 일반적인 현재 상태 안내도 질문별 근거 부족 판단을 대신하지 못한다.

직전 전문가 검수는 정본/인용의 정보 보존을 확인한 것이며, **원래 답변 기능 전체를 완성했다고 해석한 것은 과도했다.** v6를 폐기하지 않고 근거 상세보기와 비교 기준선으로 유지하되, 새로운 답변 후보가 실패하면 전체 나열로 바꾸어 성공 처리하지 않는다.

## 3. 목표 출력과 구현 경계

### 3.1 질문 해석은 짧은 작업 명세로

한 호출 안에서 `requirements` → `answer_items` 순서로 작성한다. 요구에는 질문에서 직접 확인한 대상·비교 기준·조건/방향·요청한 현재성 여부만 적는다. 숨은 사고과정·자기평가 점수·자유로운 다단계 계획은 받지 않는다. 이는 별도 Local/Global 자동 분류기가 아니며 사용자가 선택한 Local 모드를 유지한다.

예를 들어 A-5는 ‘각 숫자의 출처/집계 범위를 비교’와 ‘현재 빈집을 확인할 수 있는지’를 구분하는 것이 적절하다. 질문에 없는 ‘임대상가가 차이의 원인’은 요구/사실로 만들지 않는다. 이 예는 설계 설명이며 제품 프롬프트에 A-5 정답·과제 ID 분기를 넣지 않는다.

v5의 `unanswered_question_ids`처럼 별도 자기판정을 먼저 내리고 고정문을 붙이는 방식은 재사용하지 않는다. 답할 수 있는 부분의 인용 답변과 확인하지 못한 부분의 짧은 설명을 같은 답변에서 평가한다. 정답이 근거에 있는데 일괄 확인 불가로 처리하면 오답이다.

### 3.2 출처별 맥락 카드는 요청 안에서만 구성

- 경계: 같은 주체 + 같은 자료 버전 + 고정된 원문 위치. CSV는 행, PDF/HTML 표는 파싱 실행·페이지/표 식별·행, 본문은 실제 블록/명시 절을 사용한다. `table_key()` 등 기존 처리의 위치 구분을 재사용한다.
- 역할: 관련 수치뿐 아니라 같은 행의 유형·단위·표 머리글을 함께 볼 수 있게 한다. 전체 행의 모든 내용을 자동으로 답변 본문에 넣지는 않는다.
- 같은 대상/속성의 다른 출처·범위 값은 입력에서 공존시킨다. 카드에 출처명·날짜 역할·scope·근거 ID·속성 정의를 표시한다. 단순한 파일명·숫자 일치로 합치지 않는다.
- 문서 날짜를 통계/사실의 유효기간으로 바꾸지 않는다. 같은 행의 임대상가 표시는 차이 5의 원인이라는 근거가 아니다.
- 원문을 보충할 때도 수락 사실의 위치/해석을 위한 연결 근거만 사용한다. 현재 스냅샷 밖 미검토 사실을 답변 근거로 몰래 추가하지 않는다.
- 지금은 `explains` 같은 새 온톨로지 관계나 별도 의미 연결 DB를 만들지 않는다. 실제로 재사용되는 업무 관계가 확인될 때 기존 후보 검토 흐름으로 추가할 수 있다.

### 3.3 본문은 답, 상세보기는 근거

- 단순 조회: 결론 1~2문장. 조건 질문: 이전 조건/다음 대상 등 필요한 구분을 짧은 항목으로. 출처 비교: 출처·시점·값·범위를 담은 간단한 행/항목과 확인 불가한 부분 설명.
- 숫자·단위·유형·조건을 선택한 사실 ID와 연결하고, URL/위치/인용은 기존 서버 구성 유지. ID 정합 검사가 문장 의미까지 증명한다고 간주하지 않는다.
- v6 정본 표시 기능은 접힌 ‘근거 상세’로 재사용한다. 본문에 모델 미선택 사실을 자동으로 덧붙이지 않는다. 정답은 상세를 펼치지 않아도 본문에서 이해돼야 한다.
- 필요한 원문 한 문장이 이미 짧고 정확하면 그대로 인용해도 된다(Q7). 모든 답변을 억지로 요약하거나 반대로 전부 원문으로 고정하지 않는다.
- 상충 값·중요 조건을 지워 글자 수를 줄이지 않는다. 형식적인 면책문이나 반복 출처명도 간결성 비용에 포함한다.
- 기존 상태/범위·인용·출력 절단 확인 유지. 의미 실패를 전부 나열하는 fallback이나 추가 평가/재작성 모델로 숨기지 않는다.

구현 접점은 `search.py`의 입력 구성·프롬프트/출력 파싱, 필요한 응답 필드와 `KnowledgeSearch.tsx`의 본문/상세 분리다. 스냅샷·활성화·등록부·민원 Q0~Q7·모델 기본값을 바꾸지 않는다.

## 4. 좁은 비교 실험

### 4.1 후보 3개, 우선 같은 모델

| 방식 | 질문/입력·출력 | 비교 목적 |
|---|---|---|
| A 현재 v6 | 현재 묶음 추천 + 정본 전체 표시 | 정보 보존과 읽기 부담의 기준선 |
| B 요구 정리 + 짧은 답변 | 기존 속성 중심 입력, 동일 호출에서 요구 정리·근거 선택·짧은 인용 답변 | 원래 답변 기능을 복원했을 때의 오류/간결성 확인 |
| C B + 출처별 맥락 카드 | B와 같은 질문/답변 지침, 입력의 묶음 방식만 변경 | 설명 맥락이 필요한 정보 선택과 범위 보존을 실제로 돕는지 확인 |

A→B는 질문 정리뿐 아니라 출력 방식도 바뀌므로 ‘질문 정리만의 효과’라고 주장하지 않는다. B→C는 가능한 한 입력 구성만 바꿔 비교한다. 구조화 요구가 먼저 출력된다는 사실도 독립적인 이해 검증이 아니다.

EXAONE로 먼저 비교한다. 설치된 Qwen은 EXAONE 후보에서 중요한 의미 오류가 남거나 충분한 개선이 없는 경우에만 **가장 나은 동일 구성 하나**로 비교한다. 프롬프트·정답·자료를 Qwen용으로 따로 유리하게 바꾸지 않고 `think=false`와 실제 호출 옵션을 기록한다. 모델 자동 선택기는 만들지 않으며 기본 모델 변경은 결과를 본 뒤 판단한다.

### 4.2 기존 3건 + 추가 4건

추가 질문은 아래 범위로 정하되 **실행 전** 원문과 허용 스냅샷/출처, 필수 사실·불필요한 사실·금지 추론을 사람이 읽을 수 있는 작은 평가 파일에 고정한다. 아래는 아직 실행하지 않은 질문 제안이며 평가 정답·스냅샷 확정 완료를 뜻하지 않는다.

| 추가 질문 | 확인할 다른 요구 |
|---|---|
| “양산사송 A-5의 CSV에 적힌 동수만 알려줘.” | 다른 수치/유형을 전부 펼치지 않는 좁은 선택 |
| “A-5의 CSV와 PDF 수량 차이가 5이니 임대상가가 5호라는 뜻인가?” | 잘못된 인과 전제 거절. 값 비교와 원인 입증 구분 |
| “양산물금5단지의 CSV 세대수와 주택유형만 알려줘.” | A-5 외 대상/다른 수치로 전이, 불필요한 날짜/모집 정보 혼입 방지 |
| “Q7은 공공분양 당첨에 사용한 통장도 다시 사용할 수 있다고 설명하나?” | 이전 조건과 다음 대상의 방향을 뒤집는 오독 방지. 자료 미확인과 현실의 불가능 구분 |

기존 3건에서 형식/예산을 조정한 뒤 후보·프롬프트를 고정하고 추가 4건을 각 방식 1회 확인한다. 추가 질문의 결과를 보고 튜닝하면 그 질문은 개발에 노출된 것으로 기록하며 독립 검증으로 재사용하지 않는다. 같은 자료의 새로운 질문이고 설계자에게 내용이 노출되므로 blind/외부 일반화 검증이라고 부르지 않는다. 네 질문 중 셋은 익숙한 자료의 다른 요구이고 하나만 다른 대상이므로 전이 확인도 제한적이다.

정상 최초 실행은 **7질문 × 3방식 = 21회**. 필요 시 Qwen 7회 추가. 개발/형식 실패 재확인은 실패한 경로만 별도 기록하며 전 조합을 다시 반복하지 않는다. 오늘은 계획 단계로 이 호출들을 실행하지 않았다.

### 4.3 공정성과 판정

- 같은 질문·스냅샷·허용 주장 집합·출처/기준일·모델 버전·temperature·컨텍스트/출력 예산 사용. B/C에서 정보량 자체를 추가하지 않고 구성만 바꾼다. 길이 초과 시 어떤 주장 집합이 달라졌는지 기록하고 그 행을 순수 입력 구성 비교로 해석하지 않는다.
- 초기 예산은 현재 12,000자·컨텍스트 16,384·출력 1,536토큰을 재사용한다. 개발 3건에서 절단이 확인된 단계만 조정하고 비교 후보에 동일하게 적용한다. 문자 수를 토큰 수로 간주하지 않는다.
- 기존 원문/기대 기준으로 답변을 읽고 판정한다. 별도 상시 LLM 심사 호출 없음. AI 개발 검수를 현업 사람의 검증으로 표현하지 않는다.
- 기록은 기존 Run과 간단한 JSONL로 충분하다. 질문/입력·프롬프트/모델/코드 식별·원출력·본문·근거·호출/시간·개발 노출·실패 사유 보존. 새로운 평가 플랫폼 없음.

| 평가축 | 무엇을 보는가 | 성공으로 세지 않는 것 |
|---|---|---|
| 사실 정확성 | 각 문장의 대상·출처·수치·단위·시점·조건·방향이 맞는가 | ID만 일치하거나 사실이 상세 패널에 존재함 |
| 요구 충족 | 질문의 각 요청에 직접 답했는가, 적절한 확인 불가인가 | 답할 수 있는 질문을 전부 확인 불가로 처리 |
| 선택 정확성 | 필수 근거 누락과 무관한 근거 선택을 각각 기록 | 서버가 뒤에 전부 붙여 누락을 보충한 것을 모델 선택 성공으로 처리 |
| 요약 충실성 | 필요한 조건은 유지하고 반복만 줄였는가 | 짧아졌지만 유형/범위가 삭제됨 |
| 간결성 | 본문 글자 수, 중복/불필요 항목 수, 상세를 열지 않고 답을 이해 가능한가 | 작은 글자 수만으로 정확성 실패를 상쇄 |

채택 순서는 **정확성·요구 충족 → 선택/요약 충실성 → 간결성 → 시간/호출 수**다. 점수를 합쳐 중대한 오류를 가리지 않는다. 고정 7건에서 중대한 출처 혼합·허위 원인·조건 삭제·역방향 해석이 없어야 채택한다. 좁은 조회와 비교 질문에서 불필요한 본문이 줄고, 다른 과제의 필요한 정보가 유지되는지 과제별로 확인한다. 더 복잡한 C가 B보다 이득이 없으면 B를 선택한다. 둘 다 기준을 못 맞추면 v6를 임시 근거 조회로 유지하고 **K6 미완료**로 남긴다. 출력 길이 목표를 맞추려고 정답 기준을 줄이지 않는다.

## 5. 실행 순서·종료 조건

| 묶음 | 추정 | 산출물 |
|---|---|---|
| K6-C1 질문/평가 고정과 최소 후보 | 1~2일 | 추가 4건의 원문 기반 기준 고정, B/C 요청 내 입력/출력 구현, 비교 21회 및 필요한 실패 경로 확인 |
| K6-C2 채택·화면·인도 | 1~2일 | 필요 시 단일 Qwen 구성 비교, 가장 단순한 통과 후보 연결, 본문/근거 상세 분리, 관련 단위/실제 인용 화면 확인, 결과/한계 기록 |

기간은 추정이며 통과를 보장하지 않는다. 전체 12과제·민원 전체 테스트·Windows 환경 확보·새 모델 다운로드·KG 확대는 선행 조건이 아니다. 현재 사용자 결정이 필요한 사항 없음. 다음 작업은 위 기준을 고정하고 후보 비교를 시작하는 것이며, 이번에는 분석·계획과 상태 문서 정정만 수행했다.
