# K6 세 핵심 문제의 제한적 보완 계획

- **실행 결과:** [후보 구현·25회 실행·독립 검수 기록](../../30_manuals/knowledge_k6_targeted_fix_result.md). 출처/인과는 개선됐지만 조건 오판·회귀가 남아 미채택. 아래는 최초 계획이며 실측에 따른 계약 수정/추론 진단은 결과 기록에 구분했다.
- 기준: 2026-09-29 [28건 재분류](../../30_manuals/knowledge_k6_output_reclassification.md). 기존 작업 트리·민원 모델·활성 지식 보존, 커밋/푸시 없음.
- 목표: 출처/수치/단위 혼합, 근거 없는 인과 추측, 조건 방향의 오독/미응답을 보완. 동수·자료시점 등 부가 정보 전체 출력을 필수화하지 않음.

## 구현

1. 기존 1회 Ollama 실행·고정 스냅샷·정본 표시를 재사용한다. Qwen 비추론 모드로 D 후보 하나를 구현한다. 별도 질문 분석/평가/재작성 호출 없음.
2. 모델은 필요한 사실 ID를 선택한다. 수치·단위·범위·조건·예외·출처는 서버가 정본에서 표시하며 자유 문장으로 재작성하지 않는다. 선택하지 않은 사실은 본문에 자동 추가하지 않는다.
3. 판단 요청은 원질문의 연속 발췌, 선택 근거, `supported / not_established / contradicted`로 반환한다. 조건 질문은 원문 조건 발췌를 함께 제시한다. 서버가 짧은 판단 문구를 표시하므로 새 원인·계산을 자유 서술할 경로는 두지 않는다.
4. `contradicted`는 직접 반증이 있을 때만 사용한다. 같은 행/숫자 차이·역방향 조건은 그 자체로 인과나 반증이 아니며 `not_established`로 구분한다. 발췌/ID의 존재 검사는 의미 판단의 정확성 보장이 아님을 유지한다.
5. 같은 출처의 선택 사실은 제목을 묶고 조건/예외/범위를 보존한다. 화면은 짧은 답변과 접힌 근거 상세로 구성한다. 사실 정본·원문·원장·사용 상태 검증은 제거하지 않는다.

## 필요한 확인과 채택

- 실행 전에 [기존 7문항 + 추가 2문항](../../../configs/knowledge/k6_targeted_v2.json)을 고정했다. 새 문항은 PDF 건설호수를 공실로 해석하는 전제와 Q7의 정상 방향 긍정 확인이다. 평가 기준은 모델 입력에서 제외한다.
- 기존 7건을 먼저 확인한다. 명확한 실패가 있으면 해당 경로만 수정/재확인하고 기록한다. 후보를 고정한 뒤 새 2건을 확인한다. 최초 정상 호출은 9회, 실패/통합 확인은 별도 기록. 기존 28회나 민원 전체 검증을 반복하지 않는다.
- 자동 확인은 ID/발췌/절단, 정본 값 보존, 미선택 사실 본문 제외, 사용 상태 변경, 기존 호출 계약의 관련 테스트에 한정한다.
- C(핵심 오류)와 N(필수 누락)을 먼저 판단한다. S(부가 정보 누락)는 실패가 아니며 P(표현 문제)는 따로 기록한다. 기존 7건의 성공을 새로운 독립 정확도 증명으로 표현하지 않는다.
- 핵심 확인을 통과하면 지식 검색 전용 Qwen 설정과 D 기본 실행, 화면을 연결한다. 통과하지 못하면 실패를 숨기는 fallback 없이 범위/미완료 사항을 보고한다.
- 별도 제3자 에이전트는 최종 코드와 실제 출력에 대해 독립 검수한다. 의미 오류와 일반 코드 결함을 구분하고 필요한 수정만 반영한다. 이는 AI 개발 검수이며 현업 승인 아님.
