# A1~A6·K10 통합 평가 계획 검수 기록

- 날짜: 2026-09-30
- 대상: [통합 후 평가 계획 v1.0](post_k10_evaluation_plan.md)
- 수행: 원논문·공식 표준/제품 문서 조사, 현재 PRD·평가 계약·입력 manifest 확인, 전문가 역할 AI 에이전트 3개의 초안 독립 검수.
- 완료 범위: 계획 검수와 지적 사항 반영. 실제 모델 비교·사람 시험·현업 전문가 승인·산업 효용 측정은 미수행.

## 1. 검수 방식과 역할

각 에이전트는 독립적으로 자료를 조사한 뒤, 작성된 계획 파일을 직접 읽고 필수 수정과 선택 보완을 구분해 반환했다. 검수자가 문서를 직접 수정하지 않았으며 작성자가 의견을 취합·반영했다. 같은 AI 계열의 역할 분담이므로 독립된 인간 전문가·기관 심사를 대신하지 않는다.

| 역할·에이전트 | 검수 범위 | 주요 결과 |
|---|---|---|
| 온톨로지 평가 방법론 / `ontology_eval_methods` | 표준·연구의 지위, 단일 정답 강요, CQ 분모, 의미 채점, 서지 | 구조/CQ/업무/사람 평가 분리 적절. 논문 제목 정정, 자료 존재와 실제 적재 분리, 최종 승인본 채점 명시 필요 |
| 인간 감독·산업 평가 / `eval_human_industry` | 비용·참여자 노출·배정·감독·사용성·산업 주장 | 소규모 설계 적절. 누락 구축비를 제외한 절감률 방지, CSV 도구 공정성, 정답 노출자 시험 분리 필요 |
| 제품·평가 계약 감사 / `eval_product_audit` | 기존 과제·manifest·A/K 범위·강한 B1·실행량·비용 귀속 | 기존 과제 보존과 새 묶음 분리 적절. CSV 범위 전체 사실 구축, 시스템별 ID 구분, 미측정 총비용 판정 보완 필요 |

## 2. 반영한 수정

| 지적 | 반영 내용 | 위치 |
|---|---|---|
| R8 논문 제목이 실제와 다름 | 원문 제목 `Large Language Models Assisting Ontology Evaluation`로 정정 | 계획 §11 |
| CQ 실행 실패를 자료 부족으로 숨길 수 있음 | 허용 원문의 근거 존재 / 시스템 실제 적재 구분. 고정 CQ 전체 분모에서 미실행·실패 제외 금지 | §6 |
| 승인본 의미 품질 채점 연결이 불명확 | 모델 초안·최초 승인본·수정본에 같은 의미/요구/CQ 기준 적용 | §6 |
| 구축비 미측정 항목을 빼면 시간 이득 과장 | 필수 비용 하나라도 미측정이면 총비용·절감률·10% 판정 미산출, 부분 시간만 보고 | §7.1 |
| 강한 B1을 문서 RAG에 가둘 위험 | 양쪽에 일반 CSV 필터·정렬·집계·산술 허용, 준비·확인 비용 포함 | §5.2 |
| 대표행에서 개념을 찾는 것과 전체 집계 사실 구축은 다름 | 작은 집계 행 범위 고정. B2의 해당 범위 K4 검토·K5 활성화 및 비용 필요 | §5.2 E-G1 |
| CSV/API ID가 자동 대응한다는 전제 위험 | 공식 대응 근거가 없는 시스템별 ID는 별도 네임스페이스로 유지 | §5.2 E-L1 |
| 오류 위치를 아는 검토자의 결과 해석 | 카드·정답 작성자·사전 노출자의 결과는 노출된 사용성 점검으로 분리 | §5.3 |
| 반복 판정을 사람 수로 오해할 위험 | UI별 판정 수와 고유 카드·누락·참여자 수 명시 | §5.3 |
| C와 E의 비용·노출 규칙 불일치 가능성 | C에도 동일 노출/피드백 규칙, C0의 온톨로지 비용을 B1에 강요하지 않음, 2인 E 비용 귀속 명시 | §5.1·7.2 |

별도 대규모 벤치마크·OWL 저장소·평가 서버·전 모델 비교는 추가하지 않았다. 현재 계약에 맞는 작은 실제 비교와 기존 경계 확인을 재사용한다.

## 3. 자료·경로 재확인

- 작성 중 원래 작업 폴더가 이전 main으로 전환되고 최신 프로젝트가 `a1-input-grounding` 작업트리로 이동한 것을 읽기 전용 Git 상태에서 확인.
- 작성자가 새 계획 파일만 현재 문서가 있는 작업트리로 이동. 기존 코드·자료·PRD·Git branch/commit/stash 상태는 변경하지 않음.
- 확인 기준: `56b4d1e` 통합 상태. 입력 manifest는 앞서 확인한 `46c70bd` 버전과 bytes 동일.
- manifest SHA-256: `eb1379a48588ba7bf6c2be3dc109a797f9da1740ac5599aca85b33bdea315cdf`.
- 현재 선정 15출처·19파일, 보류 14출처. 이전 DEV/NEW 12개 과제의 `source_ids`와 보류 ID를 다시 대조해 전부 중첩 확인.
- `0/12`는 현재 입력 범위만으로 원래 평가 조건을 완전히 재현할 수 없다는 뜻. 자료의 불법성·기존 성적 무효를 판정한 것이 아님.
- 전문가들은 원래 경로의 초안을 검수했으며, 경로 이동 후 manifest 동일성과 반영 문구·내부 링크는 작성자가 확인. 이를 세 명의 별도 현업 검증으로 표현하지 않음.

## 4. 완료와 후속 작업

- 진행 이유: 표준 도구 통과나 클래스 수로 품질을 과장하지 않고, 필요한 의미·최종 업무 결과·사람 수고를 함께 비교하기 위함.
- 결과: 연구/표준/제품 문서의 근거와 소규모 실행 절차를 계획에 명시. 지적된 분모·비용·노출·자료 범위의 모호함 보완.
- 미완료: 실제 질문·대상 행·근거 판정표 고정, 사람 참여, 실행·효용 측정. 현재의 6과제는 선정 방향이며 완성된 정답 데이터셋이 아님.
- 다음: A1~A6·K10 통합 후 실제 과제·참여자·설정 고정 → 작은 비교 → 확인된 핵심 오류만 보완.
- **현재 사용자 결정이 필요한 사항 없음.** 실행 전에 참여 가능한 사람·이용 자료 범위를 확정하며, 인력이 부족하면 해당 사람 효과는 미측정으로 보고.
