# 근거 판단·실제 교정 연결 후속 실행 계획

현재 추가 범위는 **#614의 동일 선행 상태에서 연결 문맥과 역할 설계 비교**다. [두 번째 재개 검증 기록의 후속 절](../../70_research/company_knowledge/ontology_second_resume_20261005.md)에 대상 선정·전문가 사전 검토·출력 전 기준과 실제 결과를 기록한다. 과거 실행·중단 결과는 보존하고 아래 과거 상태를 현재 구현 지시로 중복 실행하지 않는다.

- 실제 오류가 생기기 전 Builder의 기존 유형 없음·원문·필수 자연어 설계 명제를 공통으로 고정한다. 연결 정보 추가만으로 새 역할의 선언 범위와 사용처가 달라지는지 권한 실패와 매입 공급 정상 대조에서 비교한다.
- Concept 구절 발췌만으로 성공 가능한 대상은 제외했다. 최종 비교는 실제 Builder 유형 설계이며 Concept 발견 효과·선택 알고리즘 우수성·전체 교정/CQ/A3 효과로 확대하지 않는다.
- 최초 4회, 출력 조건을 가린 독립 검토. B만 실제 범위 오류를 해소하고 정상 대조에 악화가 없을 때만 동일 설정으로 역순 4회 재현 한 번을 허용한다. 그 외 설정 변경·추가 호출은 하지 않는다.
- 기존 #614와 기록만 갱신한다. 동일 이슈 생성·PR 본문/댓글 작업·병합은 추가하지 않는다.
- 실제 4회 결과: 권한 A는 출력 상한으로 의미 판단 불가, B는 장관 국소 역할의 시도지사 재사용 오류가 남았다. 매입 정상 대조는 양쪽 정상·동등이다. 기본 비활성을 유지하며, 사전 재현 조건 미충족으로 추가 호출 없이 종료했다. 모델 호출 경과 합계 1,680.831초이며 실제 교정·전체 CQ·A3 개선을 주장하지 않는다.

두 번째 재개의 구현과 제한 실행 결과는 [원명제 추적·정상 끝점 보존 검증](../../70_research/company_knowledge/ontology_second_resume_20261005.md)에 기록했다. 조사 주소 상한·원명제 추적·재판정 정상 보존·정상 끝점 고정을 구현했고, 실제 추론 7회를 수행했다. E의 권한 한정은 보존됐으나 R의 자료 상태 오류 미탐지와 Binding의 역할 범위 오류 미탐지가 남아 실제 교정은 0건이다. 독립 N 한 쌍은 모두 정상 종료했지만 추가 관계의 의미 개선은 확인하지 못했다. 전체 완료 기준 미달이며 동일 실패의 추가 조정·재시도 없이 결과를 보존한다. 최신 사용자 정정에 따라 별도 PR 본문·댓글 정리는 하지 않고 관련 파일 커밋·푸시와 기존 이슈의 실제 상태 기록만 수행한다.

- 작성일: 2026-10-05. 기준 `feature/ontology-grounded-recovery`, `e936db2`, 초안 PR #609.
- 현재 상태: 사용자 지시로 재개한 판정 단순화와 N 구현·실제 제한 비교를 수행했다. 정상 표현 판정은 개선됐으나 필수 한정 복구는 미달이고, N은 출력 실패·역할 범위 오류로 기본 채택을 보류한다. C 실제 교정 시험은 선행 원문 판단의 반복 출력/상한 실패로 중단했으며 실제 교정·같은 CQ·A3는 미달이다. [재개 검증과 중단 근거](../../70_research/company_knowledge/ontology_resume_validation_20261005.md)를 따른다. 아래 재개 절은 승인된 실행 범위와 기준의 기록이며, 이전 중단 이력도 보존한다. 기존 이슈와 초안 PR #609를 유지한다.
- 목표: **정상 의미를 유지하며 실제로 수정하고, 같은 업무 요구를 다시 확인하며, 필요한 후속 변경안까지 연결한다.** 보류 증가·후보 삭제·복구 차단·형식 통과는 이 목표의 성공이 아니다.
- 사용자 사진의 순서: ① 정상 결과 동반 실패 방지·복구 연결 → ② 필수 의미 대조·자료 부족/생성 누락 구분 → ③ 정상 의미 보존 부분 교정 → ④ 작은 실제 복구·재판정. 연결 이웃 선택 N은 별도 개념화 변경으로 유지한다.
- Ponytail: 기존 주소·실행기·저장소·교정 경로를 활용하되, 현재 기능이 부족하면 필요한 기능을 새로 구현한다. 재사용 때문에 목표를 축소하지 않는다. 새 범용 프레임워크·그래프 DB·에이전트 계층은 필요하지 않다.
- 기존 작업 이슈: [P1 #610](https://github.com/Hangi-n42/Civil-Complaints-System/issues/610), [P2 #611](https://github.com/Hangi-n42/Civil-Complaints-System/issues/611), [P3 #612](https://github.com/Hangi-n42/Civil-Complaints-System/issues/612), [P4 #613](https://github.com/Hangi-n42/Civil-Complaints-System/issues/613), [N #614](https://github.com/Hangi-n42/Civil-Complaints-System/issues/614). 사진 순서의 핵심 경로와 별도 N을 구분하며 과거 완료/미완료 이력은 유지한다.

## 확인된 실패와 가설

고정 후보 19개 시험은 E HTTP 2회에서 멈췄다. 첫 응답에는 긍정 의무/권한의 부정 표시, 규칙 존재와 실행 세부 조건의 혼동, 제공 목록 내부 자료의 외부 부재 오분류가 있었다. 둘째 응답은 출력 상한에 도달해 최종 JSON이 없었다. R·실제 교정·join·A3는 실행되지 않았다. 과거 국소 원명제 보존·끝점 교정의 성공은 이번 결과와 구분해 보존한다.

코드에서 한 의미의 검증 오류가 전체 E를 실패시키는 경계를 확인했다. 원문 조사 범위 검사 수정은 이미 완료됐으므로 반복 구현하지 않는다. 모델 능력 자체의 한계, 새 계약의 표현 방식, 판단 단위의 크기는 아직 구분하지 못한 원인이다. 코드의 행동표가 의미 진위를 보장하지 않는다.

## P1 정상 결과 격리와 실제 후속 처리 연결

**왜 먼저:** 정상 의미가 저장되지 않거나 추가 읽기·복구가 실행되지 않으면 의미 판정 개선이 최종 결과로 전달되지 않는다.

**문제/근거:** `analysis.call`의 전체 Pydantic/원문 참조 복원과 `meanings.grounding`의 row 예외가 전체 단위를 실패시킨다. `route`는 challenge 대상 키만 제외하지만 `authorized`는 challenge 하나로 같은 표현 묶음의 모든 복구를 차단한다. `refresh`는 action에서 반환하지만 route는 recover/correct만 처리하고 assess는 source_challenges만 재진입하므로, 후속 입력 확보·재판정 예약이 연결되지 않는다. 전문가가 호출 경로에서 확인했다.

**변경:**
- 전체 응답 구조·원문 조사 범위는 전체 계약으로 검사한다. 개별 의미의 필드/근거/자료명 오류는 기존 record error 패턴으로 격리하고, 정상 레코드 및 원래 응답을 보존한다. 누락된 필수 의미와 오류 레코드는 미완료로 남기고 전체 완료로 합산하지 않는다. 형식상 정상인 의미를 의미상 정답으로 승격하지 않는다.
- 무효화·challenge 범위는 해당 의미와 실제 의존 전제/표현으로 제한한다. 근거 없는 독립 정상 후보 재교정과 같은 묶음 전체의 복구 차단을 피한다. E뿐 아니라 R/join의 개별 레코드 복원/검증 경계도 같은 원칙으로 확인한다.
- 제공 자료 내부 미선택은 구체 블록/참조 대상을 확인한 뒤 기존 원문 읽기/검색으로 필요한 구간을 확보한다. 선택 이력과 새 지문을 저장하고 해당 근거 판정만 갱신한다. 제목/비슷한 이름만으로 같은 조문이라고 확정하지 않는다.
- 용량 초과는 조건·예외·기간·명시 참조를 보존하는 논리 단위로 나눈다. 작은 필수 단위 자체가 못 들어가면 capacity로 남긴다. 동일 실패 입력의 무제한 재시도는 하지 않는다. 후속 descriptor와 `pending_calls` 예약은 같은 plan에서 산출하여 읽기/재판정 비용을 빠뜨리지 않는다. 같은 실패 ID를 덮어쓰지 않고 바뀐 입력의 새 지문을 저장한다.

**모듈/입출력/저장:** `discovery_analysis.call/normalize`, `discovery_grounding.normalize/assess/challenge/authorized`, `discovery_meanings.grounding`, 기존 `discovery_segments`/context 읽기. 응답 묶음 → 정상 의미+개별 오류+미완료 범위 → 현재 의미별 후속 작업. 기존 `analysis_units`, `recovery_requests`, 원문 지문과 입력/응답 기록 사용.

**검증/완료:** 정상+형식 오류 혼합에서 정상 결과 보존, 오류 부분만 미완료, 독립 정상 recover 실제 실행, 관련 challenge만 차단. 내부 자료 미선택이 실제 읽기→새 판정으로 이어지고 외부 부재는 생성 명령으로 바뀌지 않는다. 코드 연결 완료와 모델 의미 성공은 분리 보고한다.

## P2 원문 의미 판단 단위와 자료 상태 교정

**왜 필요한가:** 새 E/R 구조에서도 E 자체가 규칙 존재와 사례 적용을 혼동했다. 프롬프트에 '엄격히 검수'를 추가하는 것만으로는 판정 대상이 분명해지지 않는다.

**변경:**
- 기존 원명제 `statement_type`과 원문 주소를 재사용해 정의/규칙/사례를 구별한다. 부족한 경우 판단 대상 계약을 추가하여 **원문 규칙의 내용**, **특정 사례의 조건 충족**, **여러 의미에서 도출하는 연결**을 구별한다. 미승인 Relation 출력은 해석 단서이며 정답 근거가 아니다. 새 Relation 실행을 E의 필수 선행조건으로 만들지 않는다.
- 규칙을 이해하는 데 필요한 문맥과 규칙을 실제 적용할 때 필요한 사실을 구분한다. 의무·권한·참조 사실은 보존하고, 외부 상세가 필요한 별도 의미만 unknown으로 남긴다. 의미별 전제 목록의 내용은 모델이 판단하며 서버가 문자열로 정답을 주입하지 않는다.
- `negation`은 원명제의 극성이고 `source_status`는 그 명제의 원문 지지 여부임을 입출력에서 명확히 구분한다. 부정이 적용되는 구절·술어를 원문 주소와 함께 유지한다. 정의 안의 국소 부정이나 '불구하고'를 정의 전체의 부정으로 확대하지 않는다. 원문에 없는 부정을 서버가 자동 생성/삭제하거나 모두 affirmed로 덮어쓰지 않는다.
- 자료 위치는 현재 제공 목록/선택 주소를 기준으로 확인하고, 원문으로 결론을 낼 수 있는지는 별도로 판단한다. 내부 미선택/위치 불명/외부 미제공/읽었으나 의미 미확정/용량 실패를 다음 행동에 연결한다.
- 출력 미완료는 의미 오판과 별개로 다룬다. 더 작은 판단 단위와 간결한 출력 계약부터 사용하고 실제 입력량·출력/사고 토큰·완료 응답을 비교한다. 매개변수나 모델을 바꾸면 별도 조건으로 기록한다.

**모듈/입출력/호출:** `discovery_meanings` 모델·본문 키·프롬프트·action, `discovery_grounding.source_packet/packet_descriptors`, 기존 scope/segments. 원문+CQ+검토 가설 → 의미 종류/극성/범위/전제별 근거 결과 → R 대조. 내용이 바뀌면 새 의미키와 이전 키 참조, 영향 받은 결과만 갱신한다. 기존 자유 서술 cause 경로와 새 판정을 이중 실행하지 않는다.

**검증/완료:** 기존 실패 원문과 작은 정상 대조에서 긍정 의무·권한 보존, 외부 상세는 미확정, 근거 없는 법적 포함 복구 없음, 실제 제공 누락은 recover, 부정/예외/기간 보존, 내부 자료에 대한 실제 후속 읽기 확인. 최소 대조는 시행규칙 제15조의 선정 의무/기준 설정 권한, 법 제2조의 공공매입 정의 내 '직접 건설하지 아니하고'에 해당하는 실제 원문 구절, 법적 포함 미확정, 내부 법 제2조와 외부 시행령 제2조다. 실제 원문의 정확한 구절/범위를 시험 준비 시 확인한다. 같은 모델에서 좁은 계약 변경을 먼저 확인하고 모델·문맥·출력 한도를 동시에 바꾸지 않는다. 기존 전체 시험을 반복하기 전에 이 경계에서 실제 최종 응답과 의미를 확인한다.

## P3 정상 의미를 유지하는 부분 교정과 누락 복구

**문제:** 현재 새 계약의 교정 연결은 대역 검사만 통과했으며 실제 수정 실적은 없다. `route`는 의미별로 첫 오류를 교정한 뒤 같은 후보의 다음 오류를 correction_plan에 있다는 이유로 건너뛴다. 또한 `queue_recovery`가 기존 원문/role 요청에 새 의미를 병합했을 때 candidate_ref가 빈 누락 요청은 두 번째 의미키/판정 지문 전달에서 빠진다. 반대로 candidate_ref 동일 조건은 다른 과거 원인의 요청 메타데이터까지 덮어쓸 수 있다. 모두 전문가의 코드 확인 사항이다.

**변경/이유:** 같은 후보의 현재 근거 있는 교정 요구를 모아 잘못된 필드와 보존 의미를 함께 전달한다. 관계 끝점은 Builder, 원명제/정의는 Revision, 실제 빠진 의미는 Concept/Relation에 전달한다. 같은 후보 수정 횟수를 늘려 임시로 우회하지 않는다. queue_recovery가 실제 생성/갱신한 요청 ID를 반환해 의미별 판정 권한을 정확히 병합하고 과거 무관 요청은 보존한다. 기존 before/after·focused Critic·preservation 기능을 재사용하되 수정 후 같은 의미의 R을 다시 실행한다. 새 근거가 이전 보존 판정을 반박하면 이유/근거와 함께 정정한다.

**모듈/저장/순서:** `discovery_grounding.route`, `discovery_analysis.queue_recovery/recovery_groups`, `discovery_synthesis.revise/review_context`, `discovery_scope.preserve`. 현재 E/R → 후보별 수정 묶음 → 실제 after → 오류 제거+정상 의미 보존 → 변경된 R. 기존 candidate/revision ID·원본 before·after·판정 지문을 보존한다.

**검증/완료:** 과거 잘못된 끝점 또는 근거 없는 효과를 포함한 고정 사본에서 실제 수정하고 정상 선정 역할·조건·범위를 유지한다. 한 후보에 두 독립 오류가 있는 대조에서는 둘 모두 한 번의 교정 입력에 들어가고 두 의미 모두 재검수되어야 한다. 별도 실제 누락 사례에서 필요한 의미를 실제 추가하고 병합된 각 의미의 권한·결과와 중복 생성 여부를 확인한다. 정상 대조는 불필요하게 바꾸지 않는다. 합성/구성 오류, 과거 오류 재현, 신규 자연 발생 오류는 출처를 구분한다. 정답 검수 주입·후보 삭제·보류를 성공으로 세지 않는다.

## P4 같은 업무 요구와 필요한 후속 변경안 재확인

**문제:** 개별 E/R 성공을 합산하면 문서 간 연결의 전제 누락을 놓친다. 초기 E에는 다른 패킷의 의미키가 제공되지 않아 교차 전제를 처음부터 참조할 수 없으며, join은 기존 전제의 상태만 검수한다. 따라서 교차 전제 연결을 실제 제안·근거 재판정할 좁은 경로가 필요하다. join의 입력 초과 처리도 미완료·미검증이다.

**변경:** 관련 의미와 직접 전제/원문/현재 표현을 묶어 연결을 검수한다. 제공된 여러 문서를 함께 읽어야 하는 연결은 별도 결합 단위로 판단하고 새 근거/모순은 관련 E로 돌려보낸다. 입력 초과 시 의미 의존 묶음별로 나누되 묶음 사이 공유 전제·상충 검사를 남긴다. supported 수의 합계나 모든 원문 재전송을 전체 검수의 대체물로 쓰지 않는다.

**모듈/입출력:** `discovery_grounding.packet_descriptors/saved/challenge`, `discovery_requirements`, `discovery_analysis.finish`, 기존 `ontology_changes.publish/preview`. 현재 의미/표현+연결 전제 → 같은 CQ의 충족/구체 공백 → 필요한 실제 유형·관계·계층과 검수 기록의 A3 변환. 사람 승인/발행은 실행하지 않는다.

**검증/완료:** P2/P3의 작은 경로가 성공하면 원래 두 문서·같은 CQ를 다시 실행해 근거 있는 업무 연결과 불확정 외부 연결을 구별한다. 실제 교정의 before/after·보존·새 R/join을 확인하고 필요한 실제 생성 계층/양방향 검수 및 A3 포함 내용을 확인한다. A3 입력 부족을 제품 결함이라고 단정하지 않는다. 과거 #605/#606의 남은 완료 증거와 연결하되 이슈를 자동으로 닫지 않는다.

### 작업 A — #611의 표현 판단 계약과 필수 한정 재판정

**확인된 문제:** v106 R2는 후보가 정확하다는 설명과 `incorrect/absent/locations=[]`를 함께 반환하고 의미키 하나를 누락했다. 제49조·주택사업 목적 제한은 정상 후보에는 있으나 E 본문/조건/전제에는 없다. 원문이 없거나 후보에 조건이 없다는 문제가 아니다. 모델 능력·입력 복잡도·독립 필드 부담의 상대적 기여는 아직 가설이다.

**변경:** `Expression`의 독립 `status/assertion` 조합에서 assertion을 제거하고 기존 네 status를 현재 표현에 관한 단일 결론으로 정의한다. 원문 판정에 맞게 표현/실제 표현 누락/잘못된 현재 주장/판정 불가를 구분하고, 현재 원문 상태와 결합해 기존 maintain/recover/correct/gap/refutation/refresh 행동을 도출한다. missing은 위치 목록이 비었다는 이유만으로 서버가 추정하지 않는다. 불확실한 근거의 확정 주장과 적절한 미확정 표현을 결론 정의에서 구분해야 한다.

현재 제공된 의미키를 고정된 응답 대상에 사용하고 각 키가 요구되는 keyed 응답을 기존 스키마 조립에 통합한다. 공용 `$ref`를 사용하고 스키마 비용도 `input_size`에 계산한다. 의미마다 별도 모델 호출을 신설하지 않는다. 정규화 후에는 기존 checks/receipt/record_errors/pending을 유지하여 후속 소비자를 재사용한다. 고정 키는 대상 누락을 줄이는 계약이며 내용의 정답을 보장하지 않는다.

E의 한정 누락은 기존 원문과 현재 후보의 실제 필드를 대조한 `source_challenge`로 해당 E만 보완한다. 후보에 이미 있는 내용을 새 후보 누락으로 복구하지 않는다. E의 의미 본문이 바뀌면 새 키·supersedes와 현재 원문 근거를 보존하고, 같은 R을 다시 확인한다. 재판정 대상키가 주어진 경우 supersedes 허용키를 그 범위로 한정하고 독립 정상 의미는 기존 병합에서 보존한다. 정상 후보 문구나 정답 검수 결과를 E의 확정 근거로 주입하지 않는다.

**모듈/호출/저장:** `discovery_meanings.Expression/Representation/representation/action/records`, `discovery_grounding.contract/prompt/challenge/assess`, 기존 `analysis.input_size/recipe`와 검수 저장. 현재 E+후보 실제 위치 → 고정 키 R → 필요한 E 재판정 또는 기존 부분 교정 → 같은 키/새 현재 키의 R. 계약/지문을 바꾸고 과거 실행은 변환하지 않는다.

**완료:** 정상 후보를 실제 위치와 함께 유지하고, 필수 한정을 E에서 실제 보완하며, 자료 부족을 생성 명령으로 만들지 않는다. 형식 적합·누락키 보류만으로 성공 처리하지 않는다.

### 작업 B — #614의 실제 Relation→Concept·연결 이웃 선택

**구현:** 현재 묶음에서 Relation을 먼저 실행하고 성공한 자연어 원명제의 끝점에 직접 붙은 관계·상대 끝점을 Concept와 필요한 Builder 문맥에 전달한다. 직접 정의 원문 경로는 유지하며 Relation 실패/0개가 취소·공통 예산 종료·필수 원문 실패가 아닌 한 직접 정의 Concept을 차단하지 않는다. Concept-only 복구는 고정된 성공 Relation 풀을 쓰고 Relation-only 복구는 Concept을 강제 재실행하지 않는다.

**식별/선택:** 기본 `(relation_id, endpoint)` 노드와 근거 구간에서 유일하게 확인된 정확 언급 주소만 쓴다. 명칭 유사도나 다른 위치의 동일 문자열로 병합하지 않는다. 대상의 역할·조건·구분을 설명하는 직접 관계를 먼저 선택하고 같은 근거·범위·조건의 표시 중복만 제거한다. 원 관계 ID는 모두 보존한다. 저장/입력에서 관계 이웃, 문서 구조 문맥, 명시 참조, 검색 비교 자료를 구분한다.

**필수 문맥/예산:** 원명제와 의미를 결정하는 조건·예외·기간·참조, 양끝점과 방향 및 현재 근거를 한 패킷으로 취급한다. Relation의 예외는 별도 필드가 아니라 conditions/원문 구조에 있을 수 있다. 필수 패킷 우선, 남은 예산에 선택적 이웃을 넣는다. 필수 내용은 개수 상한에 맞춰 자르지 않으며 내부 미선택 자료는 기존 읽기/분할을 실행한다. 원자 패킷 자체가 초과하면 capacity로 남기고 구체 누락을 기록한다. 미제공 참조는 실제 자료명으로 공백을 남긴다.

**실제 코드 경계:** `process_group`의 stage별 context/deps를 별도 복사하고, `source_projection`과 `discovery_synthesis`의 작은 공용 selector를 재사용한다. `context_for/assemble/synthesize`의 기존 비교 문맥 공급과 통합한다. `analysis_context.retained()`/`tool_originals` 제거에서 이웃 명제·근거가 따로 사라지지 않도록 한다. `compact/make_prompt`의 최종 직렬화에서 relation ID·방향·상대 끝점·원문 위치가 실제로 전달되는지 검사한다. 선택 기록만 저장하는 구현은 불충분하다.

**입출력/저장:** 대상 endpoint/언급 주소+현재 원문+고정 성공 Relation 풀+필수 문맥+남은 예산 → target별 선택 이웃·근거·범위·추출/검수 상태·제외 이유. 기존 analysis_units/candidate_groups의 입력과 정책/풀/선택 지문에 저장하여 성공 호출 재개 입력을 고정한다. 미승인 추출은 unreviewed 상태이며 확정 사실로 승격하지 않는다. 새로운 DB·프레임워크·선택용 모델 호출은 추가하지 않는다.

**완료:** 빈 ontology, 직접 정의의 독립성, 모호한 동명 언급, 필수 조건, 중복, 예산·분할·자료 공백·재개를 작은 검사로 확인하고 실제 모델 N0/N1 입력·산출을 확보한다. 효과가 없거나 악화되어도 비교 결과를 남기고 채택을 따로 판단한다.

### 작업 C — #612/#613의 실제 수정·복구와 같은 요구 확인

작업 A의 판정이 가능한 경로에서 기존 7197의 잘못된 끝점 사본을 실제로 고치고 선정 역할·의무·조건을 보존한다. 실제로 제공된 필수 의미가 빠진 고정 대조에서도 생성→재검수를 확인한다. 기존 `route/revise/binding/preserve/recovery_groups`를 사용하며 완료된 P1/P3 경계를 다시 구현하지 않는다. 원본 before/after·현재 근거·같은 CQ를 저장한다.

필요한 유형·관계·계층 및 현재 검수 기록이 갖춰진 경로에서 A3의 실제 포함 내용을 확인한다. 개별 supported 합계를 전체 요구 충족으로 보지 않는다. 핵심 경로가 계속 실패하면 그 완료만 미완료로 남기며 작업 B의 모델 비교는 반드시 별도로 진행한다.

### 구현 순서·효과 측정·채택

1. 기존 P1/P3 및 입력 계약을 확인한 뒤 A의 좁은 계약 변경과 B의 실제 선택/순서 변경을 구현한다. 같은 모듈의 편집은 직렬로 조정하되 A 모델 시험의 성공을 기다려 B를 착수하지 않는다.
2. 실행 전 원문·질문·원 Relation provenance·기준·모델 digest·설정·코드/입력 지문과 실제 패킷별 호출/시간 상한을 동결한다. 기존 후보 투영본의 attempts=0을 새 Relation 추출 실행이라고 보고하지 않는다. 원 실제 추출 단위로 출처를 검증하거나 필요한 Relation을 한 번 실제 추출해 양군이 공유한다.
3. A/C의 실제 판정·교정 시험과 B의 N0/N1 비교는 독립 수행한다. N 비교는 법 제2조 0:628 직접 정의와 규칙 제15조 0:539 역할/권한 원문을 우선 사용한다. 입력과 대상은 결과를 본 뒤 유리하게 바꾸지 않는다.
4. N0/N1 양쪽은 같은 Relation 선행 결과·원문·CQ·모델·설정·현재 핵심 계약·기준 유형·독립 문맥 발견을 사용한다. N0 기존 문맥/선택 비활성, N1 직접 연결 이웃 선택 활성에서 각각 Concept/필요 Builder를 실제 호출한다. 한 군의 생성 후보를 다른 군에 제공하지 않는다. 차이가 실제 prompt에 존재해야 한다. 이 비교는 문맥 선택 효과이며 순서 변경의 인과 효과가 아니다. 실제 순서 연결은 작은 제품 호출 경로로 확인하고, 추가 순서 대조는 분리 필요성이 확인될 때만 한다.
5. 필수 의미·조건·예외 보존, 역할/유형/끝점/범위, 신규 출력 전체의 중복·허위 연결, 실제 교정/누락 복구, 같은 요구/필수 후속 산출물, 호출·실제 입력 char/byte/token·최종 출력량/전체 생성 token·시간을 비교한다. 공유 Relation은 각 군 논리 비용에는 포함하고 신규 HTTP 소비에는 한 번만 계산한다. 실제 교정이 발생하지 않은 비교는 교정 효과 미측정이다.
6. N0/N1 표식을 가린 실제 산출물을 원문·동결 기준으로 독립 의미 검토한다. 정상 의미가 다른 필드에 있어도 인정하되 인용 주소만으로 충족으로 세지 않는다. 개선/악화/동일/판단 불가 및 두 단계의 한계를 모두 보고한다. 이웃이 실제 선택되지 않거나 두 입력이 같으면 선택 효과는 미식별이다.
7. 같은 실패의 설정 조정/전체 실행은 반복하지 않는다. 실패한 한 경로를 멈춰도 독립 경로는 실행한다. 결과에 따라 N 채택/보류를 명시하고, 전체 제품 완료를 입증하지 못하면 초안 상태와 열린 이슈를 유지한다. 같은 브랜치에서 커밋·푸시하고 PR #609 및 기존 이슈에 최종 근거를 반영한다.

## 2026-10-05 두 번째 재개: 응답 완결·원명제 추적·오류 끝점의 실제 교정

기준은 `feature/ontology-grounded-recovery`의 `fb1b167`, 기존 PR #609다. 사용자 요청으로 재개한다. 기존 #610–#614에 아래 범위를 반영하며 동일 이슈나 새 기본 설계를 만들지 않는다. 앞선 [최종 검증 기록](../../70_research/company_knowledge/ontology_resume_validation_20261005.md)의 실패와 원본 DB·동결 출력은 유지한다.

### 목적·사실·실행 순서

사진 순서대로 **① 정상 결과가 후속 경로에 도달할 수 있는 응답 완결 → ② 필수 의미와 자료 상태 대조 → ③ 정상 의미를 유지한 실제 부분 교정 → ④ 같은 요구와 다음 산출물 확인**을 진행한다. 원문 판단 E와 표현 판단 R의 분리는 유지한다. 이웃 선택 N은 별도 효과 시험이며, E나 국소 교정의 성공을 선행조건으로 두지 않는다.

- 확인된 실패: C의 조사 주소 배열이 같은 6개 주소를 반복해 출력 상한으로 잘렸다. 읽을 수 있는 부분에도 권한자–공급 조건의 짝, 법적 한정·예외가 빠졌다. 두 문제는 별개다.
- 확인된 산출 오류: N의 시도지사 관계가 장관/LH 명제에 한정된 목적어 역할을 재사용했다. N 비교는 Builder까지만 실행했으므로 Binding Critic까지 실패했다고 단정하지 않는다.
- 기존 정상 기능: 원문/표현 분리, 항목별 정상 결과 보존, 의미별 복구 요청, 실제 Binding→Builder 교정과 보존 검수, Relation→Concept·이웃 선택은 재사용한다. 역할 검수에 필요한 원명제·정의·role_source는 이미 전달된다.
- 원인 가설: 모델이 권한 분기를 축약하는 원인에서 모델 능력·입력 구성·판단 단위의 상대적 기여는 미확정이다. 원명제 가설 연결과 끝점 교정 경계 보완의 효과를 실제 출력으로 확인한다.

### 1. #610 — 조사 주소의 유한 출력과 정상 결과 보존

**변경 이유:** `discovery_grounding.contract()`는 허용 주소 enum만 만들고 배열 길이를 제한하지 않는다. `discovery_meanings.grounding()`은 집합으로 조사 범위를 검사하므로 주소 반복은 정보를 더하지 않는다.

**수정:** 공유 응답 스키마의 `examined_source_refs.maxItems`를 현재 고유 제공 주소 수로 제한한다. 완전한 JSON의 동일한 허용 주소 중복은 원시 응답을 보존하고 순서 유지 중복 제거 후 기존 구간 커버 검사를 적용한다. 범위 밖 주소·미조사는 계속 미완료다. 서버가 조사 목록을 자동 채우거나 잘린 JSON의 앞부분을 성공으로 복원하지 않는다. 같은 종류의 유한 참조 배열은 호출 경로를 확인하여 필요한 최소 경계만 적용한다.

**입출력·저장·재사용:** 기존 source_ref와 Grounding 응답 → 유한 조사 선언 → 기존 정상 meaning/record_errors/assessment 저장. 별도 검수 호출은 추가하지 않는다. 입력 제공·조사 선언·의미 정확성을 구분한다.

**완료:** 작은 스키마/완전 응답 대조에서 상한·부모 구간 포함·실제 미조사·정상 의미 보존을 확인하고, 변경된 실제 E가 유효하게 저장돼 R로 이어지는지 확인한다. 형식 완료는 의미 완료가 아니다.

### 2. #611 — 미승인 원명제에서 E/R까지 같은 의미를 추적

**확인된 연결 공백:** 현재 `source_packet()`에는 독립 발견 가설만 있으며 raw Relation→E 의미 대응이 없다. 기존 `meaning_registry/meaning_usage`는 E→후속 생성의 반대 방향이다. R은 현재 E 키만 보면 E가 통째로 놓친 명제도 놓칠 수 있다.

**새로 구현할 최소 계약:**
- 실제 성공한 원문 Relation 단위의 `source_projection()`을 출처·버전·파싱·블록·구간과 함께 `unapproved_relations` 가설로 E/R에 전달한다. 승인된 유형이나 교정된 끝점·과거 판정을 정답으로 넣지 않는다. 현재 패킷의 제공 원문과 연결된 실제 추출만 사용하고, Relation 실패가 직접 원문 판단을 차단하지 않는다.
- `SourceMeaning.proposition_refs`로 실제 제공 가설과 의미의 대응을 저장한다. 빈 목록·여러 가설의 한 의미·한 가설의 여러 의미를 허용한다. 원명제 하나마다 supported를 강제하지 않으며, 가설 밖의 원문 의미도 발견할 수 있어야 한다.
- R에도 같은 가설·원문·대응을 전달한다. 기존 의미의 조건 누락은 기존 meaning_key challenge, 통째로 빠진 가설의 재판정은 새 `proposition_ref` challenge로 구분한다. Challenge에는 두 참조 중 정확히 하나만 허용하고, 실제 제공된 가설 ID만 받는다. 원명제 ID를 임의 의미키로 위장하지 않는다.
- 기존 challenge 경로가 해당 가설의 원래 source receipt로 재진입한다. 신규 대상은 `reassess_proposition_refs`로 추적하고 supersedes는 비운다. E가 원문으로 supported/refuted/unknown/비해당을 판단한다. 서버가 내용을 채우지 않는다.
- 재판정에서도 요청한 가설의 대응이 빠지면 새 정상 의미는 저장하되 해당 요청은 pending이다. 미매핑 가설을 자동 생성 누락으로 바꾸지 않는다. 현재 원문 지지+실제 표현 누락일 때만 기존 생성 복구를 허용한다.

**모듈·호출·저장:** `discovery_grounding.source_packet/packet_descriptors/challenge/prompt/contract`, `discovery_meanings.SourceMeaning/Challenge/records`, 기존 `discovery_design.source_projection`과 원문 주소 복원. raw 가설+원문→E 의미/가설 대응→R→필요한 E 재판정 또는 기존 교정/복구→같은 R. 새 대응·요청은 기존 analysis_units/context/meaning 기록에 저장하고 계약/프롬프트 지문을 갱신한다. 과거 기록은 변환하지 않는다.

**검증·한계:** 권한자–조건 쌍·제49조/설립 목적·예외를 원문 기준으로 확인한다. 잘못된 미승인 가설을 반박하는 대조, 전체 가설 누락 후 실제 재판정, 가설 밖 의미, 자료 미제공/내부 미선택을 작게 검사한다. 가설이 조건을 빠뜨렸다면 E도 따라 빠뜨릴 수 있다. 참조 연결 자체를 의미 검증으로 계산하지 않는다. 필수 원문은 유지하고 같은 명제/인용을 중복 직렬화하지 않는다.

### 3. #612 — 정상 끝점을 고정한 실제 부분 교정

**재사용할 경로:** 현재 원명제·선택 유형의 선언 범위→기존 Binding의 subject/object 판정→complete_reviews→endpoint issue→기존 revise(Builder)→수정 후 검수. 필요한 역할 정보가 이미 입력에 있으므로 새 검수기를 만들지 않는다. 먼저 실제 미실행 경로에서 오류를 판단하는지 확인한다.

**확인된 코드 보완:** 현 연결 교정은 원명제 불변은 검사하지만 정상 끝점 변경도 허용한다. 현재 유효한 검수의 끝점별 판정과 binding_before로 반박된 끝점만 교정 대상으로 정한다. `revise()`가 이 허용 범위를 전달하고 `response_contract()`는 정상 끝점을 기존 ID로 고정하며 저장 직전에도 검사한다. 양쪽 오류는 양쪽 수정이 가능해야 한다. 오래된 검수로 교정 권한을 만들지 않는다.

**범위 경계:** 관계 ID나 원명제가 다르다는 이유만으로 재사용을 전면 금지하지 않는다. 역할 출처 현재성은 의미 범위 포함 증명이 아니다. 실제 사용 범위가 선언 범위에 포함되는 정상 재사용은 허용하고, 원문으로 충돌이 확인된 끝점만 수정한다. 확정 불가는 unknown으로 구분한다.

**실제 대상·완료:** 보존된 N 권한 r2/t3 오류를 실제 원명제/Binding 검수에 넣고, r1과 정상 주체·조건을 유지하며 r2 목적어만 적합한 기존 유형이나 r2의 출처 역할로 재연결한다. 기존 7197 양끝점 오류도 현재 판정이 가능한 경로에서 확인한다. 전후 후보·검수·보존 기록과 같은 권한 요구 재확인이 있어야 성공이다. t3 전체 삭제·후보 보류·원문 조건 축약은 성공이 아니다.

국소 Binding 교정에는 전체 문서 E 성공이 코드상 필수 선행조건이 아니다. 국소 원명제/끝점 판정과 현재 지문이 유효하면 독립 실행한다. 그 성공을 전체 CQ나 A3 완료로 확대하지 않는다.

### 4. #613 — 실제 수정·실제 누락 복구 뒤 같은 요구와 A3 확인

같은 두 문서·원래 CQ를 유지한다. 부분 교정 후 현재 지문의 E/R/연결 전제를 다시 확인한다. 제공된 의미가 실제 빠진 작은 사본 대조에서는 근거 판정→기존 recover→실제 생성→같은 의미 재검수를 확인한다. 구성한 누락과 자연 발생 오류를 구분하고 정답 판정을 주입하지 않는다. 문서 간 법적 포함이나 미제공 별표/시행령 상세를 만들어 채우지 않는다.

실제 유형·관계·필요 계층과 현재 양방향 검수가 갖춰진 경우 기존 변경안 preview/변환으로 A3 포함 내용을 확인한다. 자료/검수 입력이 없어 막혔다면 제품 결함이라고 단정하지 않는다. 국소/전체 요구/변경안 상태를 각각 기록한다. 정상 의미 보존+실제 수정/복구+같은 요구 재확인+필요한 후속 단계가 완료 기준이다.

### 5. #614 — 추가 연결 관계 하나의 독립 효과 확인

Relation→Concept와 선택기는 이미 구현됐다. 재구현하거나 기본 활성화하지 않는다. 앞선 전체 on/off 비교에서 Builder의 주분석 밖 이웃이 0개였던 한계를 보완한다.

authority의 장관–LH r1을 주분석 대상으로 고정한다. 시도지사–지방공급 r2는 같은 목적어의 정확한 원문 주소(version `a4475cf8e17e4602abd59dde10063d24`, parse `0100c5fec09449bdba396d9b6654bae3`, block `1e4c6a6dfc69410b923e15b9e748efa4`, span `[329,380]`)로 연결된다. 제품 selector→최종 프롬프트에서 추가 r2 패킷 한 개가 실제 전달되는 것을 전문가가 확인했다. 이름 유사도 결합이 아니다.

**최소 비교:** 같은 저장 Concept 후보·r1·전체 원문·Relation 기록·모델·설정을 고정한다. 기존 Builder의 유형 설계 경로에서 양군 모두 primary r1 메타데이터를 유지하고 제품 selector가 만든 r2 패킷만 미제공/제공으로 바꾸는 진단 조건을 둔다. 새 제품 설정이나 일반 ablation 프레임워크는 만들지 않는다. 신규 모델 호출은 우선 한 쌍이다. 이는 기존 feature false/true 비교와 별개인 추가 구조화 관계 노출 비교다.

원문 자체는 양쪽에 있으므로 새 자료 획득 효과가 아니다. r1의 주체·LH 조건·예외가 유지되는지, r2 조건이 섞이지 않는지, 역할/중복/근거 없는 연결·실제 입출력/시간을 비교한다. 주분석 밖 r2를 새 성과로 세지 않는다. 동일/악화/판단 불가도 그대로 보고하고 독립 의미 검토를 받는다. 핵심 E 또는 교정 실패만으로 이 독립 비교를 생략하지 않는다. 출력 완료성 보완이 있다면 양군에 동일하게 적용한다.

### 실행·중단·전문가 검토

- 구현 편집은 1→2→3 순서로 조정하고 관련 작은 검사만 한다. 이미 완료한 P1/P3/N 코드를 반복 작성하지 않는다. 4는 필요한 실제 수정·검수 결과에 의존하고 5는 독립이다.
- 기존 실패와 정상 대조·원문·CQ·실제 Relation provenance·모델 digest·코드/설정·기준을 먼저 고정한다. E 변경 묶음의 개선을 개별 필드의 독립 인과 효과로 주장하지 않는다. 실제 의미 검토는 모델 자기평가와 분리한다.
- 먼저 작은 E/R와 독립 Binding 교정을 실행한다. 같은 원인에 대한 설정 조정/전체 실행은 반복하지 않는다. 확인된 원인의 수정 후에도 같은 실패가 지속되고 실제 개선이 없으면 그 경로를 멈추되 독립 가능한 N은 수행한다. 중단은 성공이 아니며 미달과 비용을 남긴다.
- 새 모델·출력 예산·정답 후보를 동시에 바꾸어 성공시키지 않는다. 과거 입력·DB·응답을 보존하고 새로운 실행 디렉터리를 사용한다. 사람 시험·병합·배포는 하지 않는다.
- `/root/platform_architecture_audit`: 유한 주소 계약, 중복만으로 전체 E 실패 금지, 기존 Binding 입력/교정 재사용, 정상 끝점 고정 경계 확인.
- `/root/comparison_evidence_audit`: 미승인 원명제→E/R 참조와 새 가설 challenge, 정상 형제 보존, 국소 교정의 독립성, 실제 수정/같은 요구 완료 기준 검토.
- `/root/autoschema_method_audit`: 정확 주소로 연결된 추가 관계 한 개 비교 가능 확인. 다른 관계라는 이유의 전면 재사용 금지 및 국소 교정 성공을 N의 선행조건으로 두는 제안은 다른 두 검토와 조정해 채택하지 않는다.
- 계획 검토는 착수 가능성 판단이다. 구현/모델/교정 성공을 미리 확정하지 않는다. 필요 신규 기능은 구현하되 새 에이전트 계층·범용 프레임워크·DB 없이 기존 서비스와 표준 기능을 우선 사용한다. 관련 파일만 커밋·푸시하고 기존 PR #609와 이슈를 실제 결과로 갱신한다.
