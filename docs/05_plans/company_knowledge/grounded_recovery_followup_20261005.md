## 확인된 실패와 가설

고정 후보 19개 시험은 E HTTP 2회에서 멈췄다. 첫 응답에는 긍정 의무/권한의 부정 표시, 규칙 존재와 실행 세부 조건의 혼동, 제공 목록 내부 자료의 외부 부재 오분류가 있었다. 둘째 응답은 출력 상한에 도달해 최종 JSON이 없었다. R·실제 교정·join·A3는 실행되지 않았다. 과거 국소 원명제 보존·끝점 교정의 성공은 이번 결과와 구분해 보존한다.

코드에서 한 의미의 검증 오류가 전체 E를 실패시키는 경계를 확인했다. 원문 조사 범위 검사 수정은 이미 완료됐으므로 반복 구현하지 않는다. 모델 능력 자체의 한계, 새 계약의 표현 방식, 판단 단위의 크기는 아직 구분하지 못한 원인이다. 코드의 행동표가 의미 진위를 보장하지 않는다.

## P1 정상 결과 격리와 실제 후속 처리 연결

**왜 먼저:** 정상 의미가 저장되지 않거나 추가 읽기·복구가 실행되지 않으면 의미 판정 개선이 최종 결과로 전달되지 않는다.

**문제/근거:** `analysis.call`의 전체 Pydantic/원문 참조 복원과 `meanings.grounding`의 row 예외가 전체 단위를 실패시킨다. `route`는 challenge 대상 키만 제외하지만 `authorized`는 challenge 하나로 같은 표현 묶음의 모든 복구를 차단한다. `refresh`는 action에서 반환하지만 route는 recover/correct만 처리하고 assess는 source_challenges만 재진입하므로, 후속 입력 확보·재판정 예약이 연결되지 않는다. 전문가가 호출 경로에서 확인했다.

**변경:**
- 전체 응답 구조·원문 조사 범위는 전체 계약으로 검사한다. 개별 의미의 필드/근거/자료명 오류는 기존 record error 패턴으로 격리하고, 정상 레코드 및 원래 응답을 보존한다. 누락된 필수 의미와 오류 레코드는 미완료로 남기고 전체 완료로 합산하지 않는다. 형식상 정상인 의미를 의미상 정답으로 승격하지 않는다.
- 무효화·challenge 범위는 해당 의미와 실제 의존 전제/표현으로 제한한다. 근거 없는 독립 정상 후보 재교정과 같은 묶음 전체의 복구 차단을 피한다. E뿐 아니라 R/join의 개별 레코드 복원/검증 경계도 같은 원칙으로 확인한다.
- 제공 자료 내부 미선택은 구체 블록/참조 대상을 확인한 뒤 기존 원문 읽기/검색으로 필요한 구간을 확보한다. 선택 이력과 새 지문을 저장하고 해당 근거 판정만 갱신한다. 제목/비슷한 이름만으로 같은 조문이라고 확정하지 않는다.
- 용량 초과는 조건·예외·기간·명시 참조를 보존하는 논리 단위로 나눈다. 작은 필수 단위 자체가 못 들어가면 capacity로 남긴다. 동일 실패 입력의 무제한 재시도는 하지 않는다. 후속 descriptor와 `pending_calls` 예약은 같은 plan에서 산출하여 읽기/재판정 비용을 빠뜨리지 않는다. 같은 실패 ID를 덮어쓰지 않고 바뀐 입력의 새 지문을 저장한다.

**모듈/입출력/저장:** `discovery_analysis.call/normalize`, `discovery_grounding.normalize/assess/challenge/authorized`, `discovery_meanings.grounding`, 기존 `discovery_segments`/context 읽기. 응답 묶음 → 정상 의미+개별 오류+미완료 범위 → 현재 의미별 후속 작업. 기존 `analysis_units`, `recovery_requests`, 원문 지문과 입력/응답 기록 사용.

**검증/완료:** 정상+형식 오류 혼합에서 정상 결과 보존, 오류 부분만 미완료, 독립 정상 recover 실제 실행, 관련 challenge만 차단. 내부 자료 미선택이 실제 읽기→새 판정으로 이어지고 외부 부재는 생성 명령으로 바뀌지 않는다. 코드 연결 완료와 모델 의미 성공은 분리 보고한다.

## P2 원문 의미 판단 단위와 자료 상태 교정

**왜 필요한가:** 새 E/R 구조에서도 E 자체가 규칙 존재와 사례 적용을 혼동했다. 프롬프트에 '엄격히 검수'를 추가하는 것만으로는 판정 대상이 분명해지지 않는다.

**변경:**
- 기존 원명제 `statement_type`과 원문 주소를 재사용해 정의/규칙/사례를 구별한다. 부족한 경우 판단 대상 계약을 추가하여 **원문 규칙의 내용**, **특정 사례의 조건 충족**, **여러 의미에서 도출하는 연결**을 구별한다. 미승인 Relation 출력은 해석 단서이며 정답 근거가 아니다. 새 Relation 실행을 E의 필수 선행조건으로 만들지 않는다.
- 규칙을 이해하는 데 필요한 문맥과 규칙을 실제 적용할 때 필요한 사실을 구분한다. 의무·권한·참조 사실은 보존하고, 외부 상세가 필요한 별도 의미만 unknown으로 남긴다. 의미별 전제 목록의 내용은 모델이 판단하며 서버가 문자열로 정답을 주입하지 않는다.
- `negation`은 원명제의 극성이고 `source_status`는 그 명제의 원문 지지 여부임을 입출력에서 명확히 구분한다. 부정이 적용되는 구절·술어를 원문 주소와 함께 유지한다. 정의 안의 국소 부정이나 '불구하고'를 정의 전체의 부정으로 확대하지 않는다. 원문에 없는 부정을 서버가 자동 생성/삭제하거나 모두 affirmed로 덮어쓰지 않는다.
- 자료 위치는 현재 제공 목록/선택 주소를 기준으로 확인하고, 원문으로 결론을 낼 수 있는지는 별도로 판단한다. 내부 미선택/위치 불명/외부 미제공/읽었으나 의미 미확정/용량 실패를 다음 행동에 연결한다.
- 출력 미완료는 의미 오판과 별개로 다룬다. 더 작은 판단 단위와 간결한 출력 계약부터 사용하고 실제 입력량·출력/사고 토큰·완료 응답을 비교한다. 매개변수나 모델을 바꾸면 별도 조건으로 기록한다.

**모듈/입출력/호출:** `discovery_meanings` 모델·본문 키·프롬프트·action, `discovery_grounding.source_packet/packet_descriptors`, 기존 scope/segments. 원문+CQ+검토 가설 → 의미 종류/극성/범위/전제별 근거 결과 → R 대조. 내용이 바뀌면 새 의미키와 이전 키 참조, 영향 받은 결과만 갱신한다. 기존 자유 서술 cause 경로와 새 판정을 이중 실행하지 않는다.

**검증/완료:** 기존 실패 원문과 작은 정상 대조에서 긍정 의무·권한 보존, 외부 상세는 미확정, 근거 없는 법적 포함 복구 없음, 실제 제공 누락은 recover, 부정/예외/기간 보존, 내부 자료에 대한 실제 후속 읽기 확인. 최소 대조는 시행규칙 제15조의 선정 의무/기준 설정 권한, 법 제2조의 공공매입 정의 내 '직접 건설하지 아니하고'에 해당하는 실제 원문 구절, 법적 포함 미확정, 내부 법 제2조와 외부 시행령 제2조다. 실제 원문의 정확한 구절/범위를 시험 준비 시 확인한다. 같은 모델에서 좁은 계약 변경을 먼저 확인하고 모델·문맥·출력 한도를 동시에 바꾸지 않는다. 기존 전체 시험을 반복하기 전에 이 경계에서 실제 최종 응답과 의미를 확인한다.

## P3 정상 의미를 유지하는 부분 교정과 누락 복구

**문제:** 현재 새 계약의 교정 연결은 대역 검사만 통과했으며 실제 수정 실적은 없다. `route`는 의미별로 첫 오류를 교정한 뒤 같은 후보의 다음 오류를 correction_plan에 있다는 이유로 건너뛴다. 또한 `queue_recovery`가 기존 원문/role 요청에 새 의미를 병합했을 때 candidate_ref가 빈 누락 요청은 두 번째 의미키/판정 지문 전달에서 빠진다. 반대로 candidate_ref 동일 조건은 다른 과거 원인의 요청 메타데이터까지 덮어쓸 수 있다. 모두 전문가의 코드 확인 사항이다.

**변경/이유:** 같은 후보의 현재 근거 있는 교정 요구를 모아 잘못된 필드와 보존 의미를 함께 전달한다. 관계 끝점은 Builder, 원명제/정의는 Revision, 실제 빠진 의미는 Concept/Relation에 전달한다. 같은 후보 수정 횟수를 늘려 임시로 우회하지 않는다. queue_recovery가 실제 생성/갱신한 요청 ID를 반환해 의미별 판정 권한을 정확히 병합하고 과거 무관 요청은 보존한다. 기존 before/after·focused Critic·preservation 기능을 재사용하되 수정 후 같은 의미의 R을 다시 실행한다. 새 근거가 이전 보존 판정을 반박하면 이유/근거와 함께 정정한다.

**모듈/저장/순서:** `discovery_grounding.route`, `discovery_analysis.queue_recovery/recovery_groups`, `discovery_synthesis.revise/review_context`, `discovery_scope.preserve`. 현재 E/R → 후보별 수정 묶음 → 실제 after → 오류 제거+정상 의미 보존 → 변경된 R. 기존 candidate/revision ID·원본 before·after·판정 지문을 보존한다.

**검증/완료:** 과거 잘못된 끝점 또는 근거 없는 효과를 포함한 고정 사본에서 실제 수정하고 정상 선정 역할·조건·범위를 유지한다. 한 후보에 두 독립 오류가 있는 대조에서는 둘 모두 한 번의 교정 입력에 들어가고 두 의미 모두 재검수되어야 한다. 별도 실제 누락 사례에서 필요한 의미를 실제 추가하고 병합된 각 의미의 권한·결과와 중복 생성 여부를 확인한다. 정상 대조는 불필요하게 바꾸지 않는다. 합성/구성 오류, 과거 오류 재현, 신규 자연 발생 오류는 출처를 구분한다. 정답 검수 주입·후보 삭제·보류를 성공으로 세지 않는다.

## P4 같은 업무 요구와 필요한 후속 변경안 재확인

**문제:** 개별 E/R 성공을 합산하면 문서 간 연결의 전제 누락을 놓친다. 초기 E에는 다른 패킷의 의미키가 제공되지 않아 교차 전제를 처음부터 참조할 수 없으며, join은 기존 전제의 상태만 검수한다. 따라서 교차 전제 연결을 실제 제안·근거 재판정할 좁은 경로가 필요하다. join의 입력 초과 처리도 미완료·미검증이다.

**변경:** 관련 의미와 직접 전제/원문/현재 표현을 묶어 연결을 검수한다. 제공된 여러 문서를 함께 읽어야 하는 연결은 별도 결합 단위로 판단하고 새 근거/모순은 관련 E로 돌려보낸다. 입력 초과 시 의미 의존 묶음별로 나누되 묶음 사이 공유 전제·상충 검사를 남긴다. supported 수의 합계나 모든 원문 재전송을 전체 검수의 대체물로 쓰지 않는다.

**모듈/입출력:** `discovery_grounding.packet_descriptors/saved/challenge`, `discovery_requirements`, `discovery_analysis.finish`, 기존 `ontology_changes.publish/preview`. 현재 의미/표현+연결 전제 → 같은 CQ의 충족/구체 공백 → 필요한 실제 유형·관계·계층과 검수 기록의 A3 변환. 사람 승인/발행은 실행하지 않는다.

**검증/완료:** P2/P3의 작은 경로가 성공하면 원래 두 문서·같은 CQ를 다시 실행해 근거 있는 업무 연결과 불확정 외부 연결을 구별한다. 실제 교정의 before/after·보존·새 R/join을 확인하고 필요한 실제 생성 계층/양방향 검수 및 A3 포함 내용을 확인한다. A3 입력 부족을 제품 결함이라고 단정하지 않는다. 과거 #605/#606의 남은 완료 증거와 연결하되 이슈를 자동으로 닫지 않는다.

## N 별도 개념화 개선: 추출 연결에서 이웃 선택

기존 승인 계획의 N을 그대로 구현 대상으로 유지한다. 핵심 판단 분리의 선행조건이 아니며 P1~P4의 작은 완료 경로 후 진행한다. AutoSchemaKG의 개체 주변 연결 활용 원리와 우리 규칙/역할·필수 문맥·결정적 선택 확장은 구분한다.

- 그룹 내부 Relation→Concept→Builder. 직접 정의 추출은 유지하고 Relation 실패가 직접 정의까지 차단하지 않게 한다.
- 현재 성공한 원문 Relation의 끝점 및 유일하게 확인된 원문 언급 주소로 Python 목록/사전 이웃 구성. 동일 이름만으로 다른 문서/시점의 개체를 합치지 않는다.
- 원명제·조건·예외·기간·명시 참조가 우선이며 남은 예산에서 실제 연결된 역할/대상 관계를 안정적으로 선택한다. 문서 인접/검색 유사문맥과 그래프 이웃을 별도 표기한다.
- 필수 원문과 이웃 명제는 원자적으로 추가/제외하고 미승인 상태·출처·선택/생략 이유·풀 지문을 저장한다. 미제공 자료를 만들거나 이웃을 확정 근거로 승격하지 않는다.
- 모듈: `discovery_analysis.process_group`, `discovery_design.source_projection`, `discovery_synthesis.context_for`, `discovery_analysis.analysis_context` 내부 `retained()`, 기존 segments/input_size. 상세 입출력·순서·예산은 원 설계 N을 따른다.
- 검증: 같은 작은 원문·모델·기준에서 핵심 변경만 적용한 조건과 N 결합 조건을 구분해 직접 정의 회귀, 역할/대상·조건 보존, 생성 결과와 호출·입력량·시간 비교. 이웃 선택으로 비용/품질이 좋아진다고 미리 주장하지 않는다. 모든 2×2 실행을 의무화하지 않는다.

## 실행·검증·중단 원칙

1. P1 → P2 → P3 → P4 → N. 단계별 코드/저장 재생 확인은 작은 관련 범위만 수행한다. 전문가 검토 후 작업별 GitHub 이슈와 구체 실행 지시를 연결한다.
2. 실제 시험 전 원문·질문·필수/금지 의미·허용 표현·후보 출처·모델 digest·코드/설정·호출/시간 상한을 고정한다. 정답 기준을 생성 입력에 몰래 제공하지 않는다. 원래 실패 자료는 개발 노출 자료로 표시하고 별도 전이 사례는 작게 확인한다.
3. 입력/연결 오류 수정과 의미 판단 개선을 분리하고, P2/교정의 실제 효과가 확인되면 기존 고정 19개 및 원래 CQ로 확대한다. 검수 가능한 최종 응답이 없는 호출은 의미 성공으로 집계하지 않는다.
4. 같은 원인을 고치지 않은 재실행과 무작정 상한 증액은 금지한다. 최초 원인 수정 후 다른 원인이 확인된 경우의 한 차례 보완까지도 같은 병목이 계속되고 실제 수정 개선이 없으면 기존 사용자 중단 조건을 다시 적용해 현재 증거와 미완료를 보고한다. 호출 수 제한을 완수 대신 쓰지 말고, 각 비교는 질문과 판단 기준이 있어야 한다.
5. 코드 계약·저장 응답 재생·실제 모델·독립 AI 의미 검토·사람 효용을 분리한다. 사람 시간/오류 시험, 배포, main 병합, 정본 자동 승인은 범위 밖이다. 원문·DB·과거 동결 기록은 보존한다.
6. 같은 브랜치에서 커밋·푸시하고 기존 초안 PR #609의 최종 제목/본문을 한국어로 갱신한다. 실적과 미완료를 구분하며 결과로 입증된 이슈만 완료 처리한다.
