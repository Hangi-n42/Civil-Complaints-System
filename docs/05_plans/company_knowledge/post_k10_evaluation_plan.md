- 상태: 조사·평가 설계. 실제 비교 실행·사람 시험·효용 측정은 미수행.
- 실행 시점: A1~A6와 K10까지의 관련 기능을 통합한 후. 평가 준비를 구현 착수의 추가 조건으로 삼지 않음.

## 1. 무엇을 입증할 것인가

**좋은 온톨로지는 클래스·관계가 많은 온톨로지가 아니라, 필요한 업무 의미를 정확히 표현하고 실제 업무를 적은 수고로 처리하게 하는 온톨로지다.** 하나의 이상적인 구조와 문자열을 맞추는 대신, 고정된 자료·업무 요구·근거에 대해 아래 질문을 각각 판정한다 [R1~R5].

| 평가 질문 | 확인할 결과 | 이것만으로 확인되지 않는 것 |
|---|---|---|
| 자율 탐색이 필요한 지식을 찾는가 | 필수 의미·조건·예외의 발견, 근거 위치, 잘못된 병합·일반화, 누락 보충 비용 | 읽은 파일 수가 많다는 이유만으로 지식 완전성 인정 |
| 온톨로지가 적절한가 | 구조 계약, 개념·관계 의미, 업무 질문을 표현할 능력, 변경 후 의미 보존 | 스키마 검증 성공만으로 사실 정확성 인정 |
| 구축 지식이 실제로 작동하는가 | 사실·개체 연결, Local·Global 답변, 변경 영향 집합, 민원 요구 처리 | 온톨로지 품질만으로 검색·답변 품질 인정 |
| 사람 감독이 작동하는가 | 그럴듯한 오류의 수정·기각, 정상 후보 보존, 누락 발견, 최종 승인본의 오류 | 사람이 화면을 열거나 승인했다는 사실로 감독 인정 |
| 도입할 가치가 있는가 | 같은 수준의 완료 결과에 필요한 구축·검토·갱신·조회의 총 사람 시간 | 일부 답변 생성 시간만으로 ROI 또는 산업 우월성 인정 |

평가 축을 하나의 가중 종합 점수로 합치지 않는다. **핵심 오류, 필수 요구 충족, 사람 시간**을 우선 제시하고 나머지는 원인 설명에 사용한다. “더 잘 만들었다”의 결론은 평가한 업무·자료·참여자 범위에 한정한다.

## 2. 조사한 표준·방법론과 적용 범위

아래는 공식 문서·원논문에서 확인한 방법이다. 국제 표준, 연구에서 시험한 방법, 이 프로젝트의 운영 규칙을 구분한다. 모든 온톨로지에 통용되는 단일 인증 점수나 정답 구조를 채택하는 계획이 아니다.

| 근거 | 지위·확인 내용 | 채택 | 그대로 가져오지 않는 부분 |
|---|---|---|---|
| Ontology Development 101 [R1] | Stanford 설계 지침. 목적에 따라 복수의 타당한 모델 존재 | 범위·사용 목적·CQ와 허용 가능한 대안 구조 | 유일한 클래스명·계층·ID를 정답으로 강제 |
| Ontology evaluation survey [R2] | 금 표준 비교·응용 기반·자료 기반·사람 평가를 분류한 연구 | 구조·원문·업무·사람 결과의 교차 확인 | 한 방식의 점수를 전체 품질로 확대 |
| FOCA [R3] | Goal–Question–Metric 기반 연구 방법론과 평가 모델 | 요구 → 평가 질문 → 관찰 지표 연결 | 논문의 회귀식·가중 점수를 한국어 LH 자료에 미검증 이식 |
| OQuaRE [R4] | SQuaRE 품질 모델을 온톨로지에 적용한 연구 프레임워크 | 기능 적합성과 구조·유지보수 비용의 분리 | OQuaRE를 ISO 인증으로 표현, 클래스 수·깊이를 높일 목표로 사용 |
| OntoClean [R5] | 정체성·경직성 등 메타속성을 통한 분류 검토 방법론 | 역할/본질적 유형, 하위 유형/부분 관계의 혼동 검수 | 전 개념 메타속성 작성과 전용 추론기 도입. 반경직성과 일반 비경직성의 혼용 |
| OOPS! [R6] | RDF/OWL 함정 탐지 도구·목록 | 모호한 관계, 중복 의미, 정의·참조 문제 중 현재 표현에 맞는 점검 | LinkML 검사에 “OOPS! 통과” 명칭 사용. 내부 스키마를 외부 서비스에 전송 |
| CQ 기반 LLM 온톨로지 평가 연구 [R7, R8] | 구조 품질·CQ 표현 가능성·사람 판단 등을 평가. CQ Yes/No 판정은 질의 실행 정답과 다름 | 구조 표현 / 자료 존재 / 실행 답변을 각각 측정 | LLM이 CQ 충족이라고 답하거나 질의를 만들었다는 사실을 정답으로 계산 |
| OWL 2·SHACL [R9] | W3C 의미론·RDF 제약 검증 표준 | 누락·논리 모순·업무 제약 위반의 구분 | 현재 JSON/SQLite에 SHACL을 이름만 붙임. OWL에서 값이 없으면 거짓이라고 간주 |
| ISO 9241-11:2018 [R10] | 맥락에 따른 효과성·효율성·만족도의 개념. 특정 평가 절차를 지정하지 않음 | 완료·오류 / 사람 비용 / 검수 부담의 분리 | 개발자 파일럿을 현업 사용성 입증으로 표현 |
| ISO/IEC 25010:2023·25040:2024 [R11] | 제품 품질 모델·품질 평가 체계 | 목적·기준·평가 환경·결과 해석을 사전 명시 | 특정 지표·합격 수치가 ISO 의무라고 표현 |
| NIST AI RMF 1.0·AI 600-1 [R12] | 위험 관리·평가 지침. 독립 평가, 사용자 맥락, 인간 역할·숙련도 확인 | 개발자·AI 검수·독립 인간 검수의 구분, 최종 인간-AI 결과 확인 | AI 역할별 검수를 독립 현업 전문가 승인으로 대체 |
| 인간-AI 의사결정 실험 [R8, R13] | 잘못된 조언·환각이 사람 성능을 낮출 수 있고 숙고 개입에 비용·한계가 존재 | 틀린 설명 반박, 정상 후보 보존, 최종 승인 오류와 부담 측정 | 경고·설명·클릭 증가 자체를 감독 효과로 인정 |
| Stardog ICV 공식 운영 문서 [R17] | 상용 KG 제품에서 도메인별 SHACL 제약·위반 보고·변경 시 제약 강제를 제공 | 명시한 데이터 제약에 대한 위반 기록을 품질 관리에 사용하는 실제 제품 사례 참고 | 기능 제공을 고객 ROI·온톨로지 의미 정확성의 실증으로 간주하거나 Stardog 도입 요구 |

- ISO 항목은 공식 공개 개요·정의를 확인한 수준이며 유료 표준 전체의 조항별 적합성 심사가 아님.
- 연구에서 검증된 결과도 해당 연구의 표본·과제에 대한 결과다. 우리 시스템의 효과 크기를 대신하지 않는다.
- 현재 LinkML 정본에는 기존 `SchemaView`·파생 스키마·참조 검사를 사용한다. OWL 변환은 LinkML의 모든 제약을 보존하지 않으며 OWL DL 범위를 벗어날 수 있음 [R14]. RDF/OWL이 실제 제품 산출물이 될 때만 해당 검사를 추가한다.
- 상속 순환은 제품 계약이 금지한 경우 위반이다. OWL에서 상호 하위 클래스 선언 자체가 항상 논리 모순인 것은 아니다 [R9].

## 3. 평가 자료와 기존 12과제의 관계

### 3.1 현재 입력으로 가능한 범위

기준은 [2026-09-30 입력 manifest](../../../configs/knowledge/lh_input_bundle_20260930/input_manifest.json)의 `selected_sources[].input_files`다. 현재 선정 자료는 **15출처·19파일**, 보류 자료는 14출처다. 자동 탐색 입력·사람 비교 입력에 같은 범위를 적용한다.

| 자료군 | 용도 | 평가에서 지킬 경계 |
|---|---|---|
| current_discovery: API 업무 명세·코드, 단지 CSV, 현행 법령 발췌·별표 | 필드 의미·공식 ID·주택 유형·조건·예외의 구조와 조회 | API 예시값을 실제 공고·단지 사실로 사용하지 않음. CSV 기준일·행 범위를 보존 |
| contrast_extension: 5년 임대·분양전환 관련 CSV·설명 | 새로운 범위를 기존 개념에 잘못 합치지 않는지 확인 | 집계 단위·시점·사업자 범위가 다른 자료를 근거 없이 개체 연결하지 않음 |
| historical_change: 2020년 시행령 정의·분류와 연결 조항 | 실제 과거 의미 변경, 참조 확장, 영향 재검토 | 별도 빈 계보 사용. 현행 자료·미래 단계·그 파생 색인·요약·후보를 앞 단계에 주입하지 않음 |

원문 이용 조건·파일 해시·선정 상태를 실행 직전 확인한다. 새로운 법률 판단이나 개인별 입주 자격·실제 공실·기관 담당 부서를 이 자료만으로 확정하는 평가가 아니다. 필요한 자료가 없으면 그 요구의 정답을 `확인 불가와 필요한 추가 자료 제시`로 고정하거나 과제에서 제외한다.

### 3.2 기존 과제를 조용히 바꾸지 않음

[기존 고정 과제](../../../configs/knowledge/pilot_v1/README.md)의 DEV/NEW 12건을 manifest와 대조한 결과, **모든 과제에 현재 보류된 필수 자료가 적어도 하나 포함됨**. 현재 자동 입력 범위만으로 원래 조건을 충족해 재실행 가능한 과제는 0/12다. 이는 불법 자료라는 판단이 아니라 **현재 선정·이용 범위와 기존 평가 범위의 불일치**다.

| 기존 과제 | 의존하는 보류 자료의 핵심 |
|---|---|
| DEV-01·02·03·04 | 양산 정정공고 HTML/PDF |
| DEV-05 | 안내 문서·정정공고 PDF 등 |
| DEV-06 | 과거 사규 |
| NEW-01·02·03·04 | LH 안내·Q&A |
| NEW-05·06 | LH Q&A |

- 기존 질문·정답·해시·과거 성적 보존. `NEW` 명칭도 현재 비노출 평가임을 뜻하지 않음.
- 자료 이용 범위가 확인되면 원래 12과제는 기존 계약의 별도 세션으로 재개 가능. 미실행을 통과나 0초로 계산하지 않음.
- 본 계획은 선정 자료로 **새 평가 묶음 `post_k10_lh_v1`**을 준비한다. 기존 12과제의 대체 성적·기존 PRD 게이트 달성으로 보고하지 않음.
- 아래 과제는 평가 설계다. 정확한 질문·대상 행·원문 구간·정답은 아직 고정되지 않았으며, 평가 실행 전에 §4 절차로 고정해야 함.

## 4. 정답은 어떻게 만들고 판정할 것인가

### 4.1 단일 정답 온톨로지 대신 요구·근거 판정표

선정한 작은 업무 모듈에 대해 아래 내용을 생성 결과를 보기 전에 작성한다. 회사 전체의 완전한 정답 온톨로지를 사람이 먼저 구축하지 않는다.

| 필드 | 기록 내용 |
|---|---|
| `requirement_id`, CQ | 무엇을 구별·연결·조회해야 하는지. 생성 모델에는 업무 질문만 제공 |
| 필수 의미 | 대상·범위·조건·예외·단위·시점·관계 방향 중 정답에 필요한 항목 |
| 근거 | source/version/block/span 또는 CSV 행·열, 짧은 인용 |
| 허용 대안 | 같은 의미를 보존하는 다른 구조. 예시 목록이며 완전한 목록 아님 |
| 금지 의미 | 근거 없는 동치·유형/개체 혼동·범위 일반화·조건 생략 등 |
| 기대 결과 | 실제 질의의 결과·조건·인용 또는 확인 불가 사유 |
| 판정 확실성 | 판정 가능 / 자료 부족 / 평가자 불일치. 후자는 정오 분모와 별도 기록 |
| 중요도 | 업무 결론을 바꾸는 핵심 오류 / 비핵심 의미 문제 / 표현 문제 |

정본의 정의·포함/제외 기준은 설계 제안일 수 있다. 원문과 문장이 동일하지 않다는 이유로 오류 처리하지 않고, 범위·근거·CQ에 부합하는지 판단한다. 반대로 사실 주장에는 실제 원문 지지가 필요하다.

### 4.2 판정자의 역할과 미리 없는 정답 처리

- 원문·업무 의미 판정자와 온톨로지 구조 검토자가 기준을 확인. 가능하면 직접 구현·해당 출력 작성에 참여하지 않은 사람 배정.
- 초기에는 1차 판정자가 작은 범위를 전수 채점하고, 2차 판정자는 핵심 오류·불일치·판정 불가를 검토. 인력이 한 명이면 독립 인간 검수 미수행으로 표시.
- 방법명을 가린 산출물에 원문을 제공해 채점. UI·작업자는 조건이 보여 완전 맹검이라고 부르지 않음.
- 생성기·Critic·다른 LLM의 판정은 오류 후보 제안이며 정답이 아님. AI만 채점했으면 `AI 보조 점검`으로 보고하고 의미 품질 확정은 보류.
- 기준표에 없는 출력은 즉시 오답으로 세지 않고 `추가 판정 필요`로 분리. 타당한 대안·정답 누락이면 사유와 기준표 새 버전을 남기고 **모든 비교 방식에 동일 재채점**. 최초 성적도 보존.
- 완전한 정답 집합을 확보하지 못한 경우 `전체 recall` 대신 `고정 요구 충족률`로 보고. 검토하지 않은 후보를 정답으로 간주하지 않음.
- 범위를 사전에 작게 고정해 그 범위의 후보·사실을 전수 검토. 계획한 검토 예산을 초과하면 미검토 수와 부분 평가를 표시하고, 좋은 후보만 골라 정확도를 계산하지 않음.

## 5. 실행 묶음과 비교 방식

**기본 실행은 생성 비교, 업무 비교, 감독 시험, 기능 경계를 분리한다.** 기존 개발 결과 중 입력·설정·코드·비용 기록이 동일한 것은 재사용한다. 전 모델 조합·전체 민원 회귀·외부 시스템 재현을 추가하지 않는다.

| 묶음 | 기본 범위 | 주된 판정 |
|---|---|---|
| C 자율 구축 | 동일 작은 모듈 초기 구축 2방식 각 1회 + 대비 자료 증분 2방식 각 1회 | 자동 탐색의 누락·불필요 후보·사람 보완 비용 |
| E 업무 효용 | 새 업무 과제 6건 × B1/B2 각 1회 = 최초 제출 12건 | 최종 업무 품질과 준비부터 수정까지 총 사람 비용 |
| H 감독 결함 탐색 | 정상 4·오류 4의 8카드와 묶음 밖 요구 누락 2개, 검토자 2명 | 최종 오류 통과·정상 훼손·누락 발견·검수 부담 |
| F 기능 경계 | 관련 기존 테스트 재사용, 부족한 경계만 작은 fixture | 상태·참조·실패·재시도·계보 계약 |

위 횟수는 **과제/산출물 수이지 LLM 호출 수가 아니다**. 실제 호출은 각 정상 흐름과 실패·재시도까지 계측한다. H 카드·정답을 C/E의 생성 입력으로 사용하지 않는다.

### 5.1 C: 자율 온톨로지 구축과 증분 보완

- C0: 사람이 원문을 탐색·선택하고 AI 초안을 요청한 뒤 수정·검수.
- C1: A1~A6 자율 탐색·분석·초안 후 사람이 변경사항 검수.
- 같은 입력 후보 목록·CQ·모델 역할·예산·편집 기능·최종 의미 요구 제공. C0도 새 구조의 편집 기능을 사용할 수 있게 하여 구 UI의 표현 한계를 자동 탐색의 효과로 계산하지 않음.
- 필수 근거 파일·구간·정답 관계 목록을 C1에 미리 찍어주지 않음. C0의 실제 자료 찾기·CQ 작성·원문 대조도 시간에 포함.
- 초기 작은 모듈은 current 자료군에서 선택. 두 방식의 초기 제출을 각각 보존한 뒤 동일 contrast 범위를 추가. 별칭/기존 유형/새 유형/범위 충돌/근거 부족 구분과 수정 비용 확인.
- C1 결과가 E의 B2 준비 지식으로 그대로 재사용될 때 구축 비용은 한 번만 귀속. 다른 조건이면 별도 실험이며 무료 사전 구축으로 처리하지 않음.
- A6의 동일 입력 처리 순서 2가지 비교는 기록이 있으면 재사용. 없으면 같은 시점의 C1 한 경로만 추가 확인하고 의미 차이를 진단. 시간 순서는 뒤집지 않으며 한 쌍으로 순서의 인과 효과를 주장하지 않음.
- C는 자율 탐색의 비교다. B1/B2 업무 비교나 KG 단독 효과·OntoEKG 대비 우월성으로 바꾸어 해석하지 않음.
- C에도 §7.2의 작업자 노출·순서·피드백 규칙을 적용. C0만을 위한 온톨로지 제작 비용을 온톨로지가 불필요한 B1에 부과하지 않음.

### 5.2 E: 강한 문서 기반 B1과 지식 계층 B2 비교

| 방식 | 허용 작업 |
|---|---|
| B1 | 동일 파서·공식 ID·메타데이터 필터·어휘/벡터 검색·문서 diff·동일 생성 모델. 문서별 사실/요약→종합, 사람이 만든 관계표·변경표, 일반 CSV 필터·정렬·그룹 집계·산술 도구 허용 |
| B2 | B1 공통 자산 + 검토된 온톨로지·사실·관계·스냅샷·Local/Global·변경 영향·민원 연결 |

- 같은 업무 결과를 요구하되 B1에 LinkML·그래프·B2 내부 API를 만들라고 요구하지 않음. 관계를 표로 표현해도 의미와 근거가 맞으면 인정.
- 두 방식 모두 작은 별도 개발 예제로 실행·검색 설정을 준비할 기회 부여. 평가 결과를 보고 B1만 기본값으로 방치하거나 B2만 튜닝하지 않음.
- CSV·산술 도구는 양쪽에 동일하게 허용하고 준비·작성·확인 비용 포함. 문서 RAG로 해결하기 부적합한 집계를 B1에 강요하지 않으며 별도 범용 집계 엔진은 개발하지 않음.
- B1/B2 추가 호출 수를 강제로 같게 맞추지 않음. 공통 역할의 모델·설정은 같게 하고 각 방식의 추가 작업·호출을 모두 비용에 포함.
- 별도 DB·작업 폴더에서 준비. 다른 방식의 승인 지식·정답·답변을 복사하지 않음. 자체 산출물은 후속 과제에 재사용.
- B0 완전 수작업은 기존 12과제 계약에 남김. 이번 최소 비교의 주대상은 더 강한 B1. B0가 구매 대안인 현장이 확보되면 동일 과제의 별도 비교를 추가하되 현재 기본 실행을 3배로 늘리지 않음.

#### 새 업무 과제 6건의 고정 방향

아래는 질문 원문이 아니라 **선정 기준**이다. 이용 가능한 근거로 답·범위·예외를 확정할 수 없는 과제를 억지로 만들지 않는다.

| ID | 자료·업무 | 고정할 정답과 완료 조건 |
|---|---|---|

| E-L2 Local | current 법령/별표의 한 유형·조건과 적용 범위 | 근거가 명시한 조건·예외·연결. 공개 자료만으로 확정 못 하는 사항 구분 |

| E-I1 변경 | historical 계보의 실제 전이 1건 | 전후 의미 변화·직접 참조·확정된 재검토 대상·무영향 대조·연결 미확인 |
| E-C1 K10 민원 | 선정된 근거로 재구성한 복합 문의 1건 | 서로 다른 근거를 요하는 요구 2개 이상 + 자료로 답 못 하는 요구 1개. 요구별 답/보류·근거·수정 후 재조회 |

- 생성 입력에는 질문·허용 원문·시스템 상태만 제공. 정답 필드·금지 관계·기대 목록은 평가자 파일로 분리.
- E-G1은 작은 CSV 행 범위와 그 안의 전수 집계를 사전 고정. B2는 해당 행 범위의 K4 사실 검토·K5 활성화를 수행하고 비용 포함. C의 대표행 기반 개념 발견 성공을 전체 행의 사실 구축 완료로 대신하지 않음.
- E-I1은 manifest 역사 순서를 유지. 초기 상태에서 목표 전이 전까지 필요한 단계를 처리하고 그 준비 비용 포함. 미래 단계 및 현행 계보의 파생 지식도 차단. 모델 사전학습까지 비노출이라고 주장하지 않음.
- 공개 법령의 변경만으로 실제 후속 업무 영향 집합이 확정되지 않으면, 원문 변화와 **별도로 만든 의존 관계 fixture**를 구분. 후자는 합성 관계 영향 검사이며 실제 LH 운영 영향 탐지율이 아님.
- E-C1은 실제 민원 원문이라고 표시하지 않음. 부서 배정·해결 확약·개인별 자격을 근거 없이 생성하면 핵심 오류. 사용자 검토→수정 저장→재조회→근거 상태 변경 후 사용 재확인까지 수행.
- K10 한 사례는 연결 기능 시연이다. 일반 민원 처리 효용·재민원 감소·버스 변경의 인과 효과를 입증하지 않음. 버스 P1은 별도 자료·기능 범위이므로 이번 필수 평가에 자동 추가하지 않음.

### 5.3 H: 인간이 있다는 사실과 감독이 작동하는 사실의 구분

기존 [A6 검수자 시험](autonomous_ontology_plan.md#113-검수자-시험)을 사용한다. 새 대규모 사용자 연구를 만들지 않는다.

- 정상 4·오류 4를 A/B 묶음에 정상 2·오류 2씩 배정. 각 묶음에 요구 누락 1개 배정. 하나는 빈 CQ, 하나는 AI가 잘못 충족이라고 설명한 CQ.
- 오류 종류: 범위/시점 오적용, 잘못된 병합·계층, 인용이 존재하지만 관계를 지지하지 않음, 예외 누락. 근거로 정오를 확인할 수 있는 것만 오류 카드로 사용.
- 검토자 1: 기존 UI A → 개선 UI B. 검토자 2: 개선 UI A → 기존 UI B. 누가 어느 순서를 맡을지는 무작위 배정·기록. 같은 사람이 같은 카드를 두 번 보지 않음.
- 별도 짧은 예제로 UI 사용법 교육. 교육 시간 기록. 두 조건 완료 전에 정답·다른 참여자 결과를 제공하지 않음. 작업 중 계속 설명하도록 요구하여 한 조건의 숙고 비용을 늘리지 않음.
- 참여자는 교육·시험 목적과 오류 포함 가능성을 알고 참여. 개별 카드의 정오 표시는 숨김. 원문 확인에 필요한 문맥은 두 UI 모두 접근 가능하게 제공.
- 최종 승인 내용으로 채점. 오류를 언급했어도 승인본에 남으면 통과 오류. 정상 후보를 전부 보류하여 오류율만 낮추지 못하도록 정상 수락·훼손·보류·완료를 함께 보고.
- 사람 1명이면 사용성 점검, 2명이면 탐색적 교차 관찰. 8카드의 반복 판정을 독립 참여자 수로 계산하지 않음. 오류를 인위적으로 넣었으므로 자연 발생 오류율 추정에 사용하지 않음.
- 계획대로 모두 수행하면 UI별 오류 판정 4·정상 판정 4·누락 판정 2건. 전체 카드 판정은 16건이지만 고유 카드 8개·고유 누락 2개·참여자 2명임.
- 카드·정답 작성자나 사전 정답 노출자가 참여한 결과는 노출된 사용성 점검으로 분리. 비노출 감독 관찰과 합산하지 않음. 추가 사람 확보가 안 되면 감독 효과는 미측정으로 남김.
- 수정 후 같은 카드 재시험은 회귀 확인이며 새로운 독립 사람 효과 평가가 아님. 사람 시험이 없으면 미측정으로 남기며 구현을 막지 않음.

### 5.4 F: 필요한 기능 경계만 확인

| 경계 | 최소 확인 |
|---|---|
| A1·A2 | 허용 입력/고정 블록·단계별 계보, 성공 단계 재사용, 예산 초과·잘림·실패 표시 |
| A3·A4 | 존재하지 않는 참조·범위 오류·금지 순환, 별칭/동치/하위 유형 구분, 수정·보류·낡은 revision 충돌 |
| A5·K4·K5 | 정본/파생 구조·추출 매핑 호환, 병합/폐기 참조의 처리, 과거 snapshot 보존·선택/활성화 구분 |
| K7 | 직접 종합 / 실제 입력 예산 초과 묶음 요약 / 중간 실패·잘림 / 생성 중 상태 revision 변경 |
| K8 | 변경 전후 영향 목록·직접/2단계 경로·무영향 대조, Local/Global·중간 요약의 사용 상태 |
| K10 | 문장→근거 이동, 수정 저장·재조회, 근거 사용중단 후 이전 답변 재사용 처리 |

기존 관련 테스트가 현행 코드에서 통과한 기록이 있으면 재사용. 부족한 경계만 작은 자동 fixture로 확인한다. 의미 정답을 모두 코드에 하드코딩하는 새 검증 플랫폼은 만들지 않는다. K7 실제 모델은 E-G 과제의 정상 경로를 사용하고, 묶음 요약 경로가 실행되지 않았다면 그 품질은 미측정으로 남긴다. 해당 품질 주장이 필요한 경우에만 같은 허용 범위로 한 번 추가한다.

## 6. 채점 지표와 분모

원시 건수를 먼저 제시하고 비율은 보조로 쓴다. 자료에 없는 사실·관계를 모델 상식으로 보완해 정답으로 판정하지 않는다.

| 평가 층위 | 필수 지표·분모 |
|---|---|
| 구조 계약 | 참조·range·폐기 ID·버전·금지 순환의 위반 건수/유형. 기존 검사별 결과 |
| 생성 의미 | 판정 가능한 개념·속성·관계별 지지/모순/무근거 건수. 정의 제안의 부적합·불필요 후보 건수 별도 |
| 필수 요구 | 충족 요구 수 / 사전 고정 필수 요구 수. 이름이 존재해도 조건·예외·방향이 빠지면 미충족 |
| CQ 3단계 | 구조 표현 가능 / 필요한 실제 자료 존재 / 실행 결과·조건·예외·인용 정답. 각 분모를 별도 유지 |
| 사실·연결 | 잘못 연결·누락·조건 오적용 수. 공식 ID와 근거의 의미를 확인. 문자열 유사도만으로 정답 판정하지 않음 |
| 영향 집합 | TP: 실제 재검토 대상 제시, FN: 고정 대상 누락, FP: 근거상 무영향 대상 포함. 근거 부족 대상은 미판정으로 별도 기록 |
| 업무 답변 | 핵심 사실 오류 / 필요한 정보 누락 / 부가 정보 누락 / 표현 문제. 핵심 요구와 인용 적합성 우선 |
| 감독 | 오류 최종 통과/제시 오류, 올바른 수정/제시 오류, 정상 훼손/제시 정상, 누락 발견/제시 누락, 정상 수락·보류 수 |
| 비용·사용성 | 모든 역할의 사람 시간, 호출·대기·경과시간, 수정/추가/보류 건수. 완료 후 원문 확인 어려움·부담·재사용 의향의 동일한 짧은 질문 |

- 실제 CQ 조회는 기존 API 또는 검토된 테스트 질의로 수행. 임의 LLM SQL 실행이나 SPARQL DB를 추가하지 않음. 스키마가 표현 가능하지만 사실이 없는 경우를 스키마 실패와 구분.
- CQ 구조 표현의 분모는 사전 고정된 적용 가능 CQ 전체. 자료 존재는 `허용 원문에 근거 존재`와 `시스템에서 조회 가능한 사실·근거로 실제 적재`를 별도 기록. 원문에 있는데 추출하지 못한 항목을 외부 자료 부족으로 처리하지 않음.
- CQ 실행 정답의 분모는 사전 고정 CQ 전체이며, 기대 답 또는 기대 보류의 충족 여부를 판정. 미실행·실패를 분모에서 제외하지 않음. 구조 표현이 불필요한 보류 과제는 고정 시 명시하고 실행 후 분모를 줄이지 않음.
- `정확 항목/(정확+오류)`를 표시할 때 판정 불가·미검토·미출력도 함께 표시. 분모 0은 N/A이며 100%가 아님. 답변 거절·전체 보류는 정확도 개선의 대체물이 아님.
- 영향 precision/recall을 계산하려면 지정 범위의 영향 집합·대조 집합이 사전 확인돼야 함. 불완전하면 `확정 대상 중 발견/누락`으로만 보고.
- 그래프 경로가 있다는 것과 실제 인과 영향은 다름. K8 지표는 근거·정의 변경에 따른 **재검토 대상**을 평가하며 민원 발생량·현장 피해를 예측한 수치가 아님.
- 만족·부담 질문은 정성 의견이다. 표준 SUS 점수나 검증된 설문 척도라고 부르지 않음.
- 모델 초안, 사람 검수 후 최초 제출, 채점 후 수정본을 각각 보존. 수정본 성적으로 최초 오류를 지우지 않음.
- 생성 의미·필수 요구·CQ 지표는 세 단계 산출물에 같은 기준으로 각각 적용. 단계별 추가·삭제 항목과 판정 가능·불가 건수를 함께 기록.

## 7. 사람 비용·공정성·설정 고정

### 7.1 측정 구간

`총 사람시간 = 준비·자료 탐색·CQ 작성·구축·검수·운영·조회·갱신·제출 전 근거 확인의 human_active_s 합 + 채점 후 repair_s 합`

- 두 사람이 동시에 일하면 각 사람 시간을 합산. 같은 사람의 같은 구간은 중복 계산하지 않음.
- `repair_s`를 별도 시도에 기록할 경우 같은 시간을 그 시도의 `human_active_s`에 다시 넣지 않음.
- `system_wait_s`는 사람 작업과 겹치지 않은 대기, `elapsed_s`는 실제 경과, `model_total_s`는 실패/재시도를 포함한 모델 시간. 이 셋을 사람 시간에 더하지 않음.
- 정상 업무의 근거 확인은 비용에 포함. 결과를 별도 정답표로 채점하는 연구자 `grading_s`만 운영 시간에서 제외.
- 공통 자료 수집·권리 확인·정답 제작·평가 환경 준비는 연구 준비 비용으로 별도 공개. 방법별 운영 교육·설정은 총 사람시간에 포함하고 부분 합도 표시. 실험 절차 교육만 공통 연구비로 분리하며 귀속은 실행 전에 고정.
- E의 current 준비와 historical 초기 상태 준비를 각각 S0로 기록. 구축·승인·색인·대비 자료 갱신을 무료로 제공하지 않음. 준비에서 수행한 변경은 E 과제 시간에 다시 청구하지 않음.
- C/A6 구축 결과를 E에서 실제 재사용할 때 `cost_event_id`·Run ID로 한 번 귀속. 과거 사람 시간을 기억·모델 실행시간으로 복원하지 않음. 필수 준비·구축 사람 시간이 하나라도 미측정이면 해당 비교의 **총 사람시간·절감률·10% 판정은 산출하지 않음**. 측정한 부분 시간과 품질 참고만 별도 보고하며 누락 비용을 0으로 두지 않음.

### 7.2 최소 인력과 순서

- 작업자 2명이 가능하면 독립 작업공간에서 각각 두 방식을 수행하고 방식 순서를 반대로 배정. §5의 12건은 **작업자 1명 기준 기본 실행 수**이며 2인 반복 시 최초 제출은 24건. 반복은 선택 사항이고 참여자 수를 숨기지 않음.
- 2인 E 반복은 작업자별 별도 구축을 기본으로 각자의 총비용·절감률을 먼저 보고. 승인 지식을 공유하는 다른 설계라면 공동 구축 비용 배분을 실행 전에 정하고 개인별 독립 구축 비교와 섞지 않음.
- 작업자 1명은 의존 순서를 지키며 방식 시작 순서를 기록한 개발자 파일럿. 같은 질문 기억과 숙련도 차이를 제거했다고 주장하지 않음.
- 인간 감독 H는 별도 2인 교차가 기본. E와 같은 사람이면 노출을 기록하고 H 정답은 C/E 완료 전 제공하지 않음.
- 원문 경험·질문 경험·정답 경험·구현 참여 여부를 사람별 기록. 배정·교차만으로 기억 효과가 사라지지 않음 [R15].
- 비교 방식의 최초 제출을 마치기 전에 정답 피드백·튜닝 금지. 이후 수정은 별도 시도로 측정. 다른 자료의 짧은 연습은 허용.
- 현업 담당자 없이 수행하면 개발자 파일럿으로 표기. 연구의 검토자 역할을 맡은 AI는 사람 작업자·독립 현업 전문가 수에 포함하지 않음.

### 7.3 실제 실행 설정

- 코드 commit+dirty diff 해시, 자료/과제/정답 버전·해시, 파서·프롬프트·스키마·snapshot ID, 하드웨어·OS를 세션에 한 번 기록.
- 모델은 실제 해석된 tag/digest와 역할, 컨텍스트/출력 예산·temperature·think·timeout 기록. `STRUCTURING_MODEL`, `KNOWLEDGE_REVIEW_MODEL` 등 **실제 해당 경로가 사용하는 설정**을 확인.
- 기존 평가 계약의 `CIVIL_LLM_RUBRIC_MODEL`·과거 토큰 예산을 현행 온톨로지 호출에 그대로 적용하지 않음. 역사 기록을 수정하지 않고 새 실행 설정으로 명시.
- 공통 파서·생성 역할의 설정은 B1/B2 동일. 지식 계층 고유 Critic·탐색 단계는 별도 비용 포함. 하드웨어 부하·콜드/웜 실행·캐시 상태 기록, 동시에 다른 모델 실험을 돌리지 않음.
- 측정 중 모델·프롬프트·예산 변경은 새 세션. 결함 수정 후 해당 사례 재확인은 허용하되 최초 성적을 교체하지 않음.
- 실행한 OS의 결과만 보고. Windows 전체 환경 확보나 전 모델 벤치마크를 이번 계획의 선행 조건으로 추가하지 않음.

## 8. 결과 판정과 주장 범위

아래는 **프로젝트 제품 판단 규칙**이며 ISO·W3C·논문의 공통 합격선이 아니다.

| 판정 | 조건·표현 |
|---|---|
| 기능 경계 확인 | F의 필수 계약 통과. 실패 경계가 있으면 해당 기능 미완료로 표시 |
| 제한 범위 품질 충족 | 사전 고정 필수 의미·업무 요구 완료, 승인본에 핵심 오류 없음. 비핵심 결함·보류는 별도 공개 |
| 자율 구축 효용 관찰 | C0/C1 완료 품질이 같거나 C1이 높고 총 사람 수고가 감소. 부족한 품질을 빠른 시간으로 상쇄하지 않음 |
| 업무 효용 관찰 | B1/B2가 같은 필수 업무 결과를 완료, B2 핵심 오류·영향 누락 증가 없음, 총 사람 시간 감소 |
| 내부 확장 기준 | 위 조건 아래 새 묶음의 B2 총 사람 시간이 B1보다 10% 이상 감소하면 해당 묶음의 내부 확장 기준 충족. 기존 PRD 수치를 사전 적용한 것이며 기존 12과제 통과·통계적 유의성 아님 |
| 판단 유보 | 한 방식 미완료, 비용 미측정, 공정성 훼손, 모호한 정답, 효과가 작업자·순서로 설명될 가능성을 분리 못 함 |
| 품질·비용 절충 | 정확성이 높아졌지만 시간이 늘면 그 차이를 그대로 보고. “동일 품질에서 더 효율적”이라고 표현하지 않음 |

- 시간 절감률: `(B1 총 사람시간 - B2 총 사람시간) / B1 총 사람시간`. 분모가 0/미측정이면 계산 불가. 최초 제출과 완료까지의 수정 포함 비용을 함께 공개.
- 과제별 결과와 구축/갱신/조회/민원별 부분 합을 먼저 보고. 반복 판정·문장·노드를 독립 사용자 표본처럼 세거나 작은 표본에 유의확률을 붙이지 않음.
- H는 오류 통과와 정상 훼손을 함께 보고. 몇 카드의 통과를 감독 체계의 안전성 보장으로 표현하지 않음.
- 소규모 사례의 핵심 오류 0건은 관찰 결과이며 오류 확률 0의 증명이 아님. 버스·타회사·다른 모델 일반화에는 별도 자료의 확인이 필요.
- OntoEKG의 삼중항 fuzzy F1 [R16]과 본 계획의 요구 충족률을 같은 정확도처럼 비교하지 않음. Palantir·상용 제품을 실행하지 않고 우월성 주장하지 않음.
- KG 단독 효과가 필요한 경우에만 효과가 나온 과제에서 관계 사용 여부를 한 요소만 바꿔 진단. 모든 장치 제거 실험·다중 모델 전체 재현은 기본 범위 밖.
- 산업 도입 판단은 실제 담당자·실제 이용 빈도·갱신·교육·연동·유지 비용이 있는 별도 단계. 현재 파일럿으로 연간 ROI나 구매 의향을 계산하지 않음.

- 허용 범위 밖 자료, 세션 설정 오염, 핵심 상태/참조 위반 발견 시 해당 실행만 멈추고 사유 기록. 원인이 같은 다른 실행을 무작정 반복하지 않음.
- 예산 초과·출력 잘림·부분 처리·모호한 원문은 실패/부분/보류로 기록. 상한을 결과가 좋아질 때까지 늘리지 않음.
- 한 차례 보완 후에도 미해결이면 한계·이슈로 남김. 모든 평가가 통과할 때까지 전체 제품을 반복 수정하는 체계를 만들지 않음.
- 아직 평가 질문을 고정하지 않았으므로 생성·비교 호출을 시작하지 않음. 본 문서는 실행 준비 계획이지 새 벤치마크 완성 보고가 아님.

별도 서버 없이 기존 로컬 평가 폴더 사용:

```text
data/knowledge/evaluations/<session>/
  session.json       # 실제 설정, 입력/기준 해시, 참여자 노출·배정
  criteria.json     # 평가자용 요구·근거·허용대안·금지의미·정답
  records.jsonl     # 방법/과제/시도, 상태, 품질, 시간, cost_event_id, Run 링크
  artifacts/        # 초안·최초 제출·수정본·기존 실행 로그 참조
```

- 원문·답변 등은 기존 Git 제외 로컬 정책 유지. 정답 파일은 생성 입력 목록·색인에 포함하지 않음.
- 기록은 `not_run/pass/partial/fail/deferred`, 미측정은 null, 실제 0만 0. 준비 비용·채점 비용·운영 비용의 귀속을 명시.
- 결과 보고서는 `docs/70_research/company_knowledge/`에 요약만 작성. 외부 공개는 자료 이용 범위·참여자 동의 범위 안에서 수행.

## 10. 다음 작업과 필요한 결정

- 현재: 방법론 조사·계획 작성 및 AI 전문가 역할의 독립 검수. 실험 실행·현업 승인·산업 효과 확인은 미수행.
- 다음: A1~A6·K10 통합 이후 §9 순서로 실제 자료 구간·6과제·정답 근거·참여자를 고정. 그 전에는 기존 계획의 작은 개발 확인만 수행.
- 실제 시험 전에 필요한 자원: 원문 의미를 검토할 사람, UI 검토자 2명, 기록 가능한 작업자. 현업 인력이 없으면 개발자 파일럿으로 범위를 유지.
- **현재 사용자 결정이 필요한 사항 없음.** 현업 참여나 타회사 일반화·논문용 확장이 필요할 때만 별도 범위 결정. 기존 PRD·12과제·구현 범위를 본 문서로 변경하지 않음.
