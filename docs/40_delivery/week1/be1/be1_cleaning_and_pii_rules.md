# BE1 Week1 정제·PII 마스킹 규칙 초안

문서 버전: v1.0  
작성일: 2026-03-18

## 1. 텍스트 정제 규칙

### 1.1 공통 정규화

- 줄바꿈/탭 정규화: `\r\n`, `\r`, `\t` -> 공백 또는 `\n`
- 다중 공백 축소: 연속 공백을 단일 공백으로 통일
- 제어문자 제거: `\x00`~`\x1F` 중 문장분리 불필요 문자 제거
- 노이즈 토큰 정리: `_x000D_` 제거

### 1.2 민원 본문 보존 원칙

- 의미 단위(문장/구문)는 유지한다.
- 원문 분쟁 가능성이 있는 법령/조항 문구는 삭제하지 않는다.
- 정제 전/후 텍스트 길이 차이가 30% 이상이면 경고 로그를 남긴다.

### 1.3 구조화 전 분리 규칙

- `Q :` ~ `A :` 구간을 우선 분리한다.
- `제목 :` 라인은 `context` 후보로 우선 사용한다.
- 문장 단위 분리는 마침표/개행 기준으로 수행한다.

## 2. PII 마스킹 대상 패턴(초안)

### 2.1 필수 마스킹

- 전화번호: `01[0-9]-?\d{3,4}-?\d{4}`
- 주민등록번호 유사: `\d{6}-?[1-4]\d{6}`
- 계좌번호 유사: `(\d{2,6}-){2,}\d{2,6}`
- 이메일: `[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}`
- 상세주소 유사: `([가-힣0-9]+(로|길|동|읍|면)\s*\d+(-\d+)?)`

### 2.2 조건부 마스킹

- 성명/담당자명: `▲▲▲`, `홍길동` 형태는 문맥에 따라 마스킹
- 차량번호: `\d{2,3}[가-힣]\d{4}`

### 2.3 마스킹 출력 규칙

- 기본 토큰: `[REDACTED:TYPE]`
- 예시: `010-1234-5678` -> `[REDACTED:PHONE]`
- 원본 저장 필요 시 암호화 저장소 분리

## 3. 로그 보안

- 로그에는 원문 전체를 남기지 않는다.
- 실패 케이스는 200자 이내 snippet만 남긴다.
- 마스킹 전 원문 접근 권한은 BE1/BE3로 제한한다.
