# 8주 WBS 문서 (v2 - 2026-03-11 최신화)

문서 버전: v2.0 (최신화)  
기준 문서: [PRD](prd.md), [MVP 범위 문서](mvp_scope.md)  
작성일: 2026-03-11  
최신화: Priority 1 완료 후 Week 2~8 일정 재정의

## 1. 문서 목적

본 문서는 4인 팀 기준 8주 동안 프로젝트를 실제로 완성하기 위한 작업 분해 구조(WBS)를 정의한다.  
**2026-03-11 현재: Week 1은 대부분 완료 (기획 + Priority 1 스캐폰딩)되었으므로, Week 2~8의 일정을 최신화하였다.**

## 2. 운영 원칙

### 2.1 일정 운영 원칙
- 매주 월요일: 목표 및 리스크 점검
- 매주 수요일: 중간 통합 점검
- 매주 금요일: 결과물 확인 및 KPI 업데이트
- 각 주차는 **설계 → 구현 → 검증 → 통합 기록** 순서로 운영한다.

### 2.2 WBS 작성 기준
- 모든 작업은 담당자와 산출물이 명확해야 한다.
- 기능 개발과 동시에 평가 및 로그 설계를 병행한다.
- 후반부 병목을 막기 위해 인터페이스 고정 작업을 초반에 배치한다.
- 발표 준비는 마지막 주가 아니라 7주차부터 병행한다.

## Week 2 — Priority 2~5 병렬 착수 & PoC (⏳ 2026-03-12 시작)

### 주간 목표
- **Priority 2~5를 병렬로 착수하여 각 모듈의 실행 가능성을 검증한다.**
- 실제 기술 스택 (Ollama, ChromaDB, BGE-m3)을 로컬에서 테스트한다.
- 단 건 샘플로 구조화, 검색, QA를 각각 동작시킨다.

### 역할별 작업

#### FE (도훈) - Priority 4 (Streamlit UI 프로토타입)
- Streamlit 기본 화면 구현 완성 (3탭 레이아웃 + 사이드바)
- 파일 업로드 드래그앤드롭 UI 구현
- 검색창 및 결과 카드 UI 목업 구현
- 채팅 입력/출력 UI 구현

#### BE1 (현기) - Priority 2 (샘플 데이터 + 정제 규칙)
- 샘플 민원 20~50건 수집 (구조화 전 원본, `data/raw/` 저장)
- 텍스트 정제 규칙 구현 (공백 정규화, 특수문자 처리)
- 4요소 추출 초안 구현 (규칙 기반 또는 간단한 LLM 호출)
- 신뢰도 점수 계산 로직 초안

#### BE2 (민건) - Priority 3 (벡터DB 비교 + 임베딩)
- ChromaDB vs Milvus 빠른 비교 테스트
- BGE-m3 임베딩 모델 로컬 다운로드 및 단순 임베딩 테스트
- 샘플 5~10개 문서를 임베딩하여 ChromaDB 저장 테스트
- 자연어 쿼리로 Top-K 검색 동작 확인

#### BE3 (현석) - Priority 5 (성능 기준선 + API 초기화)
- Ollama 서버 로컬 실행 확인
- Qwen2.5 7B 모델 다운로드 및 `/api/generate` 테스트
- 간단한 프롬프트로 JSON 응답 파싱 PoC
- FastAPI `/health` 엔드포인트 테스트

### 공통 산출물
- Priority 2: 샘플 데이터 20+건 + 정제 규칙 문서
- Priority 3: 벡터DB 비교 결과 메모 + 검색 PoC 결과
- Priority 4: 와이어프레임 이미지 + UI 컴포넌트 리스트
- Priority 5: 성능 기준선 초안 (응답 시간 측정값)
- 공통: 각 PoC 실행 로그 및 에러 정리

### 완료 기준 ✅
- 로컬 환경에서 Ollama + Qwen2.5 실행 가능
- ChromaDB에 문서 저장 및 검색 최소 1회 성공
- 샘플 5건 이상 구조화 완료
- Streamlit UI에서 3탭 모두 클릭 가능한 상태

### Week 2 예상 위험 ⚠️

## Week 6 — 품질 측정 및 최적화

### 주간 목표
- **입수 → 구조화 → 검색 → QA 각 단계의 KPI를 실제로 측정**
- 가장 치명적인 병목을 특정하고 우선 개선

### 역할별 작업

#### FE (도훈)
- 응답 시간 / 상태 표시 UX 개선
- 데모용 로딩/오류 상태 정리 및 테스트

#### BE1 (현기)
- 구조화 오탐/누락 분석
- 샘플 50건 수동 검증 (정답 레이블링)
- 규칙 기반 후처리 보완
- F1/Precision/Recall 측정 스크립트 작성
- **산출물**: 구조화 KPI 리포트

#### BE2 (민건)
- 검색 성능 평가 (Recall@5, nDCG@K, MAP@K)
- 임베딩 모델/청크 크기/메타데이터 필터 튜닝
- 검색 병목 분석 (응답 시간, 정확도)
- **산출물**: 검색 성능 리포트 및 튜닝 결과

#### BE3 (현석)
- QA 응답 지연 시간 측정 (Ollama 추론 시간)
- 프롬프트 길이/모델 파라미터 튜닝
- OOM 및 폴백 동작 점검
- 전체 파이프라인 응답 시간 측정
- **산출물**: 성능 벤치마크 리포트

### 공통 산출물
- **KPI 중간 리포트** (구조화, 검색, QA 각각)
- 실패 사례 분석 문서 (왜 이 사례가 실패했는가)
- 개선 우선순위 목록 (어떤 항목부터 개선할 것인가)

### 완료 기준 ✅
- 구조화 F1 >= 0.70
- 검색 Recall@5 >= 0.60
- QA 응답 시간 <= 5초
- 파이프라인 전체 응답 시간 <= 10초
- KPI 값이 명확하게 기록됨

### Week 6 예상 위험 ⚠️
- 예상보다 낮은 성능 → 모델 다운스케일 또는 기능 축소 결정 필요
