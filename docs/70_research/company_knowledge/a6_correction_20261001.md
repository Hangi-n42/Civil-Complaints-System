## 저장 문맥 재현

동일 저장 원문과 저장된 역할 출력으로 `process_group`/`make_prompt`만 재구성했다. 모델 호출·도구 실행·원장 저장을 대체하고 SQLite는 `mode=ro`로 열었다. 기존 DB와 대상 결과 파일의 전후 SHA-256은 동일하다. 이 표는 **입력 구성 변경**이며 새로운 모델 응답 성공이나 정확성 결과가 아니다.

| 저장된 입력 초과 단위 | 이전 길이 | 보완 길이 | 12,000자 이내 |
|---|---:|---:|---|
| contrast Relation / `70f72e…` | 12,820 | 10,779 | 예 |
| contrast Relation / `dfb196…` | 12,751 | 10,710 | 예 |
| contrast Concept / `7e40c8…` | 14,329 | 12,352 | **아니오** |
| history2 Relation / `c42466…` | 12,044 | 10,218 | 예 |
| history2 Relation / `58cb06…` | 12,026 | 10,200 | 예 |
| history2 Relation / `689dae…` | 12,026 | 10,200 | 예 |
| history2 Concept / `b55dcb…` | 12,165 | 10,403 | 예 |

- 위 7건 모두 기존 UTF-8 기반 보수적 토큰 상한 이내. contrast Concept은 문자 상한 때문에 여전히 미처리 대상이며 원문 절단·상한 증액을 하지 않음.
- 검수 역할의 실제 제공 원문 범위는 넓혔지만, 기존 저장 실패인 유형/개체 혼동·조건 누락·중복 add·제37조 누락 쟁점의 잘못된 후보 연결은 해결됐다고 판정하지 않음. 저장된 제37조 원문을 재구성된 Concept 입력에서 유지한 사실과 새 응답의 의미 정확성은 별개.
- 번호 목록 탐지는 `1.`/`2.`가 함께 나타나는 제한된 구조 신호. 날짜·소수·숫자로 시작하는 문장을 제외하는 회귀 포함. 모든 목록을 탐지하지 않으며 번호 수가 필요한 후보 수라는 뜻도 아님. 경고가 없어도 의미 완전성은 미검증.
- 자동 재시도·추가 탐색 라운드·후보 상한·검색 예산을 늘리지 않음. 성공 단위의 상태와 원문 인용 수는 보존하고 용량 미확인은 완료 집계와 실행 상태에서 별도 표시.

## 검증·검수 기록

- Python 3.11.9, 기존 의존성 사용. 관련 A2/A6 테스트 **67개 통과(5.91초)**. 최종 채점 출력·빈 판정자 검사 보완 후 A6 **14개 재확인 통과(0.46초)**.
- 독립 AI 전문가 2명이 실행/평가 계약과 의미/용량 경계를 검수. 둘 다 추가 탐색의 `required=False` 그룹에 용량 경고가 있어도 review_ready가 되는 동일 결함을 재현. `capacity_pending` 자체를 partial 조건에 넣고 필수/추가 그룹 회귀 반영.
- 의미 전문가는 최종 수정에서 추가 차단 결함 없음 확인. 실행 전문가는 해시 결합·분모·읽기 전용 처리·검색 경로를 검수하고 최종 재현 확인.
- 실제 기존 원장으로 새 카드 준비 → 합성 완료 기록 → `adjudicate` → 별도 합성 판정 → `score` CLI를 확인. 새 준비 파일 10개와 합성 확인 파일은 별도 디렉터리에 저장. 이전 12개 준비 파일은 보존. 합성 판정은 사람의 오류 발견 성과가 아님.
- 로컬 재현 원장: `data/knowledge/a6_correction_v1_replay_20261001.json`, 카드/합성 확인: `data/knowledge/a6_correction_review_20261001/`. 원문·DB·전체 출력은 커밋하지 않음.

## 사용 방법과 남은 작업

[실행 안내](../../30_manuals/knowledge_a6_runbook.md)의 새 `adjudicate` 단계를 사용한다. 참가자 기록을 완료한 뒤 양식을 만들고, 독립 판정자가 `bound_record`의 실제 수정문과 원문을 대조하여 판정 항목만 작성한다. 완료 기록을 수정하면 새 판정 양식과 독립 판정이 필요하다.

과거 평가의 생성 재실행과 쓰기 가능한 API inspect는 당시 코드 동결 검사를 유지한다. 현재 코드에서 과거 결과를 읽을 때는 저장 JSON 또는 읽기 전용 카드 준비/재현 경로를 사용한다. `inspect_knowledge_a6.py`는 결정이 없어도 변경안 생성 등 쓰기가 있어 읽기 전용 도구로 간주하지 않는다.

남은 범위는 contrast의 잔여 입력 초과, 실제 모델의 유형·조건·중복·누락 개선, 현업 검토자의 오류 발견·시간 측정이다. 이번 보완으로 그 품질이나 효용을 입증하지 않았다. 전체 비교 평가·다중 모델·Windows 실기를 반복하지 않았다. 다음 작업은 남은 문맥 조립과 의미 문제를 별도 고정된 작은 확인으로 다루고, 실제 사람 시험은 준비된 카드와 연결된 독립 판정으로 수행하는 것이다.

현재 사용자 결정이 필요한 사항 없음.
