# I1 Critic 원명제·유형 정의 검수 계약 보완

- 대상 #563, 최신 main `27b8639`에서 시작한 `feature/ontology-critic-grounding`, recipe `discovery-a2-v39`.
- H4에서 이미 있는 조건을 누락으로 오판하고 원문 밖 유형 정의를 통과시킨 문제에 대응한다. 확인된 입력 혼재와 검수 계약을 보완하며 모델의 내부 판단 원인은 단정하지 않는다.

## 구현

- 기존 공통 `make_prompt`에서 Critic용 관계를 자연어 원명제와 후보 ID로 투영한다. 실제 유형 ID의 연결은 `relation_bindings`에 작게 분리하고 제공된 유형 정의와 대조한다. 입력 크기 검사·최초 검수·수정 후 검수가 같은 경로를 쓴다.
- 원본 context·supplied·후보 지문·원문 구간·의존 근거는 보존한다. 서버의 유형 연결과 원명제 저장 계약은 바꾸지 않는다.
- 새 관측 supported 판정에 분류·정의 전체·조건·예외의 개별 대조를 요구한다. 누락·반증은 해당 관측만 기존 미검수 경로로 격리한다. 기존 저장 판정을 소급 변경하지 않는다.
- issues가 없는 관측 refuted/unknown도 기존 수정에 연결하고 그 판정 사유·근거를 전달한다. 수정 후 재검수·재개·A3 검수 연결을 재사용한다.

## 실제 확인과 한계

- 관련 계약·분석 검사 141개, 예산·복구 검사 19개 통과. 최초 추가 검사 하나의 테스트 설정 누락을 바로잡고 그 검사만 재확인했다.
- 정상 이웃 격리, 관측 부정 판정→수정→재검수→A3, 재개 시 추가 호출 없음, 기존 관계 수정·끝점 변경·근거전용 수정의 경계를 확인했다.
- 저장 H4 두 번째 Critic 입력 재조립: 14,735→14,050자. 원명제 두 개와 제공 유형 정의 연결, 원문 blocks/span/source_refs·dependencies 동일, context/supplied/후보 지문 불변을 확인했다.
- 재현 기록 `data/knowledge/semantic_i1_20261002/result.json`. H4 원 result·DB·started·calls 해시 불변, 실제 모델 호출 0, 새 토큰 null. 합성 응답과 저장 입력 재조립은 의미 정확도 측정이 아니다.
- 계획 및 구상 세션이 전달한 의미·실행 전문가 검토에서 차단 결함 없음. Windows 실기·전체 민원 평가·사람 효용은 수행하지 않았다.
- 다음 I2에서 모순 판정 격리와 원명제 수정 실패 시 원후보 보존을 보완한 뒤 I3에서 제한된 실제 모델 평가를 진행한다. 상위 #534/#539의 품질 목표는 아직 미완료다.
