## P1 정상 결과 격리와 후속 원문 연결

기존 전체 응답 검증은 의미 한 항목의 형식/근거 오류로 정상 항목까지 버렸다. E/R/join의 전체 응답 구조·원문 조사 범위 검사와 개별 항목의 Pydantic·원문 참조 복원·판정 검사를 분리했다. 정상 항목은 기존 실행 단위에 보존하고, 실패한 원래 항목과 이유는 `record_errors`, 미완료 의미키는 `pending_meaning_keys`로 남긴다. 형식 유효가 의미 정답을 뜻하지 않으며 오류가 남은 요구를 완료로 집계하지 않는다.

- 서로 다른 local_ref가 동일 canonical 의미키가 되는 중복도 항목 오류로 격리. 실패 항목에 의존한 의미는 미완료로 유지.
- 유효하거나 잘못 작성된 source_challenge의 대상 키와 의존 의미만 복구 차단. 무관한 정상 누락은 기존 복구 요청에 전달.
- `internal_unselected`가 정확한 고정 입력 block_id를 지정하면 같은 plan에서 추가 읽기와 새 판정 descriptor 예약. 기존 frozen read로 버전·본문·주소를 대조하고 선택 이력 저장. 같은 실행에서 한 번 수행하고 완료 결과 재사용.
- 추가 원문을 읽은 E 이후 R에도 같은 현재 원문·근거 영수증·주소 전달.
- 입력 상한 초과 시 기존 논리 구간 분할과 공유 조건/예외 보존 사용. 더 나눌 수 없는 큰 구간은 그대로 capacity 실패로 남기며 문자 수로 잘라 맞추지 않음.
- 요청 병합과 후보별 다중 오류의 실제 수정은 P3 범위이며, P1의 요청 전달 검사를 실제 교정 실적으로 세지 않음.

## P2 고정 원문 대조

규칙 내용/구체 사례 적용/도출 연결의 판단 대상을 분리하고 기존 원명제 statement_type을 재사용했다. 주명제 극성과 국소 부정, 자료 위치와 의미 충분성도 구분하도록 계약을 명시했다. 서버는 내부 읽기 주소의 inventory 소속과 실제 frozen read 일치를 확인한다. 자연어 자료명만으로 제공 문서와의 동일성을 자동 증명하지 않으며 제목 유사매칭을 사용하지 않는다.

- 실제 실행: `data/knowledge/evaluations/grounded_recovery_followup_20261005/p2_v2/`.
- 같은 `gemma4:31b-it-q4_K_M`, think=true, context 81920, output 16384, timeout 1800초 유지.
- HTTP 최대 4회, 총 7200초, 의미 재시도 0회. 입력·기준·모델·코드·설정·상한을 실행 전에 고정.
- 대조: 선정 규칙 114자, 기준 설정 권한 539자, 공공건설/매입 정의 628자, 원래 법적 연결 CQ 1167자.
- 평가 기준은 freeze에만 저장하며 모델 입력에는 넣지 않음. 원래 실패 자료는 개발에 노출된 자료로 표시.
- 질문/원문 크기가 이전 전체 E와 다르므로 계약 변경만의 개선율로 계산하지 않음. 독립 E 진단에는 후속 R/join 예약·실행이 없으며 전체 제품 경로와 구분.

## 한 차례 보완과 실제 재판정 조건

독립 의미 검토의 통합 판정은 국소 의미 일부 개선, P2 미완료다. 권한 대조에서는 지방공사의 「지방공기업법」 제49조 및 주택사업 목적 설립 제한이 결과 본문/조건에서 빠졌고, 법적 연결 대조의 공통 대통령령 참조는 동일성의 근거가 아니었다. 원문 주소가 있어도 필수 한정을 출력에서 생략한 것을 보존 성공으로 인정하지 않는다.

확인된 같은 필드 책임 혼동에 대해 한 차례만 계약을 보완했다. applicability는 질문상 표현 필요성, applies_to는 실제 원문 대상/범위, relation_kind는 의무·권한·정의·동일성 등 관계의 뜻, missing_source는 실제 자료명이라고 명시했다. 최초 E의 supersedes는 빈 문자열만, 재판정은 실제 이전키 또는 빈 문자열만 스키마에 허용한다. 모델의 unknown/identity를 서버가 required/authority로 바꾸지 않는다. 외부 부재와 명시 내부 블록 주소의 모순은 거부하되 자유 자료명에 대한 유사매칭은 하지 않는다.

### P3 연결 결함의 코드 수정

- 같은 후보의 현재 오류·수정할 필드·정상 보존 의미를 먼저 수집한 다음 기존 revise를 한 번 호출. 첫 오류를 고쳤다는 이유로 다음 독립 오류를 누락하지 않음.
- queue_recovery가 실제 갱신한 요청 ID 반환. 같은 candidate_ref라는 이유만으로 무관한 과거 요청의 판정 근거를 덮어쓰지 않음.
- 병합 요청의 의미키별 source_receipt/representation_unit_id 권한 보존. 현재 허용된 의미만 실제 복구 입력으로 선택하고 남은 의미는 unattempted로 기록.
- 현재 요청의 필수 의미키가 모두 실제 현재 R에 존재하고 supported인 경우만 요청 해결로 집계. 하나가 격리/누락되면 독립 정상 의미는 진행해도 요청 전체는 미완료.
- 관련 5개 파일 237개 검사 통과(10.60초). 추가 기존 corrections 검사는 14개 통과·2개 실패. 입력+스키마 상한에서 실패한 두 schema 경계 검사는 작업 시작 커밋 e936db2에서도 동일하게 재현. 실제 수정 성공의 증거와 분리함.

### 고정 재판정 경로

- `p2_reassessment_v2`: 저장된 실제 priority_authority E를 이전 계약의 미승인 출력으로 명시해 별도 실행에 복사하고 현재 원문과 정상 권한 후보를 대조.
- 실제 모델 R이 오류를 발견해 source_challenge를 제출해야 기존 E 재진입 경로가 실행되고, 바뀐 근거로 다시 R을 수행. 정답 challenge를 수동으로 주입하지 않음.
- 정상 장관/시도지사 권한 후보는 고정 대조군이다. 이 실행은 근거 판정 수정이며 실제 잘못된 후보의 신규 교정으로 계산하지 않음.
- 최대 HTTP 3회/5400초, 동일 모델·문맥/출력 상한·timeout. 첫 R의 입력+스키마 24794바이트, 허용 65536바이트. E/R 후속 입력은 실제 앞 단계 출력으로 결정되며 실행 시 같은 상한 검사.
- 재판정 준비본 v1은 병합 요청 완료 집계 수정 전 자료, 실제 호출 0회. 실행 기록은 v2만 사용.

- 지방공사의 **제49조·주택사업 목적 설립 제한은 정상 후보의 conditions/role_source에는 있었다. E의 공통 의미 본문·조건·전제에서 빠졌고 재판정 후에도 빠졌다. 후보의 누락으로 보고하지 않는다.**
- R2는 형식상 유효한 두 check를 반환했으나 설명과 상태/위치가 모순된다. 서버가 설명문을 읽어 supported 또는 maintain으로 덮어쓰지 않았다. 외부 세부 기준의 세 번째 의미키도 검수되지 않았다.
- 원본 DB/실행 중 코드 해시, 이식 전 실제 E, 정상 후보 결과 모두 불변 확인. R/E 단위의 succeeded는 형식 저장 상태이며 의미/요구 통과가 아니다.
- **실제 온톨로지 후보 교정 0회·새 누락 생성 0회. 같은 요구 재검수 미완료. 전체 CQ/A3와 N은 실행하지 않았다.** 근거 판단 필드의 실제 부분 수정은 위와 같이 별도 실적으로 남긴다.

독립 의미 전문가는 부분 성과와 잔여 오류를 대조한 뒤 조건부 중단에 동의했다. 한 차례 원인 보완 후에도 원문 한정 누락·설명/상태/위치 불일치·검수키 누락이 이어져, 승인된 중단 조건에 따라 추가 모델 호출·P4/A3·N 확대를 중단했다. R2 실패를 출력 한도나 자료 미제공 탓으로 돌릴 근거는 없다.

## 종료 전 연결 경계 수정과 검증 범위

최초 고정 원문 대조 4회 후 한 차례 계약을 보완하고 v106에서 재판정 3회를 수행했다. 이후 독립 실행 검토에서 확인한 이번 변경의 세 연결 경계만 v107에서 수정했고 **추가 모델 호출은 하지 않았다.**

1. 내부 자료 읽기와 의미 challenge가 같은 base 파생 여부를 횟수로 소비하던 문제 수정. read/challenge 사용을 별도로 저장해 읽기→challenge와 challenge→읽기를 각각 허용하고, 같은 동작의 반복은 막는다.
2. 먼저 허용된 A 의미를 제출한 뒤 나중에 B가 허용되어도 실행되지 않던 병합 요청 수정. 이미 제출한 의미는 제외하고 새 의미 집합의 별도 실행 키를 사용한다. 기존 A의 성공 입력·ID를 변경하지 않고 submitted_meanings/group_ids 및 제안·비용 집계를 누적한다.
3. source_challenge 대상/의존 의미가 다른 오류 수정의 정상 보존 근거로 들어가지 않도록 제외한다. 현재 유효한 독립 정상 의미는 유지한다.

이는 제어 흐름 수정이며 실제 모델 교정 성공을 추가로 입증한 것은 아니다. 최종 v107의 `grounding/recovery/completion/roles/scope` 5개 파일 집중 검사 **241개 통과(10.83초)**, `git diff --check` 통과. 독립 실행 전문가는 세 경계 및 인접 호출·저장·회귀 검사 범위를 재검토해 차단 결함 없음으로 보고했다. 실제 모델 시험 결과를 v107의 재시험 결과로 해석하지 않는다.

추가 `corrections` 검사는 14개 통과·2개 실패이며 두 실패는 작업 시작 커밋 `e936db2`에서도 재현했다. 두 경우 모두 `test_relation_call_reaches_model_with_nested_preservation_schema[False/True]`의 입력과 스키마 상한 검사에서 모델 호출 전에 실패한다. 전체 테스트 통과나 전체 온톨로지 품질 통과를 주장하지 않는다.

## 남은 범위와 다음 작업

- P1: 항목 격리·내부 읽기·두 후속 동작·현재 영수증 연결을 코드/대역/저장 재생으로 확인. 새 계약의 정상 누락이 실제 생성까지 이어지는 전체 증거는 남아 있다.
- P2: 근거 판정의 국소 극성/규칙·상세 분리와 실제 필드 수정은 관측했지만 필수 한정과 현재 표현 검수의 일관성 미충족.
- P3: 다중 오류 수집·의미별 권한·후행 의미의 별도 실행·정상 보존 경계는 수정. 실제 잘못된 후보의 before/after 교정과 실제 누락 생성·같은 의미 재검수 미완료. 과거 7197 결과를 신규 실적으로 계산하지 않음.
- P4: 같은 원래 두 문서 CQ, 교차 문서 전제/상충, join 용량 처리와 필요한 실제 A3 내용 확인 미완료.
- N: Relation→Concept 및 추출 연결 이웃 선택은 미구현·미실행. 핵심 실패를 해결한 것으로 간주하지 않고 원래 후속 범위를 유지.

**확인된 병목:** 설명·상태·실제 표현 위치의 불일치, 필수 검수키 누락, E에서의 원문 한정 누락. **가설:** 모델 능력, 독립 필드 조합 부담, 입력 복잡도의 상대적 영향. 이번 증거로 어느 하나를 유일한 원인으로 단정하지 않는다.

다음 설계 검토는 실제 표현 위치와 단일 판정을 연결하고 불필요한 독립 상태 조합을 줄일 수 있는지에 한정한다. 이유 문장을 서버가 성공값으로 자동 치환하는 방식은 사용하지 않는다. 이번 작업에서는 추가 구현/시험을 시작하지 않는다. 사람 효용·일반화 품질·Windows 실기는 미검증이다.

원본 DB·원문·동결 응답·로컬 평가 출력은 Git에 포함하지 않는다. 이 기록의 모델 시험은 개발에 노출된 자료와 정상 후보 대조를 사용했으며 독립 일반 성능 점수가 아니다. 현재 사용자 결정이 필요한 사항 없음.
