## 원문·구조 전달 경로

HTML 파서는 `element_path`, 제목 수준, 표 행·열·병합 범위를 기록하고 `service.py`는 locator를 블록 payload에 저장한다. `autoschema.source_packet`은 element_path를 제외하되 일부 제목·표 정보를 남긴다. `list_parents`는 실제 DOM 목록 부모를 계산하며, 업무 판단 호출은 해당 부모를 별도로 전달한다. `chunks`의 예외 키워드 문맥 추가는 실제 DOM 부모와 다른 기능이므로 물리 구조로 재명명하지 않는다.

부산은 제품 평가 DB의 parent run `cedacf0841e540cf83934db6d821140c`에서 실제 블록 ID·source_version_id·parse_run_id·locator를 읽기 전용으로 대조했다. 연구 입력 10개 블록은 원문 문자와 순서가 일치한다. b30/b31의 목록 부모는 b29이고, b32는 별도 형제 항목이다. 기존 연구 입력에도 제목 수준과 b30/b31→b29 관계 및 b32 전체 문장이 있었다. 따라서 부산의 실패를 부모 문맥 누락으로 설명할 수 없다. 복사된 평가 DB 옆에 원본 raw HTML은 없으므로 이번 조사에서 부산 HTML 재파싱까지 검증했다고 주장하지 않는다.

## 종료·재현 범위

A의 주소 실행 개선과 정상 의미 보존은 남기되 c47 자동 오류 특정에 실패했다. B의 AR 개발 1건 U/C 개선과 새 자료의 표 설명 개선도 보존하지만, 별도 원문에서 U/C 혼동이 유지돼 현재 구성은 제품 기본 경로에 채택하지 않는다. 해당 과제/자료/로컬 모델 구성의 결과이며 직접 ID 선택이나 물리 구조 전달 일반의 불가능을 증명하지 않는다.
