# 실제 민원 확보와 변경 영향 검토 시연

- 조사일: 2026-09-29
- 목적: 재구성 문의 대신 실제 공개 민원을 확보하고, 버스 민원 처리 과정에 변경 영향 검토를 연결할 수 있는지 확인.
- 선행 조사: [시연 자료 선정](demo_data_selection_2026-09-29.md)
- 후속 판정: [데이터 충분성 검토](demo_dataset_sufficiency_review_2026-09-29.md). 아래 원문 확보는 전체 영향 측정 준비 완료를 뜻하지 않음. LH 운영 자료와 버스 변경안·경로 연결 보완 필요.
- 결과: LH 관련 시민 작성 원문 2건, LH가 피신청인인 공식 결정문 1건, 실제 버스 노선 개편 민원 원문·답변·지도 4장 확보.
- 구분: **LH 자체에 접수된 시민 신청서 원문은 미확보.** LH 관련 다른 기관의 공개 문의, 실제 LH 사건의 결정문, 시민 직접 작성 원문을 각각 표시.

## 1. LH 원문 확보 결과

### 1.1 LH 자체 민원 조회

- [LH 민원신청 안내](https://www.lh.or.kr/menu.es?mid=a10302010000)의 실제 바로가기 확인.
- [민원 조회 경로](https://www.lh.or.kr/user/minwonReq/list.do?mid=a10302010000)는 본인인증 화면으로 연결.
- 비로그인 공개 범위에서 LH 직접 접수 신청서 전문을 확보하지 못함. 공개 원문이 전혀 없다고 일반화하지 않음.
- 기존 2026 Q&A를 시민 접수 원문으로 간주하지 않음.

### 1.2 시민이 직접 작성한 LH 관련 공개 원문 2건

| 자료 | 확인 내용 | 사용 판단 |
|---|---|---|
| [제주 주거복지센터 보증금 문의](https://jejuhwc.co.kr/community/qna.htm?act=view&page=11&seq=645), 2023-10-17 | LH 기존 거주자가 대출 상환 후 지역 보증금 지원을 받을 수 있는지 문의. 10월 20일 기관 답변 존재 | 짧은 실제 문의를 사용한 조건 판별 시연에 적합 |
| [하남시 1인 가구 임대주택 민원](https://www.hanam.go.kr/sotong/selectCvplRceptWebView.do?cvplCode=MINWON5&key=9580&listTy=N&pageIndex=82&pageUnit=10&rceptNo=6740&searchCnd=all), 2024-10-16 | LH·GH 등의 공급 조건에서 배제된다고 느끼는 시민의 공급 확대 요청. 10월 22일 시 답변 존재 | 신청 가능 여부와 정책 개선 요구를 구분하는 확장 사례 |

- 두 건 모두 원문 HTML 저장, 민원 본문과 기관 답변을 별도 텍스트로 추출. 작성자 메타데이터는 시연 입력에서 제외.
- **접수 기관은 LH가 아님.** 화면에는 각각의 실제 기관을 표시.
- 제주 문의의 연결 대상: 기존/신규 입주 상태, 임대 유형, 지원사업, 신청 조건, 담당 기관.
- 제주 사례는 해당 시점의 사업 안내가 추가로 필요. 당시 답변만으로 현재 지원 가능 여부를 확정하지 않음.
- 하남의 공급 확대 요구를 현재 신청 자격에 대한 단순 질문으로 축소하지 않음. 공급 확대 약속도 생성하지 않음.
- 기존 양산 공고를 제주·하남 민원에 적용하지 않음. 같은 LH 업무라는 이유로 지역·사업·시점 차이를 무시하지 않음.

### 1.3 프로젝트 목적에 특히 적합한 실제 LH 고충민원

- 자료: [국민권익위 임대주택 동호 변경 결정문](https://www.acrc.go.kr/boardDownload.es?bid=1010&list_no=69656&seq=2), 8쪽.
- 의결: 2024-02-26, 피신청인 한국토지주택공사.
- 요청: 같은 단지의 다른 주택에 새로 계약한 신청인이 이사 없이 기존 주택에 거주하도록 동호 변경을 요구.
- 쟁점: 기존 주택의 배정 상태, 새 주택의 공급 가능성, 신청인의 이사 부담, 수선 필요성.
- 결정문은 기존 주택에 다른 예비입주자가 없다는 사실 등을 검토한 뒤 동호 변경 의견을 표명. 실제 이행 여부는 확인하지 못함.
- 위치: 1~2쪽 신청원인, 2쪽 LH 주장, 2~3쪽 사실관계, 4쪽 판단·결론, 5~7쪽 당시 규정.
- **시민이 제출한 문장 그대로의 신청서가 아니라, 기관이 사건을 정리한 비실명 결정문 원본.** 재구성 민원 입력을 만들면 별도로 표시.

**시연 설계 제안**

- `신청인 → 기존 주택 / 신규 계약 주택 → 공급 상태 → 예비입주 배정 → 수선 관련 판단` 연결.
- 변경 검토 시 다른 배정 대상과 충돌하는지, 어떤 주택의 공급 상태를 다시 검토해야 하는지 표시.
- 익명 주택은 사건 내부 식별자로 유지. 이름을 추측해 실제 양산 단지에 연결하지 않음.
- 결정문에 적힌 판단 근거를 재현하는 역사 사례로 사용. 수선비 절감액이나 입주 일정은 만들지 않음.
- 시민 원문 확보가 최우선이면 제주 문의, **지식 관계를 통한 업무 판단을 강조하려면 동호 변경 사건**이 더 적합하다는 선정 의견.
- 기존 FAQ형 시연에 실제 민원을 억지로 맞추지 않고, 선택한 실제 사례에 필요한 근거를 보충하는 방향 권고.

## 2. 실제 버스 민원 확보

- 출처: [도봉구 공개 1127번 노선 개편 민원](https://ceo.dobong.go.kr/bbs.asp?bmode=D&code=10000662&intPage=11&pcode=12745939).
- 접수 2026-09-04, 답변 2026-09-27. 공개 작성자는 익명 처리됨.
- 시민 요청: 주거지와 창동역 접근을 개선하기 위한 경유 구간·회차 조정.
- 기관 답변: 우회 증가가 기존 승객과 배차에 미칠 우려를 들어 수용이 어렵다고 설명.
- 확보: 시민 본문, 기관 답변, 경로를 표시한 지도 이미지 4장. 이미지의 개략 경로 직접 확인.
- 지도는 시민이 그린 제안이며 승인된 노선이나 정확한 정차 ID 목록이 아님.
- 시민이 주장하는 무증차·무추가예산 효과와 기관의 운행 영향 우려는 **각 주체의 주장·검토 의견**으로 보존. 계산 결과로 승격하지 않음.

### 전후 자료의 혼동 방지

- 이전 조사에서 확보한 2025년 10118 → 10011 변경은 별도 사건. 이번 2026년 시민 요청의 처리 결과로 연결하지 않음.
- 2026-09-02 기준 서울시 [노선별 정류소](https://data.seoul.go.kr/dataList/OA-1095/L/1/datasetView.do)·[위치정보](https://data.seoul.go.kr/dataList/OA-15067/S/1/datasetView.do) XLSX 추가 확보.
- 해당 시점 1127 노선 ID 100100143, 정차 행 60개 확인. 민원 접수일에 가까운 기준 자료로 사용 가능.
- 보행망은 기존 도봉구 자료 재사용 가능하나 카탈로그상 2020년 기준. 접속 지점·현장 경로 차이는 선택 구간에서 확인.
- 전체 노선 변경의 비교 범위가 도봉구 밖으로 나가면 해당 구간의 보행 자료를 추가하거나 미계산 범위를 표시. 구 밖 영향을 없는 것으로 처리하지 않음.

## 3. 담당자의 답변·검토 과정에 연결하는 방법

**구현 가능. 공통 민원 화면에서 조회형 요구와 변경형 요구를 구분하는 방식 권고.**

| 단계 | 담당자가 확인할 내용 | 시스템 역할 |
|---|---|---|
| 민원 접수 | 시민이 원하는 개선과 변경 대상 | 원문에서 요구·대상·사유를 구조화 |
| 대상 확정 | 노선, 방향, 기존 정류장, 제안 위치·정차 순서 | 실제 ID 연결, 불명확한 부분은 담당자가 지정 |
| 변경안 작성 | 유지안과 요청 반영안 | 기준 자료를 보존한 별도 변경안 기록 |
| 영향 검토 | 바뀌는 관계와 연결된 대상 | 관련 후보 탐색 후 전후 비교 |
| 답변 검토 | 편익·불편·추가 확인 사항 | 계산값·관계 경로·원문에 연결된 초안 제시 |
| 결정 저장 | 수용·수정안·보류·수용 곤란의 사유 | 담당자 검토와 사용 자료 버전 저장 |

- 요청의 문제와 제시한 해결책을 분리. 접근성이 문제라고 해서 시민이 제안한 경로가 유일한 해법은 아님.
- 같은 정류장명이라도 방향과 ID 구분. 정류장 자체 이전과 특정 노선의 정차 변경도 구분.
- 입력에서 확정되지 않은 새 정류장 위치·순서를 AI가 임의 확정하지 않음.

### 영향 관계와 계산 항목

| 변경 | 직접 바뀌는 관계 | 확인할 연결 대상 | 계산·표시 |
|---|---|---|---|
| 승차 위치 변경 | 노선의 정차 지점, 승차 지점의 보행 접속 | 대표 시설 출입구·보행 경로·횡단 구간 | 전후 보행거리, 경로 변화, 대체 승차 지점 |
| 정차 추가·제외 | 특정 방향의 노선·정류장 정차 관계 | 새로 연결되거나 연결을 잃는 출발·목적 지점 | 직통 연결 유지·추가·상실 여부 |
| 경유 순서 변경 | 노선의 방향별 정차 순서 | 기존 목적지, 환승 연결, 우회 경로 | 정차·연결 변화. 운행시간은 별도 운행자료 확보 시 계산 |

- 그래프의 연결은 **영향 후보**를 찾는 근거. 연결됐다는 이유만으로 피해나 개선을 확정하지 않음.
- 영향 경로는 `민원 요구 → 변경안 → 바뀐 정차 관계 → 사용 가능한 보행/승차 경로 → 대상별 전후 차이`로 제시.
- 비교할 출발지·목적지·노선 방향·계산 조건을 유지. 가까운 정류장이라도 목적지로 갈 수 없으면 동등한 대안으로 취급하지 않음.
- 거리·연결 계산은 코드, 요청 해석·계산 결과 설명은 LLM, 최종 조치 선택은 담당자 역할.
- 대기시간·혼잡·실제 승객 수·사고 감소·새 민원 발생 확률은 연결 그래프만으로 계산하지 않음.
- 전체 요청 중 일부 구간만 계산하면 그 범위를 화면에 표시. 부분 비교로 전체 요청 수용 여부를 자동 결정하지 않음.

### 화면에 보여줄 핵심

- 왼쪽: 실제 민원 원문과 요구 목록.
- 가운데: 현행/변경안 지도와 변경된 관계, 선택 대상의 연결 경로.
- 오른쪽: 대상별 전후 결과, 출처, 추가 확인 사항.
- 하단: 검토 결과를 반영한 답변 초안과 담당자 결정.
- 결과 종류: `계산된 변화`, `자료에 기록된 검토 의견`, `추가 확인할 영향`을 구분.
- 생성 전에는 기존 기관 답변을 제외. 비교 단계에서 별도 열람해 단순 답변 복사를 방지.

## 4. 현재 기반과 추가 구현 범위

- 현재 코드 확인: `app/knowledge/snapshots.py`는 검토 지식·근거·버전 보존, `search.py`는 개체 식별과 관계 경로 조회 제공.
- 현재 Local 검색의 관계 탐색은 2단계 탐색. 교통의 방향·정차 순서·보행 최단경로 계산을 이미 지원하는 것으로 해석하지 않음.
- 추가 범위: 교통 도메인 정의, 민원 요구와 변경안 연결, 방향별 정차·보행 경로 비교, 영향 패널과 답변 연결.
- 단일 승차 위치 변경부터 비교를 구현하고 노선 조정으로 확장. 별도 범용 시뮬레이션 플랫폼이나 도시 전체 교통 예측 체계를 선행하지 않음.
- 2026년 실제 민원은 전체 요청을 보존하되, 첫 계산 범위를 명시해 검토. 2025년 실제 변경 자료는 별도의 계산 확인 사례로 활용 가능.
