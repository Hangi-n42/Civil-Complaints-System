## 필요한 최소 신규 기능과 재사용

연구 전용 `scripts/compare_business_condition_contrast.py`에 다음을 준비한다. 기존 R34/R36 동결 파일·기준·응답·제품 공용 파일은 수정하지 않는다.

## 결과 전에 고정할 기준

- 생성: 지원3분모·정확 주소·원형보존·조건 한 의미 차이·주체/행위/대상/다른 조건/기간 보존을 각각 보고한다. 서버 보존 성공을 의미 성공으로 승격하지 않는다. 생성 모델의 자체 이유만으로 한 의미 차이를 승인하지 않는다.
- 판단: 원본3의 개별/공동 라벨·이유·정확 오류 위치·실제 근거를 비교한다. 정상2보존, c47의U 및 일반화 이유는 기존 기준이다. counterpart gold는 생성 결과로 정상/오류를 유리하게 고르지 않고 판단 호출 전에 원문과 생성문을 조율 세션이 검토·동결한다. 모든 생성 결과를 포함하며 애매한 결과는 미확정이다.
- R36의 U/C와 정상 의무·동의·명시부정·자료부재 통제를 유지해야 한다. source-ID 복원은 새 의미 증거가 아니며 reasons의 금지/무의무 혼동·자료부재 과장도 평가한다.
- 공동이 새 계약 singleton보다 개선되면 공동 입력의 적용 근거다. 둘 다 좋아졌으면 새 구성 전체의 적용 범위이며 상대 필요성을 주장하지 않는다. 둘 다 못 찾으면 해당 자동 조건 삭제 구성은 미채택하되 A 전체 실패로 확대하지 않는다.
- 부분효과가 나오면 별도 확인·정상 동의 표현에 필요한 최소 비교만 진행한다. 자동 오류가 실제 저장 후보에서 위치·이유·근거까지 확인된 때 기존 편집/저장/보존/같은 요구/그래프·검색/답변으로 연결한다. 이 단계는 아직 실행하지 않았다.
- 각 비교 종료 즉시 원장을 갱신한다. 주소/실행 실패만으로 의미 비교를 못 했으면 새 A횟수에 넣지 않는다. 별도 확인과 안정성은 같은 가설의 하위 실행이며 독립 A횟수가 아니다.
