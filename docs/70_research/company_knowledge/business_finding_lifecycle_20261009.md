# R02 원문 재판정·이의 해소·기존 후보 선택 및 활용 연결

## 범위와 기준

기준 커밋은 `0876ae81bbcb8bbb1a07acd3e0f5f49775fc4d93`다. 부산 R02의 기존 원문, 후보 119개(활성 117개), 질문·기준을 그대로 사용했다. 이미 개발에 노출된 제한 사례이며 일반 정확도, 실제 사람 시험, 현업 효용을 측정한 결과가 아니다. #616·#617·#620을 재사용하고 새 추출·119개 전체 검수·외부 모델·학습·버스/LH/R05 비교는 수행하지 않았다.

- 질문: 양수인이 방문하지 못하고 대리인이 신청하면 무엇이 달라지는가?
- 기준: 미방문 조건, 위임·신분 확인, 양도증명서의 날인 위치, 법인인 경우의 대체 서류를 구분한다.

실행은 과거 평가 DB의 별도 복사본에서 수행했다. 원래 DB·원문·후보·과거 assessment·snapshot을 보존했다. 이번 드라이버는 실제 제품 `reassess_source`, `review_candidates`, `represent`를 호출하며 원문 블록 교체, 이의 복원, 원하는 해석·수정문 주입을 하지 않았다. 기존 결과를 묶어 assessment를 만드는 제한 실행 드라이버는 수동 기록 조립이며, 전체 `assess`를 자동으로 다시 수행한 결과와 구분한다.

## 수정 이유와 채택 코드

1. **이의가 가리키는 원문 문맥 공급:** 원래 의미의 인용만으로 재판정하면 그 인용 밖에서 제기된 이의를 확인할 수 없다. 종합 검수에 있던 출처 검색을 공유해 재판정에도 관련 이의·문맥을 전달했다. 이의는 정답이 아닌 검수 가설이다. 특정 block ID나 고정 47개 블록을 넣지 않았다.
2. **의미 갱신과 이의 해결 분리:** 선택 의미를 재판정했다는 이유만으로 기존 finding을 삭제하지 않는다. 원래 ID를 유지해 기존 종합의 근거 있는 `resolved`·`not_required`와 실제 활용 차단 계산으로 연결한다. `complete`·`gaps=[]`만으로 개별 이의를 해결하지 않는다.
3. **실제 원문 호출 이력 귀속:** 원문 재판정 뒤 적용성 호출이 실행돼도 새 이의·재판정 이력은 실제 원문 호출을 참조한다. 검증 실패는 현재 원문 호출 항목에 기록하고 적용성 호출이나 재사용한 원본 성공 항목을 실패로 바꾸지 않는다.
4. **원문 위치가 확인되는 기존 관계 값의 선택:** 검색 상위 8개 밖의 후보 중 `raw.Tail` 전체가 의미 문장과 실제 인용문에 모두 존재하고, 같은 출처 버전·parse·block·span의 후보 근거에 포함되면 검수 대상에 추가한다. 문자열 연결은 후보 선택 근거일 뿐 관계 타당성이나 전체 지지 판정이 아니다. 기존 chunk 근거를 정밀 근거로 변경하지 않는다. 표 직접 비교는 표 후보 전용이므로 기존 `exact_evidence` 주소 검증을 재사용했다.

5. **현재 미해소 안내와 과거 이력 분리:** 보존한 finding을 모두 미확정으로 다시 표시하던 QA 소비 경계를 보완했다. 기존 검증된 resolution에서 같은 finding ID의 상태가 유일한 `resolved` 또는 `not_required`일 때만 현재 `review_notes`에서 제외한다. 원본 finding·이유·해소 기록은 보존한다. 누락·중복·unknown·required_gap/source_error/claim_error/unresolved는 계속 표시하며 과거 scope 오류와 전체 partial도 유지한다. 서버가 설명의 진위를 재판정한 결과는 아니다.

## 첫 실제 실행: 이의 생명주기

원문 재판정은 제품이 선택한 48개 블록, 관련 이의 8개, 의미 3개로 실행했다. 실제 최종 요청에 ‘양수인(사는사람) 본인이 직접등록 [신분증 지참]’ 본문이 포함됐고, 응답은 이번에는 그 존재를 인정했다. 세 의미의 문장·조건·예외·기간·참조 내용은 바뀌지 않았다. 원문 문맥과 이의 입력이 함께 바뀌었으므로 단일 요인의 의미 이해 개선으로 귀속하지 않는다. 본인 등록과 미방문 목록이 있다는 사실을 법적 기본/예외 관계 전체가 증명됐다는 주장으로 확대하지 않는다.

기존 이의 10개는 원래 ID와 내용 그대로 유지됐다. 원문 호출 `37564686dde54d5287cba17a173009c8`와 적용성 호출 `1c4dbb76f7ff408dad568de93c07620b`를 구분했고, 재판정 이력은 전자를 참조한다. 새 원문/적용성 호출 2회 뒤 표현 3회·종합 1회를 실행했다. 변경된 요청에 이전 응답을 억지로 재사용하지 않았다.

종합은 기존 10개를 9개 `not_required`, 1개 `resolved`로 판단했다. 모델의 `source_completeness=complete`, `satisfied=true`와 저장 결과의 `partial`은 다르다. 저장 결과에 남은 이유는 과거 source batch의 `local_source_inspection_scope_mismatch`다. 해당 기록을 삭제하거나 이번 10개 이의를 미해소로 다시 계산하지 않았다.

선택 보완 전 실제 저장·자격 계산에서 c11·c46·c13 3개가 eligible이었다. 그러나 `agent_application_documents`를 c11+c46만으로 완전하다고 판단한 것은 위임장의 ‘양수인 도장 날인’ 조건을 표현하지 못하는 조합이었다. 기계적 자격을 실제 완전성으로 승격하지 않고 이 단계의 승인·QA는 보류했다.

## 후속 실행: 이미 있던 후보를 검수에 연결

c10 `claim_4ac9c4011b8d99b5c377e9ac`의 원래 Tail은 `위임장(양수인 도장 날인)`이다. 후보가 없는 문제가 아니었다. 정상 검색 순위 9위이고 근거 정밀도가 `chunk`여서 상위 8개와 정밀 근거 보완 규칙 모두에서 빠졌다. 이전 검수 묶음을 보존한 드라이버만의 영향이 아니라 정상 제품 선택에서도 확인한 경계다.

후속 코드는 `code_selection`으로 별도 동결했다. 원문·이의 생명주기 실행의 `code`와 결과는 그대로 보존했다. 같은 의미의 후보 선택은 기존 8개를 유지하고 c10과 c12 `claim_05b9382c1028126d1aa778ea`(대리인 신분증)를 추가해 10개가 됐다. 상위 한도를 9로 바꾸거나 ID/업무 문구를 하드코딩하지 않았다.

두 후보의 자기 원문 검수는 미방문 조건과 실제 서류 목록을 근거로 모두 `supported`를 반환했다. 해당 의미의 새 표현 검수는 c10+c11+c12+c46을 실제 조합으로 선택했다. 다른 두 의미의 최종 요청은 기존 요청과 정확히 일치해 2개 응답을 재사용했다. 원문 재판정은 반복하지 않았다.

후속 종합은 세 의미의 실제 표현과 자기 원문 지지 상태를 유지했고 `meaning_challenges=[]`, `source_challenges=[]`, `join_errors=[]`, 의존 전제 `[]`를 반환했다. 모델/시스템 상태 통계는 기존 10개 중 9개 `not_required`와 1개 `resolved`다. 마지막 1개의 설명 품질은 아래 한계와 같이 별도로 판단했다.

## 남은 경계와 이슈

후속 종합의 마지막 이의 해결 설명에는 다시 “b28의 부재로 인해 의미가 훼손되지 않는다”는 문구와 기본/예외 해석이 남았다. 실제 b28 본문이 제공됐으므로 부재를 검증된 사실로 인정하지 않는다. 원문 재판정에서 존재를 인정한 결과와 후속 설명의 부정확성을 함께 보존한다. 승인 대상은 b29-b31의 직접적인 조건·서류·날인 의미와 해당 후보 조합이며, 이 자유 설명이나 법적 기본/예외 관계를 승인 의미로 추가하지 않았다.

- 원문에 그대로 나타나는 전체 관계 값만 보완한다. 동의어·변형 표현·후보 자체의 부재를 해결한 결과가 아니다. 검색·선택 결과는 계속 원문 및 의미 검수를 받아야 한다.
- 선택 전 실제 모델이 필수 조건이 없는 조합을 완전하다고 판정했다. 이번 특정 조합은 보완했지만 일반적인 부분/완전 표현 구분이 해결됐다는 근거는 없다.
- 넓은 chunk 근거 때문에 다섯 후보가 같은 검색 구간에 함께 연결된다. 검색의 의미 분별력 개선은 검증하지 않았다. 공개 질문/기준에 같은 세 의미가 중복 표시되는 답변 구성도 남아 있다.
- 과거 조사범위 기록 오류 때문에 전체 요구는 부분 완료 상태로 남는다. 현재 원문 이의의 해소, 정상 사실의 개별 활용, 전체 요구 완료를 구분한다.
