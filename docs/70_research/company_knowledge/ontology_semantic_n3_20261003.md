## 진행 이유와 구현 선택

M2에서는 입주자를 주택 유형에 연결한 오류를 두 모델 모두 정상으로 판단했다. 한편 관계 ID가 그대로인 상태에서 선택 유형의 정의만 바뀌면 과거 검수가 남을 수 있는 별도 코드 경계도 확인했다. 먼저 의존성을 바로잡고, 연결만 묻는 제한 진단이 통과한 뒤 제품 호출을 분리했다. 기존 SQLite, 직렬 실행기, 후보 지문·근거·수정 helper를 재사용했으며 새 프레임워크·별도 의미 판정 규칙은 만들지 않았다.

- N1 `9df5721`: 관계 검수에 실제 선택한 주체·대상 유형의 지문을 저장하고 읽을 때 확인한다. 유형 정의·조건·예외·시점이 바뀌거나 필요한 유형이 없으면 해당 최신 검수는 유효하지 않다. 다른 유형의 변경은 영향을 주지 않는다. 기존 legacy 검수와 원문 관계·관측의 과거 계약은 유지한다. 새 검수가 무효이면 오래된 supported 판정으로 되돌아가지 않는다. finish와 A3가 같은 경계를 사용한다. 이 결함은 합성 실행 회귀로 재현했으며 과거 실제 모델 실행에서 발생했다는 증거로 확대하지 않는다.
- N2 `5a18570`·`f301b74`: 생성 서비스의 기존 호출 경로로 연결 판단만 물었다. 실제 HTTP 모델·옵션·prompt/schema를 대조하고 원응답을 보존한다. 전체 A2 검수 단위나 완료를 가짜로 만들지 않는 별도 제한 진단이다.
- N3 `4b9d669`: 관계 원명제 검수와 선택 유형 연결 검수를 각각 실제 unit/HTTP로 실행한다. N2의 짧은 연결 지시와 schema를 공통 모듈로 재사용한다. raw 관계·관측에는 불필요한 연결 호출을 만들지 않는다. 연결만 8192 출력 상한을 사용하고 나머지는 기존 4096, 모두 think=false다.
- 같은 묶음·원문 범위·현재 관계·선택 유형 지문을 가진 필수 부분 응답만 읽기 결과로 결합한다. 부분 응답을 후보의 최종 검수로 사용하지 않는다. 합성 결과는 추가 모델 호출이나 가짜 성공 unit이 아니며 실제 두 unit ID를 보존한다. 재개 시 성공 단위를 재사용하고, focused_reviews→수정→finish→A3가 같은 합성 경계를 사용한다.
- 실제 추가 연결 호출과 수정 후 재검수를 예산 예약에 포함했다. 원명제 응답에 연결 판정이 섞이면 해당 잘못된 기록을 정상 처리하거나 교정 근거로 삼지 않는다. 기본 제품 예산을 일괄 늘리지 않았다.
- 진단 runner `e5f8c35`: 해당 묶음의 필수 실제 단위 전부 성공 및 합성 결과 존재로 실행 상태를 계산한다. 마지막 단위나 과거 다른 실패로 사례 전체를 잘못 집계하지 않는다. 의미 통과는 이 실행 상태와 별도로 평가한다.

- 확인된 개선은 선택 유형 변경의 과거 검수 무효화, 제한 연결 판정, 실제 부분 호출/재개/합성 경계다. N3 고정 D에서는 명시적으로 추가된 정의 사실을 잡았지만, 자연 생성에서 “선정→자격 부여”로 확장한 새 정의는 Builder와 관측 Critic 모두 통과시켰다. 따라서 다음 병목은 새 유형 정의의 사실 추가와 이를 지지하는 관측 검수다.
- 연결 전용 분리가 이 사례의 판단을 개선한 결과는 있다. 모델 내부 원인, 지시·출력 상한 각각의 기여율, 새로운 자료에서의 일반 성능은 확인되지 않았다. 같은 모델의 생성·검수가 유사한 추론을 공유한다는 설명은 관측된 동시 오류와 양립하지만 단일 원인으로 입증한 것은 아니다.
- 다음 계획은 이 자연 실패를 그대로 고정하고, 근거 있는 역할 추상화와 추가 인과·자격 부여 주장을 구별하는 최소 진단을 설계하는 것이다. 현재 원문·정답·실패를 바꾸거나 특정 표현을 금지하는 규칙으로 성공을 만들지 않는다. 관측 검수 개선이 검증된 뒤에만 새로운 승인 범위의 자연 교정·종단 평가를 판단한다. 이번 실행에서는 추가 구현·반복 평가를 시작하지 않았다.
- 원시 자료는 로컬 `data/knowledge/semantic_n2_20261003/`, `semantic_n3_20261003/{product_once,correction_once}/`, 각각의 preflight 폴더에 보존한다. 원문·DB·원응답·개인 자료·.env는 커밋하지 않는다. Git에는 코드·관련 검사·동결 설정·이 보고서만 포함한다.
