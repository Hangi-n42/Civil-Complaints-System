# 원문 선택 투영과 문장 확률 비교 (2026-10-10)

이 문서는 #641 원문 선택 투영과 #642 문장 확률 비교를 구분한다. 연구 checkout은 `feature/business-semantic-modality-research`, 비교 시작 HEAD는 `1ff1b9b7bb0f03491db0fc46ba6d6d694339dc12`다. 제품 checkout 시작 HEAD는 `18cee9fb6f3eb4a163894a8f21b7740aadd764cb`다.

연구 비교는 완료했지만 제품 목표는 미달이다. A는 개발 사례의 정상 회귀 2건을 해소했고 B는 두 문서의 제한된 양태 순위 신호를 얻었다. 새 문서의 의미 오류, 실제 저장 후보의 주소 실패, 같은 문서 안의 점수 역전과 전체 점수 겹침이 남아 두 구성 모두 제품 기본 경로에 채택하지 않는다.

## 목적과 범위

정상 일부 사실과 조건부 의무를 보존하면서 원문이 입증하지 않는 확대를 구별하는 변경을 시험했다. 이전 #639/#640의 실패를 삭제하지 않고, 원문 선택 자체의 효과와 함께 전달된 생성 해석의 효과를 분리하는 제한된 비교를 수행했다. B는 판정 기호 확률인 #632/#633과 다른 문장 확률 식이다. 두 후보를 결합하지 않았다.

실행기 네 개만 추가했다. 기존 원문·후보, 판정 프롬프트/파서, 주소 검증기, 토큰화/API 함수를 재사용했다. 제품 기본 경로, 추출, DB, 그래프·검색·답변은 바꾸지 않았다. R05 cb9의 문서상 담당·제외 안내와 복합 처리·용어 대응 미확인 명시라는 제한적 성과는 유지하며 이번 자동 교정 성과로 합산하지 않는다.

## A: 생성 해석을 제외한 정확 원문 구간

`compare_business_selected_source.py`는 저장된 B1 응답의 from/target 및 unresolved target 주소에서 원문 block ID/SHA, 시작·끝 문자 오프셋, 정확 인용만 남긴다. 관계 종류, 연결 방향/그룹, 이유, 상태, 조사 완료 선언은 판단 입력에서 제거한다. 동일 주소만 중복 제거하고 다른 위치의 같은 문구는 유지한다. 잘못 해석한 유효 연결도 사람이 걸러내지 않는다. 원문 전체와 제목·부모·후보는 그대로다.

추가 문구는 선택 구간이 자동 선택이며 정답 관계나 확정 적용 범위가 아니라는 경계와 전체 원문 기준 판단이다. **투영과 이 최소 문구가 함께 바뀐 묶음 효과**다. 특정 삭제 필드나 모델 내부 원인을 독립적으로 입증한 실험이 아니다.

## B: 입력 문장 자체의 확률

[Merrill et al. (2024) 논문](https://aclanthology.org/2024.findings-acl.161/)과 [공식 구현 58ed848](https://github.com/ZhaofengWu/entailment-from-lm/tree/58ed848cc744f645b17c2f062d2a6f0c54650951)의 학습 없는 식을 독립 구현했다. 원 저장소 라이선스 확인 없이 코드를 제품에 복사하지 않았다.

동결 실행기 docstring의 “Wu et al.”은 공저자를 첫 저자로 적은 출처 표기 오류다. 올바른 저자는 Merrill et al.이며 실행 중 코드 SHA 보존을 위해 원 실행본은 변경하지 않았다. 수식/계산에는 영향을 주지 않는다.

`E = log p(x + SPACE + y) - log p(x + EOS) - log p(y + SPACE + y) + log p(y + EOS)`

공백은 ASCII 1개이며 EOS는 x와 y 단독 항에만 붙인다. 각 토큰열의 첫 토큰 확률을 제외하고 나머지를 합하며 길이 평균을 하지 않는다. 큰 E를 지지 방향으로 실행 전에 고정했다. 판정 기호 확률, CAD, 임베딩 유사도, 학습을 사용하지 않았다.

이 문서의 “전체 원문”은 기존 동결 case에 제공한 원문 블록과 메타데이터 전체다. 부산 원사이트나 모든 원문 섹션을 새로 수집한 전문이라는 뜻이 아니다. 이번 비교에서 정답에 맞춰 블록을 추가로 잘라내지 않았다.

x는 기존 blocks/source_parents/source/source_versions 전체를 정해진 순서로 JSON 직렬화하고 y는 원래 Event 그대로다. Entity는 Event에 있는 명사의 중복임을 확인했다. 원문 요약이나 정답에 유리한 발췌가 없다. 판정 ChatML이 없지만 구조화된 긴 문서 JSON이므로 논문의 짧은 자연문 적용과 다르다.

### 기술 가능성 및 보존한 실패

초기 C++ 경로는 설치 dylib가 x86_64뿐인 아키텍처 불일치로 컴파일 실패했다. 네이티브 arm64 실행파일은 동작하나 같은 라이브러리로 링크할 수 없었다. 0회 추론, 소스/오류/아키텍처 증거를 보존했다. Rosetta·대형 프레임워크 설치나 모델 교체로 확대하지 않았다.

첫 HTTP 검사는 1토큰 생성이 불완전 UTF-8 조각에서 끝나 `completion_probabilities`가 빠져 실패했다. 원응답과 실패를 보존했다. matching pinned server 코드는 불완전 문자열의 결과 추가를 건너뛰는 경로를 확인했다.

수정 probe는 출력 직렬화만 완결되도록 ASCII 토큰 16의 생성에 bias를 주고, **원래 입력 토큰 접두부에 대한 pre-sampling 전체 어휘 분포**에서 실제 다음 입력 토큰의 확률을 읽었다. 생성한 ASCII는 원문 접두부나 목표 토큰으로 대체하지 않는다. sampler가 logits 복사본에 bias를 적용하고 원 context logits에서 pre-sampling 분포를 다시 읽는 pinned 코드 경로를 확인했다.

6개 입력 위치 중 4개가 모델 greedy 토큰과 다른 목표 토큰이었다. 고정 2개 접두부에서 bias 유무 전체 어휘 분포 최대 차이는 모두 0.0 nats였다. 성공 9호출의 전체 248,320개 token ID가 유일하고 유한함을 검증했다. 기술 실패 1회까지 합한 probe는 10호출이다. 이는 의미 판단 개선 증거가 아니다.

원 분포 합은 1.0000267~1.0012593이었다. 네이티브 float 정규화 확률의 로그를 받아 Python double logsumexp로 재정규화했으며 합 오차 최대는 4.44e-16이었다. raw double logits 접근이나 양자화 이전 확률을 얻은 것은 아니다.

### 동결한 의미 비교

K01/K02/H05/H06/H02, c46/c47, AR01/AR02/AR03의 10건은 모두 개발 노출 자료다. 문서 내 정상/오류 순위 9쌍, 핵심 5쌍, 전역 S5 대 비지지5의 25쌍과 엄격 전역 분리(minS > maxnonS)를 기록한다. 비지지는 연구 집계용 U/C 묶음이며 제품 구분을 없애지 않는다. 사례/업무 임계값이나 결과 후 부호 뒤집기는 없다. K01>K02와 AR01/AR02>AR03의 두 문서 양태 신호는 c47와 별도 제한적으로 평가한다.

전체 결합 문자열을 tokenizer에 넣었고 add_special true/false는 모든 40개 열에서 같았다. BOS 248044는 자동 추가되지 않고 EOS 248046은 단독 항 마지막에만 실제 존재한다. 결합 경계에서 토큰이 바뀔 수 있으므로 문자 길이가 아니라 정확 token-LCP로 동일 확률 항만 상쇄했다. 모든 원문은 후속 토큰 문맥에 남는다. 같은 ID 접두부의 분포는 한 번만 받아 여러 목표에 재사용한다. 네 개 전체 logp 각각을 실측했다고 주장하지 않는다.

676개 잔여 항, 고유 접두부 585개, 총 요청 입력 토큰 321,508, 최대 접두부 1,499다. 동결 SHA는 `44db1ce7beae91b13824f36682bd82f5569c657ff13b21e6edaf9502911cbd00`다. 4개 전체 합과 상쇄 합의 수치 일치, 결합 경계 불일치 보존, 전체 계획 재구성 selfcheck를 통과했다. 전문가도 수식·EOS·LCP·목표 대응에서 계산을 무효화할 중대 결함이 없음을 실행 전에 확인했다.

## 재현과 보존

로컬 자료 루트는 `data/knowledge/evaluations/business_source_selection_probability_20261010`이다. 기존 #639/#640 재현 JSON은 입력·원시응답 재사용 의존성으로 유지한다. 새 재현 패키지는 동결 입력/설정/코드 식별자, 원응답·실패·평가·파일 해시를 보존한다.

동명 `.json` 패키지는 포함 파일 70개와 로컬 전용 manifest 669개를 담는다. JSON value는 UTF-8/ensure_ascii=False/indent=2/마지막 개행으로, verbatim text는 그대로 복원하고 bytes/SHA를 확인한다. 기존 `business_independent_scope_20261010.json`을 먼저 복원하는 의존성이 명시돼 있다. B의 네 항·순위·비용 계산은 `b_semantic/analysis_recipe.py`에 보존했다. 원본을 덮어쓰지 않는 임시 폴더에 해당 레시피와 token_plan/criteria/run/result만 복사하면 추가 추론 없이 assessment를 다시 산출할 수 있다. `package_recipe.py`는 완료·자원 해제·원문 비포함·바이트 복원 조건을 검사한다.

코레일 원문은 공공누리 제4유형의 로컬 연구 범위로 확보했다. 전체 HTML/본문과 이를 포함하는 모델 입력·응답은 로컬 보존하며 원격 보고에는 URL/SHA/로컬 manifest/최소 판정만 포함한다. 문장 확률 전체 어휘 gzip도 로컬 보존하며 원격에는 목표 확률·해시·실행 결과를 담는다. 공개 Git 자료만으로 로컬 제한 자료가 자동 복원된다는 주장은 하지 않는다.

## 남은 제품 목표

실제 저장 오류 자동 발견 → 수정·저장 → 정상 의미 보존 → 같은 요구 재확인 → 그래프/검색 반영 → 필요한 근거 선택 → 답변의 연결은 이번 A에서 달성하지 못했다. 평가 후보의 판정이나 점수 연구를 실제 저장 교정 완료로 계산하지 않는다. B는 단일 점수이므로 오류 위치·이유·자료 부족 구분을 자동으로 해결하지 않는다.

585호출 완료 후 소유 native PID 15679를 SIGTERM으로 종료하고 포트 닫힘과 Ollama 적재 모델 없음까지 확인했다. 전체 585개 접두부/목표/입력 길이/유한 어휘 분포/저장 gzip SHA와 동결 코드·입력 해시를 확인했다. 재현 패키지는 포함 파일의 바이트 단위 복원과 제한 원문의 비포함을 검사한다.
