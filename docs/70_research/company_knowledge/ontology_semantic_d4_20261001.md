# 의미구축 D4 — 원인별 최소 복구와 반복 제한

- 대상: #538, 상위 #534. D3 `a585c592ca77d286ce90741c27afc3510c6a05dd` 이후 변경.
- 브랜치: `feature/ontology-semantic-improvements`.
- 목적: 미완료를 원인·실제 대상별로 보존하고 필요한 역할만 실행한다. 기존 recovery 요청·역할·revision·직렬 실행·SQLite·예산·재개를 재사용하며 새 DB, scheduler, 상태 프레임워크, 의존성은 추가하지 않는다.

## 원인과 처리

| 원인 | 처리와 남는 한계 |
|---|---|
| `extraction_missing` | 담당 원문 구간의 해당 Concept 또는 Relation만 추가 실행한다. 같은 역할/구간의 누락은 한 작업의 `meanings`에 모두 보존한다. |
| `evidence_error` | 근거 검증 오류만 있는 기존 후보도 검토 묶음에 전달한다. 기존 revision이 후보 ID와 의미·끝점을 유지하고 근거 선택만 보완한다. 의미 변경은 거절하고 원출력은 보존한다. |
| `endpoint` | D3 Builder가 만든 연결 결과 또는 명시 검수로 남긴다. 정상적으로 추출한 관계를 끝점 때문에 다시 생성하지 않는다. |
| `alignment` | 실제 제공된 해당 기존 정의 ID와 명시 대응 검수로 남긴다. 다른 이름의 자동 대응 방어를 유지하며 Concept 재추출로 해결하지 않는다. |
| `source_absent` | 부족한 원문/조항·확인 범위의 구체 사유와 함께 종료한다. 미제공 원문을 같은 원문의 재분석으로 대체하지 않는다. |
| `budget_exhausted` | 실제 예산·예약 호출·추가 round·수정 한도에 맞춰 종료 사유를 기록한다. 모델의 예산 종료 주장도 서버 잔여량으로 검사하며 자동 증액하지 않는다. |
| `content_error` | 기존 후보의 의미 수정은 기존 revision 경로와 한도를 유지한다. 무효·범위 밖 검토는 자동 수정 대상으로 삼지 않는다. |

## 보존과 반복 경계

- 작업 ID는 원인·실제 대상 후보/끝점 또는 담당 구간·역할·허용 scope/step과 분석 범위로 정한다. 의미 문구나 호출별 source_ref 변화가 새 작업을 만들지 않는다.
- 같은 구간의 서로 다른 누락은 별도 의미 항목으로 보존한다. 실행에 제출한 목록은 고정하고, 뒤에 추가된 요청은 `unattempted_meanings`로 남겨 기존 성공 입력을 바꾸지 않는다.
- 공백 차이·새 후보 ID만 다른 기존 의미 반복은 새 유효 복구 후보로 인정하지 않는다. 의미의 모든 의역을 판정하는 유사도 모델은 추가하지 않았으며 동일 작업의 호출 한도로 반복을 제한한다.
- 성공 unit의 출력·해시·의존·시도 기록은 재개 시 유지한다. 입력이 달라졌다면 새 실행을 요구하며 기존 성공 unit을 실패 상태로 덮어쓰지 않는다. 실패한 동일 복구 추출과 기존 revision은 반복 호출하지 않는다.
- 분석 선택 밖 또는 담당 구간 밖의 비교 원문은 추출 복구 대상으로 승격하지 않는다. Critic/후속 역할의 비교 검색도 새 원문 분석으로 자동 확장하지 않는다. 실제 담당자의 유효한 요청은 앞선 비교 전용 요청의 거절 때문에 소실되지 않는다.
- `proposals_created`는 제안 생성 상태다. 의미 충족·사람 검수 완료로 집계하지 않으며 `unresolved_recovery_requests`에 남긴다. `semantic_status`와 `proposal_review_status`는 `unverified`다. 변경 없는 revision도 새 복구 제안으로 집계하지 않는다.
- 기존 metrics에 복구 호출·모델 경과 시간·실행된 작업 수·원인별 잔여만 추가했다. 재개 시 저장된 시도 기록에서 산출하며 재사용을 새 호출로 세지 않는다.
- 프롬프트 레시피는 `discovery-a2-v18`이다. 이전 레시피의 저장 원장은 수정하지 않으며 이전 실행을 새 프롬프트로 조용히 재개하지 않는다.

## 미검증 범위와 다음 작업

- 위 결과는 기존 실행기와 결정적 모델 대역으로 확인한 구현 계약이다. 실제 모델의 원인 분류 정확도·복구 품질·시간/비용 우위는 측정하지 않았다. 기존 8개 후보의 수락 가능성도 재평가하지 않았다.
- 원문/의미를 식별할 수 없는 잘못된 모델 응답은 기존 실패 기록으로 남는다. 자동으로 의미를 추측해 새 추출 대상으로 만들지 않는다. 끝점·대응은 명시 검수, 자료 미제공은 실제 자료 확보, 예산 종료는 별도 실행 결정이 필요하다.
- 실제 모델·전체 평가·브라우저 종합 시험·Windows 실기는 실행하지 않았다. 참가자 없음과 사람 작업시간/오류 미측정 상태를 유지한다.
- 다음 #539에서 고정 C2 조건을 비교한다. 기존 5호출·추가 round 0·revision 0 조건은 실제 복구 성능을 측정하지 않으며 이 한계를 보고해야 한다. D5 예산은 자동 확대하지 않는다. 이번 단계에서는 #539를 시작하지 않는다.
- 현재 사용자 결정이 필요한 사항 없음.
