# 최소 차이 두 원문의 공동 대조 판단 (#647)

2026-10-10, 기준 commit `a5fd5c9b931c70a7207a12334d3b3afc8497451f`. 고정 대조 3쌍을 실행했다. 허용/의무 쌍에서는 원래 놓친 의무 강화를 검출했지만, 명시 반증을 미지지로 바꾸는 회귀와 동의 표현 쌍의 공동 오판이 남았다. 현재 구성은 제품 미채택이며 역순·자동 대조 구성·추가 확인으로 확대하지 않는다.

## 기존 비교와 변경 범위

[#637](business_entailment_boundary_20261009.md)의 원본과 세 파생 입력 및 독립 판정 A를 그대로 재사용했다. B는 전체 원문 두 개와 동일 후보를 한 호출에서 비교하고, 실제 차이와 각 상황의 지지 범위를 함께 반환한다. 라벨 순열·다수결·예시 추가·원문 QA·VitaminC를 반복하는 방법이 아니다. 새 학습이나 별도 검수 모델도 아니다.

X/Y는 독립 문서 상황이며 한쪽 근거를 다른 쪽 사실로 사용하지 않는다. 후보 raw는 공통으로 한 번 제공하고, 각 상황의 모든 원문 블록과 ID를 유지한다. 제품 판단 프롬프트에는 original/d1/d2/d3 이름, 고정 기대 라벨, 변경 방향, 운영자의 정답 해석이나 수정문을 넣지 않았다. 반환값은 differences와 X/Y judgments이며 후자에는 숫자 label 또는 null, 오류 필드/구절, 정확한 근거 인용, 이유가 있다. 반드시 한쪽만 정답이라고 강제하지 않는다.

동일 Qwen3.8 27B Q4_K_M GGUF와 native engine 해시, context 8,192, 출력 2,048, temperature 0, seed 42 및 기존 sampling을 고정했다. 과거 독립 요청 4개의 전체 token IDs/설정과 현재 tokenizer 결과가 동일하며 runtime props는 랜덤 media marker 외 동일했다. 과제·차이 설명·복수 판정·JSON prefill이 함께 바뀐 하나의 입력 구성 비교이며 각 요소의 개별 인과 효과를 분리하지 않았다.

## 고정 입력과 결과

후보의 의무 주장에 대해 원본 `수령 가능`, d1 `수령할 수 있음`, d2 `수령해야 함`, d3 `수령할 의무는 없음`을 비교한다. 이는 기존 평가용 파생 상황이며 실제 기관 정책 변경이 아니다. S=지지, U=원문 미지지, C=명시 반증이다. 의무 없음과 행위 금지는 다르다.

| 쌍 | X / Y | 고정 기대 | B 실제 label | 실제 관찰 |
|---|---|---|---|---|
| p1 | 원본 / d2 | U / S | U / S | 원본의 Event `수령해야 한다`를 정확히 오류 구절로 찾음. 허용이 의무를 확립하지 않는다고 설명하고 명시 의무 d2는 보존 |
| p2 | d1 / d3 | U / C | U / U | d1 label 개선. d3는 반증이라는 이유를 쓰면서 숫자 2를 반환해 회귀 |
| p3 | 원본 / d1 | U / U | S / S | 동의 표현임을 정확히 찾았으나 둘 다 절차 맥락에서 의무 주장을 지지한다고 오판. 오류 구절 없음 |

p2 X의 이유에는 “오히려 의무가 아님을 시사할 수 있으므로”가 포함된다. 미지지 label의 개선과 원문을 넘어서는 설명 위험을 별개로 기록한다. p2 Y는 이유 끝에서 label 3이라고 쓰더라도 실제 label 필드는 2다. 사후에 이유를 읽고 라벨을 고치지 않았다. p3은 서로 다른 답을 강제로 만든 실패가 아니라, 동등함을 인식하면서 양쪽의 허용→의무 강화를 놓친 실패다.

| 고유 입력 4개 | 과거 A의 읽을 수 있는 의미 label | 이번 B에서 각 출현의 label |
|---|---|---|
| 원본 | S (기대 U) | p1 U, p3 S |
| d1 | S (기대 U) | p2 U, p3 S |
| d2 | S (기대 S) | p1 S |
| d3 | C (기대 C) | p2 U |

반복 입력을 독립 사례 6개로 부풀리거나 다수결로 합치지 않는다. 원본과 d1은 대조 상대에 따라 label이 달라졌다. p1의 부분 효과를 지우지 않으면서도 일관된 자동 개선은 입증하지 못했다. 과거 A 4개는 숫자 계약 대신 전체 단어 label을 출력한 엄격 형식 실패가 있었다. 읽을 수 있는 의미 결과와 이 형식 실패를 분리한다. 과거 A에는 error_spans를 요구하지 않았으므로 이를 사후 실패 사유로 추가하지 않는다.

## 검증과 비용

## 판정과 범위

평가 담당과 독립 검토는 회귀·공동 오판·설명 과잉 및 상대 의존성 때문에 현재 공동 대조 구성을 기각했다. 역순 호출 0, 자동 쌍 선택/구성 0, 새 확인 자료 0이다. 사람이 고른 적절한 p1 쌍의 효과를 자동 오류 발견 경로의 효과로 확대하지 않는다. c13/c46 정상 의미 보존 또는 c47 조건 확대 검출을 이번 양태 쌍의 결과로 대신 입증하지 않는다.

모든 입력은 이미 노출된 개발 자료다. [#646](business_document_boundary_20261010.md)의 제한된 저장 경로 노출 조사를 생성 전에 재사용했고 기존 AR/BI/KR를 새 확인으로 부르지 않았다. 정상 d2 의무는 보존됐지만 이것은 전반적인 정상 후보 보존율의 증거가 아니다.

자동 오류 발견 이후 실제 수정·저장·같은 요구 확인·그래프·검색·후속 답변은 실행하지 않았다. 제품 기본 경로와 #616/#617/#620은 미완료 상태 그대로다. 전체 제품 테스트와 전체 자료 재평가는 하지 않았다. 원인 후보는 대조 상대에 민감한 판단, 절차 맥락을 의무로 확대하는 해석, label과 이유의 불일치이며 이번 출력만으로 내부 원인을 확정하지 않는다.
