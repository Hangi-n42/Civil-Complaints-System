# J2 집중 검수의 사전 동결 진단

- 관련 이슈 #567, 선행 J1 7b5b30c. I3에서 확인된 정상 조건 오탐과 원문 밖 정의 미탐에 대해, 검수 역할 분리와 직접 문구 대조의 결합 효과를 검사한다.
- J1의 review_batches → make_prompt → call 경로로 R-A(정상 관계 2), R-B(LH 건설·공급 조건 제거 관계 1/정상 관계 1), D(원문 밖 정의 1/정상 설계 추상화 1)를 생성했다. 정상 4/오류 2의 총 6판정이며 I3와 분모가 다르다.
- 입력·스키마·원후보 지문·원문·코드·모델 digest·recipe·옵션·별도 독립 정답을 semantic_completion_j2_v1.json에 고정했다. 정답은 생성 입력에 포함하지 않는다.
- R-A/R-B의 모델 입력 차이는 의도한 conditions 한 필드뿐이다. 프롬프트는 각각 8,236/8,204/8,209자이며 양 모델의 프롬프트·스키마가 동일함을 실제 call 진입점에서 확인했다.
- Qwen 각 1회(3HTTP/900초, 호출당 300초), 실패 시 기존 Gemma를 검수 역할로만 변경해 같은 3회를 수행한다. 합계 6HTTP/1,800초, 수정 생성 0회. 첫 설정이 모든 판정과 근거를 충족하면 대안은 생략한다. 둘 다 실패하면 J3 운영 연결은 수행하지 않는다.
- 기존 진단 runner에 동결 설정 선택·해당 예산·집중 단위 키만 연결했다. 실제 synthesis와 같은 수정 진입 조건을 적용해 정상 응답의 불필요한 수정 요청 집계를 방지했다.
- 두 모델 설정별 과거 응답 3개 재생으로 runner 연결 확인(실제 HTTP 0). 별도 최소 검사에서 정상 supported 응답은 수정 진입 0회, refuted 응답은 1회 확인했다. 재생은 의미 품질 평가가 아니다.
- 의미·평가 사전 검토 완료. 기본 제품 실행기는 변경하지 않았다. 원문·DB·과거 결과는 보존한다.
- 사람 0명, 총 작업시간 null, 사람 효용 미측정. 개발 노출 진단이며 일반화 성능을 주장하지 않는다.

실제 결과는 실행 후 추가한다. 현재 사용자 결정이 필요한 사항 없음.
