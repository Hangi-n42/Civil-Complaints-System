# 의미구축 D5 — 실제 모델·검수 경로 통합 확인

## 목적과 판정 단위

- 대상 #539, 상위 #534. 브랜치 `feature/ontology-semantic-improvements`.
- 기존 SQLite 원장, 직렬 실행기, 역할과 검수 화면을 확장한 D1–D4가 실제 모델 산출의 의미 보존·유형 연결·검수 완결로 이어지는지 확인한다. 새 평가 플랫폼·정답 그래프·역할·의존성을 추가하지 않는다.
- 자동 원문 의미, 승인 가능한 구조, 유효 Critic 판단, AI 작업자의 명시적 보완, 승인 정본을 각각 판정한다. 후보 수나 `can_accept`를 의미 정확도로 계산하지 않는다.
- 참가자 0명, 사람 총 시간 `null`. AI 전문가 검수와 브라우저 조작은 사람 시험이 아니다. 사람 오류 감소·시간 절감·현업 효용은 미측정이다.
- 작은 공개 개발 사례의 확인이며 전체 LH 자료, `types_purchase`, 19파일, K9 12과제, 다중 모델, Windows 실기는 범위에 포함하지 않았다. 운영 활성화·배포·PR 병합 없음.
- 최종 판정: D1–D4 코드 경계와 실제 출력의 AI 보완→유형2/관계1 승인·재조회는 확인했다. 자동 C1+C2는 두 버전 모두 시간 예산에서 `partial`이며 중복·오분류·조건/끝점 오류와 검수 미완료가 남았다. 자동 생성 품질 향상·전체 완결·사람 효용은 입증하지 못했다. #539와 #534는 OPEN으로 유지하고 미달 품질 항목을 완료 처리하지 않는다. 최종 실행/검수일은 2026-10-02(KST)다.

## 남은 병목과 후속 우선순위

1. **새 응답의 필수 작업 계약:** Builder의 설계 유형 근거 선택과 관계별 연결 또는 구체적인 미해결 사유가 실제 출력에서 빠진다. Critic의 `supported` 판정에도 직접 근거가 빠진다. 저장된 legacy 출력의 읽기 호환과 새 응답 검증을 분리하고, 기존 스키마·서버 검증·부분 완료 집계·D4 복구 분기 안에서 다룬다. 오래된 원장 재작성, 개체의 강제 유형 승격, 기존 후보 인용을 Critic의 독립 근거로 자동 대체하는 처리는 피한다. 관계별 새 호출·전체 재생성·새 프레임워크는 필요하지 않다.
2. **허용 표현 전체의 의미 대조:** Critic은 관계가 이미 표현한 규범을 Concept 누락으로 오판한다. 개념뿐 아니라 조건·예외를 유지한 관계 등 허용 대안 전체를 확인한 뒤 누락을 제안해야 한다. 끝점 설계 문제는 내용 재추출과 분리한다. `can_accept`는 형식/참조 경계이며 조건부 역할을 일반 정의로 승인하지 않는 의미 검토가 필요하다.
3. **기존 예산·문맥 조립의 잔여 병목:** `discovery_analysis.process_group`은 새 분석마다 Builder/Critic2회만 예약하고, 같은 라운드 추출을 끝낸 후 합성한다. 실제 `assemble`은 입력 크기/후보12개/CQ에 따라 여러 묶음으로 나뉘므로 필요한 검수 비용에 비례한 예약이 아니다. 새 기능을 설명하는 Builder 지침 증가도 후보 입력 여유를 줄였다. 최소 후속안은 Builder 지침·후보 표현을 간소화하고, 기존 assemble로 예상 미완료 묶음을 구해 실제 Builder/Critic 호출과 남은 시간을 예약한 후 다음 추출 여부를 결정하는 것이다. 성공을 보장하는 성능 예측이 아니라 저장 입력과 코드에서 확인한 개선 지점이다.
4. **복구 입력 범위:** `recovery_groups`는 같은 블록의 이전 후보 전체를 모은다. Relation 복구에서는 같은 관측이 `previous_observations`와 `unapproved_observations`에 중복 전달되며 `analysis_context`의 축소 대상도 아니다. 기준본의 복구 입력20,060~38,318자 초과와 관련된 경로다. 최소 후속안은 요청 span·필수 끝점 관련 후보만 한 번 전달하고 중복 검출 signature는 서버에 유지하는 것이다. 원문 조건·공유 문맥은 보존해야 한다. 이번 동결 실행 중에는 이를 수정하거나 별도 재실행하지 않았다.
5. **반복 관측과 유형 중복:** 같은 정의를 여러 분석 묶음에서 재관측한 뒤 서로 다른 class add로 종합하면서 계층 충돌이 발생했다. 최소 후속안은 기존 Concept/Alignment→assemble 등록 경계에서 source version·근거 span·종류·정의·조건/예외·시점·범위가 정확히 같은 반복 제안의 후보 ID를 재사용하고 관측/발견 이력은 보존하는 것이다. 이름만으로 병합하지 않으며 다르거나 불확실한 정의는 근거 있는 reuse/new/defer 제안으로 남긴다. 승인 정본 병합을 자동 확정하지 않는다. 이 정확 일치 처리는 동의어·다른 원문·변경 정의의 동일성까지 해결하지 않으므로 별도의 의미 대응이 필요하다. 이번 실행 중에는 변경하지 않았다.
6. **사람 효용:** 실제 참가자가 확보되면 동등한 최종 품질에서 준비·검수·수정·갱신까지의 사람 총 작업시간과 오류를 비교한다. 참가자가 없는 현재는 효용을 미측정으로 유지한다. 이번 작은 AI 수정 성공으로 자동 구축 완결 또는 사람 효용을 주장하지 않는다.

## 보존한 로컬 증거

루트는 `data/knowledge/semantic_d5_20261001/`다. 원문·DB·전체 모델 응답·개인 환경은 Git에 포함하지 않는다.

- `preflight.json`: 기준선 재사용17검사, 원장/모델/설정/코드 해시.

- `c2_semantic_review.md`: ID/필드별 독립 의미 판정. 원문 관계 충족, Builder 연결 누락, Critic 오판을 분리.
