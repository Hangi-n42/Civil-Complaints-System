# 독립 한국어 의존 구문 분석의 조건 귀속 정보 점검 (#645)

## 상태와 비교 이유

2026-10-10, 연구 브랜치 `feature/business-semantic-modality-research`의 #643/#644 완료 commit `c111f8ad10d0a1953ae3b8eefe590a2c8fdb2d16`에서 시작했다. 제품 코드·환경·평가 DB는 수정하지 않았다. 이 기록은 독립 파서의 실행 및 정보 가치 점검이다. 제품의 자동 검출→교정→저장→정상 보존→요구 재확인→그래프→검색→같은 질문 답변의 완료 증거가 아니다.

- #627의 [scope tree](business_scope_tree_20261009.md)는 생성 모델이 조건·효과·양태 및 대응을 작성했다. 형식 실패뿐 아니라 구비품목을 일반 반납 의무로 해석하고 조건 함의 방향을 잘못 대응한 의미 실패가 있었다.
- [Natlogic](business_natlogic_20261009.md)의 정렬·관계 판단도 c47을 해결하지 못했다. 설명의 부분적 정확성과 최종 판단의 정확성은 다르다.
- [원문 선택 확률](business_source_selection_probability_20261010.md)의 부분 인용 주소 실패와 달리, [직접 선택](business_direct_selection_structure_20261010.md)은 c47의 지역 조건이 포함된 원문 전체 행을 정확히 전달했으나 기존 판단은 여전히 S였다. 이번 원인은 원문 미전달로 전제하지 않는다.
- 이번 신규 정보원은 Qwen이 다시 생성한 조건 설명이 아니라 별도 Stanza 한국어 구문 분석 모델이다. 구문 분석 출력에 업무상 조건·행위 관계의 정답 지위를 부여하지 않는다.

## 연구 원리와 미검증 가설

[Source–Cue–Scope](https://aclanthology.org/2026.acl-long.1362.pdf)의 source는 문서 주소가 아닌 주장 주체(conceiver)이며, 영어·중국어 귀속 학습 과제다. 주장 주체·양태 표현·적용 구간을 구분한다는 원리를 참고한다. 공개 [umrlib](https://github.com/umr4nlp/umrlib/tree/eb67b6337c6fa272b342a83943b1df8ae15fc2ec)는 UMR/MDP baseline 실행 묶음으로, 해당 논문의 신규 시스템 전체 재현을 확인한 것은 아니다.

[LEXDEMOD](https://aclanthology.org/2022.emnlp-main.795/)는 영어 계약서의 주체별 양태·trigger span 학습이다. [공식 저장소](https://github.com/adobe-research/LexDeMod/tree/7a5e7d02a672bd9d586dd014378c5cd39bf5f7ad)의 비상업 이용 조건을 가진 코드·데이터는 이번 연구에 반입하지 않았다. 영어 계약 성능을 한국어 업무 성능의 근거로 쓰지 않는다.

[LINC](https://arxiv.org/abs/2310.15164)의 [공식 구현](https://github.com/benlipkin/linc/tree/718dfe8fae342028a837a96096e5e1e412ad4f2e)은 확보한 논리 입력에 대해 결론과 그 부정을 증명한다. 계산기는 최초 자연어 해석·대응 오류를 고치지 않는다. 이 구현의 Uncertain을 이번 파싱 실패의 의미 라벨로 전용하지 않는다.

위 논문·코드 대조는 계획 및 구상 채팅의 공식 자료 검토를 공유받았다. 이번 구현은 세 학습 시스템의 재현이 아니다. **독립 한국어 구문 정보를 기존 판단에 추가하면 조건 귀속 오류가 줄어드는가**는 별도 검증 대상인 프로젝트 가설이다.

## 입력과 주소 계약

#643 고정 원문 10개 블록 310문자를 한 글자도 고치지 않고 블록별로 분석했다. 세 후보의 모든 raw 문자열 필드 13개 187문자도 각각 분석했다. c13의 Head/Relation/Tail을 문장으로 합치지 않았고 c46/c47 Event·Entity 값도 바꾸지 않았다. 원문은 세 후보에서 동일함을 확인하고 한 번만 분석했다.

원문 버전·실제 parser block ID·저장 locator는 #643 `originals.json`에서 재사용한다. 블록 간 부모 관계와 제목은 기존 판단 입력에 남긴다. 독립 문서 간의 의존 연결, 생략된 동사, 사람이 정한 조건 연결은 추가하지 않는다. 후보를 보고 원문을 분할하거나 정규화하지 않는다.

`Token`의 표면·보고 offset과 `Word`의 표면·lemma·품사·head·deprel·보고 offset을 따로 저장했다. 표면이 원형 문자열의 `[start:end]`와 같을 때만 exact 주소로 인정한다. 원형에서 다시 검색해 주소를 보충하지 않는다. lemma는 분석 결과이지 원문 인용이 아니다. 대응 실패는 null, 분석되지 않은 문자 구간은 공백 여부와 함께 기록한다. 반복 구절·주소 불일치·lemma 불일치·비공백 누락 탐지·필드 경계 selfcheck를 통과했다.

실제 23개 문서가 23개 sentence, 151개 Token/Word로 출력됐다. 이번 출력의 Token과 Word는 모두 1:1이지만 이 사실을 일반 MWT 계약으로 확대하지 않는다. 151/151 원문 위치 대응, 비공백 누락 0은 **주소 및 실행 성공**이며 의미 성공이 아니다.

## 비교 동결과 노출 경계

A의 과제·프롬프트는 #643의 c47/c13/c46 `plain` 원시 요청과 동일하다. 과거 입력 토큰은 각각 1,860 / 2,041 / 2,319이며 결과는 S/S/S(고정 기대 U/S/S)다. #627의 다른 context 설정은 기준선이 아니다.

B는 동일 A의 system 지시·user 원형·필수 부모/제목·selected spans·assistant prefix를 보존하고 user JSON 끝에 `independent_dependency_parse` 한 필드만 추가한다. 보조 필드에는 자동 분석임과 미검증 상태, 필드 설명, 전체 token/word/연결/주소만 있다. 정답·라벨·교정문·운영자가 정한 연결은 없다. A의 user 값을 B에서 해당 필드 제거 후 비교해 완전 동일함을 확인했다.

최초 token/word 중복 배열은 입력 7,979 / 8,078 / 9,408으로 출력 2,048 예약과 함께 기존 8,192 한도를 넘었다. 표면·주소·id가 동일한 1:1 token/word를 공유하는 읽기 가능한 TSV로 무손실 변환한 뒤에도 6,302 / 6,420 / 7,480이었다. 모든 token/word 필드와 gap의 원형 복원 일치를 확인했다. 표면 대신 offset으로 문자열 복원을 요구하는 추가 압축 초안은 평가 담당이 읽기 용이성을 이유로 기각했다. 해당 초안으로 생성하지 않았다. 파서 결과는 모든 준비 단계에서 동일하며 head/lemma/품사를 고치거나 유리한 연결만 고르지 않았다.

**생성 결과를 보기 전에** 평가 담당 결정으로 양쪽 문맥을 12,288로 확대하고, 새 A 3회와 B 3회만 실행하도록 동결했다. 과거 8,192의 A 응답은 참고 결과이고 새 비교의 기준선으로 재사용하지 않는다. 새 A request의 token IDs와 sampling은 과거 요청과 완전히 같고 context만 달라졌다. 동일 Qwen3.8 27B Q4_K_M·GGUF·native engine 해시를 확인했으며 runtime props 차이는 `n_ctx`와 랜덤 media marker뿐이다. temperature 0, seed 42, 출력 2,048, context shift 없음, 단일 slot 설정을 양쪽에 적용했다. 최대 입력 7,480 + 출력 2,048은 12,288 이하다. 호출 순서는 A(c47,c13,c46) 다음 B(c47,c13,c46), 최대 6회이고 재시도는 없다.

c47/c13/c46 및 기존 K01/K02/NLC/A02/SL/AR/BI/KR 결과는 개발 노출 자료다. 기존 AR/BI/KR를 미사용 확인 자료라고 부르지 않는다. `exposure.json`에 기존 입력 파일과 노출 내역을 생성 전에 기록했고, 이번 비교 전 새 확인 자료를 만들지 않았다. 개발 비교에서 의미 있는 효과를 확인한 경우에만 별도 확인을 검토한다. 자동 조건/행위 대응이 정확하게 확보되지 않았으므로 #627 범위 계산기는 연결하지 않는다.

## 실제 비교 결과

| 개발 사례 | 고정 기대 | 새 A | B | 원시 응답 검토 |
|---|---|---|---|---|
| c47 조건 확대 | U | S | S | 양쪽 모두 지역 조건이 포함된 b32 첫 행 전체를 인용하지만, 괄호의 반납·변경 의무가 일반 후보를 지지한다고 판단. 오류 위치 없음 |

| c46 정상 서류 목록 | S | S | S | b29와 b30/b31의 목록·법인 대안을 유지, 원문에 있는 포함 내용을 지지 |

양쪽 정확도는 이 개발 사례에서 각각 2/3, 개선 0, 정상 보존 2/2, 조건 확대 검출 0/1이다. 호출 6/6은 형식·주소 인용 계약을 통과했고 모든 응답이 EOS로 종료됐다. 형식 성공을 의미 성공으로 합산하지 않는다. c47 B는 `error_fields=[]`, `error_spans=[]`, `missing_premise=null`, `source_state=present`를 반환했다. 오류를 찾은 뒤 U/C만 혼동한 BI03과 달리 **조건 확대 자체를 놓친 실패**다. 이번 세 사례에는 별도의 C 대조가 없어 U/C 경계 전반을 평가했다고 주장하지 않는다.

문맥을 8,192에서 12,288로 늘린 새 A의 라벨은 과거 A와 같았다. 이것이 모든 입력에서 문맥 변경이 무영향이라는 증거는 아니다. B의 판단 이유는 파서가 제공한 조건 연결을 올바르게 해석했다고 볼 근거를 보여주지 않는다. 응답만으로 파서를 전혀 사용하지 않았다고 단정할 수도 없다.

주소와 일부 구문 단서는 확보됐지만 필요한 업무 조건·같은 행위의 대응이 자동으로 정확하게 확보되지 않았고, 최종 오류 검출도 개선되지 않았다. 별도 확인 자료는 0건이며 새로 작성·실행하지 않았다. 기존 AR/BI/KR를 새 확인 결과로 재사용하지 않았다. #627 계산기나 추가 생성 설명 단계도 연결하지 않았다.

## 비용과 검증

## 판정과 제품 상태

평가 담당과 독립 전문가의 최종 판정은 **현 Stanza 1.15.0 KAIST+Qwen 보조 입력 구성 기각**이다. 설명에서도 새로운 의미 개선을 확인하지 못했다. 확보한 일부 구문 단서나 주소 성공은 원래 조건 귀속 병목의 해결이 아니다. 확인된 실패는 원형 단편의 품사/lemma와 관계 연결 오류, 그리고 전체 원문과 구문 정보가 함께 있어도 지속된 c47 범위 확대 오판이다. 이 단일 비교로 파서 오류, 생성 모델의 구문 활용, 표현 비용 중 어느 요소가 오판을 유발했는지 분리하지는 못했다. 모든 독립 파서 접근이 불가능하다는 결론도 아니다.
