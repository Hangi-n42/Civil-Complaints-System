# H3 원문 조건 수정과 별도 재검수 연결

- 대상: #559, 상위 #534·#539. H1·H2 후속 구현이며 실제 모델 품질은 H4에서 판정한다.
- 기존 `conditions`, revision/history, Critic, 후보 지문과 A3 변환을 재사용했다. 새 판정 모델이나 법령별 정답 규칙은 추가하지 않았다.

## 원인과 변경

- G4는 원문에 있는 지방공사의 설립 목적 한정을 누락했다. 기존 71자 조건에 해당 한정을 포함한 평가용 표현은 103자로, 240자 상한 안에 들어간다. 이는 표현 가능성 확인이며 모델이 성공했다는 증거가 아니다. 평가용 표현은 생성 입력에 넣지 않았다.
- Relation·Critic 지시는 상위 전제·예외·주체별 분기·괄호 정의의 적용 범위를 대조하도록 보완했다. 이미 표현한 동등 조건과 실제 누락, 외부 자료 부재를 구분한다.
- 이전 수정 경로는 새 제안을 저장해도 `source_relation`을 옛 값으로 복사했고 자동 재검수가 없었다. 선정된 비근거전용 원명제 수정 대상을 call/normalize에 함께 전달한다. `issues=[]`이고 관계 판정만 refuted/unknown인 경로도 포함한다.
- 자연어 주체·목적어가 같으면 기존 유형 ID를 유지하되 새 조건과 유형 정의를 함께 Critic에 제공한다. 끝점이 바뀌면 미연결 관계로 보류하며 기존 연결로 자동 완료하지 않는다. 근거만 수정하는 대상은 의미를 변경할 수 없다.
- 원 Critic과 revision의 원응답·수정 전후 이력을 유지하고 별도 Critic unit을 저장한다. 집계와 A3는 수정된 후보 지문에 맞는 검수를 사용한다. 수정된 근거/원문은 새 `source_relation`에도 연결한다.
- 수정 직전에 수정+재검수의 호출/시간을 함께 확보한다. 성공한 수정 이후 재개는 남은 Critic만 계산한다. 재검수에 저장 revision의 전체 의존성을 상속하고 기존 원문 선택/크기 검사를 재사용한다.
- 재검수에서 새 도구 요청이 생기면 추가 자동 호출 없이 명시 보류한다. 사람 수락과 구조 미리보기는 별개다. 기존 미리보기는 선택 후보의 구조를 투영하므로 deferred 행이 있어도 구조가 유효할 수 있다. 미처리를 성공으로 계산하지 않는다.

## 확인 결과와 범위

- 관련 discovery contracts/analysis/budget/recovery 4개 파일: 첫 실행 152 통과, 수정 후 자동 Critic이 없다는 과거 기대 2건 실패. 해당 기대를 새 계약에 맞춰 수정하고 두 건 재확인 통과했다. 기존 Pydantic 직렬화 경고 13건은 별개로 유지했다.
- 신규 집중 회귀 7개 통과: round0/revision1 수정→Critic, issue 없는 비-supported 관계, 끝점 변경, 재검수 추가 도구 보류, 수정+검수 예산 부족, 동등 조건에 추가 수정 없음, 수정 저장 직후 취소→남은 Critic만 재개.
- 원 unit과 history.before 보존, 수정 조건과 정확한 근거, 현재 지문/A3 원문 및 전체 의존 미리보기, 성공 unit 재호출 0회를 함께 확인했다. 위 검사는 합성 모델 대역이며 실제 의미 품질 검증이 아니다.
- 실행·의미 전문가 최종 검수: 차단점 없음(계획 및 구상 세션 전달). 전체 민원/Windows 실기/사람 효용은 시험하지 않았다. 실제 새 모델 호출 0, 사람 참가자 0, 사람시간 null.
- 평가용 용량 기록: `data/knowledge/semantic_h3_20261002/condition_capacity.json`, SHA256 `be942c61b0222cea6d2003d02126735367d6f24401ea37a3a6e01f4d8acd697a`. G4 결과·원본 DB·기존 동결은 변경하지 않았다.
