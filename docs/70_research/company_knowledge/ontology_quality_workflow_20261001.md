# 온톨로지 생성 의미와 비개발자 검수 흐름 개선

- 신규 추적: [#534](https://github.com/Hangi-n42/Civil-Complaints-System/issues/534)
- 기준: `26b28aa4f1b41426ed2d0b329e5d9f8c21a507ed` (A6 보완 병합 후 main). A5/A6 완료 기록·동결 자산은 수정하지 않음.
- 범위: 기존 개념 대응, 최종 입력·출력 용량, 같은 블록의 누락 복구, 기존 UI 연결. 모델·DB·큐·에이전트 프레임워크 추가 없음.

## 구현 선택

1. `ConceptAlignment.meaning`으로 동일·변경·별개·미확정을 구분한다. 명시적으로 동일한 검토 기준은 기존 target ID의 근거 보강 변경으로, 의미가 달라졌으면 정의/조건 변경으로 변환한다. 동명만으로 병합하지 않는다. 미확정 대응은 보류하며, 같은 기준의 반복 근거 보강은 원래 관측들을 보존한 하나의 변경안으로 묶는다.
2. 원장은 그대로 두고 부모 block ID와 Python 문자 구간의 분석 뷰를 만든다. 큰 번호 목록·문단·글머리를 구조적으로 나누고 공통 머리말·열거의 상위 조건·명시적 예외를 함께 제공한다. 의미 완전성을 보장하는 법령 파서가 아니다. 경계를 정하지 못하거나 공유 문맥 자체가 크면 실패/미처리로 남긴다.
3. 정의·비교 후보·원문을 합친 최종 프롬프트를 계산한다. 주 분석 원문을 잘라 넣지 않으며, 넘치는 비교 정의는 이후 Builder/Critic의 작은 비교 묶음으로 넘긴다. 끝내 비교하지 못한 ID는 partial 결과에 남긴다. 제공·형식 성공·구간별 양 역할 근거 연결·의미 해결을 분리한다.
4. Critic의 `missing_meanings`는 역할·CQ/허용 범위·실제 제공 원문 구절을 요구한다. 기존 후보 수정과 별개의 Concept/Relation 재분석으로 연결한다. 원문 구간과 역할 기준으로 중복 요청을 제한하고, 출력 상한도 같은 구간의 제한된 추가 분석을 요청한다. 기존 의미의 동일 출력 반복은 복구로 세지 않는다. 새 제안은 다시 Builder/Critic 경로를 거치며 자동 승인하지 않는다.
5. 프런트엔드는 기존 실행·근거·변경·결정 API를 사용한다. 자료·업무 질문·검토 기준을 선택하고, 이름과 정의로 관계 대상을 선택한다. 범위·시점·부정·양방향 판단을 일반 입력으로 편집하고, 원문 선택으로 근거를 연결한다. 질문의 누락 목록에서 검색 후 미승인 제안을 추가할 수 있다. 수락 결과에도 정의·조건·관계를 표시한다. JSON 상세는 고급 확인용으로 남긴다.

## 실제 결과와 판정

최초 current 변경 실행 중 원문 공통 조건 누락을 고친 이력은 위와 별도로 보존한다. 수정본 current는 `discovery-a2-v10`, types_purchase는 `v11`로 실행했다. v11은 **수정 역할에도 실제 제공 원문 구간 검사를 적용**하고 캐시 재개 버전을 바꾼 보완이다. current 수정본에는 revision 호출이 없어 이 보완 경로를 실행하지 않았다. 각 실행의 정확한 코드 파일 해시는 로컬 `started.json`/`result.json`에 남는다.

| 사례 | 코드 | 실제 HTTP 호출 | 모델 초 | 전체 경과 초 | 실행 결과 |
|---|---|---:|---:|---:|---|
| current | 기준 main | 10 | 591.535 | 598.545 | partial |
| current | 변경 v10 | 21 | 1437.850 | 1447.251 | partial |
| types_purchase | 기준 main | 7 | 462.043 | 467.446 | partial |
| types_purchase | 변경 v11 | 24 | 1691.706 | 1702.187 | partial |

- current C1: 기준선은 건설/매입의 정의와 포함 계층을 제안했다. 변경본에도 직접 건설/비직접 취득 정의가 있지만, 일부 공공임대 정의를 entity로 분류하여 매입 포함 계층의 대상이 A3에서 연결되지 않는다. 유형과 개체의 분류 오류가 남는다.
- current C2: 기준선은 별표4 원칙·잔여주택 자격 완화·LH 건설공급/장관 분기를 제안했지만, 선착순과 지방자치단체/지방공사→시도지사 분기의 후보 의미가 빠졌다. 변경본은 선착순 문구와 두 주체 이름을 관측에 담았으나 property_value로 분류했고 Relation 결과는 없어, A3에서 검토 가능한 조건부 규칙/관계로 연결되지 않았다. 두 주체와 각각의 조건 연결도 충분하지 않다.
- current 변경본은 Critic의 쟁점 참조 오류 1건, 복구 미해결 6건, 필수 미처리 묶음 10건을 반환한다. 원문 없는 CQ를 현재 묶음에 다시 요청하는 잘못된 Critic 누락 판단도 남았다. 호출 예약 범위 안에서 복구를 완료하지 못했다.
- current 판정: 일부 원문 의미가 추가됐지만 비용 증가와 분류·관계 손실이 있으므로 **기준선 대비 생성 품질 개선으로 채택하지 않음**. 관측 수 증가는 성능 향상으로 계산하지 않는다.
- types_purchase 기준선: 제2조 8유형 중 영구·국민·행복·통합 4유형의 정의만 제안, 장기전세는 관계만 있고 분양전환·매입·전세임대 정의는 누락. 제37조 대상/규모/승인/개량 조건은 후보에 없었다. 국민·통합의 기존 정의 대응 2건이 있었으나 A3는 모두 새 target ID를 만들었다. Critic 인용 불일치 1건도 남았다.

- types_purchase 변경본: 요구된 8유형의 정의가 모두 A2 관측에 생성됐고 지원·대상·공급 조건도 포함됐다. 국민·통합의 명시적인 same 대응 2건은 A3에서 기존 target ID의 근거 보강 update로 연결됐다. 그러나 별도 관측에는 대응 없는 국민·통합 add도 남아 **중복 제거가 완성된 것은 아니다**.
- 분양전환 정의를 국민임대의 changed 대응으로 내는 오류도 있었다(reason은 distinct로 모순). A3에는 국민임대의 정의를 분양전환 의미로 바꾸는 미승인 변경안이 남았다. 이 변경을 수락하면 의미가 잘못되므로 거절/수정해야 한다. 구조 검사 통과는 이런 의미 정확성을 보장하지 않는다.
- 제37조 공동주택 규모 제한·사전 장관 승인·지원 조건·개량 예외 문구는 A2에 관측됐지만 대상/절차를 entity/property_value로 분류해 대부분 A3 변경안으로 연결되지 않았다. 개량의 철거·재건설 포함/단순 보수 제외 어휘는 남았다. Relation은 0건이며 매입계획 세부 사항과 후반 절차는 미처리다. 제공되지 않은 85㎡ 수치를 추가한 관측은 없었다.
- 역사 변경본의 후보 묶음 6개 중 Critic 완료는 1개, 복구 미해결 2건, 필수 미처리 묶음 10건이다. 예산 차단 5개 단위는 추가 HTTP 호출을 하지 않았다. 전체 생성 품질이나 비용 대비 효율의 개선으로 채택하지 않는다.
- 마지막 Critic이 비교 전용 과거 시행본을 현재 선택 원문처럼 재분석하도록 요청한 사실을 발견했다. 이 실행에서는 예산 예약 때문에 해당 복구 호출이 없었다. 최종 **v12**에서 선택 `analysis_block_ids` 밖의 복구는 validation에 남기고 실행하지 않도록 보완, 해당 경계 6개 테스트로 확인했다. v12의 실제 모델 실행을 추가로 수행한 것은 아니다.
- 완료/중단 실행 5건 모두 각 실행 중 코드 파일 해시와 원본 DB 불변을 확인했다. 결과는 `data/knowledge/quality_20261001/<사례>/result.json`과 `completed-evidence-index.json`에 보존했으며 원문·DB·전체 모델 출력은 커밋하지 않는다.

## 사람 비교 시험 연결

- 기존 [평가 계획 §7](../../05_plans/company_knowledge/post_k10_evaluation_plan.md)의 비용 분리를 재사용한다. 실제 참여 시 UI의 `사람 비교 시험 기록`에서 익명 참가자·C0/C1 또는 B1/B2·교육/준비/CQ/구축/검수/수정/갱신/조회/운영/민원/제출 전 근거 확인을 기록하고 내려받는다.
- 모델 대기·휴식은 타이머 중지. 탭이 숨겨지면 중지한다. 필수 비용 중 빈칸이 있으면 총 사람시간은 null. 실제 미발생 활동만 확인 후 0을 입력한다. 측정을 시작하면 비교 조건 변경을 막는다. 다른 조건은 기록을 내려받은 뒤 새로고침하여 시작한다.
- 같은 작은 과제·원문·완료 기준으로 두 방법을 비교하고 최초 결과와 수정 결과를 보존한다. 가능하면 두 사람이 순서를 교차한다. 결과물의 필수 의미·오류를 별도로 대조한 후에만 시간 비교를 해석한다.
- 사용자가 실제 참가자 없음으로 확정. 현재 실제 참가자 0명. 총 사람시간·절감률·10% 확장 판정·현업 효용은 미측정. AI 브라우저 조작 시간이나 모델 대기시간을 사람 시간으로 대체하지 않는다.

## 남은 한계

- 구조적 분할은 의미를 자동 보장하지 않으며, 복구 후보 생성도 요구 의미를 충족했다는 판정이 아니다. 미승인 후보끼리의 의미 동치 판정과 후보 오류는 사람이 검토한다.
- 실제 current 비교에서 생성 품질 개선을 입증하지 못했다. 이 변경은 기능과 실험 결과를 담은 검토 브랜치이며 운영 품질 승인본이 아니다.
- 출력/호출/검색 한도와 필수 미처리·복구 잔여는 유지한다. 상한을 늘려 결과를 통과시키지 않는다.
- Windows 실기, 전체 19파일/기존 12과제, 여러 모델 비교, 실제 민원 운영은 이번 확인에 포함하지 않음.
