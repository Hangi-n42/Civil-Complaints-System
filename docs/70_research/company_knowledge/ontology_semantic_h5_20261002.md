# H5 원명제 수정 입력의 설계 ID 혼재 제거

- 대상 #561. H4 실제 실패에서 확인한 입력 경계만 사후 보완했다. H4 평가 코드 `0a920cf`와 실패 결과는 그대로 유지한다.
- H4 revision 입력은 최상위 subject/object에 유형 ID, statement_type에 design_proposal을 두고 중첩 source_relation에 자연어 끝점과 rule을 동시에 제공했다. 실제 모델은 최상위를 복사했다. 이 혼재는 확인된 입력 문제이며 모델 내부 판단 원인은 확인할 수 없다.

## 구현과 검증

- 공통 `make_prompt`에서 source_change_ids에 해당하는 모델용 targets만 기존 source_relation과 원후보 ID로 투영한다. 입력 크기 검사와 실제 호출에 같은 투영이 적용된다. 서버 supplied, Builder 유형 연결, 원이력·수정 전후 저장은 유지한다.
- recipe `discovery-a2-v38`로 구분하고 기존 지시의 중첩 필드 참조만 새 입력 표현에 맞췄다. 새 정규식, 유형 ID 역변환, 의미 교정기, 추가 에이전트는 만들지 않았다.
- 정상 자연어 수정·끝점 변경 보류·evidence_only·현재 지문·원기록·재개를 포함한 관련 선택 검사 **16개 통과**. 수정 대상만 투영되며 근거전용/다른 수정의 계약은 그대로다.
- 저장 H4 입력 재조립: 5,973자에서 5,196자. 후보 ID는 유지하고 `시ㆍ도지사`→해당 기준의 자연어 끝점과 rule을 한 위치에 제공했다. 입력 context와 supplied가 바뀌지 않았음을 확인했다.
- 실제 H4의 ID 복사 응답을 바이트 그대로 재생했다. 정상 명제로 교정하지 않았고 subject/object 미연결 보류가 유지됐다. 새 측정 토큰은 null이며 재생 메타데이터는 H4 당시 기록이다.
- H4 원 result/DB/started/calls 해시 불변, 추가 실제 모델 호출 **0**. 새 입력의 실제 생성 품질과 Critic 거짓양성 개선 여부는 **미측정**이다. H4 C2 실패와 current 미실행 판정을 바꾸지 않았다.
- root·실행 전문가 최종 diff 검수 통과(계획 및 구상 세션 전달). 전체 테스트·Windows 실기·사람 효용 검사는 확대하지 않았다.
