# Task Calibration의 원점수 대비 비교 (#650)

2026-10-10, 기준 commit `c79d1e05e6bcd8456a06b22f8e527dce90317251`. 기존 원문+후보 분포 9개를 그대로 재사용하고, 원문만·후보만 분포 18개를 새로 얻었다. 정답은 원점수 7/9에서 보정 후 4/9로 감소했다. 기존 오류 교정은 0, 기존 정답 회귀는 3이다. 사전 기준에 따라 이번 구성을 기각하고 라벨 배치 변경·새 확인 자료·오류 위치 판단으로 확대하지 않았다.

## 공식 방법과 구현 범위

[Task Calibration 논문](https://aclanthology.org/2025.findings-acl.362/)과 [공식 코드](https://github.com/chuchun8/TaskCalibration/tree/1159a5be1777c5c43933340697512f3a188fcf4a)를 확인했다. 고정 revision은 `1159a5be1777c5c43933340697512f3a188fcf4a`이며, MIT LICENSE와 내려받은 원본 파일의 URL·SHA를 로컬에 보존했다. `src/eval.py`는 선택지 logits에 softmax를 적용하고 다음 점수의 최댓값을 선택한다.

```
a = P(label | source, candidate), b = P(label | source), c = P(label | candidate)
TC(label) = a * log((a*a + 1e-10) / (b*c + 1e-10))
```

각 a/b/c는 동일한 세 선택지 안에서 정규화한 값이다. 계수 a와 공식 epsilon을 유지했다. 단순 log 차이·비율, 매 생성 토큰의 context-aware decoding, 문장 발생확률 또는 6개 라벨 순열 평균이 아니다. 임계값·가중치·epsilon을 결과에 맞춰 탐색하지 않았다. 최상위 점수 차이 ≤1e-12만 수치상 동률로 미확정 처리하며, 미확정을 U 정답으로 계산하지 않는다.

native 서버가 반환한 전체 어휘 248,320개 **pre-sampling log probability**에서 숫자 토큰 1/2/3을 선택했다. 이를 raw logits라고 부르지 않는다. 공통 정규화 상수는 세 선택지의 재정규화에서 소거되며, log-sum-exp로 계산했다. 직접 공식과의 값 일치, 작은 확률, 균등 동률, 입력 삭제와 원형 보존을 selfcheck했다.

공식 `utils.py`의 편측 입력은 같은 템플릿의 premise 또는 hypothesis 내용만 빈 문자열로 바꾼다. 이 저장소에서는 같은 지시·출력 prefill·라벨 매핑을 유지하면서 원문만 입력의 `raw={}`를 만들고, 후보만 입력은 원문의 `blocks/source_parents/source_versions=[]`, `source={}`로 만든다. 실제 입력 키를 조사해 그 밖의 원문 필드가 남지 않음을 확인했다. case ID와 raw는 후보만 입력에 남는다. JSON 빈 컨테이너, 한국어 지시와 숫자 라벨, Qwen3.8 27B Q4_K_M은 논문의 원래 템플릿·모델과 다르다. 이는 공식 식을 적용한 로컬 비교이며 논문 전체의 동일 재현이 아니다. 편측 입력에는 정답을 부여하거나 제품의 자료 누락 판정으로 저장하지 않았다.

## 동결 비교 결과

S=지지, U=원문 미지지, C=명시 반증. 기존 #632 primary의 8개와 #633 confirmation의 NLC-C04를 사용했다. 모두 이미 노출된 개발 자료이며, c47/H03/A02는 원점수에서 이미 맞힌 사례다.

|---|---|---|---|---|
| K01 | S | S | S | 정상 허용 보존 |
| K02 | U | S | S | 의무 강화 오류 미해결 |
| c13 | S | S | S | 정상 보존 |
| c46 | S | S | S | 정상 보존 |

| NLC-C04 | U | S | C | 다른 오답으로 이동 |

총 개선 0, 회귀 3, 정답 유지 4, 오답 유지 2다. C04가 S를 벗어났다는 이유로 올바른 오류 검출로 계산하지 않는다. 두 방법 모두 같은 both 분포에서 출발한다. TC의 판단에 원점수와 다른 원문·후보·양자화·프롬프트를 섞지 않았다.

편측 분포의 높은 U와 낮은 C가 보정식에서 C를 상대적으로 올리는 계산을 확인했다. 한쪽 정보가 없는 상황의 U 선호를 제거해야 할 잘못된 편향이라고 단정할 근거는 없다. 이 관찰은 이번 구현·모델·자료에 한정되며 Task Calibration 연구 전체의 불가능을 뜻하지 않는다.

## 검증·비용·중단 범위

원문+후보 기존 9개는 요청의 모든 token IDs·설정·원시 분포 SHA를 확인하고 재호출하지 않았다. 새 18개도 전체 어휘의 ID·유한 점수·greedy 결과 및 압축 전후 SHA를 검증하고 공식 식을 다시 계산했다. 동률·미확정·잘림·실패는 0이다. 숫자 라벨 1/2/3의 접합 토큰 일치, 모든 입력의 8,192 context 내 수용을 사전 확인했다.

Qwen3.8 27B Q4_K_M, 동일 native 엔진/GGUF 해시, temperature 0, seed 42, 기존 sampling을 유지했다. 새 18회 입력 15,053토큰·출력 18토큰, 응답 경과 합계 97.165659초, 전체 wall 97.183177초, prompt cache 0이다. full-vocabulary 응답 처리 비용이 포함되며 기존 both 9회의 과거 비용은 이 신규 비용에 더하지 않는다. 런타임 식별·종료 증거는 함께 실행한 [후보 공동 판단](business_candidate_contrast_20261010.md)과 공유한다.

사전 기준은 기존 오류를 하나 이상 교정하고 기존 정답 및 정상/반증/참조 부재 통제를 전부 보존하는 것이다. 이를 충족하지 못했으므로 UCS 후속 0회, 새 확인 0회다. A 공동 판단의 성패와 독립적으로 결정했다. 이미 마련한 새 원문의 작성·blind review 기록은 보존하되 실행하지 않은 확인을 성과로 계산하지 않는다.

공유 확인 자료의 포함 4·제외 0·미확정 0과 작성/검토 provenance는 [A 보고서](business_candidate_contrast_20261010.md) 및 두 manifest에 보존했다. 실제 도구 반환 식별자는 `/root/candidate_confirmation_author`, `/root/candidate_confirmation_reviewer`이며 dispatch는 `gpt-6-astra/high`, `fork_turns=none`이다. 관측 receipt 구간의 wall은 작성 139.990275초, blind 검토 242.477826초, 동결 후 대조 71.670367초다. 토큰·비용 및 런타임 모델 자체식별은 미제공이며, 이 자료 준비 비용을 B의 18회 제품 모델 호출 비용과 합치지 않았다.

라벨 점수만 비교했으므로 오류 필드·구절, 필수 자료 부재의 별도 `source_state`, 실제 수정·저장·같은 요구 확인·그래프·검색·후속 답변의 개선을 입증하지 않는다. 제품 기본 경로와 #616/#617/#620은 미완료다. 전체 제품 테스트·전체 자료 재평가는 하지 않았다. 로컬 `data/knowledge/evaluations/business_task_calibration_20261010/`에 원시 증거를 보존하고 공개 [manifest](business_task_calibration_20261010.json)에 해시와 결과를 남겼다. 현재 사용자 결정이 필요한 사항 없음.
