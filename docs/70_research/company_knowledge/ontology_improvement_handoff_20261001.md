- 관계 4개는 실제 주체/대상을 원문 표기로 남겼지만 유효한 class ID 양 끝점으로 연결하지 못해 unresolved/deferred다. 현재 관계 스키마의 domain/range는 class ID를 요구한다. 관계 내용 추출 성공과 스키마 연결 완성은 다르다.
- 8개 모두 `can_accept=false`, `can_accept_with_dependencies=false`. 사람이 버튼만 누르면 되는 대기 상태가 아니며 현재 값으로 수락하면 거절된다. 두 유형의 인용을 고치고 유형 정의/근거 성격/관계 끝점을 확정해야 한다.
- 별도로 Critic은 관계 판단 인용 불일치로 실패했다. 필수 미처리 2개·검수 미완료 후보 7개·미해결 복구 요청 1개가 남았다. 이들은 서로 다른 단계 집계이며 A3 후보 8개와 더하거나 같은 분모로 보지 않는다. Critic 실패만이 8개 수락 차단의 원인은 아니다.

## 남은 문제와 원인: 확인된 사실과 미확인 가설

| 문제 | 확인된 발생 경로/원인 | 현재 처리와 남은 한계 |
|---|---|---|
| 유형·개체·값 혼동 | 모델이 일반 정의를 entity/property_value로 출력하면 A3는 참고 관측으로 제외 | 지시 개선 및 원문 관계 보존. 모델 능력/지침/문맥의 원인 기여율은 분리 측정하지 않음 |
| 기존 개념 오대응·중복 | 초기 A3는 alignment를 소비하지 않았고, 보완 후에도 모델의 잘못된 changed와 대응 없는 반복 add가 존재 | 기존 ID 연결·오대응 차단은 구현. 의미 동일성 판단과 전체 중복 제거는 미완성 |
| 관계가 있어도 수락 불가 | A2의 자연어 주체/대상과 A3의 class→class 계약 사이에 유효한 유형 정의가 없음 | 억지 클래스 생성 대신 원문·미해결 끝점 보존. 다음에는 필요한 역할/대상 유형을 근거와 함께 확정해야 함 |
| 긴 원문/출력 누락 | 최종 비교 문맥을 더하면서 입력 상한 초과, 제한 출력 안의 필수 의미 누락, 구간 분할 시 공통 조건 유실 | 구간·공통 조건·최종 문맥 배분 보완. 입력이 들어갔다는 사실로 의미 완전성을 주장할 수 없음 |
| 누락 복구 실패 | 기존 revision은 신규 후보를 만들지 못함. 별도 복구 연결 후에도 Critic의 엉뚱한 CQ/부재 자료 요청·동일 후보 반복·예산 소진 | 제한 복구·선택 범위 차단 구현. 실제 필수 의미 복구와 호출 효율은 미완성 |
| 인용 검증 실패 | Concept 두 유형 및 Critic 판단의 quote가 제공 원문 구간과 정확히 일치하지 않음 | 잘못된 근거를 통과시키지 않음. 모델이 인용을 변형한 세부 원인은 분리 측정하지 않음 |
| 사람 효용 미확인 | 참가자 0명 | 기록 UI와 시험 준비만 있음. 시간 절감·오류 감소 수치는 산출하지 않음 |

모든 실패를 자료 부족이나 모델 크기 탓으로 단정하지 않는다. 실제 있는 조문을 놓친 경우, 입력에 없는 참조 조문, 분류 오류, 끝점 미연결, 형식 오류, 예산 종료를 구분해야 한다. 조건을 annotation으로 보존한 것은 법률 조건 질의/추론 엔진을 구현한 결과가 아니다.
