### 1. 권고: 학습된 오류 구절 탐지 — LettuceDetect v2 Qwen 2B

[공식 논문](https://arxiv.org/abs/2607.00895), [공식 모델](https://huggingface.co/KRLabsOrg/lettucedect-v2-qwen-2b/tree/4511d95c6a5f24df1e810a097685d068208cb149), [공식 코드](https://github.com/KRLabsOrg/LettuceDetect)를 확인했다. 공개 모델은 Qwen3.5-2B에 오류 구절·유형을 출력하도록 학습해 배포한 가중치다. 자체 학습은 하지 않는다. 원문/요청/답변을 입력받아 후보 안의 정확한 부분문자열과 contradiction/unsupported_addition/fabricated_reference 유형을 반환한다. 공식 설명 변형은 구절별 explanation도 요청한다. 기존 일반 Qwen의 span 지시나 ClearCheck의 문장 전체 판정과 달리 **학습 과제 자체에 국소 오류 위치가 포함**된다.

선정 근거는 큰 모델·긴 추론의 기대가 아니라 목표 출력과 학습 과제의 일치다. 단, 공식 평가 14언어 목록에 한국어는 없고 한국어 규정·양태 판별 성과도 확인 불가다. 일반/code benchmark 점수를 이 업무 정확도로 사용하지 않는다. 카드의 3유형은 자료 부족의 독립 상태를 제공하지 않는다. 빈 구절을 항상 정상이라고 처리하는 방식도 전문부재를 놓칠 수 있다.

**이번 실행 권고 범위는 자동 위치·이유 능력의 제한 진단**이다. 공식 설명 템플릿을 그대로 고정하고, A02에서 자료 부재를 이유로 정확히 설명하는지 별도 보고한다. 코드가 이유를 임의 해석해 네 번째 의미 상태를 만들어내지 않는다. 공식 출력 계약으로 표현할 수 없는 부분은 '계약 미지원'으로 남기며 실행 실패나 원문 U와 합치지 않는다. 이 한계가 남은 모델을 전체 판정기의 대체품으로 채택하지 않는다.

로컬 공개 가중치 파일은 4,548,221,488 bytes/BF16, 2,274,069,824 parameters다. 메타데이터의 revision은 `4511d95c6a5f24df1e810a097685d068208cb149`; Apache-2.0 표기다. 현 transformers4.46.3은 이 Qwen3.5 구성을 지원하는 실행 환경으로 검증되지 않았으므로 전용 연구 venv의 최신 호환 runtime을 별도 준비해야 한다. MPS 또는 CPU에서 전체 모델 실행 성공·피크 메모리·시간은 미확인이다. 4.55GB 파일 크기를 전체 메모리 요구량으로 쓰지 않는다. 다운로드와 runtime 선택은 조율 결정 후에 한다.

성공하면 같은 원문 밖 소규모 확인 및 실제 저장 후보의 자동 위치·이유 전달 가치를 평가한다. K02/C04를 계속 놓치거나 정상 후보를 공격하면 이 구성은 기각한다. 한국어 prompt 번역·예제 추가·다른 seed/threshold로 이어가지 않는다. 라벨만 개선하고 위치/이유가 실패하면 부분효과로 남긴다.

### 2. 예비: 한국어 양태 표지를 보존하는 제한 연산자 대조

[한국어 법 규범 유형 연구](https://www.scitepress.org/publishedPapers/2020/101224/pdf/index.html)는 의무·허용·금지의 한국어 표지를 분류한다. [Korean AMR 지침](https://github.com/choe-hyonsu-gabrielle/korean-amr-guidelines/blob/master/korean-amr-guidelines.md)은 가능·허가·의무의 별도 표상과 한국어 프레임의 빈틈도 명시한다. 이것은 우리 데이터에서 자동 분석이 정확하다는 증거가 아니다.

새 가설은 모델이 자유로 생성한 modality 값을 믿는 대신 **실제 양태 표지의 위치·부정 범위를 먼저 보존하고**, 행위/주체/조건의 대응이 확인된 좁은 문형에서만 명시 가능한 연산 관계를 계산하는 것이다. #627의 양태 생성/자동 guard 전체 파싱과 달라지는 부분은 연산자 출처다. 설치된 Kiwi 0.23.1은 표면형·품사 분해에만 사용할 수 있고 규정 의미 판정기가 아니다.

그러나 '수 있다'는 능력·가능·허용이 중의적이며, 같은 동사가 다른 주체·조건에 붙을 수 있다. 허용에서 의무가 도출되지 않는다는 것은 의무가 금지되었다는 뜻이 아니다. 두 표지만 발견해 U를 선언하면 문서 다른 곳의 명시 의무를 놓친다. 단순 정규식 경보는 이번 목표의 자동 의미 개선으로 세지 않는다. 한국어 전체 scope 연결을 자동 해결하는 검증된 규칙/파서도 현재 확인하지 못했다. 따라서 현시점은 **예비 설계이며 즉시 구현·실행 권고는 아님**이다. 첫 후보의 실제 오류 위치가 이 경계에 집중될 때만 별도 설계 근거를 검토한다.

DDL 파서+solver는 [현재 논문](https://arxiv.org/abs/2506.08899)이 영어 규정의 원자화·자동 형식화를 다루지만 #627의 잘못된 원문 형식화 원인을 바꾼 한국어 근거가 없어 새 후보로 세지 않았다. Granite Guardian 4.1의 BYOC도 공식 자료를 확인했으나 이 과제의 정확한 오류 구절·자료 부족 구분을 보장하지 않아 추가 모델 순회 대상으로 넣지 않았다.

## 초기 동결 제안

아직 실행 동결이 완료된 것은 아니다. 다음 조건을 조율한 뒤 manifest·실제 messages·코드·모델 SHA·runtime을 고정한다.

1. **입력:** 기존22행의 source version, 필수 부모/전체 원문, raw 후보를 원본 해시로 복사한다. 오류 label/정답 이유/기대 수정문은 별도 평가 파일. 질문은 오류 힌트 없는 동일 일반 검증 요청을 사용한다. 인과적 단일 요소 비교가 아니라 새 모델+전용 과제 구성 비교임을 명시한다.
2. **대조:** #633 여섯평균과 #632 설명 결과는 동일 후보의 역사적 결과로 보존하며 새 모델의 엄격 동일설정 A/B로 쓰지 않는다. 위치·이유의 동시 대조가 필요하면 설치 Qwen27B에 동일한 공식 span+explanation 템플릿을 22회 적용하는 A, Lettuce2B22회 B를 먼저 고정한다. 엔진/가중치/정밀도 차이를 순수 학습 효과로 주장하지 않는다. 대조 재호출 필요성과 총44회 상한은 조율 대상이다.
3. **출력·검사:** raw 출력, 정확 후보 구절/유일 위치, 원문과 이유 대조, 유형, 정상의 빈 구절을 각각 저장한다. 잘린/빈/비JSON/없는 구절/반복 위치 모호함은 실패 분모 유지. 모델이 원문 근거 위치를 반환하지 않는 한 설명의 단어를 서버가 정답 근거에 붙여 자동 evidence라고 만들지 않는다.
4. **사전 의미 관문:** K02와 C04 둘 다 U 유형·실제 의무 확대 구절·정확한 가능/조건 이유를 얻고, 정상10건을 모두 보존해야 후속 확인을 검토한다. 기존 주체/조건/기간/충돌 대조의 회귀가 없어야 한다. c47은 결과를 별도로 유지하고 유일 gate로 삼지 않는다. A02의 자료부족 설명은 필수 감사이며 공식 계약의 미지원 상태를 숨기지 않는다. 정확한 오류 위치의 허용 범위와 정상 세부 보호 기준은 실행 전에 확정한다.
5. **상태:** supported / source-unsupported / explicit-conflict / insufficient-source / execution-format-failure를 보고서에서 분리한다. 공식 native 유형이 표현하지 못하는 상태는 method-contract-unsupported라는 능력 한계로 별도 기록하고 모델이 구분했다고 세지 않는다. 모든 미지원·미확정이 늘어난 결과는 성공 아님.
6. **설정:** 공식 `enable_thinking=False`, greedy/do_sample=False, 초기 출력512, 단일 사례 순차 실행을 후보로 둔다. full necessary context를 자르지 않는다. 실제 tokenizer 길이와 stop IDs/runtime 호환을 실행 전에 확인한다. 출력 한도·실행 시간 한도는 준비 검사 이후 **첫 의미 호출 전에** 고정하며 결과를 보고 늘리지 않는다.
7. **계속/중단:** 유효 비교 실패면 같은 방법의 prompt/예시/모델 순회를 중단한다. 확인된 런타임 결함만 한 번 수정할 수 있고 의미 결과와 분리한다. 제품 연결은 조율자가 실제 자동 위치·이유·정상 보존을 검토한 뒤 제품 세션에 넘긴다. 실제 저장 오류에서의 성과가 없으면 연구 비교 완료와 제품 미완료를 분리한다.

## 초기 조사 시점의 환경·다음 작업

2026-10-09 확인: Apple M4 Max (`Mac16,5`), 물리 RAM 38,654,705,664 bytes=36GiB. Ollama 서비스 PID1490은 유지, 조회 때 로드 모델0. 설치 태그는 위 G/Q 두 개뿐이다. 전용 native 연구 프로세스는 시작하지 않았다. GitHub CLI 계정은 `Hangi-n42`다.

현재 제품 venv의 패키지 metadata는 torch2.5.1, transformers4.46.3, safetensors0.7.0, tokenizers0.20.3, Kiwi0.23.1이다. 제품 venv를 업그레이드하지 않는다. 공개 모델 metadata/README/config만 새 연구 디렉터리에 저장했으며 가중치와 새 runtime은 설치하지 않았다.

다음은 조율 세션의 방법/비교 구성/장비 배정을 받은 뒤 전용 runtime·동결 입력·작은 계약 검사를 준비하고 실제 비교하는 일이다. 기다리는 동안 기존 결과의 읽기와 독립 준비만 수행한다. 현재 사용자 결정이 필요한 사항 없음. 이 보고는 초기 조사이며 연구 목표 완료·의미 개선·제품 채택 증거가 아니다.


## 방법 선택 후 준비와 호환 검사

조율자가 [#636](https://github.com/Hangi-n42/Civil-Complaints-System/issues/636)을 생성했다. LettuceDetect v2 **B22를 먼저** 실행하고, 핵심 K02/C04의 오류 유형·구절·이유가 맞으며 정상10과 기존 대조를 보존했을 때만 동일 공식 prompt의 Qwen A22 및 소규모 후속 확인으로 진행하기로 했다. 제한 연산자/정규식 후보는 실행하지 않는다. 과거 #632/#633은 역사적 비교다. 실제 한국어 모델 호출 전 의미 기준·messages·설정·코드를 동결한다.

전용 연구 venv에 torch2.14.1, transformers5.19.0, accelerate1.15.0을 설치했다. 제품 venv는 변경하지 않았다. 모델 revision은 위와 같으며 9개 파일을 내려받아 영수증의 크기·SHA를 검증했다. BF16 safetensors SHA256은 `1bf174e49071aacef98966d0224f9e99b90e2efef7bac39a3a0c0e969f1f56dd`다. 다운로드는 266.24초였다.

기존22행은 원문·부모·source version·raw 후보를 그대로 복사했다. 22개 실제 messages와 chat template, token IDs를 저장했다. 입력927–1,941토큰으로 context8192에 들어가며 잘림은 없다. Transformers와 원래 tokenizer.json의 토큰열이 모두 동일함을 확인했다. 새 runtime의 `apply_chat_template` 반환값 기본 차이는 준비 중 명시적인 `return_dict=False`로 맞췄고, Qwen tokenizer의 원래 regex는 변경하지 않았다. 이 준비 단계에서 모델 생성은 없었다.

별도 확인 후보 문서는 서울도서관 전자도서관 [이용안내](https://elib.seoul.go.kr/service-guide/info)다. 2026-10-09에 받은 21,827-byte HTML SHA256은 `b274a1987704f577159c1d629239aca92c411833b70bc06dbc77e594182dc105`다. 이전 연구의 docs/company_knowledge와 data/knowledge/evaluations 안 JSON/MD/TXT에서 URL·특징 문장을 찾지 못했다. **그 범위에서의 미발견**이며 사전학습·조회하지 않은 기록의 비노출 증거가 아니다. 설계자는 본문을 보았으며 사례·gold는 아직 작성하지 않았다. 새 기관·문서이나 도서관이라는 같은 업무 영역이다.

호환 검사 실패는 의미 평가와 별도 보존했다.

| 차수 | 관측 결과 | 해석·조치 |
|---|---|---|
| 최초, MPS BF16/SDPA | 가중치 로딩 도중 SIGSEGV/EXC_BAD_ACCESS, 생성0회 | crash report의 복수 로더 스레드가 Metal copy/cast/hash-table 경로에 있었다. 정확한 upstream 경쟁 원인은 확정 불가. 설치된 Transformers의 `HF_DEACTIVATE_ASYNC_LOAD=1`로 병렬 materialization만 껐다. |

조율자가 종료 계약 정합을 허용했다. 별개의 구체 결함이 확인되었기 때문이며 의미 결과를 보고 설정을 바꾸는 실험이 아니다. EOS는 `[248044, 248046]`으로 고정한다. 배포 generation_config의 endoftext와 토크나이저/chat의 im_end를 모두 허용하고, 패딩은 원래248044를 유지한다. 입력·기준·프롬프트·가중치·seed·정밀도·512 출력 상한은 그대로다. 생성 전 두 native EOS가 실제 목록에 포함되는지 검사한다. 실패 출력은 `probe_mps_async_failed/`, `probe_eos_mismatch/`로 각각 보존한다. 제품 QA 종료 뒤 같은 영어 예제의 정상 종료를 확인한 다음에만 개발 평가를 동결한다.


## 최종 동결 실행 결과

종료 계약을 맞춘 동일 영어 probe는39토큰/1.275초에 EOS248046으로 끝났고 엄격 JSON·유일 구절 위치 검사를 통과했다. 이전 실패의 요청과 최초39 token IDs가 정확히 같다. 새 의미 점수로 세지 않으며 이전512토큰 미완료 결과도 유지했다. 이후 한국어 첫 호출 전에 inputs/messages/criteria/settings/code/runtime와 준비 영수증의 SHA를 `freeze.json`으로 고정했다.

최종 설정은 pinned BF16 가중치, MPS/SDPA, thinking=false, greedy, seed42, context8192, 출력512, max_time300초, EOS `[248044,248046]`, pad248044다. 입력과 출력 잘림0, 중복 호출0이며22건을 각1회 순차 실행했다. 모든 가중치는 실제 MPS BF16으로 로드됐다. 공식 CUDA 최적화 대신 설치된 Transformers의 reference PyTorch convolution/gated-delta 경로를 사용했다. 최적화 패키지를 더 설치하거나 엔진·정밀도를 순회하지 않았다.
