- N1의 시행규칙 제15조 부족 표시와 읽기·검색 제안은 현재 패킷 밖의 정보 필요성으로 구분한다. 전체 고정 자료에는 제15조가 있으며 이 제한 비교에서 후속 읽기·검색은 실행하지 않았다. 제안 자체를 요구 충족이나 회복 성과로 집계하지 않는다.
- 정의 자료 전체로는 N0 지정 공급 관계 3개, N1 매입 관계 1개의 사용 가능한 연결 결과가 있다. 양쪽 Concept 실패가 Builder의 역할 설계로 없어지는 것은 아니며, 법적 유형의 완전한 정의나 전체 질문 완료로 보지 않는다.
- 권한 자료에서는 반대로 N0 Builder가 상한 종료했고 N1은 역할 유형 3개와 관계 2개를 저장했다. 두 조건에서 서로 다른 부분이 실패하므로 전체 파이프라인의 일관된 개선이나 기본 채택의 근거로 삼지 않는다.
- 권한 N1의 최종 독립 검토에서 **끝점 역할 범위 오류 1건**을 확인했다. 공통 목적어로 재사용한 기준 유형의 실제 정의는 ‘이 명제 안의 역할’이며 role_basis·source_relation_ids·role_source가 장관/LH 관계에만 연결된다. 시도지사/지방공급 관계는 그 LH 조건을 포함하지 않는데 이 유형을 목적어로 재사용했다. 설명문이나 원문 전체 인용만으로 저장된 선언 범위가 확장되지는 않는다.
- 두 권한의 원명제·조건 및 주체 끝점은 정확하고 장관 관계의 목적어 연결도 적절하지만, 시도지사 관계의 목적어는 선언 범위와 사용처가 불일치한다. 따라서 저장된 권한 관계 2개를 모두 완전한 연결 성공으로 세지 않는다. 공통 유형을 쓰려면 실제 공통 범위를 선언하거나 분기별 역할을 나누어야 한다. 이번에는 이 결과를 얻기 위한 모델 재시도나 추가 구현을 하지 않는다.

## 과거 잘못된 끝점의 실제 교정 시험과 중단

- `c_repair_v1`에서 실제 원문 판단 요청을 시작했다. 첫 패킷은 잘못된 7197의 교정에 필요한 시행규칙 제15조 선정의무 원문이다.
- 첫 요청은 1,237.212초, 입력 2,947토큰·생성 16,384토큰 후 `done_reason=length`로 실패했다. 최종 응답 앞부분에 의미 항목들이 있었지만 이후 `examined_source_refs`에서 같은 근거 ID 묶음이 반복되어 응답이 잘렸다. 입력 크기만의 문제가 아니며 완전한 판정은 저장되지 않았다. 앞부분을 임의로 떼어 성공한 의미로 승격하지 않았다.
- 잘린 응답의 독립 진단에서는 `loc2`의 선정의무와 `loc1/4`의 법 제2조 내부 미선택 구분은 타당했지만, `loc6` 권한 요약은 장관↔LH/시도지사↔지방공급의 짝을 OR로 합치고 제49조·주택사업 목적·지역 실정·제1/2항 예외·공급비율·선정순위를 빠뜨렸다. `loc5`는 잔여주택·완화·선착순 조건을 유지했으나 ‘제1항에도 불구하고’라는 예외를 빠뜨렸다. 이 내용들은 선택 원문에 있어 자료 부족이 아니다. **응답 완결 실패와 필수 조건·분기의 의미 손실은 별개**이며, 이 진단을 유효한 저장 판정이나 부분 성공으로 집계하지 않는다. 독립 검토도 중단에 동의했다.
- 별표 4를 참조한다는 원문 사실과 별표 4의 실제 내용을 확보했다는 주장은 구분한다. 원문 의미의 축약과 근거 ID 반복을 하나의 추정 원인으로 합치거나 단순 입력 용량 부족으로 단정하지 않는다.
- 이미 시작한 별도 법 제2조 패킷은 이 교정 대상의 실패한 선행 판정을 대신할 수 없다. 승인된 중단 기준에 따라 해당 진단 프로세스에만 SIGINT를 보내 219.746초에서 클라이언트 요청을 취소했다. 프로세스 종료 코드는 130이며 최종 응답·생성 토큰은 확보하지 못했다. 이 비용을 0이나 정상 완료로 처리하지 않는다.
- 종료 기록은 전체 1,458.293초, HTTP 2회(완료된 실패 1회+중간 취소 1회)다. 원본 자료/DB와 동결 코드 지문은 유지됐다. 실행 DB도 중단 당시 상태로 보존하고 `execution/cancellation.json`에 중단 이유·비용·DB 지문을 별도로 기록했다. DB의 중간 running 상태는 살아 있는 프로세스나 성공 결과를 뜻하지 않는다.
- 7197 후보는 사전 입력과 전 필드가 동일하고 신규 수정 history는 0개다. **실제 끝점 교정 0회, 누락 의미 생성 0회, 같은 질문 완료 미달, A3 확인 미달**이다. 허용 근거가 없는 후속 교정·전체 검수로 진행하지 않았으며 추가 설정 시험이나 N 재실행은 하지 않았다.

## 최종 상태와 다음 작업

- 구현: 표현 판정 단순화·필수 의미키 검사, 관계 우선 처리와 직접 연결 문맥 공급, 정상/미완료 결과 보존, 실행기 입력 계약 및 표시 중복 보완.
- 확인: 집중 테스트 250개와 모델 없는 Builder 실제 호출 경계 6개 통과. 실제 A의 정상 판정 유지와 외부 상세 보류, N의 일부 역할·관계 생성 및 조건 보존 확인. 각각의 실패와 의미 오류도 위에 기록했다.
- 미달: E의 필수 한정 복구, 안정적인 조건 간 역할 재사용, 실제 잘못된 끝점 교정·누락 생성·같은 CQ·A3 완료. 코드 통과와 이 완료 기준을 구분한다.
- 이웃 문맥은 기본 비활성으로 유지한다. #610–#614는 열린 상태, PR #609는 초안으로 유지하고 병합하지 않는다. 사람 효용·일반화 성능·전체 A6·Windows 실기는 미검증이다.
- 다음 검토 대상은 검사한 근거 목록의 반복 출력을 막는 응답 계약과, 실제 선언 범위를 넘는 역할 재사용의 검수다. 이후 고정된 잘못된 후보의 실제 교정부터 다시 확인해야 하며 동일 조건의 실패를 무작정 반복하지 않는다.
- 다음 응답 계약의 최소 후보는 `examined_source_refs`의 길이를 해당 호출에 제공된 고유 source_ref 수(실패 호출은 6개)로 제한하는 것이다. 현재 스키마는 enum만 제한하고 길이 상한이 없으며 저장 검사는 집합으로 범위를 확인하여 반복 자체가 새 정보를 주지 않는다. 이번에는 이 변경을 적용하지 않았다. 조사 목록을 서버가 자동으로 채우거나 의미별 인용의 합으로 대신해 ‘제공됨·조사했다는 선언·의미 정확성’을 같게 취급하지 않는다. 이 제한만으로 필수 한정 누락이나 다른 필드의 반복이 해결된다고 보지 않는다.
- 현재 사용자 결정이 필요한 사항 없음.
