## 진행 이유와 M1 변경

L4에서 선택한 주택 정의가 실제 입력에 있었는데도 모델이 입주자와 주택 유형을 잘못 대응했다. 입력량 초과나 출력 잘림은 관측되지 않았다. 원명제, 연결 ID·Builder 이유, 비교 유형 정의가 떨어져 제시되는 구조는 확인했으나 이 배치가 오판의 원인인지는 가설이었다.

- 기존 make_prompt의 관계 집중 Critic 입력에만 선택 유형 옆 binding_uses를 붙였다. relation_ref·subject/object 구분·source_relation의 해당 표현을 담는다. 유형 ID·레이블·정의·조건·예외·시점은 기존 유형 본문에 한 번만 유지한다.
- 실제 context에 이미 제공된 유형만 사용한다. supplied에 있지만 입력에서 빠진 유형을 끌어오거나 E-A에 정상 입주자 유형을 넣지 않았다. 공유 유형은 본문 하나와 여러 사용처로 나타낸다.
- 해당 관계 Critic의 relation_bindings에서 Builder reason만 제외했다. 원래 ID 연결, 저장 설계 이유, Builder·Revision 입력, 관측 Critic의 설계 출처는 유지한다.
- source_expression은 원명제 후보의 표현이며 검증된 원문 인용이 아님을 명시했다. 제공 원문에 대한 semantic_checks를 계속 요구하고, 선택 유형의 정의 전체와 실제 끝점이 지칭하는 대상을 대조하도록 관계 지시만 보완했다.
- 저장 후보·현재 지문·정규화·출력 schema·수정 경로 변경 없음. 새 상태·의미 정규식·프레임워크·모델 단계 추가 없음. fits, 실제 호출, 수정 후 검수는 기존 공통 make_prompt를 사용한다. prompt v49.
- 구현 커밋 `a22e2fcd56537a3492c91b42ab55b2aa1a315c39`, 3파일 47줄 추가·3줄 삭제. Ponytail 원칙에 따라 기존 투영과 표준 라이브러리를 재사용했다.
- 관련 검사 4개 통과(0.89초): 공유 유형 본문 중복 없음, 끝점 사용처 정확성, 입력/후보 불변, 생략 유형 비수입, raw 관계에 가짜 연결 없음, 관측/Builder/Revision 입력 보존, 수정 후 최신 정의 투영, 실제 focused schema/call 경로. 실행 전문가의 좁은 검토에서 차단 결함 없음. 단위 검사를 모델 의미 정확도 증거로 사용하지 않는다.

## 확인된 병목과 다음 최소 작업

- 확인된 사실은 두 모델이 정의를 제공받고도 유형 포함 관계와 업무상 연관성을 잘못 대응한 것이다. M1의 결합 변경(인접 배치와 Builder 이유 제외)만으로 이 사례를 해결하지 못했다. 배치의 단일 인과효과, 모델 내부 원인, 일반적 모델 우월성을 확정하지 않는다. 이미 노출된 세 사례의 제한 비교다.
- 전문가 권고는 공통 프롬프트나 형식 guard를 더 붙이기보다, 연결만 묻는 작은 진단을 먼저 수행하는 것이다. 현재 명제와 연결은 필드·정규화·수정 경로에서 분리되지만 같은 호출에서 생성되므로 판단이 섞인다는 가설이 남아 있다. 이번 작업에서는 이 추가 진단을 실행하지 않았다.
- 제품에 별도 focus를 바로 추가하면 안 된다. semantic_checks가 필수이고 valid_ids/review_coverage/latest_by_candidate는 후보 단위여서 부분 판정 둘이 서로 덮거나 전체 검수로 오인될 수 있다. 제한 진단에서 효과를 확인한 뒤에만 같은 현재 지문 아래 필수 판정 결합·부분 실패·재개 경계를 맞춰 통합하는 순서다.
- 추론 설정을 비교한다면 model_call의 think=False 고정도 함께 확인해야 한다. recipe 값만 바꾸고 실제 추론 옵션을 비교했다고 주장할 수 없다. 이번에는 추론 설정을 변경하지 않았다.
- 사람 검수를 유지한다. 실제 사람 참가자 0명, 사람 총 작업시간 null, 동등 품질에서 사람 시간·오류 감소 및 현업 효용 미측정. 전체 온톨로지·지식 그래프 품질은 아직 입증되지 않았다.
- 이슈 댓글·종료는 계획 및 구상 세션이 담당한다. M1 구현 완료와 M2 제한 평가 수행을 M3 성공으로 확장하지 않는다. 상위 #534/#539 및 M3 #579는 미완료로 유지한다. PR·main 병합·배포·자동화 없음.
- 현재 사용자 결정이 필요한 사항 없음.
