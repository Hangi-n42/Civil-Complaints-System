# 후보 검수 부분 응답 보존과 정확 구간 대조의 기각 결과

시작 HEAD는 `41087e5f859056cf87c8d28bc27add0f6a759230`이다. **정확 인용·필드 선택은 일부 정형 문제를 해결했지만, 완결 응답에서도 c47의 지역 한정 반납을 일반 반납으로 연결해 대안은 기각했다.** 첫 실행의 대상 누락과 보완 실행의 의미 실패를 구분한다. 아래 계획은 실행 전에 저장·공유했고 `pre_call_plan.md`와 해시로 보존했다. 이전 Qwen false/true 및 Gemma true는 다시 호출하지 않았다.

이와 독립적으로 확인된 **부분 응답 때문에 유효 정상 후보까지 버리던 제품 경계는 수정했다.** 관련 80개 코드 검사와 저장 정상 응답의 오프라인 변형 재생으로 후보별 보존·재검수 대상을 확인했다. 이 코드 성과는 모델의 범위 오류 검출이나 실제 교정 성공과 다르다.

## 최소 대체 과제

원문의 의미를 `target/action/condition` 의역으로 새로 쓰던 과제를 **정확한 인용 구간을 선택해 연결하는 과제**로 바꾼다. 같은 10개 원문 블록·부모 관계, c13/c46/c47 원시 후보·버전, 원래 R05와 저장 평가 기록을 유지한다. 제공 원문을 사람이 의미별로 나누거나 제한어의 정답 연결을 선택지로 주지 않는다.

모델은 각 후보마다 원문 측 연결과 후보 측 연결을 반환한다. 한 연결은 `targets`, `actions`, `qualifiers`의 정확 인용 선택 목록과 `form`(구비 항목/의무/기술/미확정)만 담는다. 이 연결 안의 제한어는 그 연결의 행위·대상에 적용된다는 모델의 주장이다. 서로 다른 적용 범위는 다른 연결로 표현한다. 의역 문장을 원문 의미로 대신 쓰지 않는다. 명사 나열에 없는 행위 문구를 생성하지 않는다.

원문 목록에 ‘포함한다/구비한다’ 동사가 없어도 actions를 비우고 실제 제목·목록 부모·항목 구간과 listed_item 관계로 대조할 수 있다. 문자 그대로 같은 동사가 있다는 것을 의미 동등성의 필요조건으로 삼지 않는다. 선택별 주소 오류는 기록하되 다른 선택과 후보의 raw 의미 결과를 삭제하지 않는다.

각 선택은 제공된 주소 ID와 해당 텍스트에 실제 존재하는 연속 부분 문자열이다. 원문 주소는 기존 10개 evidence_ref만 선택한다. 후보에는 실제 `raw`의 문자열 필드/배열 요소를 순서대로 순회해 `f1...` 식별자와 실제 필드 경로를 붙인다. 원시 후보는 그대로 유지하고, 추가되는 식별자 목록은 위치 정보뿐이다. 모델은 필드명을 생성하지 않고 식별자를 선택한다. 서버는 후보 소유권·실제 필드 값과 정확 인용을 검사해 `raw.Event` 등으로 복원한다.

문자 위치는 모델에게 쓰게 하지 않는다. 원문은 기존 `exact_evidence`를 재사용한다. 복원 전 선택 주소 안의 정확 문자열 등장 횟수를 검사해, 0개 또는 2개 이상이면 미확정으로 기록하고 임의 위치를 택하지 않는다. 중복 구간은 모델이 주변 텍스트까지 포함해 유일한 구간을 선택할 수 있다. 표준 문자열 위치 검사와 기존 주소 복원을 사용하며 새로운 주소 시스템을 만들지 않는다.

각 후보의 `difference`는 none/unsupported_scope/contradiction/unresolved를 유지한다. 차이가 있는 실제 후보 필드는 `difference_fields`에서 제공된 필드 ID만 선택한다. 정상 후보에는 이를 비운다. reason은 선택된 양측 연결의 차이·동등성에 대한 설명이지 원문 의미를 대체하는 새 사실 목록이 아니다. 미선택·빈 목록은 조건 없음이나 반증을 뜻하지 않는다. 서버는 문자열 차이·인용 성공만으로 의미 판정이나 오류 승격을 하지 않는다.

## 모델·변경 요소·비교 한계

변경은 과제·출력 계약과 기계적 후보 필드 식별자 목록이다. 원문/후보 내용·모델·추론 설정은 바꾸지 않는다. 따라서 과제 전체의 적합성 비교이며, 인용 선택/필드 선택/연결 표현 중 하나만의 효과로 귀속하지 않는다. 정확 주소 선택은 정형 개선이며 의미 검출 성공과 별도로 평가한다. 기존 직접 검수의 대체 후보로 한 번 호출하며 직렬 검수층을 추가하지 않는다.

## 실제 개선과 미완료의 경계

- **정형 부분 변화:** 임의 길이 목록에서 빠졌던 후보를 ID별 필수 슬롯으로 요구했고, 실제 재확인에서 세 후보가 반환됐다. 각 후보 필드 식별자는 실제 raw.Head/raw.Tail/raw.Event로 복원됐다. 이전 Gemma의 `Tail`/`Event` 경로 생성 실패를 이 출력에서는 피했다. 다른 입력의 일반 안정성까지 검증한 것은 아니다.
