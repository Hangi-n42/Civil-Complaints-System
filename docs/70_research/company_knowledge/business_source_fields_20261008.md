> 평가 정정: 이 문서의 최초 판정은 이력으로 보존한다. R05 기관 범위·불확실성에 대한 현재 해석과 새 사용자 기준에서 인정한 저장 답변의 성과는 [정정 부록 v1](business_r05_evaluation_correction_20261009.md)을 따른다. 원시 응답·기준·점수는 변경하지 않았다.

## 결론과 채택 범위

원문 전체의 지지 판정을 개별 조건·기간의 지지 판정으로 복사하던 경계를 수정했다. 기존 실제 모델 c47 편집, c116/c117 대체 결과와 기존 후보 119개를 유지한 채 원문 해석 정정 → 같은 R05 재검토 → 승인 snapshot → full 검색 → 실제 답변까지 실행했다. c47 지역 번호 조건, c13 양수인 미방문 조건, 정상 당일·2~3일은 최종 출력에 유지됐으며 미확정 추가 기간인 `상시`는 출력되지 않았다.

**전체 답변은 미완료다.** 새 요청 구절 분할 실험은 번호판 변경 유무를 나누지 않고 질문 전체를 `directly_stated`로 표시했다. 번호판 교부와 소요시간만으로 번호 변경 처리 권한을 직접 입증하지 못하며, 이 연결 공백을 출력하지 않았다. 따라서 `requested_parts` 스키마·직접 지지 표시와 실제 응답에서 사용하지 않은 `explicit_exclusion` 라벨은 기각했다. 동결 코드와 실제 실패 응답을 보존했고 추가 모델 재시도는 하지 않았다.

최종 채택 코드는 기존 `reviewed_items`의 원문 그대로 표시하는 경로에 개별 필드 상태·미확정 차단을 연결한다. 기존 `premise_keys=None`의 연결 미확정 limitations도 유지한다. 저장된 실제 선택을 최종 표시 함수로 재생하여 과장된 직접 지지 표시가 제거되고 조건·기간·인용이 유지됨을 확인했다. 이 재생은 **새 실제 모델 QA나 변경 유무별 답변 완성의 증거가 아니다.**

## 실제 원인과 수정

### 필드 지지와 원문 정정

`source_judgment`가 전체 `source_status`를 모든 비어 있지 않은 부가 필드에 복사했다. 기존 의미에는 원문 171개 block에 없는 `상시`가 7개 period로 저장돼 있었다. c13 후보 자체는 미방문 조건을 보유했으나, 별도 `transfer_certificate` 원문 의미는 이를 공통 서류로 일반화했다.

새 `field_judgments`는 statement·conditions·exceptions·period·references의 상태와 이유, 미확정 필드가 본문에도 영향을 주는지를 기록한다. 부가 주장이 없는 빈 값은 `not_applicable`, 이전 주장의 지지를 확인하지 못한 빈 값은 `unknown`으로 구분한다. 본문에 영향을 주는 미확정 조건은 승인·활용에서 제한한다. 독립성이 명시적으로 판정된 부가값만 본문을 차단하지 않는다.

기존 자료에 개별 필드 판정이 없으면 `not_assessed`로 기록한다. 정상 legacy 조건·기간은 전체 의미 묶음 안에 유지하며 개별 지지로 승격하거나 조용히 제거하지 않는다. 특정 단어 금지나 문자열 포함 여부로 의미 지지를 판정하는 규칙은 추가하지 않았다. `supported`인 기간값을 `상시`·날짜 등 단어만으로 차단하지 않는 합성 경계 검사도 포함한다. 이번 실제 정상 원문 대조는 당일·2~3일이며, 실제 원문에서 `상시`의 지지가 확인된 것은 아니다.

자동 재판정은 정정문 없이 8개 대상에 한 번 실행했다. 미방문 부모 block이 실제 입력에 있었지만 c13을 공통 서류로 유지했고, 7개 `상시`도 업무표 해석을 이유로 지지했다. **8개 목표 정정 모두 실패했다.** 이 실패를 반복하지 않고 승인된 명시 정정 경로로 분리했다.

명시 정정은 저장된 실제 모델 m4의 조건 보존 문장을 운영자가 선택하여 c13 원문 의미에 적용했다. 나머지 7개 의미는 지지되지 않은 기간 주장을 빈 값·unknown으로 정정하고, “센터 방문”이 전체 업무의 필수 조건이라는 미확정 추가 해석도 독립 상태로 기록했다. 기관 주체·직접 업무·명시 제외는 본문에 유지했다. 이는 운영 기간의 현실적 부재나 거짓 판정이 아니다. 명지 당일과 금련산 2~3일은 원문 본문에 남겼다.

업무 지식 단위검사 13개 파일에서 230개 통과(183.36초). 마지막 연결 미확정 경고 복원 후 표시·필드 경계 2개 파일의 25개도 통과했다(0.29초). `git diff --check` 통과. 합성 경계 검사는 API 계약·상태 전파·정상 의미 보존을 검증하며 실제 모델 의미 품질 점수가 아니다. 첫 확대 검사는 228개 통과·3개 실패였다. 실패는 새 선택 출력의 기본 field_judgments fixture 1개와 새 서비스 테스트의 mock status 누락 2개였으며 수정 후 위 전체 검사가 통과했다. 두 검사 집합은 겹치므로 합산하지 않는다.
