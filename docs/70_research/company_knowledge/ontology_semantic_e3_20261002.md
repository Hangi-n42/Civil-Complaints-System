# E3 원문 끝점과 검수 범위 — 2026-10-02

- 범위: [#542](https://github.com/Hangi-n42/Civil-Complaints-System/issues/542), 기준 `d691c75`, 동일 feature 브랜치·Ponytail full. 실제 모델 호출0, 사람0/시간null, E6 동결 조건 불변.
- 이유: 유형 ID만으로는 실제 행위 목적어와 적용 범위를 구별할 수 없고, 지역 후보 공백이 전체 자료 부재로 확대될 수 있었다. 기존 endpoint_labels·판정·원인별 보류를 확장했다.
- 새 생성은 원문 `endpoint_labels.subject/object`를 연결 ID와 별도 제출한다. 임시 후보 ID와 같은 문자열도 원문 표현에서는 치환하지 않는다. legacy 이름 출력은 보존하고 ID만 있던 과거 출력의 원문 표현은 새로 추정하지 않는다. 조건·의무/허용·OR·상위 전제·예외 우선·시점은 기존 predicate/conditions/time을 사용하며 새 규칙언어는 없다.
- Critic은 끝점·조건·진술 종류의 `semantic_checks`를 명시한다. 세부 판정 누락/모순은 pending이며 원문의 지지와 유형 연결 완료를 분리한다. 원문은 supported여도 미연결/오연결/타입 정의 미제공은 endpoint 수동검수·A3 보류다. 연속 문자열 포함을 의미 판정 조건으로 삼지 않는다. 자연어 의미가 맞는지는 이 구조만으로 증명되지 않는다.
- `review_scope`에 제공 source_refs·지역 범위·미제공 후보를 기록하고 재개에서 고정한다. 전체 부재는 확정하지 않는다. missing_meanings는 실제 비교 후보 ID/사유를 남기며 주검토의 관련 관측/관계 종류를 전혀 대조하지 않았다면 재추출을 보류한다. 동일 블록 ID 전부의 나열이나 고정17개 상한은 없고 생성 schema는 실제 제공 수에 맞춘다. 종류별 대조 기록도 의미 충족의 증명은 아니다.
- 원문 지지와 연결을 다시 결합하던 초기 경계, endpoint_labels의 연속 문자열 검사, 동일 블록 후보 전체 나열 요구는 계획 세션/의미 전문가의 지적에 따라 제거했다. 원문 supported/연결 오류, 떨어진 표현의 조합, 원칙·예외 관계를 대조하지 않은 concept 누락, 실제 별표 본문 미제공과 지역 범위 보류를 작은 회귀로 확인했다. span 선별은 E4 범위로 유지했다.
