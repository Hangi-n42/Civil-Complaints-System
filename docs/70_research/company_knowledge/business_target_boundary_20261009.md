## 명시 범위 설정과 이력 보존

HTML 파서에 출처별 `scope.document_controls` 선언을 추가했다. selector와 확인 사유를 저장하며, 선택 본문의 실제 하위 DOM만 허용한다. 모든 원문 텍스트·순서·위치와 원본은 보존하고 해당 영역의 locator에 선언을 덧붙인다. 링크·버튼·onclick·함수명·CSS class로 업무 여부를 자동 분류하지 않는다. 원문의 법령 링크, 서류 링크, 신청 동작, 표, 기한과 기관을 일반적으로 제외하는 규칙도 없다. 잘못된 영역을 명시하면 업무 내용을 제외할 수 있으므로 선언 자체의 타당성은 원문 검토가 필요하다.

이번 출처는 등록 SHA256 `2c20a45589ff718553057274fc446a9bb14517e3e5a5188299b9a8a082f3dde2`와 일치하는 HTML의 `#contents > div:nth-of-type(1) > ul:nth-of-type(1)` 전체를 대조했다. 공유·북마크·SNS·인쇄 일곱 블록이라는 AI 진단을 설정에 기록했다. 이는 인간 승인이나 자동 UI 발견이 아니다. 새 parse `832adb3bcefc44e6a8541b1d43cd5354`는 기존 98개 블록의 텍스트와 기존 locator 필드를 보존했다. 기존 기능의 heading_level 메타데이터와 도구 영역 선언만 추가됐다.

## 적용성 판단 전 격리

원문 응답의 키 중복, 정확한 원문 주소·인용, 대상 블록의 실제 근거 존재를 적용성 판단 전에 검증한다. 문맥 근거는 대상 근거와 함께 조건 설명에 사용할 수 있지만 문맥 근거만으로 새 대상 의미를 만들 수는 없다. 거부된 의미를 명시적으로 전제하는 의미도 격리한다. 단순 conjunction 연결은 정상 형제 의미를 함께 버리지 않고 연결의 미확정 기록만 별도로 보존한다.

원래 응답·오류·조사 영수증은 수정하지 않는다. 격리 기록을 새 필수 의미나 자동 repair 대상으로 넘기지 않으며, 정상 의미와 관련된 미확정 finding의 영향은 기존 결합 판단과 정확한 근거 검사로 결정한다. 모든 의미가 격리되면 적용성 호출을 생략한다. 격리 기록이 있다는 이유만으로 전체 요구를 무조건 실패시키지도, 목록이 비었다고 충족시키지도 않는다.

실제 저장된 17개 새 의미 중 m4/m5/m6/m17 네 개가 문맥 전용 근거로 격리됐다. 기존 정상 다섯 의미와 원문 영수증 일곱 개, 기존 finding 열두 개는 유지했다. 활성 의미는 기존 다섯 개와 새 정상 위치 의미 열세 개를 합한 18개다. 위치 검증을 통과한 m7은 지역 번호판의 반납 조건을 일반 번호판 변경에도 붙인 기존 의미 오류를 그대로 포함한다. **정확한 인용 주소는 의미 정확성의 증거가 아니다.**

같은 범위 구분을 완료 상태에도 적용할 필요가 확인됐다. 중간 저장 결과는 필수 세 의미의 지지·가용성·표현·자기 원문 검수·독립 전제가 유효하고 source gaps/meaning gaps/전체 이의/처리 오류가 모두 비어 있었다. partial의 남은 원인은 배경 두 finding의 unresolved 존재를 무조건 전체 source 불완전으로 처리하는 조건과, 모든 meaning_challenges가 비어야 한다는 조건 두 곳이었다.

## 검증·비용·남은 범위

버스 대조는 기존 승인 한 행에 대한 정적 비교다. 기준 코드와 변경 코드의 선정 묶음·행 조회·순위·그래프·구간 결과가 완전히 같았다. 새 bus 모델 호출이나 전체 버스 평가는 실행하지 않았다.

코드 검증은 첫 전체 관련 검사 320개 통과·1개 원본 부재 skip(269.06초), 오류 전파 수정 뒤 경계 141개 통과(79.03초), 완료 범위 수정 뒤 최종 관련 경계 184개 통과(135.30초)다. 마지막 수정 뒤 320개 전체를 다시 실행했다고 하지 않는다. 최종 검사에는 독립 배경 이의 보존, 필수 직접/간접 전제, 의존 미확정, 없는 키·무범위 finding 차단, 빈 격리 결과의 허위 충족 금지를 포함한다. 이 검사는 모델 의미 정확도 평가가 아니다.

모델 실행 동결 `code`, DOM identity 수정 및 초기 검사 보강 `code_final`, 감사/배경 오류 전파 경계 `code_postprocess`, 완료 범위까지 반영한 최종 `code_completion`을 별도로 보존했다. DOM 검사는 BeautifulSoup의 내용 동등성 대신 객체 identity로 포함관계를 확인한다. 같은 내용의 형제 노드에서 선택한 영역만 표시하고, 본문 밖 동일 내용은 거부하는 회귀 검사가 통과했다. 실제 원문 98개 text/locator와 도구 표시 7개는 동결 실행 결과와 완전히 같아 모델을 재실행하지 않았다. 최종 작업 파일과 마지막 동결본, 모든 이전 동결본의 해시를 확인했다.
