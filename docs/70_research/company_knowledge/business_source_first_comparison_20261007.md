## 고정한 비교와 실제 코드 변경

대상은 기존 `transfer_certificate`, `plate_change_documents` 두 의미다. 원래 R05 question·criterion·revision 1, 원문 8개 구간, 파서 조상 연결, 대상 키·원문 주소, 일반적인 재판정 사유, 간단한 v6 출력 계약을 고정했다. 원문 조건·부모를 빼거나 예상 정정 문장·후보·평가 정답을 추가하지 않았다.

- **A:** 현재 제품 `reassess_source`처럼 기존 의미의 설명·조건·판정 내용을 제공했다.
- **B:** 동일 제품 함수에서 사실 재판정의 `previous.meanings`를 `key/evidence`만 남기도록 구현했다. 기존 참조 복원이 `previous_evidence_refs`를 생성하므로 같은 대상 원문을 읽는다. 연결만 재판정하는 `link_only`는 기존 사실을 유지해야 하므로 변경하지 않았다.
- **Gemma B:** B의 전체 messages/schema/reference_map·숫자 설정을 유지하고 이번 source 재판정 호출의 review 모델만 설치된 Gemma로 바꿨다. 전체 제품 모델 역할을 바꾸지 않았다.

A와 B에서 다른 것은 두 의미의 `statement`, `conditions`, `exceptions`, `period`, `references`, `reason`, `source_status`, `availability`, `required_for_requirement` 9개 필드 제거뿐이다. system 지시, schema, 원문, 공개 요구, 조상 연결, 대상 주소, challenges, recipe, 모델 identity가 같음을 실행 전에 검사했다. 이전 의미의 결합·공백 주석은 두 조건 모두 빈 배열이었다. 이 변경은 평가 runner만의 다른 추론이 아니라 제품 `reassess_source` 경계에 구현했다.

직전 간단 계약 호출은 대상이 하나였고, 두 대상 호출은 v12 추가 scope를 썼다. 입력·출력 계약이 다른 결과를 이번 A로 재사용하지 않고 새 A 한 번을 실행했다. 같은 Qwen B 지시문을 다듬어 재시도하지 않았다. 이후 허용된 모델 비교는 이미 실행한 Qwen B를 대조군으로 사용하고 Gemma만 한 번 호출했다.

번호판 원문은 구비 항목을 제시하고 괄호 안에서 지역 번호의 반납 후 변경을 한정한다. 일반 변경 전체의 반납 의무는 이 문구만으로 입증되지 않는다. 출력의 ‘반납 후 번호 변경이 가능’은 원문의 순서 표현과 구분해 기록하되, 모델이 반납을 충분조건으로 명시했다거나 법적 허용을 확정했다고 단정하지 않는다. 이번 명확한 오류는 일반 변경 전체로의 반납 의무 확대와 요구의 사용 시점 문맥이 원문 기간 필드로 유입된 것이다. 외부 행정·법률상 진위를 확정한 결과는 아니다.

Gemma의 미방문 조건 복원은 실제 개선이다. 그러나 원문에 없는 기간 값을 유지했고 부모 원문까지 인용으로 선택한 결과도 아니다. 이를 전체 source 역할 교체나 정상 의미 완성으로 확대하지 않았다. 오류 기간을 사람이 삭제해 정상 의미처럼 후속 R에 넘기지도 않았다.

입력의 `requirement.period='방문 전 기관 및 서류 확인'`은 사용 시점 문맥이며 원문의 기한이 아니다. Qwen B는 이 값을 그대로, Gemma는 `방문 전`으로 줄여 `source.meanings[].period`에 기록했다. 원문과 공개 요구가 입력에서 구분돼 있어도 출력 사실 필드로 요구 문맥이 유입된 실제 책임 혼동이다. 특정 필드명·프롬프트·모델 하나가 유일 원인이라는 결론은 아니다.

## 확인한 범위와 확인하지 못한 원인

이 통제 비교에서는 **기존 설명 제거만으로 두 오류가 해결되지 않았다.** 기존 설명의 영향이 전혀 없다는 결론이나 특정 모델만이 유일 원인이라는 결론은 아니다. 각 조건은 한 번씩 실행한 고정 사례 비교이며 반복 표본·일반 성능 평가가 아니다. 입력 역할, 원문 구조 해석, 단순 출력 계약과 모델의 상호작용 중 개별 원인의 기여도는 아직 확인하지 못했다.

이전 금련산센터 E 두 입력(`4898a797...`, `c47cbb8d...`)에는 `unverified_interpretations=[]`이고 `previous`도 없었다. 따라서 그 주변 업무의 필수화 오류에는 이번 기존 설명 제거가 입력 차이를 만들지 않는다. 금련산 문제를 이번 가설의 성과나 새로 해결한 문제에 합산하지 않았으며 같은 호출을 반복하지 않았다.

## 종료 상태와 다음 우선순위

#616의 가설 범위를 좁혔지만 기본 E의 조건·필수 범위 판단은 미완료다. #617의 c47 저장 교정은 0건이며, #620의 교정 snapshot→검색→원래 R05 QA는 진행하지 않았다. 원문부터 실패한 결과를 후속 R로 밀어 넣거나 보류·승인 기준 완화로 성공을 만들지 않았다. 세 이슈는 전체 완료 기준을 충족하지 않는다.
