## 결론과 범위

U1–U4의 코드 연결과 제한된 실제 호출을 확인했다. **자동 근거 해석 교정 성공 또는 자동 교정의 종단 성공은 입증하지 못했다.** 명시 정정본을 저장·승인한 후 그래프와 QA 입력에 전달하는 경로와, 모델이 선택한 검토 문장을 서버가 그대로 표시하는 경로는 작동했다. 최초 실제 QA는 정정된 번호판 구비사항을 입력으로 받고도 누락했고, 이전 적용성 라벨만 제외한 동일 문맥 선택 비교에서는 해당 문장이 선택·표시됐다. 이는 수동 기준 정정본을 사용한 선택 단계 1회의 개선이다.

- **문장 편집:** 오류가 `raw.Event`에 한정되면 모델은 의미 문장과 제공된 실제 Entity 출현 위치만 선택한다. 서버가 기존 Entity/ID/원문 주소를 보존한다. 문장 분리는 줄바꿈으로 유지하며 직접 근거와 상위 문맥은 분리 저장한다. 새 구조화 Scope를 검증한 것으로 간주하지 않는다.
- **명시 승인:** 원문 해석과 후보를 같은 문장으로 함께 정정한 현재 버전만 기존 승인 단계에서 별도 확인할 수 있다. 편집만으로 승인되지 않는다. 모델의 미확정/부분 판정과 명시 확인의 출처를 스냅샷에 함께 남긴다.
- **검토 의미 답변:** 선택한 후보 묶음·원문 근거·알려진 전제가 갖춰진 의미 ID를 모델이 공개 질문/충족 기준 항목별로 선택한다. 서버가 의미·조건·예외·기간·참조를 그대로 표시하며 자유 결론 필드는 없다. 결론 연결이 부족한 전제와 구체 공백을 별도로 표시한다. 원문 해석 자체의 오류와 선택 누락까지 자동 해결하는 계약은 아니다.
