적용성 결과는 의미별로 검증한다. 누락·중복·잘못된 질문 인용은 해당 연결을 미확정으로 남기고 정상 형제의 적용성을 덮어쓰지 않는다. 이는 source record 오류로 바꾸지 않는다. 연결만 재판정할 때는 사실 필드뿐 아니라 기존 공백·결합 주석·조사 결과도 유지한다. 수정은 저장 후 `applied_awaiting_recheck`이며 전체 요구 충족이나 승인으로 자동 승격하지 않는다.

## 동결 실행과 최종 코드의 차이

증거 루트는 `data/knowledge/evaluations/business_responsibilities_20261007/`다.

- `frozen_direct_v1`은 실제 직접 검수 1회 시점의 코드다. `direct_candidates_v1/normalized/`에 원 응답, 정규화 결과와 변환 수정본을 보존했다.
- `frozen_application_v1`은 사실·적용성 2회 시점의 코드다. 당시 실제 응답은 `fact_application_v1/result.json`에 있다.
- 그 뒤 최종 코드에서 적용성 오류의 의미별 보존, 연결 전용 재판정의 주석 보존, 정확 요청 재사용·무효화, 직접 오류의 기존 수정 경로 연결, R의 중복 후보 정확성 판정 제거를 완성했다. 직접 검수 문맥에 계약과 구체 재검수 이의도 명시했다.
- 이러한 후속 연결은 코드 검사로 검증했으며 **최종 코드로 새 실제 모델 실행을 반복하지 않았다.** 동결 코드에서 최종 코드까지의 두 patch와 `final_code_manifest.json`을 보존했다. 동결 실행의 성능을 최종 연결 전체의 실제 성능으로 표시하지 않는다.

`call_ledger.json`은 실제 호출 3회와 캐시 정규화 1회를 구분한다. `final_audit.json`은 두 진단에서 후보·원문·공개 요구·기존 assessments·repairs·graph·concepts가 부모 실행과 동일함을 확인한다. 사실 재판정 대상 밖의 15개 형제 의미도 동일하다. 원래 c116→c89 교정은 유지했으며 새 교정으로 계산하지 않았다. 원문 DB와 이전 평가 결과는 덮어쓰지 않았다.
