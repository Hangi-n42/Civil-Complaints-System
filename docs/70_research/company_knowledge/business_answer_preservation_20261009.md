### 한 번의 QA 과제 변형

별도 모드·judge·역할 스키마를 추가하지 않는다. 기존 reviewed_items의 QA 한 번에서 “선택된 사실을 읽어도 공개 항목에 답하려면 어떤 주체·행위·조건 연결이 더 필요한가”를 먼저 묻는 지시문을 비교한다. 필수 보존 대상 참조를 함께 알리되 원문·질문·기준·검토 내용은 바꾸지 않는다. 기존 selected/use와 unconfirmed 스키마는 같다.

선택된 사실을 질문 결론의 자동 완료로 승격하지 않으며, 직접 명시된 조건 사실에 불필요한 보류를 더하면 실패다. 이 입력 변경은 같은 모델의 과제 변형이지 검증된 새 의미 판단 기술이 아니다. 기관명·기간·조건 문구·정답 결론을 코드에 넣지 않았다. 일반 업무나 교부기간에서 특정 조건의 권한을 확정하는 추가 추론은 실제 원문으로 평가한다. 실제 창구에서 업무가 불가능하다는 반증과는 다르다.

서버 보존 patch와 과제 변형 patch·파일 해시는 별도로 고정했다. QA 효과가 없으면 실험 지시문과 추가 입력만 제거하고 보존 경계의 독립 효과만 판단한다. 사실 목록을 늘린 것과 유용한 조건별 답변을 분리한다.

이 문장은 명지·금련산의 일반 업무/교부 정보에서 질문의 특정 조건 권한까지 연결하는 데 무엇이 더 필요한지 특정하지 않았다. 대신 이미 번호 변경 제외가 기록된 세 기관 쪽으로 불확실성을 옮겼다. 비변경 항목은 기관 다섯 개의 사실과 빈 unconfirmed로 남았다. 새로운 직접 권한 문장을 자유롭게 생성한 결과와는 구별하지만, 구체 공백 문장이 하나 생겼다는 이유만으로 조건별 답변을 올바르게 완성했다고 판정하지 않는다. 이 평가는 현실 창구의 업무 가능성을 반증한 것이 아니다.

**새 과제 지시문과 추가 모델 입력은 비채택했다.** 동결 코드·실제 입력·실패 결과를 보존하고 이 부분만 제품에서 제거했다. 기존 지시문·스키마·모델 입력을 사용하는 **필수 의미와 연결 전제의 누락 보존 경계만 제한 채택**한다. 필수 키 기록도 reviewed_items에만 추가하여 기본 synthesis와 원문 QA는 바꾸지 않는다.

제한 채택의 근거는 별도 진단용 누락·실패 응답과 전제 누락에 대한 결정적 코드 동작 및 정상 저장 응답의 보존이다. 이번 실제 R05 모델 누락을 해결했다는 근거는 없다. 해당 실행은 fallback을 사용하지 않았고, 문장 보존과 입력 전달은 이미 기존 경로에서도 가능했다. 기존 표시 함수의 내용과 조건 처리 원칙을 공통으로 재사용했으며, 새 판정기·모드·DB·일반 논리 엔진은 추가하지 않았다.

Qwen을 해제하고 `/api/ps`의 `models=[]`를 확인해 자원을 반환했다. 후속 모델 호출은 0회다. 실제 수정된 저장 후보 0개, 자동 발견 0개, 그래프 변경 0개이며 R05 전체와 실제 자동 교정 종단은 미완료다. 직전 P1 재판정 연결의 실제 모델 의미 효과도 이번 실행으로 확인되지 않았다. #616/#617/#620은 열린 상태를 유지한다.

다음 판단은 원문 사실의 보존과 구별되는 조건별 연결 근거가 있는지에 달려 있다. 같은 모델의 공백 요청 문구를 반복하거나 사실 목록 증가를 완료로 세지 않는다. 현재 사용자 결정이 필요한 사항 없음. 재추출·전체 평가·새 정상 모델 호출·PR 병합·배포는 수행하지 않았다.
