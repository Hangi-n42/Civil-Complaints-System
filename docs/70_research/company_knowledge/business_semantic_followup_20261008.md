## 관리·교정 변경과 실제 실행

자동 판별 A/B와 독립된 변경이다.

1. **교정 대상으로 집계된 의미 안의 정상 후보 보존:** `correct` action 하나에 정상 끝점과 잘못된 관계가 함께 있었기 때문에, `maintain` action만 모으면 c107이 재사용 후보에서 빠졌다. 개별 `claim_support=supported`와 오류 귀속을 함께 확인해 정상 후보를 기존 재사용 경로에 제공한다. 오류·미확정·보호 후보를 정상으로 승격하지 않는다.
2. **공개 요청 항목별 적용성:** question과 criterion은 이미 입력에 있었다. 문구 강화만 한 v1도 기관 질문만 보고 서류를 background로 분류해 실패했다. 후속 항목별 계약은 기존 `PublicAnswerItem`/`bind_answer_items`로 ID·revision·원문 구절을 검증하고 같은 호출에서 각 의미와 공개 항목의 적용성을 판단한다. 별도 계획이 없으면 question/criterion 원문 전체를 각각 사용한다. 직접 답변을 요구한 항목이 있으면 다른 항목의 outside_scope로 제거하지 않는다. 원문 의미를 덮어쓰지 않으며 receipt와 판정 fingerprint에 범위를 보존한다.
3. **다른 항목으로 적용성 판정 전파 금지:** 이미 원문 지지·표현·승인 묶음이 확인된 의미를 이전 요청의 unresolved만으로 QA 선택 전에 제외하지 않는다. 현재 공개 항목에서 다시 선택하며 과거 `requirement_link`와 항목별 적용성은 선택 입력에서 제거한다. 실제 미확인 근거·불완전 전제는 기존 경계로 계속 차단한다.

### 실제 c47 편집본 연결

`conditioned_event_v1`의 실제 두 문장 출력과 `event_storage_replay_v1` 저장본을 그대로 사용했다. `reference_both_v1`의 수동 정정 문장과 `reviewed_selection_v2` 성공 답변을 수정본으로 바꾸어 사용하지 않았다.

원문 해석은 과거 `source_exposed`에서 실제 모델이 정확하게 생성한 m5를 동일 원문 주소·버전에 대조해 재사용했다. statement·조건을 새로 작성하지 않았고 기존 key에 연결한 출처를 기록했다. 이것은 오류를 알려 준 모델 편집과 올바른 저장 모델 해석의 연결 진단이며, 자동 오류 검출 개선은 아니다. c116은 동일 후보·의미의 기존 국소 보존 판정을 재사용했고 재교정하지 않았다.

v1은 `review_ready/satisfied`였지만 c47은 적격 17개에 포함되지 않았고, 서류 항목을 제외한 채 완료했으므로 실제 R05 충족으로 인정하지 않는다. c47의 보존 설명도 일반 반납 의무를 다시 정상으로 서술했다.

v2는 동일 원문·편집본·Qwen을 유지하고 이전 QA의 공개 항목 3개를 적용성의 판단 단위로 사용했다. 모델은 documents에 applicable/direct_answer를 선택했지만 해당 항목 대신 전체 question을 requirement_quote로 반환해 서버가 unresolved로 보존했다. 별도 후보 검수는 실제 c47의 일반 구비항목과 지역 번호 조건을 모두 짚고 represented/supported로 판단했다. c117 양 끝점 보존도 확인했다. 최종 상태는 partial이었다.

최종 계약 `public-item-applicability-v2-bound-quotes`는 이미 검증된 item_id에서 요청 구절을 서버가 연결한다. 모델에게 동일 구절을 다시 작성시키지 않는다. v2의 원출력·잘못된 인용을 receipt에 남기고 의미 판정은 그대로 사용했다. 이 적용성 응답의 추가 모델 호출은 0이다. 후속 후보 검수·결합에는 별도 호출이 발생하므로 전체 실행을 0-call replay로 부르지 않는다.

일부 정상 검수까지 새로 호출된 이유는 c117의 확정 보존 판정이 생겨 repair_context가 제거되고 요청 바이트가 달라졌기 때문이다. 실제 common_documents 입력 비교에서 차이는 repair_context 길이 1→0이었다. 정상 원문 의미의 변화나 모델 개선으로 해석하지 않는다. 현재 정확 요청 기반 재사용의 비용 한계이며, 이번 동결 실행을 바꾸거나 추가 전체 재평가하지 않았다.
