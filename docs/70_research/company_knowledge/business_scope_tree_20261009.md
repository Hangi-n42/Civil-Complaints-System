# 자동 조건·효과 구조와 유한 적용 범위 비교 — 2026-10-09

연구 #627은 SG-DT에서 참고한 조건/효과/양태 분리를 기존 한국어 원문-후보 비교에 제한 적용한다. 기준 원문·후보는 `645dfc004abcd58d5144fbf01dbe92e4dd16f9eb`에서 보존한 c13/c46/c47/c11이다. 앞의 두 연구를 마친 `3d6ee9f4b31db8b2cfb7f29083d3341ef0426d96` 이후 별도로 실행하며 제품 코드·DB·기준을 수정하지 않는다.

## 참고 방법과 실제 변형

[SG-DT 논문](https://arxiv.org/abs/2606.08932)은 규정 내부의 조건·예외가 어떤 효과에 적용되는지 원문에 연결해 구조화한다. 이것은 원문-후보 검증기가 아니다. [공식 NormBench 저장소](https://github.com/AlexJJJChen/NormBench/tree/bd56aff7eb9518db02b10e189576331f271564cc)의 revision은 `bd56aff7eb9518db02b10e189576331f271564cc`다. [LICENSE](https://github.com/AlexJJJChen/NormBench/blob/bd56aff7eb9518db02b10e189576331f271564cc/LICENSE)는 CC BY 4.0이다.

공식 단일 호출 경로는 unit 분할과 st2.v3 구조를 함께 출력하고, 원문 anchor·조건 AND/OR·효과·양태·예외 분기를 보존한다. 평가 도구가 만드는 `structured_units_fixed.json`은 원래 모델 출력과 구별해야 한다. 이 저장소의 모델 라우팅/평가 코드·자료를 제품에 설치하지 않았으며 공식 코드를 복사하지 않았다. 논문 아이디어를 참고한 독립 한국어 진단이며 NormBench 전체 실행이나 성능 재현이 아니다.

이번 변형의 3단계는 다음과 같다.

1. 원문 10개 블록과 부모 정보만 주고 조건 원자, 세부 효과 원자, 각 원자의 정확한 인용과 의미, 효과의 양태, 조건-효과 branch를 자동 추출한다.
2. 원문을 주지 않고 후보 4개를 별도 문서로 자동 추출한다. 4개 후보는 한 호출의 batch에 있으므로 후보별 독립 호출은 아니다.
3. 자동 원자와 원래 텍스트를 함께 주고 원문-후보 조건의 의미 관계 및 효과의 단방향 함의/명시 반대/무관/미확정을 대응한다. 파싱 구조를 수정하거나 최종 라벨을 생성하도록 하지 않는다.

모델이 정한 대응을 입력으로 별도의 작은 계산기가 유한 조건 할당을 열거한다. 후보 효과의 적용 범위가 그 효과를 지지하는 원문 branch 범위의 합집합에 포함되는지 계산한다. JSON 형태나 정확한 인용만 확인하던 검수와 달리 **guard 포함 여부**를 계산하지만, 계산에 들어가는 의미와 귀속의 정확성은 여전히 모델에 의존한다.

## 계산 계약과 한계

조건은 OR-of-AND 형식의 Boolean 원자/극성으로 표현한다. `guard=[[]]`는 명시적인 무조건이며, 미해석/미지원은 별도 실패 상태다. 조건 누락을 unknown으로 덮어 성공 처리하지 않는다. source→claim 조건 함의는 `¬source ∨ claim`, 반대 방향은 `¬claim ∨ source`를 만족하는 할당만 남긴다. 양방향이면 두 원자 값이 같은 할당만 남긴다. ID를 무조건 합치지 않는다.

조건 원자는 한 후보 비교당 최대 12개다. 원문-후보 원자 사이에 명시적으로 대응된 제약만 계산에 사용하고, 도메인 전체의 암묵적 제약·현실 사건 발생을 추론하지 않는다. 수량 산술·복잡 시제·미해석 참조·중첩 양태가 보존되지 않으면 unsupported다. 이 한계 때문에 계산 결과는 자동 해석된 제한 표현에서의 결과이지 모든 한국어 규정의 논리적 증명이 아니다.

효과는 주체·대상·행위·수량·시점·순서·괄호 한정·양태를 함께 보존해야 한다. required_item/obligation/permission/prohibition/procedure/fact/other를 구별하며 같은 단어라는 이유로 구비품목과 반납 의무를 합치지 않는다. 원문 효과가 더 상세할 때 일부 참인 사실로의 단방향 함의는 허용한다. c11에 전체 서류를 나열하도록 요구하지 않는다. 모든 원문 효과는 각 후보 효과에 대해 함의/반대/무관/미확정 중 하나로 빠짐없이 대응해야 한다.

명시 예외는 적용 제외의 negative guard로 표현할 수 있지만 원문에 없는 바깥 효과를 만들지 않는다. 조건부 의무에서 바깥 면제/금지를 추론하지 않는다. 지지되는 범위 밖의 `scope_witness`는 **구조상 원문 미지지 할당**이며 현실의 사건·반증이 아니다. 명시 반대 효과의 원문 대응이 후보 효과의 전체 적용 범위를 덮을 때만 R을 출력한다. 나머지 미지지는 N이고, 미해석/상충/입력 실패는 N으로 대체하지 않는다.

파서의 complete 상태·블록 coverage·정확한 인용 주소는 기계적 계약 검사다. 인용된 문구를 잘못된 효과에 연결하거나 양태를 바꿨다면 의미 실패다. 구조를 사람이 교정해 계산을 통과시키지 않는다. 최종 gate는 사전 S/S/N/S와 자동 구조·대응의 원문 일치를 모두 요구하며, unknown/빈 응답/실패는 분모 4에 남긴다. 네 사례는 모두 개발 노출 자료다.

이번 구현은 각 후보와 모든 원문 조건/효과를 전수 대응하는 엄격한 진단이다. 공유 원문 구조의 계약 오류 하나로 네 후보 계산이 모두 막힐 수 있다. 미지원·주소·대응 계약 때문에 계산하지 못한 결과는 조건 의미 오판의 재확인이 아니라 **이 구성의 실행·표현 한계**로 보고한다. 결과 후 validator를 완화하거나 unknown을 N으로 바꾸지 않는다.

## 실제 자동 파싱의 계약·의미 결과

**이번 고정 구성은 채택 실패다.** 공유 원문 구조가 `source:branch_common.guard=[]`를 출력해 무조건 표현 `[[]]`와 다른 `empty_guard_or_effect` 계약 실패가 발생했다. 따라서 고정 실행의 네 후보 범위 계산은 모두 차단됐다. 이를 ‘의미 오답 0/4 또는 4/4’로 표현하지 않으며, 계산 가능한 최종 라벨이 없는 4건을 전체 분모에 남긴다.

후보 원본을 수정하지 않고 동일 validator로 각각 검사한 별도 기록에서는 c13/c46/c47/c11 모두 `modality_kind` 오류가 확인됐다. 각 effect의 modality가 none이었으나 계약상 none은 condition에만 허용된다. 실제 run은 공유 source 오류에서 먼저 멈추므로 이 후보 결함은 별도 감사 결과이며 새 모델 실행이 아니다.

형식 실패와 **별개로 확인한 원문 의미 오류**도 있다. `source:b32_effect`는 괄호 밖 `번호판변경시 기존번호판 2매 및 봉인`만 인용하면서 `기존번호판 2매 및 봉인을 반납해야 함`, modality=obligation을 생성했다. 제공 원문에서 괄호 밖은 구비품목 목록이고 반납 후 변경 의무는 괄호 안 지역 번호 조건에 붙는다. 일반 번호판 변경 branch에 반납 의무를 보탠 자동 파싱은 원문이 뒷받침하지 않는다. 지역 번호 branch를 따로 만든 사실도 일반 branch의 오류를 해소하지 않는다. validator만 느슨하게 하면 채택할 수 있는 상태가 아니다.

표현 한계도 별도로 남긴다. b30은 여러 서류와 법인 대체 조건이 복합 effect 하나에 남았고, b28의 직접등록 조건은 effect meaning 안에 있어 Boolean guard로 분리되지 않았다. c47 후보는 반납과 번호 변경을 두 effect로 나눴지만 각 meaning/branch에는 두 행위의 연결·순서를 계산할 관계가 남지 않았다. 정상 c13/c46/c11의 미방문 조건 자체가 추출된 사실을 전체 구조·의미 성공으로 계산하지 않는다.

`source_review.json`은 원문 오류/표현 한계 분석, `contract_review.json`은 수정하지 않은 원본의 별도 형식 검사다. 둘 다 모델 입력이나 교정 구조가 아니다. 원본 complete 상태와 coverage 선언을 의미 정확성으로 승인하지 않았다. 사람이 guard/양태/효과를 고치거나 결과 후 schema/프롬프트를 바꾸지 않았다.

## 마지막 대응과 최종 계산 상태

고정된 세 번째 대응 호출까지 완료해 원본을 보존했다. 대응에서도 다음 오류가 실제 출력됐다.

- 지역 번호 변경인 `source:b32_condition2`와 일반 번호판 변경인 `c47:cond_1`을 `claim_implies_source`로 연결했다. 이유는 지역 번호 변경이 번호판 변경의 일종이라고 설명하면서도 마지막 함의 방향을 뒤집었다. 제한 원자 의미상 좁은 원문 조건에서 넓은 후보 조건으로의 방향과 맞지 않는다.
- 미방문과 번호판 변경 등 7쌍을 이유에서는 ‘양립할 수 있는 별개 조건’이라고 설명하면서 관계는 `disjoint`로 출력했다. disjoint는 동시에 참일 수 없다는 제약이므로 이유와 모순되고 원문에도 그러한 배제 근거가 없다. 이 잘못된 대응은 공동 성립 할당을 부당하게 제거할 입력이다.
- c47의 반납 effect 대응은 파서가 추가한 일반 반납 의무 `source:b32_effect`를 entails 근거로 소비했다. 대응 호출이 원래 텍스트도 받았지만 이 상위 단계 오류를 unknown으로 분리하지 않았다.

c11/c46의 일부 구비 항목에는 단방향 지지 대응이 나왔으나 전체 구조·대응 성공은 아니다. 원본을 바꾸지 않은 분석은 `mapping_review.json`에 저장했다. 잘못된 대응을 바로잡아 재계산하거나, 형식 실패를 무시했을 경우의 라벨을 실제 결과로 보고하지 않는다.
