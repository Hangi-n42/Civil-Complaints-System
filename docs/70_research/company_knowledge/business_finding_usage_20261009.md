## R02: 확인한 코드 결함과 남은 의미 판정 실패

첫 실행 `52bcd2a09ef64a9a85fce344b09dee3a`는 이전 정상 후보 5개 검수·적용성 및 국소 표현 3개 응답을 재사용하고 종합 1회만 새로 호출했다. 국소 관찰 9건은 실제 인용과 함께 not_required로 나왔지만, 과거 재판정에서 생긴 `interpretation_uncertain` 한 건이 정상 의미 세 개를 계속 차단했다. 종합의 이유에는 그 관계가 필수 공백이 아니라고 적혀 있으나, 구조화된 의존은 null이고 독립키는 출력하지 않았다. 이유 문자열만으로 독립·승인으로 바꾸지 않았다.

보완 실행 `dc6d4a99dac342599075c199bcb29e83`은 기존 43개 본문을 유지하고 4개를 추가한 47개 본문을 받았다. b28은 실제 e9 본문으로 제공되고 응답에서도 인용됐다. 추가된 나머지 3블록은 기존 검색이 함께 고른 저당등록 표 행과 그 업무·연락처 문맥이다. 관련성이 모두 정확해졌다는 결과는 아니다. 입력 본문은 20,370→21,060자, 실제 입력 토큰은 8,988→9,268이었다. 그러나 모델은 기본/예외 관계가 불분명하다고 유지했고 정상 세 의미를 계속 이의에 귀속했다. source는 partial, 의미는 represented, 의존은 null이었다. 원문 제공을 고친 것과 부분 활용 성공은 다르다. 같은 의미 실패의 재호출은 중단했다.

두 실행에서 독립키 기능은 사용되지 않았다. 두 번째 실험은 내부 종합 스키마에서 필수 응답으로 바꾸려 했으나, `selected_evidence_type`이 기본 FindingResolution으로 다시 구성하면서 실제 전달 스키마에서는 선택 항목으로 남았다. 실제 전달 스키마와 원시 출력을 보존했으며 ‘필수 응답을 모델이 무시했다’고 보고하지 않는다. 따라서 계획한 필수 응답 방식은 유효하게 시험되지 않았으며 독립성 판정 방식 자체가 효과 없다고 결론 내리지 않는다. 채택 근거가 없어 이 프로토타입과 관련 필드는 제품에서 제거했다. `interpretation_uncertain`을 국소 미발견처럼 일괄 면제하지 않았다. 채택하는 변경은 확인된 **이의 문맥 검색 누락 수정**뿐이다.

## R05: 원문 구절의 역할 선택 계약

기각했던 자유 answer 생성 대신 기존 검토 의미 선택에 원문 구절과 사용 역할을 연결하는 계약을 비교했다. 업무 범위를 긍정적으로 진술한 구절, 명시 제외, 기간·절차 등의 참고를 구분하고, 질문 조건에 직접 해당하는지 추가 연결이 필요한지 선택하도록 했다. 서버는 역할별로 표시를 조립하고 원래 의미·조건·예외를 함께 유지한다. 인용 문자열 일치는 의미 역할이나 질문 적용성의 정확성을 입증하지 않는다. 일반 이전등록 구절을 번호판 변경 조건의 직접 근거로 분류해도 실패다.

첫 nullable 실행 `3147fe3653d84154a27d99ddad2dc7cd`는 모든 scope_basis를 null로 반환했다. 역할 조립은 0회이고 기존 사실 나열·일반 경고 10개·빈 unconfirmed만 남았다. 권한 단정을 새로 만들지 않은 것만으로 유용한 답변 성공으로 세지 않았다.

이 실행은 보존하고, 텍스트 의미는 역할과 구절을 필수로 응답하며 ordinary_fact를 명시 유형으로 허용하는 계약으로 한 번만 보완했다. 실제 행 셀은 기존 ID/use 선택형을 유지한다. 입력 원문·후보·질문·criterion·스냅샷·로컬 모델 설정은 같고 정답 결론·라벨은 제품 입력에 제공하지 않았다. 역할 선택·질문 적용성·출력 계약이 함께 바뀌므로 단일 필드의 독립 효과로 주장하지 않는다.

필수 역할 실행 `cd1ec56ce3ee4e6e9f37c77aed761e14`는 역할 20개를 실제 작성했지만 **기각**했다. 구비서류 요건을 positive_scope/direct로 분류하여 ‘질문 조건에 해당하는 명시 업무 범위’로 표시했다. 명지·금련산의 일반 이전등록과 교부 기간도 번호판 변경 조건의 직접 긍정 범위로 선택했다. 이는 인용 주소 검사와 별개인 의미 역할 실패다.

선택 의미문장의 부분문자열이어야 하는 quote 계약도 9건 위반했다. 원문 표의 표현이나 축약 기호가 섞여 있었으므로 이 9건 모두를 ‘현실에 존재하지 않는 원문’이라고 단정하지 않는다. 서버는 잘못된 선택 인용을 걸러 전체 결과를 unverified로 표시했으나, 기관별 제외 항목의 본문이 비었다. 번호판 비변경 조건의 일부 업무·기간, 미방문 날인 위치와 지역 번호 조건은 유지됐지만 질문 전체에 유용한 답변이 되지 못했다.

nullable 시도와 필수 역할 시도의 동결 코드·스키마·원시 선택·최종 표시를 모두 보존했다. 두 QA 프로토타입과 관련 테스트 변경은 제품 기본 경로에서 제거했다. 인용 계약만 다시 고쳐 재호출하거나 예시·추가 판정 필드로 확장하지 않았다. #620은 미완료다.
