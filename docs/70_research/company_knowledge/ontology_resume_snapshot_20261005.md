- 전체 기능 완료 또는 의미 품질 개선을 선언하지 않는다. 실행 중 비교의 후속 결과는 별도 기록한다.

## 변경 이유와 구현

- 원문 근거 판단과 후보 표현 검수에서 상태·주장 여부를 따로 반환하면 서로 모순될 수 있었다. 독립 assertion 필드를 제거하고 표현됨·누락·오류·판단 불가의 한 가지 결론으로 정리했다.
- 검수 대상 의미키를 응답 객체의 필수 키로 지정했다. 기존 부분 오류 격리·정상 결과 보존·후속 처리 기록은 재사용하며, 필수 키가 있다고 내용까지 옳다고 판정하지 않는다.
- 재판정에서 기존 의미를 교체할 때 허용된 대상키만 지정하도록 제한했다. 기존 의미를 대체하지 않는 새로운 원문 의미는 허용한다.
- 관계를 먼저 추출하고 그 관계에 직접 연결된 원문 문맥을 개념 추출과 유형 연결에 제공하는 선택 경로를 구현했다. 원문 버전·파싱·블록·언급 구간이 일치할 때만 연결하며 이름만 같다는 이유로 합치지 않는다.
- 관계 추출 실패 시에도 직접 정의 원문을 읽는 개념 추출 경로를 유지한다. 선택한 관계의 방향·조건·근거·검수 상태를 모델 입력까지 전달하고, 현재 반박된 관계는 제외한다.
- 최종 입력에는 선택 메타데이터와 응답 스키마 비용까지 반영한다. 용량을 넘으면 선택적 문맥을 통째로 제외하고 필수 원문은 보존한다. 재개 시 저장된 선택을 재사용한다.
- 기존 서비스·저장소·직렬 실행기와 설치된 의존성을 사용한다. 새 DB·큐·프레임워크·의존성은 추가하지 않았다. 이웃 선택 설정은 기본 비활성이다.

## 실제 모델 비교의 현재 상태

- 비교 대상: 같은 원문·저장된 실제 관계 추출 결과·업무 질문·모델을 사용한 기존 문맥(N0)과 연결 이웃 문맥(N1). 관계 추출은 양쪽이 공유한 과거 실제 실행이며 이번 신규 호출로 계산하지 않는다.
- 모델: `gemma4:31b-it-q4_K_M`. N 비교는 선택 효과를 대상으로 하며 호출 순서의 인과 효과·전체 온톨로지 정확도·사람 효용을 측정하지 않는다.
- 선행 n_v2의 HTTP 400 10회는 실행기 응답 스키마의 빈 작업 ID 목록 문제였다. 모델 추론 결과가 아니며 품질 평가에서 제외한다. 작업 목록과 스키마 사전 검사를 보완한 n_v3를 새로 고정했다.
- n_v3 직접 정의 자료의 개념 추출: N0 **286.774초**, N1 **342.112초**. 입력 토큰은 각각 **4,339 / 6,566**, 생성 토큰은 각각 **4,096 / 4,096**이며 생각 토큰을 포함한다. 양쪽 모두 `done_reason=length`로 최종 응답이 잘렸다. 의미 개선·악화 판정은 불가하다.
- 해당 자료의 유형 연결 단계는 양쪽 각 2개 단위가 `'required'` 오류로 실제 모델 호출 전에 실패했다. 실행기/스키마 연결 원인은 추가 확인이 필요하며 유형 연결 품질을 측정한 결과가 아니다.
- 이 시점에는 권한 자료 비교가 실행 중이다. 완료·독립 원문 검토·채택 여부는 아직 확정하지 않았다. 실행 중인 코드의 동결 해시는 유지됐다.
- 로컬 원본 DB와 원문, 동결 입력·요청·응답·실행 DB는 보존하며 저장소 커밋에는 넣지 않는다. 비교 경로는 `data/knowledge/evaluations/neighbor_resume_20261005/n_v3`이다.
