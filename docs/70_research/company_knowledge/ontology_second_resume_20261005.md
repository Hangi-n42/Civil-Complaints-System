# 원명제 추적·정상 끝점 보존의 두 번째 재개 검증

- 기준: `068683c` 이후 변경, [승인된 두 번째 재개 계획](../../05_plans/company_knowledge/grounded_recovery_followup_20261005.md). 과거 실패와 PR 중간 반영을 새 구현의 효과로 계산하지 않는다.
- 목적: 원문이 뒷받침하는 의미와 실제 후보 표현을 구분하면서 빠진 원명제를 다시 판단하고, 현재 검수에서 반박된 관계 끝점만 고친다. 자료·DB·직렬 실행기·기존 검수와 교정 경로를 재사용한다.

## 구현과 코드 경계 확인

- 현재 제공된 고유 원문 참조 수로 조사 목록과 의미별 참조 목록의 응답 상한을 제한했다. 완전한 JSON의 중복 조사 주소는 순서대로 제거하지만 원시 응답은 보존한다. 잘린 JSON을 부분 성공으로 복원하거나 서버가 조사 목록을 채우지 않는다.
- 성공했고 실제 시도가 기록된 Relation 단위의 자연어 명제만 가져온다. 버전·parse·원문 구간·인용문이 현재 패킷과 일치해야 하며, 수정된 유형 끝점이나 이전 승인 판정을 가설로 넣지 않는다. 분할·추가 읽기 이후에도 실제 제공 원문에 맞춰 가설을 선택한다.
- `proposition_refs`로 미승인 명제와 원문 의미의 다대다 대응을 기록한다. 가설 밖 의미와 빈 대응도 허용한다. 미대응만으로 원문 지지나 생성 누락을 확정하지 않는다.
- 원문 판단 E, 후보 표현 검수 R, 결합 검수에 같은 가설을 전달한다. 이미 대응된 의미의 한정 오류는 기존 의미키로, 통째로 빠진 가설은 원명제 참조로 재판정을 요청한다. 새 요청은 원래 근거 판단 기록으로 재진입한다.
- 전문가 검토에서 발견한 재판정 실패/소진의 완료 오집계와 정상 형제 의미 덮어쓰기를 수정했다. 미해결 요청은 업무 요구를 미완료로 유지하며, 정상 의미의 유지 판정은 보존한다. 범위 밖 `supersedes`뿐 아니라 같은 본문·주소를 이용한 상태 덮어쓰기도 해당 행만 격리한다.
- 기존 Binding→Builder 교정에서 현재 후보와 일치하는 유효 검수의 반박 끝점만 수정 대상으로 삼는다. 정상 끝점은 응답 스키마의 고정 ID와 저장 직전 비교로 보호한다. 양끝점 오류는 모두 수정 가능하고, 오래된 검수는 권한을 만들지 못한다. 원명제 수정 후 최초 유형 연결은 기존 경로를 유지한다.
- 계약은 `grounded-meanings-v3`, 프롬프트는 `discovery-a2-v110`이다. 과거 성공 단위는 변환하거나 새 계약 결과로 재집계하지 않는다.
- Python 3.11.9의 관련 grounding/neighbors/recovery/completion/roles/scope/corrections 검사에서 **276개 통과·2개 실패(26.10초)**. 기존 `test_relation_call_reaches_model_with_nested_preservation_schema[False/True]`의 입력+스키마 상한 실패 2개는 미해결이다. 전체 통과라고 표현하지 않는다. 변경 Python 문법·공백 검사도 통과했다.
- 신규 검사는 실제 시도 없는 투영본/다른 parse/원문 밖 가설 제외, 완전 응답의 중복 조사 주소와 실제 미조사 구분, 새 가설 재판정의 원래 근거 재진입·정상 보존·재누락 보류, 실패/소진의 요구 미완료, 범위 밖 기존 의미의 명시/본문 키 덮어쓰기 격리, 정상 끝점 스키마/저장 보호, 양끝점 수정 허용, 오래된 검수 차단을 다룬다.

## 실제 실행의 범위와 동결

실행기는 `scripts/run_knowledge_second_resume.py`이며 개발에 노출된 자료의 제한 진단이다. 각 경로의 `inputs.json`, `freeze.json`, 모델 요청/최종 응답·시간·원본 및 실행 코드 지문을 따로 기록한다. 모델 생각 텍스트를 의미 검수 근거로 사용하지 않는다.

- `grounding_v2`: 539자 권한 원문과 실제 Relation 2개로 작은 E→R 및 필요한 한 차례 E→R 재판정. 최대 4회/7,200초. 교정 전 후보를 읽는 독립 대조이며 교정 후 업무 요구 확인이 아니다.
- `binding_v2`: 이전 N1의 실제 시도지사 관계/목적어 역할 오류를 기존 명제·Binding 검수→교정→후속 검수에 전달. 최대 16회/28,800초는 예약 상한이며 실제 필요한 호출만 수행한다. 유용한 교정이 없거나 같은 실패가 지속되면 해당 경로를 종료한다.
- `neighbor_v2`: 같은 저장 Concept 2개·주관계 r1·전체 원문·모델·설정에 직접 연결된 r2 패킷 하나의 제공 여부만 변경. 신규 Builder 최대 2회/3,600초. 기존 전체 feature on/off 비교와 구분한다.
- N의 두 최종 JSON은 추가 r2 전체 패킷과 선택 ID만 차이 난다. r1 메타데이터·지시문·원문·Concept·응답 스키마는 같다. 미제공군에 r2 ID가 없고 실제 selector가 같은 목적어의 정확한 원문 위치 `[329,380]`으로 r2를 고르는 것을 독립 검토했다. 새 자료 획득 효과나 r2 생성 성공으로 집계하지 않는다.
- 같은 Gemma 모델과 기존 출력 상한을 유지한다. 경로 내 의미 재시도·설정 조정은 없다. 독립 N 비교는 E나 국소 교정의 성공에 의존하지 않는다.
- 원본 DB는 읽기 전용으로 사본을 만들고 실제 모델 시도만 새 HTTP 비용으로 집계한다. 과거 실제 Relation/Concept/Builder 수입과 신규 실행을 구분한다.
- 준비본 `grounding_v1/binding_v1`은 진단 묶음의 `status` 누락을 모델 호출 전에 확인해 수정했다. `neighbor_v1`도 같은 실행기 수정 후 v2로 재동결했다. 준비본의 신규 추론은 0회다.
- 모델 없는 실제 `a2.call` 경계 6개(E 1개, Critic/Binding 3개, Builder 2개)를 사전 확인했다. 이후 실제 의미 품질·교정 결과를 별도로 판단한다.

## 완료 판정의 경계

실제 교정이 확인되면 그 수정 후보로 같은 권한 요구를 다시 검수한다. 원래 두 문서의 전체 업무 질문과 A3 변경안은 현재 원문·후보·검수 전제가 갖춰진 경우에만 확인한다. 코드 통과, 성공 응답 수, 보류 증가를 의미 개선으로 계산하지 않는다. 관계 이웃 기본값은 비활성이며 사람 효용·Windows 실기는 미검증이다. 현재 사용자 결정이 필요한 사항 없음.

## 작은 원문 판단의 실제 결과

- `grounding_v2` 첫 E는 269.007초, 입력 2,947/생성 3,487토큰, `done_reason=stop`으로 저장됐다. 항목 오류 0개, 의미 3개, 실제 원명제 가설 2개 모두 대응했다. 생성 토큰은 생각 토큰을 포함한다.
- 두 권한의 주체–공급 조건 짝, 제1·2항에도 불구한다는 예외, 지역 실정, 공급비율·선정순위, 지방공사의 제49조·주택사업 목적 한정을 의미 본문에 보존했다. 한정이 별도 conditions 필드에서 축약됐어도 전체 의미 본문과 함께 대조한다.
- **남은 실제 오류:** 두 권한은 이미 전체 제공된 같은 원문을 `internal_unselected`로 표시하고 그 블록을 다시 읽도록 요청했다. 실행 성공을 자료 상태 판정 성공으로 간주하지 않는다.
- 별도 세부 기준의 확인 필요성은 세 번째 의미로 작성했고, 실제 미제공 세부 수치·자격을 생성하지 않았다. 이 행의 supported는 명제 내용과 availability를 함께 검토해야 하며 전체 기준을 확보했다는 증거가 아니다.
- 이번에는 응답 계약·원명제 가설 연결·프롬프트를 함께 바꿨고 과거 실패와 판단 패킷도 다르다. 응답 완결이나 한정 보존을 한 가지 변경의 독립 인과 효과로 계산하지 않는다.
- 이어진 실제 R은 272.943초, 입력 6,447/생성 2,962토큰, 정상 종료·항목 오류 0개였다. 두 권한은 후보 관계의 conditions 위치로 `represented/maintain`, 별도 세부 기준의 확인 필요성은 `missing/recover`로 표시했다.
- R의 `source_challenges=[]`이므로 잘못된 `internal_unselected`를 재판정하지 않았고, 시도지사 관계의 목적어 역할 범위 오류도 발견하지 못했다. 정상 원명제 조건을 읽은 결과를 끝점까지 정확하다는 판정으로 확대할 수 없다. **새 가설 재판정의 코드 경계는 확인했지만 실제 R→E→R 성공은 미확인**이다.
- 세 번째 안내 의미의 recover 표시는 실제 외부 기준 내용을 확보하거나 생성한 결과가 아니다. 이 독립 대조는 교정·생성 경로를 실행하지 않았으며 실제 누락 복구 성공으로 세지 않는다.
- `grounding_v2` 총 신규 HTTP 2회, 전체 543.109초, 원본·동결 코드 지문 유지. 같은 E/R 실패를 재시도하지 않고 독립 Binding 경로로 진행했다.

## 기존 국소 연결 검수의 실제 실패

- `binding_v2`: 실제 명제 검수 209.196초, 시도지사 관계의 Binding 58.677초, 정상 장관 관계의 Binding 61.066초. 신규 HTTP 3회, 전체 330.274초. 원본·동결 코드 지문 유지.

- 독립 의미 검토에서도 오류 목적어의 supported를 오판으로 확인했다. 이번 기록에서 교정이 시작되지 않은 원인은 현재 검수에 refuted가 없었던 것이며, 교정 실행 연결부가 고장 났다는 증거는 아니다. 다음 최소 개선 후보는 기존 Binding 안에서 선택 역할의 선언 범위와 사용 관계의 범위를 짝지어 포함·충돌 근거를 대조하는 것이다. ID가 다르다는 이유의 일괄 재사용 금지나 새 검수기 추가는 제안하지 않는다.
