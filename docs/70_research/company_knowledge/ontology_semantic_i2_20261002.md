# I2 모순 검수 격리와 원명제 수정 실패 보존

- 대상 #564, I1 `8eeb046` 이후 같은 브랜치의 recipe `discovery-a2-v40`.
- H4에서 모순된 내용 쟁점이 수정을 유발하고 유형 ID 복사가 원명제를 훼손한 경계를 보완했다. 기존 정규화·실패 기록·후보 지문을 재사용했다.

## 구현과 확인

- 같은 후보의 supported와 content_error가 충돌하면 기존 record_errors/pending으로 그 후보만 격리한다. 정상 이웃과 원명제 지지·유형 연결의 서로 다른 판단인 endpoint/alignment는 보존한다. 자연어 사유를 정규식으로 판정하지 않는다.
- 원명제 수정 응답을 ID 치환 전에 확인한다. 실제 제공 유형과 원관계 끝점의 ID 및 해당 모델 별칭, design_proposal 반환을 거절한다. 원문 자체와 같은 문자열은 허용하며 정상 자연어 끝점 변경은 이전 유형 연결을 재사용하지 않는다.
- 실패한 수정은 원응답·attempt·이유를 남기고 원후보를 덮지 않으며 성공 history도 만들지 않는다. 원후보 보존은 오류 해결·자동 수락이 아니다.
- 현재 지문에 해당하는 최신 검수만 최종후보와 A3에서 사용한다. 동일 지문의 최신 모순/누락을 과거 supported가 가릴 수 없다. 비교용 원문 관계처럼 지문이 다른 검수는 현재 설계 후보의 정상 검수를 대체하지 않는다.
- 그룹 완료는 자체 검수 계약과 현재후보의 최종 유효 판정을 함께 확인한다. comparison_only의 자동 원문 끝점 오류 추론만 제외하고 명시적 Critic endpoint와 주그룹의 실제 미연결은 유지한다.
- 관련 고유 검사 232개 확인. 정상 수정을 의도하면서 supported와 내용 오류를 동시에 넣던 기존 테스트 응답 3개를 일관된 refuted로 정리했다. 전문가가 발견한 비교 묶음 경계를 수정한 뒤 관련 회귀 27개를 통과했다. 의미·실행 전문가 최종 검토에서 추가 차단 결함 없음.
- H4 실제 잘못된 수정 응답을 바이트 그대로 재생해 실패 처리, 원후보 보존, 성공 history 없음, 원응답·attempt 보존을 확인했다. 원 H4 result/DB/started/calls 해시 불변. 재현은 `data/knowledge/semantic_i2_20261002/replay_result.json`에 기록했다.

## 한계와 다음 작업

- 실제 모델 호출 0, 새 토큰 null. 구조적으로 일관된 거짓양성은 이 검증으로 판별하지 못한다. 모델의 실제 조건·정의 검수 능력은 I3의 사전 동결 진단으로 별도 평가한다.
- 원래 H4 실패와 과거 검수 기록은 수정하지 않았다. Windows 실기·전체 민원 평가·사람 효용 검사는 수행하지 않았다. 참가자 0명·사람시간 null·효용 미측정.
- 다음은 정상 조건·제거 조건·근거 없는 정의를 비교하는 진단 A/B 각각 한 번이다. 진단을 통과해야 전체 C2를 실행하며 실패 뒤 반복 튜닝하지 않는다.
- 현재 사용자 결정이 필요한 사항 없음.
