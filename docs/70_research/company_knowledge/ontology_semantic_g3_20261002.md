# G3 역할별 복구 비교자료 정리 — 2026-10-02

- #555. 기존 관계의 끝점이라는 이유만으로 유형 정의를 Concept 복구의 필수 자료로 보호하던 결합을 줄였다. 기존 recovery_groups·analysis_context·compact를 수정했고 새 실행기·의존성은 추가하지 않았다. 계약 버전은 v34다.
- Concept은 Critic이 명시한 compared_candidate_ids의 실제 비교 후보·정의와 근거를 필수로 유지한다. 해당 Critic 묶음의 candidates/design_candidates를 우선하므로 같은 ID의 원관계와 모델링된 관계를 혼동하지 않는다. 모델링된 view의 source_relation과 저장 analysis_units에는 원관계를 그대로 보존한다.
- 단순 관계 끝점 유형은 Concept의 선택 가능한 비교자료로 남긴다. legacy Relation 복구의 직접 끝점 정의·근거는 계속 필수다. 같은 ID의 view 교체를 누락으로 기록하지 않도록 누락 판정도 제공 ID 집합을 사용한다.
- recovery_meanings가 있으면 모델 입력에서만 중복 recovery_meaning을 생략한다. 저장 복구 요청·원장·원문은 수정하지 않는다. 입력 한도12000·Concept 예약2000·컨텍스트32768·출력4096도 유지했다.
