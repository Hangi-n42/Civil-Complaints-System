# 소스 변경 후 구 스냅샷 현행 사용 차단 — 2026-10-10

실제 버스 변경 이력이 있는 저장 DB에서, 같은 요구 revision의 새 평가가 `needs_review`를 `partial`로 덮어쓰면 변경 전 후보가 있는 구 스냅샷이 다시 검색에 들어오는 제품 결함을 확인했다. [PRD §8.2](../../00_overview/company_knowledge_prd.md#82-상태와-갱신의-의미)에서 정한 스냅샷 불변성과 변경 근거의 현행 사용 제외를 함께 지키기 위해 조회 경계를 수정했다. [#620](https://github.com/Hangi-n42/Civil-Complaints-System/issues/620)의 제품 연결 작업이며 자동 의미 판단 연구 성과로 계산하지 않는다.

- 기준 HEAD: `18cee9fb6f3eb4a163894a8f21b7740aadd764cb`. 별도 제품 checkout에서 작업했으며 연구 checkout·원장을 수정하지 않았다.
- 원본 DB: `business_support_mechanism_20261008/bus_update/knowledge.db`; SHA-256 `def64d1e250937b82e7fad8e7a710e1a54ac1123dacbfdd907286900d13bd749`.
- 저장된 실제 변경 실행 `9fd8657075c84ba2b4b9da2e52ac3f82`: 순번 13 `affected`, 순번 12 `unaffected`. 후속 평가 `e82031d7f77a4326b23601677281c4c0`와 승인 스냅샷은 기존 기록을 사용했다. 영향 판정·추출을 다시 실행하지 않았다.
- 원문 전후 버전, 전체 실행 ID, 파일 해시와 경계 관찰은 [증거 JSON](business_source_change_snapshot_20261010.json)에 기록한다. 원시 DB·복사본·실행 스크립트는 제품 checkout의 `data/knowledge/evaluations/business_change_snapshot_20261010/`에 보존한다.

## 결함과 수정

`business_changes.apply_impacts`는 변경 이력과 `needs_review`를 기록하지만, `business_store.save_assessment`는 후속 평가 상태로 요구 상태를 바꾼다. 기존 `business_use.query`는 현재 revision·상태만 확인하므로 같은 revision의 후속 평가가 다른 원문 버전에 대한 옛 평가까지 다시 허용했다.

조회는 이제 저장된 `change_history`와 해당 `business_change`의 실제 전후 버전·diff 주소를 함께 읽는다. `affected`·`unknown` 요구의 구 스냅샷 조회를 재검토 대상으로 반환하고, 다른 요구를 조회할 때는 실제로 변경된 **이전 원문 block에 근거한 후보와 해당 block만** 조회용 복사 뷰에서 제외한다. 원문 버전 전체를 차단하거나 저장 스냅샷을 수정하지 않는다. 필터에 사용한 변경 실행·대상은 새 QA 실행의 `snapshot_invalidations`에 남긴다.

동일 전후 버전 쌍에 대한 최신 `unaffected`는 이전 요구 영향 판정을 대체한다. 이는 실제로 변경된 block의 모든 옛 후보까지 현행 사실로 재허용한다는 뜻은 아니다. 미변경 순번 12의 독립 block·후보는 남는다. 변경된 같은 block 내부의 부분 의미 독립성은 현재 요구 단위 영향 출력만으로 확인할 수 없으며 추정해 복원하지 않았다.

`run.started_at`만 새로 바꾸어 구 근거를 통과시키는 경계는 허용하지 않는다. 평가의 연결 후보와 필요한 원문 의미·전제·필드 근거 주소를 함께 확인한다. 같은 스냅샷에 이전 버전 메타데이터가 있어도 해당 평가가 after-version만 참조하면 사용 가능하다. 후보 또는 주소를 복원할 수 없으면 독립성을 확인한 것으로 간주하지 않는다. 과거 원문 확인용 `source_run_id` 경로는 별도의 비승인 원문 조회 계약을 유지한다. 요구 미지정 QA에서도 제거된 평가의 `explicit_meaning_reviews`는 남은 평가를 순회하는 답변 의미 입력에 재유입되지 않음을 검사했다.

혼합 버전 경계도 보완했다. 현재 `BusinessRequest`는 전후 버전 동시 선택과 after-only block 선택을 허용한다. 실제 저장 after-only 평가·후보를 재사용한 조정 fixture에서 before+after 메타데이터를 둔 실행을 저장하고 실제 `decide`로 승인하면, 수정 전에는 무효화할 후보가 0개인데도 요구가 차단됐다. 보완 후 같은 두 after 후보로 검색에 도달했다. 이는 **저장 평가의 제품 경계 검사**이며 새 모델 검수나 새 사람 검토가 아니다. 이전 원문에 의존하는 필드 근거가 남은 경우에는 계속 차단한다.

## 실제 검색·답변 연결 결과

저장된 QA의 메시지·스키마와 검색 구간 텍스트가 현재 입력과 달라 저장 응답 재사용을 기각하고, 조율된 로컬 자원으로 실제 조회를 실행했다. 준비 단계의 저장 hits 재생은 입력 비교에만 사용했으며 실제 검색 실행으로 계산하지 않는다.

기존 두 질문, 새 스냅샷 `996dcfe5a4054404af531942ef1b5862`, `hipporag2`·`full`, `reviewed_items`, `limit=50`과 기존 공개 답변 항목을 고정했다. `BUS-CONTROL-12`·`BUS-NEW-13` 각각 관계 선택 1회와 답변 선택 1회로 Qwen `qwen3.8:27b-q4_K_M` **실제 4회**를 실행했다. 모델 digest는 저장 실행과 동일함을 확인했다. 로컬 BGE-M3 CPU 검색은 첫 조회에서 인덱스를 구성했고 두 번째 조회는 인덱스 캐시를 사용했다.

| 실제 조회 | 원문과 대조한 결과 |
|---|---|
| 구 13번, 같은 runtime DB | `needs_review`, 검색·모델 호출 0 |
| 새 12번, `7c02742a2dca48ab8bcf60afdf4e7184` | NODE_ID `109000033`, ARS_ID `10116`, 방학사거리, X `127.0421039333`, Y `37.6622176747` 보존. `1127_after.json` `/11`, 기록 날짜 `2025-06-24`와 해당 후보 인용 |
| 새 13번, `e5f927e463d0411fbdec45b315d8c88f` | NODE_ID `109000011`, X `127.0407623758`, Y `37.6589364195` 보존. `1127_after.json` `/12`, 기록 날짜 `2025-06-24`와 해당 후보 인용. 요구 전체·최신성은 미확인이라는 안내 유지 |

13번의 ARS_ID `10011`도 선택 입력에 있었지만 최종 답변에는 선택되지 않았다. 고정 질문·criterion은 “정차 식별자와 좌표”, “실제 행의 ID와 좌표”이며 NODE_ID와 ARS_ID를 모두 명시한 필수 출력 기준은 아니다. 따라서 이 관찰을 새 필수 항목 누락 실패로 만들거나 이를 채우는 추가 QA를 실행하지 않았다. 해당 문서 행값 질문의 답변 달성과 요구 전체 `partial`·실제 현행 시점 미확인은 구분한다. 12번의 추가 연결 전제 안내도 그대로 남겼다.

두 QA 모두 해당 필수 승인 후보를 검색 결과에 포함했다. 수정 전 13번 식별자·좌표의 재유입은 없었다. 실제 LLM 시간 합계는 `104.966112초`, driver 전체 시간은 `114.448589초`다. provider 보고 입력 토큰 `13,130`, 출력 토큰 `532`이며 새 추출·평가 전체 비용이 아니다. 원본 DB·모든 저장 스냅샷이 불변임을 확인했고 종료된 QA Python 프로세스와 Qwen 적재 해제를 확인했다.

그래프는 20개 노드·34개 간선·2개 원문 구간이다. 검색 한도 50과 필수 승인 후보 포함 경로를 사용하므로, 답변 성공은 이 좁은 데이터·기존 승인 근거 전달 범위의 결과다. 자율 검색 순위 개선이나 자동 오류 발견·수정의 품질 향상으로 확대하지 않는다.

혼합 경계 보완은 실제 QA 종료 후 수행했으며 처음 동결한 코드·입력·응답은 별도 보존했다. 최종 코드로 만든 두 QA의 메시지·스키마·참조 매핑이 실제 실행 units와 모두 동일하고 그래프 구성 코드도 동일함을 모델 없이 대조했다. 실제 QA를 반복하지 않았다.

이번 수정과 좁은 버스 활용 연결은 완료했다. 같은 변경 block의 부분 의미 재허용과 자동 의미 오류 발견·교정의 남은 작업은 별도이며 [#620](https://github.com/Hangi-n42/Civil-Complaints-System/issues/620) 전체를 닫지 않는다. 합병·배포·Windows 실행은 수행하지 않았다. 다음 제품 연결 작업은 조율 세션에서 확인한 자동 판단 성과와 실제 편집·보존 경계에 맞춰 이어간다. 현재 사용자 결정이 필요한 사항 없음.
