# 자율형 온톨로지 초안 구축을 위한 LH 데이터 재검토

- 검토일: 2026-09-29.
- 기준: 사용자 제공 「에이전트 기반 온톨로지 초안 구축.md」 전체. 문서의 설계 제안을 평가 기준으로 읽었으며 구현 지시로 실행하지 않음.
- 범위: 기존 LH 자료의 내용·다양성·탐색 가능성·변경 평가·이용권리. 다른 기업 데이터셋 탐색과 온톨로지 구축은 수행하지 않음.
- 결론: **LH는 좁은 임대업무 온톨로지 실험의 적절한 도메인. 그러나 현재 확보·선정된 묶음은 첨부 설계 전체에 충분하지 않고, 전체 자료의 예정된 이용에 대한 허락도 확인되지 않음. 현재 묶음을 완비된 실사용 데이터셋으로 확정할 수 없음.**
- 권고: LH를 즉시 버리지 말고, 같은 업무 범위의 자료와 권리 공백부터 보완. 해결 가능성이 확인되기 전에 새 기업 탐색으로 확장하지 않음.
- 실제 파일·해시·판정: [assessment.json](../../../configs/knowledge/lh_autonomous_review_20260929/assessment.json). 공식 페이지 확인 기록: [evidence_sources.json](../../../configs/knowledge/lh_autonomous_review_20260929/evidence_sources.json).

## 1. 이번 목적에 맞춘 판단

- 이전 동호 변경 검토는 다른 대기자·계약·수선에 미치는 실제 영향을 측정하는 문제였음.
- 이번 목적은 **자료 구조를 살펴보고 부족한 근거를 추가 검색하여 개념·관계·계층·동의어 초안을 제안하고, 사람이 근거와 변경을 검수하는 것**.
- 따라서 실제 입주자 원장이나 개인 민원 대량 확보는 이번 목적의 필수 조건이 아님. 개인정보 없는 규정·업무 안내·시스템 명세·공개 레코드로도 해당 업무 범위의 구축을 시험할 수 있음.
- 문서·DB·코드·조직도를 반드시 모두 갖춰야 하는 것도 아님. 선택한 업무와 평가하려는 능력을 설명할 근거가 빠지지 않아야 함.
- 학습용 대량 정답쌍을 이용한 모델 재학습이 필수인 설계가 아님. 먼저 필요한 것은 로컬 검색·분석용 업무 자료와 별도 검수 기준.
- 공개 자료를 모은 실험은 내부 지식 탐색을 대리하는 파일럿. 비공개 사내 DB·권한·암묵지까지 복원했다는 증거는 되지 않음.

- 최초 구축은 기준 버전이 비어 있으므로 제안 대부분이 추가 변경. 변경집합 화면만으로 최초 의미 검수가 자동으로 작아진다고 보장할 수 없음.

## 3. 현재 묶음의 실제 구성

- 고정 파일럿: **문서10개 파일 + CSV1개 =11개 원본**. 현재 파일 존재와 기존 SHA-256 일치11/11 확인.
- 문서의 논리적 버전8개. 같은 공고의 HTML·PDF를 별도 독립 근거로 세지 않음.
- 구성: 양산 공고3버전(HTML3·PDF2), 안내3개, Q&A1개, 2015년 시행세칙1개, 단지CSV1개.
- 단지CSV: 6,217개 단지·11열. 기존 지식 입력 범위는 관련6개 단지.
- Q&A 입력은 임대 Q1~Q16. 공고PDF는 각 물리1~6쪽, 시행세칙은80쪽 원문 중 물리1~6쪽을 초기 입력으로 선정.
- 원본 전체를 이미 보관한 자료가 있으므로 **새 수집 전에 기존 원문의 활용 범위를 넓힐 수 있는지 검토 가능**. 단, 더 읽을 수 있다는 사실이 권리나 현행성을 해결하지는 않음.
- 제주·하남 문의와 울산 결정문은 다른 지역·사업·시점의 자료. 양산 업무 사례인 것처럼 묶지 않음. 이번 구축 목적에 필수 입력도 아님.

### 강점

- 실제 한국어 업무 용어와 명시적 조건·예외가 있음.
- 공고·안내·질문·표 형태가 함께 있어 문서 간 탐색 경로를 만들 수 있음.
- 공식 단지ID와 버전 관계가 있어 출처·식별자 연결을 시험하기 좋음.
- 동일 개념/유사 개념의 구분, 적용 범위, 오래된 규정 처리 등 의미 오류를 확인할 소재가 있음.

### 부족한 이유

1. **현재 묶음은 사람이 고른 작은 파일럿.** 자료를 스스로 선택하고 검색을 확장하는 능력을 확인할 탐색 범위가 별도로 마련되지 않음.
2. **레코드 수와 업무 개념의 다양성은 다름.** 단지6,217행이 임대 자격·심사·담당부서·조건 예외를6,217가지 제공하는 것이 아님.
3. **값 변경과 온톨로지 변경은 다름.** 날짜·세대수 정정만으로 개념 추가·정의 수정·별칭 병합·계층 변경을 모두 시험할 수 없음.
4. **업무 시점 정합성이 부분적.** 2015년 규정을2026년 현행 기준이라고 사용할 수 없고, 별도 개정 확인 또는 역사 자료 구분 필요.
5. **기존12과제는 전체 설계의 평가셋이 아님.** 구축·변경 일부와 Local/Global 검색 과제를 포함하지만 역할별 자율 탐색·잘못된 병합·검수 부담을 모두 측정하도록 고정된 과제가 아님. 기존 신규6건도 독립 비노출 평가가 아님.

## 5. 법적 이용 가능성 재검토

### 판정

**법적 분쟁이 절대 발생하지 않는다는 보장은 할 수 없음. 현재 확인된 이용허락을 기준으로 보면, LH 자료 전체가 예정된 용도에 명확히 허용된 상태는 아님.** 이는 불법이라는 판정이 아니라 실사용 확정에 필요한 근거가 부족하다는 판정.

| 자료군 | 확인된 근거 | 이번 판단 |
|---|---|---|
| 전국 LH 단지CSV | [공공데이터포털](https://www.data.go.kr/data/15080989/fileData.do)에 이용허락범위 제한 없음 명시 | 현 묶음 중 재이용 근거가 가장 명확. 출처·기준일 보존 |
| 공고HTML·PDF, 안내문, Q&A, 시행세칙 | 기존 권리 명세는 미확인. 이번 Q&A 게시면·관련 공식 페이지에서도 개별 허락 표시를 확인하지 못함 | 로컬 복제·분석·근거 표시·결과 공개까지 일괄 허락된 것으로 확정하지 않음 |
| 시민 작성 문의 | 기관에 공개됐다는 사실만 확인 | 시민 작성물·개인정보를 별도 취급. 이번 온톨로지 핵심 입력에서 우선 제외 권고 |
| 공식 결정문 | 익명 처리된 공식 공개 문서 | 비실명 공개와 가공·재배포 허락을 구분. 이번 목적에는 필수 아님 |

- [LH 공공데이터 이용정책](https://www.lh.or.kr/menu.es?mid=a10110010000)은 개방목록과 공공데이터포털을 통한 이용 및 미공표 자료의 제공신청 경로를 설명. 정보공개 제도와 공공데이터 개방을 구분하므로 홈페이지 모든 게시물의 포괄적 재가공 허락으로 해석하지 않음.
- 로컬 실행은 외부 전송을 줄이는 방식. 복제·재가공·공개에 관한 권리를 새로 만들어 주지 않음.
- Git에서 원본을 제외하거나 연구·교육 목적이라고 표시하는 것만으로 모든 예정 이용의 허락 문제가 해소되지는 않음.
- 사실·ID·수치와 문서의 창작적 표현·이미지·편집물은 구분해야 함. 짧은 사실 추출 가능성을 근거로 원문 전체나 첨부의 무제한 재배포까지 허용됐다고 확장하지 않음.

### 이 프로젝트에 적용할 실용적인 선정 기준

1. **명시적 허용 우선:** 이용허락 제한 없음 또는 실제 부착된 공공누리0·1유형 등 예정된 이용을 허용하는 자료 우선. 제1유형은 출처표시 등 조건 준수. [공공누리 일반증서](https://www.kogl.or.kr/info/licenseType1.do)
2. **조건부 자료 분리:** 상업적 이용 제한·변경 금지 또는 불명확한 권리는 목적과 산출물에 맞는 허락을 확인한 뒤 포함. 원문을 온톨로지로 구조화하는 모든 행위가 법적으로 동일하다고 단정하지 않으며, 이 프로젝트는 허락이 명확한 경로를 우선 선택.
3. **AI유형 과대해석 금지:** 공공누리는 AI유형도 안내하지만 실제 해당 표시가 있는 저작물에 조건을 적용. 기존 LH 파일에 AI유형을 추정 부착하지 않음. AI유형에도 산출물·인용·재판매 관련 조건이 있음. [유형별 공식 조건](https://www.kogl.or.kr/info/license.do)
4. **실사용 범위를 구체화:** 원문 로컬 저장·파싱·검색/임베딩·LLM 후보 생성·근거 발췌 표시·연구 발표/시연을 구분. 원문 재배포·결과 공개·향후 상업 이용은 각각 허용 범위를 확인. 모델 가중치 학습은 이번 설계의 필수 작업이 아님.
5. **불필요한 개인자료 제외:** 신청인·세대원·대기자 원장이나 시민 이름·연락처를 구축용으로 모을 필요 없음. 조직 자료도 부서·업무 수준을 우선 사용.

## 6. 현재 묶음에서 충분한 묶음으로 가는 최소 보완

### 우선순위1: 권리 확인과 업무 범위 고정

- 시작 범위는 LH 회사 전체가 아니라 기존 자료와 연결되는 **임대주택 모집·자격·서류·심사·입주 안내 업무**로 제안.
- 단지CSV는 유지. 나머지는 자료별 예정 이용의 근거를 확인하고 미확인 자료를 승인된 실사용 입력과 구분.
- 허락 확인이 필요하면 자료 목록·버전·처리 방식·공개 범위를 한 번에 정리해 LH 담당 채널로 문의할 수 있음. 이번에는 문의·제공신청·인증을 수행하지 않음.

### 우선순위2: 기존 원본과 LH 공개자료에서 공백 보완

- 권리 확인 범위에서 이미 보관한 문서의 필요한 절을 넓혀 읽고, 선택 업무의 정의·예외·과정·조직·필드 설명을 연결 가능한 자료로 편성.
- 초기 발견 자료 외에 관련 근거·반례를 스스로 찾을 수 있는 별도 탐색 범위를 마련. 모든 입력 문서를 사람이 질문별로 정답처럼 선별하지 않음.
- 규정·안내·공고는 같은 적용시점을 맞추거나 명시적으로 구·신 버전을 구분.
- 의미·분류·역할·새 용어가 바뀌는 실제 후속 자료를 초기 자료와 분리. 단순 값 정정만으로 온톨로지 확장 성공을 판정하지 않음.

### 우선순위3: 좁은 구축 평가 준비

- 최초 발견 → 추가 근거 탐색 → 후보 검수 → 후속 자료의 변경 검수라는 두 입력 시점을 구성.
- 개념·관계·계층·별칭·변경 유형을 모두 확인할 수 있는 판정 표본과 원문 근거를 별도로 고정. 생성 모델에 정답을 주지 않음.
- 필요한 지식 누락, 잘못된 병합, 근거 없는 관계, 사람의 수정량·검수 시간을 확인. 후보 수·승인율만으로 충분성 판정하지 않음.
- 보완 후 이 범위의 핵심 역할을 실제 실행해야 작동성과 품질을 확정할 수 있음. 이번 검토에서 모델 실행·효용 검증은 수행하지 않음.
