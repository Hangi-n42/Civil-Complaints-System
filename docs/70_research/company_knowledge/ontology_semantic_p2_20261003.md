# P2 출처 역할 선언과 직접 정의 분리

- 대상: #586, 후속 실제 의미 확인 #579. N3/O1의 새 자유 정의가 ‘선정’을 ‘입주 자격 부여’로 확장한 실패에 대해, 프롬프트 반복 대신 새 정의의 표현 범위를 제한.
- 기존 Builder·Revision·Critic·A3 저장 경로 확장. DB·큐·평가 프레임워크 추가 없음. Python 표준 라이브러리와 기존 Pydantic/SQLite 사용.
- 새 `definition_contract=source-role-v1`, prompt v52. 새 계약에서만 역할 지시·wire 분기·복원 처리 적용. 과거 실행은 자동 전환하지 않으며 기존 recipe 변경 시 새 실행 요구 계약 유지.

## 저장과 검수 경계

- 역할 선언: `role_basis={relation_ref, endpoint}`와 설계 사유. 자유 명칭·정의·조건·예외·시점 및 직접 정의 근거의 동시 제출 금지. 명칭은 출처 끝점 표현, 정의는 이 명제 안의 주체/대상 역할이라는 짧은 설명으로 서버 복원.
- 역할 유형의 일반 조건·예외·시점은 비워 둠. 원명제의 의무/허용·부정·조건·예외·시점과 정확한 버전/파싱/블록/구간 근거는 `role_source`에 무손실 보존. 행위 조건을 유형 전체의 필요충분 정의나 발생 사실로 승격하지 않음.
- 직접 정의: 기존 자유 정의와 제공 원문의 `direct_definition_source_refs`를 명시적으로 선택. 근거를 골랐다는 사실만으로 의미상 참을 보증하지 않으며 기존 의미 검수 유지.
- 초기 Builder, 잘못된 끝점 연결을 고치는 Builder, 관측 Revision이 동일한 복원 함수 사용. 저장 raw_output, 정의 선언, 서버 설명과 출처 스냅샷 구분.
- `exact_key`에 역할·출처 포함. 이름과 설명이 같아도 서로 다른 출처/끝점 역할은 자동 합치지 않음.
- 원명제 의미·근거 투영 해시로 역할 유형 검수와 선택 유형에 의존하는 관계 검수의 현재성 확인. 선택 유형 ID/설계 사유/검수 결과는 원명제 해시에 넣지 않아 순환을 피함. 출처 변경·부재·무효 유형은 이전 검수 재사용 불가.
- A3 origin → 정본 modeling_origin → A2 기준 후보 재조회까지 보존. 정본 ID 또는 새 탐색 관계 ID로 재사용할 때 현재 제공된 자연어 명제와 버전/파싱/블록/구간 근거가 모두 같은 경우에만 출처 연결. 저장된 과거 스냅샷만으로 통과시키지 않음.
- legacy 자유 정의→역할, 역할→직접 정의의 명시적 Revision은 실제 before/after/사유 기록. 직접 정의 전환 시 정본의 이전 role_basis/role_source/source_relations 잔존 방지. 외부에서 알려준 오류의 교정은 자율 Critic 발견으로 계산하지 않음.

## 확인과 한계

- 모델 대역으로 실제 생성 경계·정규화·성공 단위 저장·Revision 이력·finish·A3·정본 재조회 확인. 초기/교정 Builder, 잘못된 역할/근거/자유 한정 거부, 서로 다른 역할 구분, 원명제 변경 전파, 승인 ID 재사용의 현재성, 명시적 전환 검사를 포함.
- P2 핵심 집중 검사 결과는 아래 최종 확인 기록에 추가. 실제 생성 호출 0회. 조건부 실제 실행의 성공이나 온톨로지 전체 품질 향상을 주장하지 않음.
- 확대 확인에서 candidates/recovery의 기존 실패 8건 발견. 수정 전 P1 커밋 `8ec30b2`를 별도 임시 복사하여 같은 8건 재현. 기존 분할 검수 호출 순서·회복 상태 기대값 등이 현재 계약과 다른 실패로, P2 변경 범위 밖에 유지. corrections의 이전 분할 검수 대역 4건은 이번 연결 검사를 위해 실제 binding 호출 계약으로 맞춤.
- 직접 정의 분기의 근거 의미 선택, 원명제 자체의 의미 오류, legacy 자유 정의 Critic 미탐(#583)은 여전히 해결되지 않음. 사람 효용 측정은 사용자 지시에 따라 제외. Windows 실기·전체 민원 평가·전체 온톨로지 품질 평가는 수행하지 않음.
- 다음: 새 E-A 자연 진단 → 자연 반박이 있을 때 한 번 교정 및 현재 재검수 → 별도 자료의 정상 직접 정의 대조. 기존 helper로 호출 수를 고정하며, 모두 통과해야 C2 1회와 current 1회를 각각 새 예산으로 준비.

- 7개 변경 연관 검사 파일: **265 passed**, 13 warnings, 42.43초. 마지막 선언 경계 보완 후 roles/contracts의 **83 passed**, 13 warnings, 15.24초 재확인. 경고는 기존 Pydantic의 의도적 잘못된 검수 레코드 대역 직렬화 경고.
