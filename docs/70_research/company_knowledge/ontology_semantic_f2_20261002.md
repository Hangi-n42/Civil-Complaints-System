# F2 원문 명제와 유형 설계 분리

- 관련: #547. 신규 Relation은 자연어 주체/목적어를 유지한다. 이름 일치→유형 ID 치환과 입력 별칭 remap을 적용하지 않고 endpoint_labels는 서버가 원표현에서 보존한다. 기존 legacy ID 출력과 저장 source_relation 읽기는 유지한다.
- Builder만 파생 설계의 subject/object를 유형 ID로 연결한다. bind/defer와 원문 오류 source_error를 구별했다. 원명제 오류는 기존 revision 요청으로 연결하며 다른 타입을 붙여 오류를 감추지 않는다. 잘못된 연결을 제안하더라도 원명제/원끝점은 source_relation에 보존되어 Critic이 별도로 대조한다.
- 역할 지침에서 Relation의 유형 선택 책임을 제거하고 Builder의 역할 설계/상세 자료 공백, Critic의 원명제→유형 연결 대조 순서를 정리했다. 제공 규범 누락은 Relation, 일반 정의 누락은 Concept, 미제공 참조 상세는 source_absent로 구분한다. 단어/조사로 실제 목적어 정답을 하드코딩하지 않았다.
- 신규 원문 끝점과 같은 endpoint_labels는 모델 입력에서 중복 직렬화하지 않는다. 내부 저장은 유지하며 입력 한도/예약 여유는 늘리지 않았다. prompt v26을 사용한다.
- 관련 역할 계약·분석 회귀 111개 통과(12.40초), 기존 경고13개. 신규 자연어/legacy ID, 원문 오류의 수정 경로, 외부 별표 공백과 제공 규범 복구 분리, schema/재개/구간 경계를 확인했다. 실제 모델 호출0이며 지침 준수·오목적어 탐지 성능은 F5 평가 대상이다.
- 다음: F1 독립 검토에서 확인한 복구 focus 확대를 별도 수정한 뒤 F3 후보 비교를 연결한다. 현재 사용자 결정이 필요한 사항 없음.

## 독립 검토 후 실제 입력 경계 보완

- 원문 endpoint 보호 표지가 compact에서 먼저 지워져, 후보 ID와 같은 원문 표현이 실제 prompt에서 치환될 수 있었다. ID 변환을 먼저 적용한 뒤 표시 중복을 생략하도록 순서를 수정했다.
- 실제 make_prompt를 거친 자연어 끝점 보존과 후보 ID 변환을 함께 확인하는 회귀를 추가했다. 관련 계약23개 통과, 실제 모델 호출0. 별도 수정 레시피 v27.1이며 후속 F3는 v28을 사용한다.
