## 3. 입력·정답·노출 경계

c13/c46/c47과 기존 실제 c11을 개발용으로 사용했다. 사전 정답은 c13/c46/c11=entailment, c47=neutral이다. c47의 지역 조건을 뺀 일반 주장은 원문으로 지지되지 않지만, 원문에는 조건 밖의 명시적 면제·금지가 없어 contradiction을 정답으로 두지 않았다. 기존 제품 평가의 `incorrect scope expansion`과 논리적 명시 반증은 다른 기준이다. c11은 양수인 미방문 시 구비서류에 신분증 사본(법인인감증명서 대체)을 포함한다는 부분 사실이며, 목록 전체를 나열하지 않았다는 이유로 거짓으로 처리하지 않는다.

## 6. 공개 요구 명료화의 별도 1회 진단

원래 질문은 “현재 정차 식별자와 좌표”, 공개 criterion은 “실제 행의 ID와 좌표를 함께 확인한다”이며 NODE_ID와 ARS_ID 둘 다를 명시하지 않는다. 기존 검토 의미는 정차 식별자를 NODE_ID로 설명한다. **기존 동결 기대에서 ARS 누락은 실패로 유지하되, 이 관측만으로 원인을 모델의 필드 선택 능력으로 확정할 수 없다.** 공개 요구의 모호함과 평가가 기대한 범위의 차이도 원인 가설로 구분한다.

승인된 후속은 다음 공개 질문 하나다: “제공된 최신 정차표에서 1127번 순번 13의 NODE_ID, ARS_ID, X 좌표, Y 좌표는 각각 무엇인가?” 정답 값·라벨은 넣지 않았다. `bus_explicit_query/freeze.json`에 별도로 동결하고, 같은 snapshot과 제품 코드에서 1회만 실행했다. 원래 requirement ID/revision·criterion·답변 항목의 원문 인용은 유지했다. 제품 binder가 요구하는 기존 인용을 바꾸지 않았으므로 답변 첫 줄은 원래 공개 항목 문장이다. 바뀐 요청 필드는 question 하나지만, 그 안에서 네 필드 이름과 “제공된 최신 정차표”라는 자료 범위 표현이 함께 명료화됐다. 따라서 순수한 필드 이름 변수의 효과로 해석하지 않는다.

실행 `409352a20a414f5bbdf7fb0917eb6ca9`에서 NODE_ID 109000011, ARS_ID 10011, X 127.0407623758, Y 37.6589364195가 직접 셀로 모두 출력됐다. 다른 행값을 추가하지 않았고 최신 제공 범위 미확정은 본문·저장 limitations에 남았다. 이전 두 QA의 코드·recipe·model identity·요청 설정·단계별 system/schema·요청 한도를 그대로 유지했음을 대조했다. 원본 DB·기존 runs·snapshot도 불변이다. 재추출·재평가·제품 패치 확대는 없다.

관측은 **명시한 네 필드를 이 한 번의 제품 실행에서 전달했다**는 범위다. 원래 질문의 A/B 성공, 질문 모호성이 유일한 원인이라는 증명, 일반적인 식별자 의미 해석 능력 또는 최신성 판정의 해결이 아니다. 원래 결과·평가기준은 바꾸지 않았고 추가 반복은 없다.

추가 graph filter+QA 2호출, 입력 7,373/출력 170 tokens, 모델 시간 55.691400초다. 원래 두 질문을 포함한 이번 버스 합계는 6호출, 입력 20,536/출력 577 tokens, 모델 시간 153.632553초다. NLI 분류 비용은 별도다.

## 7. 검증·결론·남은 작업

직접 셀 전달, 원문 불일치·미승인·다른 버전·대체 후보 제외, 필드 혼합 요청의 입력 보존, 미확정 전제와 한계 저장에 대한 관련 검사 38개가 통과했다(0.28초). 기존 업무 검사 34개도 통과했다(45.18초). 후자는 최종 표시·문맥 중복 제거 전 실행이며, 이후 변경은 관련 38개 검사로 확인했다. 마지막 row context 키를 tuple로 고정한 것은 동결 QA에 포함됐다. 이 검사는 모의 선택 응답으로 코드 경계를 검증하므로 실제 모델의 ARS 선택 성공을 증명하지 않는다.

원시 데이터·동결 코드·실패 복사본은 `data/knowledge/evaluations/business_nli_20261009/`에 보존했다. [tracked JSON 보고서](business_nli_20261009.json)에 NLI 실제 입력·기준·logits·토큰 IDs·해시, 버스 두 요청의 원시 모델 출력과 선택 입력, 최종 답변·한계·비용·검사 로그를 포함한다. JSON은 당시 결과 기록이며 재평가로 덮어쓰지 않는다. NLI 스크립트의 원본 해시 검증에는 보존된 로컬 원본 파일이 필요하다.

후속 코드 검토에서 NLI 스크립트의 JSON 읽기·쓰기에 `encoding='utf-8'`을 명시했다. 운영체제 기본 인코딩에 의존하지 않기 위한 두 줄 수정이다. 실제 실행본은 커밋 `0e99f405a28a999a013122d59fbef16bc8972dc8`과 script SHA256 `27f889066a0cc470d001861230f8e7d085a4031890c77654634e598023447842`, 로컬 `compare_business_nli_executed.py`로 보존했다. 기존 freeze/hash/result를 소급 수정하지 않았다. 한국어 JSON 읽기·쓰기 왕복 검사는 통과했고 모델을 로드하거나 재실행하지 않았다. 현재 스크립트와 과거 동결 해시가 다른 것은 이 후속 이식성 수정이며, 과거 실행의 재현에는 당시 실행본을 사용해야 한다.
