# 사건형 원형 교정 경계와 무라벨 최소 편집 진단 — 2026-10-08

시작 커밋은 `cffca5e85d0dd0a0f6a2b7a74f6d74fa25a1561b`다. 기존 c47 심사 실패가 원문 기반 편집안 생성 실패까지 입증하는지 실제 저장 호출을 조사했다. 그와 별도로, `event_entity` 후보를 교정하려면 관계형으로 변환해야 하던 저장 계약의 공백을 수정했다. 두 작업의 성과는 분리한다.

## 기존 실행 대조

현재 worktree의 `business_*` 평가 DB 69개에서 business run 61개를 조사했다. 복사된 기록은 unit ID와 요청 해시로 중복 제거하여 저장 요청 2,663개를 확인했다. **이 수는 이번 새 호출 수나 독립 모델 표본 수가 아니다.** 조사 범위 밖의 저장되지 않은 실행 여부는 확인 불가다.

c47의 canonical ID를 각 요청의 reference map으로 추적했다. 직접 포함된 저장 요청은 requirement_representation 58개와 candidate_source_review 9개이며 후자에는 정규화 재사용이 포함된다. requirement_repair 저장 unit은 2개뿐이었다. 하나는 버스의 사전 판정 대상 c13/c120이고, 다른 하나는 부산 c116(`cc91e765f4ed44e1b10bcbc2ede597a0`)이다. 버스 c13은 부산 정상 대조 c13과 다른 후보다. c47 대상·변경·패치 receipt는 없었다.

따라서 **보유 기록에서 c47에 사전 오류 라벨·원하는 수정문 없이 원문과 후보를 주어 최소 편집안을 생성한 실행은 확인되지 않았다.** c116 성공으로 이 능력을 대신 입증하지 않는다.

## 독립 제품 변경: Event/Entity 유지

기존 `ClaimPatch.role`은 entity_relation/event_relation만 허용했고, 저장 함수는 항상 Head/Relation/Tail을 만들었다. c47처럼 event_entity인 후보는 문장 일부만 바꾸더라도 역할 변환이 필요했다. 이 구현 공백은 c47 심사 오판의 원인으로 입증된 것이 아니다.

- 기존 H/R/T `ClaimPatch`와 native `EventClaimPatch`를 응답의 대안으로 받는다. 두 형식의 사용하지 않는 필드를 한 패치에 함께 요구하지 않는다.
- native raw 스키마는 기존 `ATLAS_SCHEMA['event_entity']`를 사용하고, 실제 적용에서 `normalize`를 재사용한다. `statement`는 서버가 `raw.Event`에서 만든다.
- 원형 역할을 유지하면 변환 이력이 필요하지 않다. 다른 역할로 바꾸면 기존 `conversion_reason` 필수 원칙을 유지한다.
- 기존 후보의 native 교정은 해당 출처 버전과 자기 원문 근거를 요구한다. `scope_record`가 Event와 각 Entity/배열 인덱스 및 원문 주소를 검증한다.
- before, source_extraction_raw, repair_id, Scope 이력과 수정 전후 비교를 보존한다. 적용 후에도 `unreviewed`, `unknown`, `applied_awaiting_recheck`이며 자동 승인하지 않는다.
- 기존 관계형, 정확 원문 표행 보호, 정상 후보 재사용 경로를 유지한다. v8 기본값과 v13 활성 범위·검수→행동 허용 조건은 바꾸지 않는다.

수정 파일은 `app/knowledge/business_models.py`, `app/knowledge/business_run.py`이며 회귀 검사는 `app/tests/unit/test_knowledge_business_event_repair.py`다. 새 검수기나 범용 편집 체계는 추가하지 않았다.

## 무라벨 최소 편집 진단의 동결 조건

직전 비교와 같은 원문 10블록·목록 부모 2관계·c13/c46/c47 원형을 사용했다. 입력 후보는 ID·role·raw만 포함하고, 공개 요구·기존 의미 해석·오류 라벨·원하는 수정문은 제외했다. 정상 유지/필요한 최소 편집/확인 불가를 일반적으로 지시하며 특정 지역번호 조건을 연결하도록 지시하지 않았다.

각 후보의 필수 슬롯은 after_raw 또는 null, 원문 인용, 이유를 반환한다. 역할별 원형 스키마를 사용한다. 새 Scope 해석을 별도로 생성시키지 않는다. 기존 호출·정확 인용 주소 검사·원형 normalize로 **미승인 제안만** 저장한다. 실제 repair/action/판정 receipt를 만들지 않는다.

- 모델: `gemma4:31b-it-q4_K_M`, digest `6316f0629137b426c9d9b853ffc4c8209589f30ee39aebede6285096c0ff47e7`
- 설정: think=true, temperature=0, context 49,152, 출력 한도 8,192, timeout 1,800초
- 요청 SHA-256: `7c45423e3bf5a4a677c5f39887cf37524adf1c46654f786e3e1428bd31be1f03`
- 요청·출력 계약·평가 기준·기존 입력 해시·모델 identity·실행 코드 533개 파일을 호출 전에 동결했다.
- 이 비교는 **최소 편집 과제와 raw 중심 입력·응답 구조의 묶음**이다. 역할 순서 하나의 인과효과를 분리하는 실험은 아니다.

평가에서는 c13의 미방문·양도증명서 날인, c46의 미방문·서류 목록·법인 대체를 원문과 대조한다. 정상 raw 그대로가 최소 편집 계약에 적합하지만 의미가 같은 표현 변경은 불필요한 편집과 의미 손실로 나누어 기록한다. c47은 일반 구비항목과 지역 번호에 명시한 반납 의무를 구별하고, 원문에 없는 반대 규정을 만들어서는 안 된다. unresolved·잘못된 교정·정상 의미 손실·근거/형식 실패면 추가 모델 비교나 프롬프트 재시도 없이 중단한다. 성공해도 기존 검수→유효 판정→행동→적용·보존 재검수 연결이 별도로 필요하다.
