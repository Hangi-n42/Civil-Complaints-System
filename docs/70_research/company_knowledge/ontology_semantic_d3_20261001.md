# 의미구축 D3 — 근거 있는 유형 설계와 의존 묶음 검수

- 대상: #537, 상위 #534. D2 `d026219c38c170f2ddc9efa8df29f3f35c2dc870` 이후 변경.
- 브랜치: `feature/ontology-semantic-improvements`.
- 목적: 원문 관계의 역할·대상을 유형 ID에 연결하고, 유형·관계를 기존 검수 화면에서 개별 편집 후 함께 미리보기·수락할 수 있게 한다.

## 구현과 선택 이유

- 기존 Builder의 `Taxonomy`에 설계 유형 `observations`와 `relation_bindings`만 추가했다. 새 역할/서비스/DSL/규칙 엔진/DB/의존성은 추가하지 않았다.
- 기존 승인·미승인 정의를 먼저 검토하도록 하고, 새 유형은 출처 관계 ID와 추상화 이유를 갖는 `design_proposal`로 제한한다. Concept의 명시 유형, 용어·개체·값은 별도로 유지한다. 미제공 법적 정의나 별표는 자료 공백으로 남기도록 한다.
- 현재 묶음이 맡은 원문 관계만 연결할 수 있다. 비교용 다른 묶음의 관계를 덮어쓰지 않으며, 새 t1~t5 참조는 기존 동일 이름 ID와 분리한 뒤 서버 ID로 매핑한다. 미제공·잘못된 종류·검증 오류 타입과 이름만 같은 모호한 대상을 연결하지 않는다.
- 원문 관계 ID·술어·조건·OR·주체별 분기·시점·극성·근거를 그대로 보존한다. Builder는 끝점 연결과 설계 이유를 제안하며 서버가 별도 스키마 설계 표현을 구성한다. 원문 진술과 설계는 changeset origin 및 정본/LinkML의 modeling_origin에서 구분된다.
- 새 유형과 설계 관계를 assemble 비교, 묶음 소속, Critic, 수정, finish, 용어 조회, A3 매핑까지 연결했다. 원래 Builder 입력을 유지하여 재개 시 성공 결과를 재사용한다. recipe는 `discovery-a2-v17`이다.
- 원문 규범을 그대로 일반 슬롯 사실로 수락하거나 의무를 `required=true`로 번역하지 못하게 검사한다. 설계 유형은 revision의 explicit 출력에도 설계 상태를 유지하고, A3와 후속 기존 정본 수정에서도 설계 출처를 확인한다.
- UI는 기존 폼·근거 선택·수동 제안·복수 decisions를 재사용한다. 후보별 편집 저장 후 명시 선택한 유형·관계 묶음을 미리보기·수락한다. 미선택 의존의 자동 추가와 하나의 patch 복제는 없다. 기존 유형 선승인 경로도 유지한다.
- 기존 schema-preview에 선택 ID 쿼리만 추가해 실제 수락과 같은 의존 검사를 적용한다. 저장 상태나 버전은 변경하지 않는다. 관계 domain/range는 class만 선택하고 계층·어휘 선택 계약은 유지한다.
- 다른 이름의 자동 same/changed 차단은 유지한다. 사람이 기존 이름·정의를 선택하여 기존 정의 유지/정의 변경을 명시하는 경로는 수동 update 제안으로 저장하며 근거·반례·사유·전후·결정자를 보존한다.

- 설계 유형을 revision이 explicit으로 바꾸려는 반례, 기존 정본의 설계 출처가 있는 유형을 명시 정의로 바꾸려는 후속 수동 제안, 규범의 required 승격을 차단했다.

- 미승인·보류된 의존 유형을 빼고 관계만 미리보기/수락하면 실패한다. 재개는 새 모델 대역 호출 없이 설계 결과와 ID를 재사용한다. 사람 편집·결정은 원 모델 결과와 별도 이력으로 남는다.
- API 선택 ID·범위 밖 ID·미리보기 무변경 assertion 보강 후 해당 테스트 **1 passed / 1.00s**. 실제 구절의 주체별 분기까지 포함한 최종 묶음 회귀 재확인 **2 passed / 1.70s**.

- 전문가 좁은 검토에서 지적된 기존 반례 소실과 revision 설계→explicit 승격 경계를 수정하고 해당 회귀를 포함했다.

## 한계와 다음 작업

- 원문 구절은 실제 고정 자료지만 모델 출력·검수 결정은 결정적 시험 대역이다. 역할 설계의 실제 모델 품질이나 사람 작업 효용을 측정한 결과가 아니다. 특정 클래스명·그래프 또는 기존 8개 후보의 수락을 정답으로 강제하지 않았다.
- 실제 LLM 추가 호출, 원래 C2 재평가, 실제 모델 출력의 브라우저 종합 경로, Windows 실기는 이번 단계에서 실행하지 않았다. 기존 원장·모델 출력·원본 데이터·환경 파일은 변경하거나 커밋하지 않는다.
- 다음 #538 연결 보완 이후 #539에서 고정 기준의 실제 모델·브라우저 경로를 한 번 비교한다. 참가자 없음과 사람 효용 미측정 상태는 유지한다.
- 현재 사용자 결정이 필요한 사항 없음.
