# 버스 정량 시연 자료 연결과 LH 시연 범위

- 작업일: 2026-09-29
- 진행 이유: 민원 원문 확보에서 실제 계산 입력 준비로 전환. 버스는 현행·변경 후보·보행·이용 기록을 연결하고 LH는 운영 원장의 공개 확보 여부에 따라 범위 결정.
- 자료 묶음: [사용 안내와 재생성 방법](../../../configs/knowledge/demo_preparation_20260929/README.md).
- 결과: **버스 현행 정차·승하차 연결 완료, 변경 후보와 보행망 보완 완료. 전체 변경 정차 순서와 실제 보행 접속은 미확정. LH는 문서·조건 변경 영향과 근거 검토로 범위 명시.**
- 서비스 반입, 전후 거리 계산, 화면 구현, 커밋·푸시는 이번에 수행하지 않음. 기존 PRD와 작업 트리 변경 보존.

## 1. 실제 버스 민원을 정류장에 대응

- 2026-09-04 실제 1127번 민원 본문과 지도 4장 직접 대조.
- 현행 정차 60개를 유지 가정·재구성·제외 후보·미확정으로 분류.
- 시민이 경유를 요구한 지점에 대응하는 실제 정류장 후보 46개 확보.
- 부분 분석안 4개와 기존 노선에서 순서까지 확인한 참고 구간 8개 저장.
- [정차 대응표](../../../configs/knowledge/demo_preparation_20260929/bus_change_proposal.md), [기계 판독 JSON](../../../configs/knowledge/demo_preparation_20260929/bus_change_proposal.json).

**전체 변경 정차 목록을 확정하지 못한 이유**

- 원문이 남측 구간을 단방향으로 순환할지, 기존 반환 정차를 유지할지 유일하게 정하지 않음.
- 창동역 이마트 부근의 방문 순서·U턴 위치·실제 승강장 선택이 개략 지도만으로 확정되지 않음.
- 신규 우회로의 도봉보건소는 기존 중앙차로 정류장과 다른 후보. 창동역도 지도에 맞는 남서측과 역 동측을 구분해야 함.
- 확인되지 않은 회전·승강장 이용을 사실로 채우지 않음. 전체 승인 노선 대신 부분안과 미해결 선택을 보존.
- 현재 권장: 확인 가능한 부분 구간부터 비교. 전체 시나리오는 담당자가 분석 가정을 명시한 뒤 별도 버전으로 고정.

## 2. 보행망 보완

| 항목 | 결과 |
|---|---:|
| 도봉·강북·노원 병합 노드 | 25,336 |
| 병합 링크 | 32,758 |
| 끝점이 존재하고 보행 통행 허용인 링크 | 32,473 |
| 기존 도봉 누락 링크 | 123 → 48 |
| 이웃 구 자료로 끝점이 복구된 도봉 링크 | 75 |
| 병합 전체 끝점 미해결 링크 | 278 |
| 정류장별 보행 접속 후보 | 254개 정류장, 각각 3개 노드 |

- 278개는 도봉48·강북67·노원163개. 지역 확장으로 포함된 바깥 경계의 미해결 자료까지 함께 기록.
- 도봉의 남은 끝점31개 중10개를 좁게 조회했으나 정확한 노드 없음. 다음 조회는 잘못된 JSON 응답으로 실패해 원본 보존 후 나머지20개 조회 중단.
- 끝점 없는 링크를 계산용 보행망에 포함하지 않고 미해결 목록으로 보존. 링크 형상에서 노드를 만들어 공식 원본 확보로 처리하지 않음.
- 254개는 현행60개, 제안 관련 추가31개, 주변 후보163개. 제안46개 중15개는 현행과 중복.
- **접속 후보는 직선 근접 후보이며 실제 보행 접속 확정은 0개.** 학교·시설 출입구, 도로 측면·횡단과 승강장 접속을 선택 경로에서 확인해야 거리 비교 가능.
- 278개 전부를 복구하는 작업을 선행 조건으로 두지 않음. 선택한 경로가 누락의 영향을 받는지 확인하는 범위로 제한.
- [보행 집계](../../../configs/knowledge/demo_preparation_20260929/walk_summary.json), [서울시 원문 출처](https://data.seoul.go.kr/dataList/OA-21208/S/1/datasetView.do).

## 3. 승하차 자료와 대체 후보 연결

- [서울시 2026년 8월 노선·정류장·시간대별 승하차 CSV](https://data.seoul.go.kr/dataList/OA-12913/S/1/datasetView.do) 실제 다운로드: 15,602,085바이트, 42,578행.
- 2026-09-02 정차 원장의 노선명·NODE_ID와 이용 자료의 노선번호·표준버스정류장ID로 연결. 반복 정차는 원본 역명에 포함된 순번이 유일하게 대응할 때 구분.
- 현행1127 **60/60 연결**, 월간 승차118,363건·하차116,655건. 시간대별 원본도 별도 보존.
- 실제 변경 후보46개 모두 현재 경유 노선과 하나 이상의 이용 기록 연결. 새1127의 미래 이용량으로 해석하지 않음.
- 현행1127과 정류장을 공유하는 다른37개 노선, 정차관계157개 확보. 정류장 원장157/157 연결, 이용자료135개 단일대응·18개 중복미해결·4개 미연결.
- 후보 주변까지 포함하면40개 노선·2,986개 정차. 이용자료2,738개 단일대응·78개 중복미해결·170개 미연결. 미확인 이용량은 빈칸으로 보존.
- 107번의 핵심 시연 밖 정류장1개에서 표준ID는 같지만 ARS가 다른 기록 확인. 원본 두 값을 보존하고 불일치 필드 추가.
- 36·118은 현 노선 원본에 없어 연결하지 못함. 실제 미운행으로 판정하지 않음.
- **공유 정류장 존재와 대체 이동 가능성은 구분.** 정차 순서를 보존했으며 같은 목적지·방향과 시간 조건을 확인한 뒤 대체 수단으로 표시.

### 실제 연결로 드러난 검토 대상

- 수유 진입 제외 후보인 현행28~32순번5개 정차에는 8월 **승차19,467건·하차21,208건**의 기존 이용 기록 존재.
- 따라서 창동역 접근 개선만 보여주지 않고 이 구간의 기존 이용과 대체 연결을 함께 검토할 입력이 마련됨.
- 위 값은 월간 승하차 건수. 고유 피해 인원, 변경 후 감소량, 민원 발생 예측값이 아님.
- [연결 집계](../../../configs/knowledge/demo_preparation_20260929/ridership_summary.json).

## 4. LH 운영 자료 조사 결과와 현재 범위

- [별도 조사 보고서](lh_operational_data_availability_2026-09-29.md)에 공개 단지·공가·공고 API의 필드와 실제 접근 결과 기록.
- 계약정보·예비입주자 순위 조회는 비로그인 요청에 인증서 로그인 요구. 공개 조회로 동일 공급군의 동호·배정·대기 원장 확보 불가.
- 공개 공가 자료는 과거 단지·공급계층별 집계. 개별 동호·계약·대기 상태 원장을 대신하지 못함.
- **현재 LH 시연 범위: 공고·조건·근거가 바뀌면 연결된 업무 지식·안내·답변 중 무엇을 재검토해야 하는지 확인.**
- 실제 동호·계약·대기·수선 운영 영향은 같은 기준시점과 가명ID로 연결한 기관 원장 확보 후 확장.
- 공개 결정문은 당시 판단 근거 재현 자료로 구분. 실제 이행 효과로 표시하지 않음.
- 기관 연락·제공 신청·계정 인증은 하지 않음.

## 5. 확인 범위와 다음 작업

- 기존 Python 환경에서 재생성 스크립트2개 실행. 별도 서비스·큐·그래프DB·신규 의존성 없음.
- 현행60개 정차의 식별자와 월간 합계를 원본과 대조. 독립 에이전트가 이용량 중복배정0건, 미연결0치환0건 확인. 추가 ARS 불일치는 산출물에 반영.
- 보행 통행코드, 끝점 존재, 현행·제안 후보 포함 여부를 실행 중 확인. 실제 보행거리나 개선 효과를 검증한 것은 아님.
- 다음 버스 작업: 선택한 부분안의 출발지·승강장 접속 확인 → 접근거리와 기존 직결 연결 변화 계산 → 근거와 함께 검토 화면에 연결.
- 다음 LH 작업: 양산 공고군의 실제 변경 항목을 고정하고 해당 조건·안내·답변의 의존 관계 연결.
- 사용자 선택: 원문에서 확인되는 부분 구간부터 비교하거나, 명시적인 분석 가정을 두고 전체 노선 시나리오 구성. 전체안 미확정은 승인 절차 때문이 아니라 원문에 필요한 정보가 없는 문제.
