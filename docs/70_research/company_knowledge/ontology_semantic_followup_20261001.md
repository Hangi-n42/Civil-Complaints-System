# 유형 분류·개념 대응·조건부 관계 보완

- 추적: [#534](https://github.com/Hangi-n42/Civil-Complaints-System/issues/534), `codex/ontology-quality-workflow`의 `bce08c3` 다음 보완.
- 근거: 이전 실제 `changed_current_fixed`와 `changed_types_purchase` 결과. 이전 실행·정답·비용 기록은 보존한다.
- 전제: 기존 A2 관측/관계와 A3 미승인 변경 계약을 사용한다. 개체를 일괄 유형으로 승격하거나 새 규칙 실행기·메타모델을 만들지 않는다. 사람 효용은 참가자 부재로 미측정이다.

## 구현 전 계획

1. 유형/개체/값의 판단 기준을 역할 입력에 명시한다. 반복 적용되는 대상 집합·절차의 정의는 유형 후보, 개별 식별 대상은 개체, 실제 속성의 값은 property_value이다. 규칙 문장 전체를 값으로 처리하지 않고 Relation이 조건부 주장을 추출하도록 한다. 원문이 부족하면 unresolved로 보존한다. 공유·비교 문맥의 정의 반복보다 focus의 후보와 필요한 관계 끝점을 우선한다.
2. 개념 대응의 원문 관측을 유지하면서 A3의 기존 target 갱신을 보수적으로 제한한다. 명시적인 same/changed에 더해 관측 명칭과 기준 명칭이 같은지 확인한다. 다른 명칭의 대응은 동일 대상을 입증한 것으로 간주하지 않고 미해결/보류로 남긴다. 이름 일치 자체로 자동 대응을 만들지는 않는다. 별개(distinct)는 새 제안이다. 명칭 변경·동의어를 자동 처리하지 않는 한계를 기록한다. 분양전환→국민임대 오대응, 같은 이름의 유효 정의 변경, 불확실·별개 대응을 회귀 확인한다.
3. 관계 추출을 끝점의 유형 등록과 분리한다. 주체/술어/대상·조건·시점·진술 성격을 원문에서 먼저 추출하고, 제공된 유형 ID가 있으면 연결한다. 없으면 원문 명칭과 구체적인 공백을 남겨 관계를 버리지 않는다. A3는 제공된 유효 클래스의 유일한 동일 명칭만 ID로 연결할 수 있고, 개체/어휘/모호한 끝점은 자동 클래스 생성 없이 검수 보류한다. 주체별 조건과 대안(OR)을 분리해 무조건 관계로 넓히지 않는다.
4. 기존 서버 발급 ID·quote/span·버전·parse 참조, revision 이력, 허용 scope/step과 예산 경계를 유지한다. recipe 버전을 올려 이전 성공 단위에 새 프롬프트를 섞지 않는다.

## 전문가 검수 요청

- 의미 검수: 유형과 개체 기준, 개념 대응 보류의 적정성, 조건부 규칙을 기존 관계로 표현할 때 의미 손실/거짓 유형 승격이 없는지 확인.
- 실행 검수: A2→A3의 끝점 연결·validation·수락 경계, 과거 실행 재조회와 캐시 계약, 최소 회귀 확인을 점검.
- 코드 수정 전에 검수 의견을 반영한다. 후보 수 증가나 구조 검사 통과를 의미 정확성으로 보고하지 않는다.

## 확인 기준

- 잘못된 다른 명칭 대응으로 기존 정의를 바꾸는 update가 생성되지 않는다. 유효한 같은 개념의 근거 보강/정의 변경과 이전 ID 재사용은 유지한다.
- 일반 유형/실제 개체/값의 경계, 유일한 클래스 끝점/동명 중복/개체 끝점, 조건·시점·정확한 근거 보존을 관련 단위 테스트로 확인한다.
- 이전 노출 개발 사례 current/types_purchase를 기존 생성 설정·정답·모델 digest·24호출/1800초 상한 그대로 새 출력 디렉터리에서 각 1회 확인한다. 수정 재실행이 필요하면 실패와 최초 비용을 별도 보존한다. 실제 모델 실행 중 코드는 바꾸지 않는다.
- current: 건설/매입 포함 정의와 주체별 선정 조건. types_purchase: 잘못된 국민임대 갱신 차단, 유효한 기존 ID 대응, 제37조 대상/지원/승인/개량 조건을 대조한다. 누락·미처리·미승인과 비용을 그대로 보고한다.
- 전체 제품 시험·Windows 실기·사람 시험·운영 승인·배포·PR 병합은 이번 확인에 추가하지 않는다.

## 구현 전 전문가 검수 반영

- 의미 전문가와 실행/근거 전문가가 코드 및 이전 실패를 독립 검수했다. 규칙 전체를 class로 옮기지 않고 명명된 대상/과정 정의와 규범 명제를 구분한다. 허용(`할 수 있다`)·의무·OR와 주체별 조건을 보존한다.
- 끝점 명칭 연결은 A3의 전체 후보 검색 대신 **해당 호출에 실제 제공된 supplied**에서 수행한다. 유일한 유효 type만 연결하고 원래 표기를 남긴다. 명시 entity/vocabulary ID를 동명 class로 우회 연결하지 않는다. 동명 복수는 보류한다.
- 다른 명칭 same/changed를 보류하는 것은 보수적 방어이며 동명 동치 증명이 아니다. 동의명/명칭 변경은 사람의 별도 검토가 필요하다.
- 이미 게시된 잘못된 update도 수락되지 않도록 기존 A3 validation에서 동결 원 관측/대응/기준 명칭을 대조한다. 과거 원장·수락 버전을 덮어쓰지 않는다.
- 구현 독립 검수에서 미제공 ID가 다른 분석 묶음의 클래스에 연결되는 우회를 재현했다. A2에 `unresolved_endpoints`를 기록하고 A3까지 유지해 자동 연결·일괄 수락을 차단했다. 사람의 명시적 끝점 수정은 기존 검수 경로를 사용한다.

## 구현과 기능 확인

- `discovery-a2-v13`: Concept/Relation 지시 수정, supplied 안의 끝점 해소 상태와 원래 명칭 기록. 미해결 관계는 사라지지 않으며 임의 클래스를 생성하지 않는다. 새 스키마 종류·의존성·LLM 역할·모델 호출 단계 추가 없음.
- A3: 다른 명칭의 same/changed는 미해결 새 제안으로 보류. 유효한 같은 명칭 대응의 target ID·근거 보강·정의 변경은 유지. 동일 명칭만으로 대응을 새로 만들지 않는다.
- 기존 게시 후보 validation은 합쳐진 관측의 모든 대응을 검사한다. 과거 승인 버전이나 원본 후보를 덮어쓰지 않는다. 원래 잘못된 대상에 연결된 업데이트는 거절하고 올바른 대상으로 다시 제안해야 한다.
- Python 3.11.9에서 관련 세 테스트 파일 **119개 통과(10.90초)**. 미제공 ID 우회·동명 복수·명시 entity ID·revision ID 보존·과거 합쳐진 대응·원문/조건/허용/OR 저장·의존성을 포함한 수락과 기존 재개/근거 경계를 확인했다. 합성 출력 테스트는 실제 모델의 의미 정확성 증명이 아니다.
- 의미 전문가의 구현 검수에서 추가 차단 결함 없음. 실행 전문가는 발견한 미제공 ID 우회 수정 후 같은 합성 재현에서 일괄 수락 거절과 사람 수정 경로를 확인했다. 전문가별 좁은 테스트 17개/23개는 위 전체 테스트와 중복되므로 합산하지 않는다.
- 이전 실제 types_purchase의 잘못된 분양전환→국민임대 후보 `oc_0e6131bea74c41199a98b20d1018cb36`를 원장 사본에서 재조회: `can_accept=true → false`, 명칭·대상 동일성 미확인 오류. 원본 DB 해시와 전체 저장 changeset payload 불변, 모델 0회. 기록: `data/knowledge/quality_20261001/semantic_v13_legacy_guard/result.json`.

- `conditional_generation_v15.json`을 실행 전에 고정: 같은 제15조/C2·모델·정답 기준, 5호출·추가 라운드 0·revision 0의 기본 분석/검수만 수행한다. 모델 시간 상한을 늘리지 않는다. 최종 v15 관련 세 파일 **119개 테스트 통과(12.69초)**.

## 최종 v15 결과와 한계

- **5 HTTP 호출, 모델 345.329초, 경과 350.268초**, 결과 partial. 원본 DB·실행 코드 해시 불변. 기록: `data/knowledge/quality_20261001/semantic_v15_conditionals/result.json`.
- 관계 4개는 모두 affirmed이며 원문 quote/span 검사 오류가 없다. 선정 목적어는 `국민임대주택 입주자`, 공급 전제·별표4 원칙·잔여주택 일부 완화/선착순 선택·제1항 예외를 보존한다. 두 권한 관계는 LH/지자체·지방공사 분기·지역 고려·제1/2항 예외를 각각 보존한다.
- 권한 관계의 인용은 본문 `[213,394]`와 LH `[413,446]` 또는 지방 `[447,539]` 구절을 포함한다. 독립 의미 전문가가 원문을 대조해 이전 목적어·조건·인용 지적의 해소를 확인했다. 장관 관계의 지방 각호 추가 인용은 불필요 문맥이며 의미를 바꾸지는 않는다.
- Concept의 사업자·지방공사에는 인용 validation 오류가 남는다. 관측 5개의 근거 성격은 모두 unresolved이다. 규범에서 묶은 `기준 설정 주체`는 설계 판단이며, 명시적 독립 유형 발견으로 단정하지 않는다.
- Critic은 `관계 판단 인용이 제공 원문과 불일치`로 실패했다. 실패를 성공으로 바꾸거나 인용 검사를 완화하지 않았다. 필수 미처리 2개, 검수 미완료 후보 7개, 미해결 복구 요청 1개가 남았다. 추가 호출·수정은 고정한 5회 범위에서 수행하지 않았다.
- A3 관계 4개는 실제 끝점의 클래스 정의가 미확정이므로 모두 unresolved/deferred이다. 전체 변경 후보 8개가 현재 수락 불가이며 자동 승인·운영 활성화는 없다. 원문 관계 산출 개선과 수락 가능한 온톨로지 완성을 구분한다.
- 이번 세 실제 실행은 총 **23 HTTP 호출·모델 1,729.647초**를 사용했다. 실패/중단 비용을 포함한다. 결과 해시는 `semantic-followup-evidence-index.json`에 기록했다. 원장 사본 점검은 모델 0회다.
