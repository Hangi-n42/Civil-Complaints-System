# 원문·후보 행위 범위 차이 비교 — 기각 결과

기준 코드·기록은 `da21b67323a040f2307e63d4f2861cea6776ea25`다. **동결한 대체 과제 1회는 c47 범위 확대를 검출하지 못해 기각했다. 제품 반영·후보 교정·후속 평가 실행은 0이다.** 아래 계획은 모델 호출 전에 저장·공유했고, 원본은 실행 자료의 `pre_call_plan.md`와 해시로 보존했다. 기존 네 실행은 다시 호출하지 않았다. 이 문서의 평가 정답은 모델 입력에 넣지 않았다.

## 문제와 비교 단위

`direct_narrow`와 `direct_source_reference`는 c13·c46을 정상으로 보존했으나 c47도 supported로 판정했다. 후자는 정확한 `source_exposed` 원문 해석까지 받았다. `source_blind`의 일반 반납 확대와 `source_exposed`의 올바른 구분을 함께 보존한다. 기존 해석 제거가 해결책이라는 전제는 사용하지 않는다.

현행 직접 검수에도 주체·행위·조건·양태와 범위 확대를 대조하라는 지시가 있다. 이번 변경은 그 문구를 추가하는 것이 아니라, 후보 전체의 supported/incorrect 출력 대신 **각 행위가 어떤 대상·조건에 연결되는지 원문 측과 후보 측을 병렬 출력하고 차이를 지목하는 과제**다. `direct_narrow`의 사용자 입력은 바이트 단위로 그대로 사용한다. 정답·오류 표시·교정문·이전 모델 해석을 추가하지 않는다.

## 출력과 서버의 역할

각 후보를 한 번씩 포함하는 `checks`를 반환한다. 한 check는 다음만 담는다.

- `claim_id`, `candidate_fields`: 실제 검토한 후보와 실제 필드 경로.
- `evidence`: 제공된 원문 주소 선택. 주소·인용문을 생성하지 않는다.
- `source_scope`, `candidate_scope`: 각각 짧은 행위 항목 목록. 항목은 `target`(주체/대상), `action`, `condition`(바로 그 행위의 적용 조건), `form`(구비 항목/행위 의무/기술/미확정) 네 필드다. 조건과 행위의 연결이 다르면 별도 항목으로 표현한다. 긴 새 사실 목록이나 논리식·중간 의미 ID는 만들지 않는다.
- `difference`: `none`, `unsupported_scope`, `contradiction`, `unresolved` 중 하나. `none`은 후보가 표현한 범위에 차이가 없다는 뜻이며 원문 전체의 완전한 추출을 뜻하지 않는다. 범위 추가·조건 일반화는 `unsupported_scope`로, 원문의 명시적 반대와는 구별한다. 원문·해석 부족은 `unresolved`다.
- `reason`: 실제 후보 필드와 원문 행위·조건 사이의 차이 또는 동등성을 짧게 설명한다.

모델은 의미의 대응과 차이를 산출한다. 서버는 후보 ID·필드의 실재 여부, 제공 원문 주소, 실행 receipt를 검증하고 정확한 인용·버전·위치를 복원한다. 문자열 일치나 조건의 빈칸만으로 의미 오류를 새로 판정하지 않는다. 차이가 검증되면 기존 교정 입력의 해당 후보·필드로 전달한다. `unsupported_scope`는 기존 호환 상태상 교정 대상이더라도 외부 법률상 거짓으로 바꾸지 않는다. `unresolved`는 오류 검출 성공으로 세지 않는다.

이는 별도 E 의미 목록과 scope 인덱스, 효과·조건 이중 판정, 기존 전체 후보 투표를 함께 요구했던 과거 v12 경로의 복원이 아니다. 새 호출을 기존 검수 앞뒤에 직렬 추가하지 않는다. 성공할 때만 기존 직접 검수를 대체한다.

## 고정 요소·변경 요소

- 고정: 이전 `request_direct_narrow.json`의 10개 원문 블록·부모 관계·원문 버전·c13/c46/c47 원시 필드·사용자 메시지·참조 매핑, Qwen 모델 digest·temperature 0·think false·context 49152·output 8192, c116 교정 이후 부모 DB와 원본 DB.
- 변경: 시스템 과제와 출력 계약을 하나의 대안으로 교체한다. 새 스키마의 주소 선택지는 실제 제공된 10개로 한정한다. 기존 좁힌 입력 스키마에 남아 있던 미제공 주소 선택지는 제거한다.
- 해석 한계: 여러 출력 요소와 시스템 과제가 함께 바뀌므로 단일 필드의 효과로 귀속하지 않는다. 한 실행의 채택 여부를 확인하는 개발 노출 사례이며 일반화나 모델 우열을 입증하지 않는다.

## 실행·채택·중단 기준

1. 실제 요청·출력 스키마·모델 설정·기존 결과 해시·평가 기준을 저장하고 조율 세션에 공유한다. 평가 파일은 모델 메시지에서 제외한다.
2. 세 후보를 한 호출로 Qwen에서 실행한다. 캐시 재사용 0, 자동 재시도 0. 기존 네 결과가 기준선이다.
3. c13의 미방문 조건/양도증명서, c46의 미방문 조건/대리 서류/법인 대체 항목을 유지하고 `none`으로 대조해야 한다. 부모·자식 원문을 근거로 사용해야 한다.
4. c47은 실제 `raw.Event`에 대해 일반 번호판 변경 시 2매·봉인의 구비와 지역 번호에 한정된 반납 후 변경을 구분하고, 후보의 일반 반납 확대를 `unsupported_scope`로 특정해야 한다. 정상 항목·수량·지역 조건을 보존한다. 원문이 비지역 번호 반납을 금지한다고 주장하면 실패다.
5. 오인용·다른 후보로 오류 전가·새 기간/효과·정상 후보 훼손은 실패다. 형식 통과·보류 증가·그럴듯한 reason만으로 채택하지 않는다. 같은 오판이면 프롬프트·필드·검수층·동일 모델 호출을 늘리지 않고 기각 결과를 저장한다.
6. 실제 차이 검출과 정상 보존이 성립할 때만 기존 직접 검수 대체 구현과 c47 최소 교정 → 저장 후보 보존 재검수 → 원래 R05 → 그래프/검색 → 같은 QA로 진행한다. c116 교정·전체 추출을 반복하지 않는다. 부산 이후 필요한 정상 대조만 검토한다.

## 실제 실행과 원문 대조

새 실행은 `8f558efe88a84662b49ee44e2eb59c94`, unit `11079fee7e0f49da8f29c9e0ff01b01a`다. 2026-10-08 01:31–01:32 KST에 수행했다. 모델은 `qwen3.8:27b-q4_K_M`, digest `25b843619e944cd0ae6069f94ff4e5e26a16e109ccbc0a66a0f05979ed70098e`다. 실제 요청·실행 한도는 모두 context 49152/output 8192/think false이며 temperature 0이다. 제공자가 보고한 입력/출력은 **1642/770 토큰**, 호출 시간은 **53.119097초**다. 실제 호출 1, 응답 재사용 0, 자동 재시도 0이며 정상 stop으로 끝났다.

| 항목 | 실제 출력 | 원문 대조 결과 |
|---|---|---|

c47의 실제 `raw.Event`는 “번호판 변경 시 기존번호판 2매 및 봉인을 반납하여 번호를 변경한다.”다. 제공 원문 b32/e47은 다음이다.

> 번호판변경시 기존번호판 2매 및 봉인(지역 번호는 반드시 기존번호판 2매 및 봉인 반납 후 번호 변경하여야 함)

모델이 두 측에 공통으로 출력한 항목은 다음과 같다.

```json
{"target":"번호판 변경 시 구비서류","action":"반납하여 변경한다","condition":"번호판 변경","form":"listed_item"}
```

이 출력은 “구비서류” 문맥의 번호판·봉인 항목과 괄호 안 지역 번호의 반납 후 변경을 하나의 일반 반납 행위로 만들었다. reason 역시 “‘번호판변경시’ 조건 하에 … 반납 후 번호 변경을 명시”한다고 설명하며 지역 한정을 빠뜨렸다. 원문이 비지역 번호의 반납을 금지하거나 그 반납이 법적으로 거짓이라고 판정한 것은 아니다. 문제는 **제공 원문보다 넓어진 후보의 주장 범위를 검출하지 못했다**는 점이다.

e47의 전체 텍스트·지역 번호 문구·source version·parse run·정확한 span은 raw 참조에서 정상 복원됐다. 따라서 이번 관측은 주소 생성·복원 오류, 출력 잘림, 입력 용량 초과로 설명되지 않는다. 원문 측 항목 자체를 잘못 작성한 뒤 양측이 같다는 판정을 낸 출력상의 실패다. 후보에서 원문으로 복사했는지 등 모델 내부 원인은 확인 불가다.

## 검증과 남은 작업

오프라인 검사로 동결 파일·런타임 해시, 동일 사용자 메시지와 참조 매핑, 모델 digest·설정·실행 한도, 실제 호출 수, 후보 필드 실재 여부, 정확한 근거 복원, 부모 DB 및 후보·블록·요구·평가·교정·그래프·개념 불변을 확인했다. 원본 DB도 기존 SHA `62f6eda378eb1258d84c6b85e6b2ce414a595fcbeef62260b6cdae22a7fecde3`를 유지했다. 이 검사는 의미 품질 통과가 아니다.

제품 코드·기본 경로·후보 변경 0, 신규 교정 0, R05·그래프·검색·QA·버스 확장 0이다. c116 교정·추출을 반복하지 않았다. #616/#617/#620의 필수 결과는 미완료이며 열어 둔다. 제품에 연결하기 위해 준비한 별도 패치도 없다.

남은 병목은 의미 대응이다. 거시적으로는 정확한 근거 주소와 실행 이력이 있어도 잘못된 의미 연결을 자동 승인·교정할 수 없다. 미시적으로는 한 문장 안에서 일반 구비 항목과 지역 한정 행위의 연결을 분리하지 못하고, 넓은 항목 이름만으로 정상 후보 세부 대조도 생략했다. 이 실패를 또 다른 판정층이나 기본 경로로 옮기면 잘못된 정상 승인과 근거 부족한 교정을 뒤 단계에 전달한다.

다음 검토는 같은 프롬프트 반복이나 필드 확장 대신 **행위와 제한어의 실제 대응을 모델이 구분하는가**를 판별할 과제·모델 대안을 별도로 정의하는 것이다. 이번 결과에서 그 대안의 성공을 예측할 근거는 없다. 예를 들어 출력 재작성 부담을 줄인 제한어–행위 선택 과제를 고려할 수 있지만, 선택지를 만드는 서버/모델의 해석이 정답을 미리 주입하지 않는지 먼저 검토해야 한다. 이는 미채택 제안이며 새 비교·모델 호출을 수행하지 않았다. 안정적인 정상 의미 보존과 실제 오류 검출 증거가 나오기 전에는 실제 교정·R05 연결의 완료를 주장할 수 없다.

현재 사용자 결정이 필요한 사항 없음. 승인된 범위의 기각 증거 저장·검증·커밋·푸시까지 마무리하며 후속 판단은 조율 세션에 전달한다.
