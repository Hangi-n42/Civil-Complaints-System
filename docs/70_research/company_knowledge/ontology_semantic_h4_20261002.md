# H4 실제 C2 평가: 조건·유형 연결 개선과 수정 후 최종 미달

- 대상 #560, 상위 #534·#539. H1~H3의 최종 제품 결과를 G4 저장 결과와 비교했다. 여러 변경과 예산 확대가 함께 적용됐으므로 개별 변경의 인과효과나 같은 비용의 효율 향상을 주장하지 않는다.
- **C2 자동 구축은 미달이다.** 초기에는 세부 조건을 보존하고 네 관계 모두 유형에 연결했지만, Critic의 잘못된 누락 판정 뒤 revision이 자연어 끝점을 유형 ID로 대체했다. 최종 전체 미리보기는 유효하지 않다. 사전 중단 기준에 따라 두 문서 current는 실행하지 않았다.

## 무엇이 개선됐고 어디에서 실패했는가

- G4에서 빠진 지방공사의 `제49조에 따라 주택사업을 목적으로 설립된` 한정이 이번 초기 Relation의 조건에 포함됐다. 원칙, 잔여주택/자격 일부 완화 OR 선착순, 주체별 권한·예외·지역실정도 원관계에 보존됐다.
- Builder는 근거 정의를 동반해 새 유형을 선언했다. 네 원관계 모두 초기 연결에 성공했다. 원관측 10개는 정확히 같은 관측을 재사용하는 기존 계약을 통해 대표 7개가 됐다. 최종 제안은 유형 7개+관계 4개=11개이며 정답 개수나 전체 자료의 품질 분모가 아니다.
- 첫 Critic은 이미 표현된 분기를 다시 누락 후보로 제안하고, content_error 쟁점의 이유 안에서는 오히려 오류가 아니라고 설명했다. 두 번째 Critic은 실제 conditions에 존재하는 지자체/지방공사 공급 전제를 누락으로 판정했다.
- 이 잘못된 판정으로 실제 revision 1회가 발생했다. revision은 기존 조건 문구를 그대로 유지하면서 자연어 subject/object 대신 모델 입력에 있던 `dc_` 유형 ID를 반환했고, 규범 종류도 원문 rule 대신 design_proposal로 반환했다. 해당 출력은 원문 표현으로 유효하지 않다.
- 서버는 변경 끝점의 기존 유형 연결을 계속 유효한 것으로 인정하지 않고 subject/object 미연결 상태를 저장했다. 새 Critic은 수정 후보를 refuted로 판정했다. 기존 원관계와 Builder 원출력, history.before는 그대로 보존됐다. 옛 Critic 지문은 새 후보에 적용되지 않고 새 Critic 지문이 최종 후보에 일치했다.
- 세 Critic의 원응답에 missing_meanings가 각 1건 있었으나 서버는 유효한 누락 재추출 요청으로 채택하지 않았다(정규화 0건). 별도 관계 재추출은 없었다. 불필요한 수정이 품질을 악화한 실제 사례이므로 수정 경로 작동을 수정 품질 향상으로 계산하지 않는다.
- Builder가 만든 `시ㆍ도지사` 정의에는 제공 원문에 없는 행정구분이 들어갔다. 인용이 존재한다는 사실만으로 그 정의가 뒷받침되는 것은 아니다. 독립 의미 전문가는 이 원문 밖 추가를 Critic이 두 번 supported로 놓쳤음을 확인했다.

## 최종 구조와 보존 경계

- 최종 상태 partial, 후보 11개 중 unreviewed 10/deferred 1, UI 단독 can_accept 7. 이는 의미 정확도 점수가 아니며 수락된 후보는 0개다.
- 생성된 11개 후보 전체만 선택한 API 미리보기는 `invalid_preview`: 수정 관계의 subject/object 미연결, domain/range 유형 참조 오류. 유형만 따로 선택한 미리보기로 전체 C2 성공을 대체하지 않았다.
- 47개 근거 참조/고유 구간 3개에서 버전·파싱·블록·인용·위치 오류 0. 원본 DB 해시와 sources/versions/blocks/evidence, 기존 정본 3개·결정 7개·snapshot 0개가 유지됐다. 미리보기는 별도 DB 사본에서 수행했고 그 사본도 변경되지 않았다.
- 원관계/Builder 이력 및 revision 전체 의존성이 보존됐다. 실제 수정→재검수는 실행했으나 유효 의미 복구는 실패했다. 실제 실행 재개는 이번 평가에서 시험하지 않았고, 무모델 재개 검사는 H3 보고서에 분리했다.

## 독립 검수와 다음 최소 작업

- 계획 및 구상 세션이 전달한 독립 3인 검토 모두 초기 C2.1~3c 보존·초기 4개 연결, 두 번째 Critic의 거짓양성, 최종 C2 미달/current 미실행에 동의했다. 최종 `inspection/independent_reviews.json`에서 `minimum_automatic_completion=false`를 확정했다. 원 실행 결과와 기계적 중간 점검 파일은 수정하지 않았다.
- 다음 보완은 Critic이 실제 후보 조건을 대조한 뒤에만 content_error를 제출하도록 만드는 것, 원명제 수정 입력/출력에서 자연어 명제와 유형 설계 ID의 혼동을 줄이는 것, 유형 정의가 인용에서 뒷받침되는 범위만 유지하는 것이다. 평가 조건의 반복 튜닝이나 실제 모델 재실행은 하지 않았다. 확인된 입력 혼재만 #561 H5에서 별도 보완했다.
- 두 문서 current, 다문서 의미 재사용·복구 효과, 전체 LH, Windows 실기, 사람 효용은 미검증이다. 사람 참가자 0명·사람시간 null·현업 효용 미측정. 평가 수행 완료와 #534·#539 품질 목표 완료를 구분한다.
- 현재 사용자 결정이 필요한 사항 없음.
