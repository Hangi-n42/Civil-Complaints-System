# 공통 의미 참조와 근거·표현 분리: 구현 및 중단 기록

- 기록일: 2026-10-05, Asia/Seoul.
- 대상: [승인된 개선 계획](../../05_plans/company_knowledge/semantic_context_redesign_20261005.md)의 핵심 작업 1~4.
- 상태: 부분 구현, 집중 코드 검사 통과, 실제 의미 품질 확인 실패. **전체 완료 기준 미충족이며 PR #609는 초안으로 유지한다.**
- 이번 고정 비교는 기존 후보 19개(관측 11개·관계 8개)를 대상으로 한 판단 시험이다. 전체 온톨로지·지식 그래프의 정확도나 신규 생성 품질 시험이 아니다.

## 변경 이유와 방식

기존 실행은 원문으로 성립하지 않은 연결을 생성 누락으로 판정했다. 이를 분리해서 추적하기 위해 같은 의미키를 원문 근거 판단(E), 현재 후보의 표현 대조(R), 전체 요구의 연결 검수(join)에서 참조하게 했다. 모델이 자유 서술한 원인을 바로 복구 권한으로 사용하지 않고, 서버가 근거 상태와 실제 표현 상태를 조합해 행동을 정한다.

기존 서비스·SQLite 실행 기록·직렬 실행기·원문 주소·Builder/Revision 경로를 확장했다. 별도 DB·큐·프레임워크·의존성은 추가하지 않았다. 구조 변경이 의미 오판을 해결한다는 것은 검증할 가설이며, 이번 결과로 해결되었다고 판단하지 않는다.

## 구현한 연결과 확인 수준

| 구현 | 확인한 내용 | 남은 한계 |
|---|---|---|
| 공통 의미키 | 본문·범위·근거 버전/위치로 키 계산, 교체 시 이전 기록 보존, 전제 누락·순환 검사 | 자연어의 의미적 동일성이나 전제의 충분성을 서버가 증명하지 않음 |
| E/R/join 분리 | E 입력에서 현재 후보 정의·기존 판정을 제외, R은 같은 근거 판정과 현재 위치 대조, join은 의미·전제·표현 주소 사용 | 실제 모델은 E부터 실패. R/join의 실제 판단 품질 미확인 |
| 현재성·재사용 | 같은 입력의 완료된 단위 재사용, 후보 변경 후 표현 판정 무효화, 현재 CQ·원문·표현 영수증이 맞는 복구만 허용 | 여러 패킷 간 상충 판정과 관련된 부분만 무효화하는 세밀한 동작은 미완료/미검증 |
| 교정·복구 연결 | 누락 복구 요청과 잘못된 필드의 교정을 기존 소유 실행 단위로 전달, 정상 의미 보존 근거 및 1회 교정 제한 전달 | 모델 대역으로 연결 확인. 실제 수정·보존·같은 요구 재검수 성공은 미측정 |
| 호출 예산·입력 크기 | 사전 검사와 실제 호출의 응답 스키마 생성 공유, 프롬프트+스키마 크기 및 출력 예약량 반영 | 바이트 계산은 실제 토큰 측정과 다름. join 초과 입력의 분할과 최소 전체 충돌 검수 흐름 미구현 |
| 진단 실행기 | 입력/코드/설정/모델 고정, 원본 DB 읽기 전용 사본, 실제 HTTP 요청·응답·시간 보존 | 고정 후보 진단이며 원문부터 시작하는 전체 제품 경로가 아님 |

새 실행은 `grounded-meanings-v1` 계약을 사용한다. 기존 계약으로 저장된 실행은 기존 판정 경로를 유지한다. 실제 시험은 `discovery-a2-v102`, 시험 종료 후 서버 구간 검사 수정은 `v103`으로 분리했다. 기존 실행 결과를 수정된 코드로 성공 처리하거나 원본 응답을 교체하지 않았다.

## 서로 다른 실패와 저장 응답 재검사

첫 E는 결과 JSON을 만들었지만 다음 의미 오류가 남았다.

- 다섯 의미 모두 `negation=negated`로 반환했다. 원문에 긍정형 의무·권한으로 제시된 네 의미에도 부정 표시가 붙었다. 전송 스키마는 affirmed/negated 모두 허용했다.
- 별표의 구체 선정 기준이 없다는 이유로 선정 의무 자체의 전제도 불충분하다고 했다. 지역 우선공급 기준의 구체 내용/절차가 없다는 이유로 기준을 정할 수 있다는 권한 자체의 전제도 불충분하다고 했다. **조건부 규칙·권한이 존재하는 것과 특정 사례에서 실행할 세부 조건이 충족되는 것은 별개다.**
- 일부 의미는 `external_missing`인데 필요한 자료명을 비워 두었다.
- 법 제2조를 외부 미제공으로 표시했다. 해당 문서는 같은 실행의 `input_inventory`에 포함되어 있었고 다른 E 패킷으로 선택되어 있었다. 입력 내부 미선택과 외부 미제공을 혼동했다.

첫 E의 원래 서버 실패는 전체 부모 구간을 조사했다고 응답해도 포함된 하위 구간 ID까지 모두 나열하도록 요구한 검사 문제였다. 같은 블록에서 조사한 구간의 합집합이 필요한 원문 구간을 덮는지 검사하도록 수정했다. 전체 부모 구간은 허용하고 일부 하위 구간만 조사한 경우는 거부하는 회귀 검사를 추가했다.

수정 코드로 **저장된 첫 응답만 재검사(추가 HTTP 0회)**했다. 원문 범위 검사는 통과했지만 다음 검사에서 `외부 자료 부재에는 구체 자료명 필요`로 계속 거부됐다. 의미나 자료 상태를 자동으로 고쳐 성공으로 바꾸지 않았으며, 동결 실행의 실패 상태도 그대로 보존했다.

둘째 E는 생성 상한에 도달해 최종 JSON을 만들지 못한 별도 실패다. 최종 응답이 없으므로 둘째 E의 의미 정확도를 평가할 수 없다. 첫 E의 의미 오류와 둘째 E의 출력 실패를 같은 실패 원인으로 집계하지 않는다.

## 코드 검사와 그 한계

- Python 3.11.9에서 `test_knowledge_discovery_grounding`, `completion`, `roles`, `scope` 집중 검사 **212개 통과(6.53초)**.
- 범위: 불변 의미키/이전 기록, 판정→행동 표, 전제/현재성, 동일 호출 계획·재사용, 복구 권한·중복 방지, 교정 시 정상 의미 전달, 패킷 분리, 부모 구간 포함 검사.
- 모델 대역 검사는 제어 흐름과 계약 검사다. 실제 모델의 의미 판단, 유용한 교정, 온톨로지 품질 개선을 입증하지 않는다.
- 선행 입력 용량 변경 검사 당시 관련 7개 파일은 311개 통과·15개 실패였다. 별도 기준 main에서도 같은 15개 실패 ID를 확인했다. 이들은 Builder 역할/정규화 9개, Revision 문맥 4개, 형식 왕복 2개이며 이번에 해결하지 않았다. 최신 전체 경로 통과로 표현하지 않는다.
- 사람 참가자가 없어 작업시간·오류 감소 미측정. 전체 민원 테스트·전체 A6·Windows 실기는 실행하지 않았다.

## 중단 판단과 다음 원인 분리

원문 근거 단계에서 기존과 같은 규칙/세부 조건 혼동이 남았고, 의미 품질 개선 증거가 없다. 승인된 중단 조건에 따라 추가 모델 호출·매개변수 확대·교정/A3/이웃 선택 확대를 중단했다. **전체 완료 기준인 실제 수정 → 정상 의미 보존 → 같은 요구 재확인 → 필요한 후속 결과는 충족하지 못했다.**

확인된 것은 이번 입력과 계약에서 발생한 오류다. 모델 능력 자체의 한계나 분리 구조의 실패로 단정할 수 없다. 다음 원인 분리 순서는 아래와 같으며, 이번 작업에서는 새 시험을 시작하지 않는다.

1. 조건부 규칙의 존재와 구체 사례 조건 충족을 별도 판단 단위로 다뤘는지 확인한다.
2. 새 계약의 부정과 자료 가용성 설명을 기존 원명제 `statement_type` 및 문맥 발견 표현과 대조한다. 어떤 입력/표현이 오판을 유발했는지는 미확정이다.
3. 이 좁은 경계를 검증한 뒤에만 실제 교정·보존·같은 CQ/A3로 진행한다. 핵심 검증 전 작업 N을 확대하지 않는다.

## 증거 위치와 보존 범위

로컬 실행 기록은 작업 트리의 `data/knowledge/evaluations/grounded_meanings_20261005/fixed19_v2/`에 있다. `freeze.json`, `inputs.json`, `execution/call_*/http_request.json`, `http_response.json`, `execution/result.json`, `execution/receipt.json`, `normalization_replay.json`을 구분해 보존한다. 원본 자료·DB·동결 출력은 Git에 포함하지 않는다. 보고서 수치와 관측은 이 기록에 근거하며, 저장소만 복제하면 동일 로컬 자료가 자동으로 제공되는 것은 아니다.

현재 사용자 결정이 필요한 사항 없음.
