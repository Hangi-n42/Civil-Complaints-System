# 자유 결합 해석의 검수·저장·QA 수명주기

2026-10-11. 제품 branch `feature/business-requirement-answer-flow`, 시작 commit `af9521bb49c0227cad0fc675a8b9470e43113e2c`. 기존 #616/#617/#620의 제한 후속이다. 결합별 기록·전달 계약과 확인된 서버 출력 충돌 수정은 제품 코드로 채택했고, 자동 종합 판단의 의미 품질과 전체 R05 완료는 미달이다. 이전 c47 편집·원문 재판정·그래프·QA 기록을 그대로 보존하며 새 성과로 다시 세지 않는다.

## 확인된 결함과 제품 변경

기존 자유 결합 5개는 원래 run `899f5a8f82ac46b59c074a088c1ed5a7`, assessment `38f03f4e69554380bc9fb4109f4e7354`, source unit `4861a82977bd42349995eae320d18b8c`에서 유래했다. 이후 원문 의미 재판정에도 결합별 원문 지지·정정·철회 계약 없이 남아 있었고, owner join `57be258a033e4660bc696956a1c35b2e`는 전체 `conjunctions_satisfied`만 반환했다. 기존 기본 D QA 입력에는 결합별 상태가 없었다. 이 수명주기 결함은 실제 기록으로 확인했다. 특정 오답의 직접 원인이 이 결함이라는 인과는 확인되지 않았다.

같은 join에 `conjunction_reviews`를 추가했다. 원래 문장과 현재 문장의 `supported/unsupported/unknown/refuted`, 현재 문장, 원문 근거, 관련 의미키와 실제 후보 ID, 공개 요구 적용성·필요성 및 공개 항목 ID를 기록한다. 원래 결합 문장·run/unit/source 버전과 정정·철회·미확정 이력은 보존한다. `unsupported`는 현실의 거짓이 아니며 원문 지지·후보 표현 위치·승인은 별도 상태다. 미확인 결합 자체를 독립 사실의 교정 이의로 만들거나 정상 후보 전체를 차단하지 않는다. 비필수 추가 설명의 미확인을 새 필수 실패로 승격하지 않는다.

알려진 연결은 관련 의미·후보·근거와 상위 조건/표 맥락의 fingerprint에 묶고, 귀속 미확정은 전체 입력 변경으로 무효화한다. source 재판정·명시 교정 이후 오래된 판정은 이력에 남기고 현재 판정에서 제외한다. QA는 저장한 현재 판정과 버전을 확인하여 별도 `reviewed_connections`로 소비한다. 확인된 사실 ID와 결합 참조를 구별하고, 항목 매핑은 인용 구절의 부분 문자열이 아닌 공개 항목 ID로 검증한다.

공개 QA 항목은 `BusinessRunRequest.answer_items`와 기존 공유 바인더를 통해 제품 시작 시 저장한다. 이전 owner join의 공개 항목은 빈 배열이었고 이번 입력은 기존 D의 공개 항목 4개를 사용한다. 결합 계약과 공개 항목 문맥이 함께 바뀌므로 단일 요인의 의미 개선 인과를 주장하지 않는다. 원문 구절 주소 검증은 수행하되 기대 정답·gold·추가 평가 기준을 모델 입력에 넣지 않는다.

## 실제 QA와 서버 재생의 성과 분리

실제 snapshot `06b35a112b52463bbaed5c41b4324d6a`과 QA run `d829442053e14ec18c3b6d90d5c54dae`를 생성했다. 진단 actor는 AI이며 실제 사람 검토·출판 승인이 아니다. 기존 eligible 21개만 승인한 진단 스냅샷이고, 결합별 원 모델 판정은 수동 정정하지 않았다. 실제 hipporag2/full 그래프는 364 nodes/5,061 edges/171 passages/134 concept nodes이며 로컬 BAAI/bge-m3 CPU 임베딩을 사용했다. 제공·인용은 21개다. 필수 포함 21개는 자연 검색 성공이나 검색 품질 향상으로 집계하지 않는다. graph_retrieval의 실제 ranked_passages/seed_node_scores와 retrieval/mandatory는 따로 보존했다.

실제 QA는 첫 항목에서 기관·기간을 direct_fact, c47을 premise_only로 골랐고, “번호판 변경이 기존번호판 반납 후 번호 변경으로 한정되는지, 단순 번호판 재발급/교부와 동일한지”의 구체 미확인을 작성했다. 동시에 k1을 선택했고 서버는 해당 미확인 뒤에 번호판 변경 수반 이전등록의 처리 가능 결합을 긍정 출력했다. excluded 항목에서 모델은 k3/k4/k5만 선택했지만 서버는 필수 관련성을 이유로 k1/k2도 자동 추가했다. 원 모델 선택과 최종 답변을 직접 대조하여 이 서버 회귀를 확인했다. answered/error 0은 응답 형식 상태이며 의미 통과가 아니다. 정상 담당·제외·교부기간·공통/대리/매매 서류와 c47의 일반 구비 및 지역 번호 한정 반납 후 변경은 보존됐지만, 자기모순이 있어 r05-guidance-scope-v1을 통과하지 못했다.

서버 수정은 지지 판정이 있어도 QA가 선택하지 않은 결합을 긍정 출력하지 않는다. 같은 공개 항목에 선택된 지지 결합과 구체 미확인이 함께 있으면 결합 결론을 보류하고 conflict error를 남긴다. 직접 사실과 다른 항목은 그대로 유지한다. 사용자 문구는 “이 항목에는 미확인 내용이 남아 있어, 결합한 결론은 확정하지 않았습니다.”다. 지원/정상 의미를 거짓·오류로 바꾸거나 특정 업무·후보·자연어 단어를 하드코딩하지 않았다.

server_render_v3는 동결된 실제 QA 요청(messages/schema/참조/모델 설정/한도)이 정확히 일치하는 실제 응답만 재생했다. 새 모델·검색·그래프·snapshot·원문 판단은 0회다. 첫 항목의 구체 미확인·기관·기간·c47 두 의미는 유지됐고 k1 단정은 보류됐다. excluded의 비선택 k1/k2는 없어지고 선택된 정상 제외 k3~5는 남았다. documents 섹션과 인용 21개는 실제 원답과 완전히 같다. conflict error에 따라 기존 제품 query 규칙의 답변 상태는 unverified에 해당한다. 이는 저장 응답의 서버 출력 검증이며 새로운 실제 QA 성공이나 모델 개선 증거가 아니다.
