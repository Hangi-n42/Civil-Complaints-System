# K3: 대상별 수정과 한정된 유형 연결 교정

- 관련 이슈: #571, 상위 #534/#539
- 이유: J3의 3대상 Revision은 한 대상만 답해 전체 저장에 실패했고, 잘못된 목적어 유형은 수동 보류로 끝났다. 기존 직렬 실행기와 수정 이력을 확장해 독립 대상의 성공을 보존한다.
- 변경: 고정 correction_plan에 후보별 Revision 또는 한 관계의 Builder 교정과 실제 단위 ID를 저장한다. 후보당 한 번 시도하고 실패한 이웃의 응답을 버리지 않는다. 원명제 supported·binding refuted인 현재 지문의 유효 주검수만 Builder 교정 대상이다. unknown/비교 쟁점은 자동 교정하지 않는다.
- Builder: 원문 명제·관계 ID 불변, 기존 제공 유형 또는 근거 있는 새 유형만 사용. 계층·별칭·도구 행동 추가는 막는다. 교정은 history.before/after로 최종 후보에 반영하며 정상 이웃은 유지한다.
- 일관성: 기존 tool context 유형도 제공한다. 성공한 수정의 전체 effective_hierarchies를 다음 수정과 최종 재검수에 전달한다. 변경된 유형·관계·이웃은 현재 지문으로 분할 재검수한다. 과거 입력 recipe는 기존 재개 시작 경계에서 거절하며 재해석하지 않는다.
- 재개: 성공 단위 저장 직후 중단해도 parent_group_id의 성공 Builder observations에서 소유권을 유도해 중복 그룹을 만들지 않는다. 실패한 교정 Builder의 status/error/raw/attempts를 재개에서도 보존한다. 성공 단위 입력 해시·근거 차단 검사를 계속 적용한다.
- 예산: 실제 대상별 수정/교정 수와 현재 재검수 묶음, Builder가 추가할 수 있는 두 유형의 검수 여유를 예약한다. 시간·호출이 부족하면 명시 보류하고 실행 중 증액하지 않는다.
- 완료 원장: 실제 변경 이력이 있고 현재 후보 지문의 유효 최신 주검수가 지지한 요청만 AI 검수상 해결로 분리한다. 원요청·실패를 삭제하지 않으며 사람 수락으로 표시하지 않는다. 최신 binding coverage를 사용해 해결된 과거 pending이 영구 차단하지 않도록 한다. 분할 Critic과 교정 후 검수도 실제 복구 호출 집계에 포함한다.
- 전문가 검토: 실행 전문가 지적의 새 유형 소유권/실패 이유/기존 유형 재사용/누적 계층 지문 경계를 수정하고 재검토했다. 의미 전문가의 unknown 자동 수정 금지와 주검수·현재 지문 경계를 유지했다.
- 확인: 관련 8개 파일 206 통과, 기존 Pydantic serializer 경고 13개, 30.06초. 새 연결 검사 8개에 3대상 중 1실패·2성공, 재개 중복 없음, 정상 이웃/원명제/ID 유지, 연결 교정 후 A3 현재 검수, unknown 및 예산0의 교정 없음, 새 유형 저장 직후 중단, 실패 원인 보존, 기존 tool 유형 재사용 및 유효 계층 지문을 포함했다.
- 기존 검사 갱신: 3대상 수정의 한 호출 기대를 세 호출로 변경. 회복 검사에 남아 있던 단일 Critic 가정은 분할 주검수로 갱신하고, 실제 누락됐던 분할 Critic의 회복 호출 집계를 수정했다. 테스트를 건너뛰거나 성공/오류 중 임의 상태를 허용하지 않았다.
- 한계/다음: 실제 모델 호출 0. 위 결과는 결정적 응답으로 검증한 서버 계약이며 자연 모델의 교정 성공은 아직 미측정이다. K4에서 동결 진단 3회 후 통과할 때만 C2/current를 각 한 번 실행한다. 사람 참가자 0, 사람 시간 null, 현업 효용 미측정. 현재 사용자 결정이 필요한 사항 없음.
