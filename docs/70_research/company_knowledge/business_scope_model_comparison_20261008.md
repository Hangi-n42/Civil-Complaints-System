# 범위 대조 과제의 로컬 모델·thinking 비교 — 기각 결과

시작 HEAD는 `c602e5832baa584cd0c1e1564f02b1748a73c94b`다. **Qwen think=true와 동일 과제 Gemma think=true 모두 c47의 범위 확대 검출에 실패해 기각했다.** 정상 후보 근거·세부 표현은 일부 개선됐으나 제품 반영·실제 교정·후속 실행은 0이다. 기존 scope_difference run `8f558efe88a84662b49ee44e2eb59c94`는 재호출하지 않았다. 아래 실행 전 계획은 호출 전에 저장·공유했고 `pre_call_plan.md` 및 해시로 보존했다. 평가 내용은 모델 입력에 넣지 않았다.

## 확인한 지원과 미확인 질문

현재 로컬 Ollama `/api/show`는 Qwen `qwen3.8:27b-q4_K_M`와 Gemma `gemma4:31b-it-q4_K_M` 모두 `thinking` capability를 반환했다. 모델 digest는 기존 기록과 일치한다. 실제 `ModelClient`의 Ollama 분기는 `request.think`를 `/api/chat` payload의 `think`로 전달한다. 응답의 최종 `message.content`를 파싱하고 원본 응답은 별도로 저장한다. 따라서 코드를 수정하지 않고 think=true 요청이 가능하다. 모델이 실제 thinking 내용을 반환했는지는 실행 후 원본 응답에서 별도 확인한다.

직전 실패는 Qwen think=false 조건에서 원문 측의 지역 한정을 없앤 결과다. 같은 과제에서 thinking을 켠 결과는 아직 없다. 기존 Gemma 실행은 요구/기존 의미가 포함된 source 재판정 과제였으므로 이번 원문–후보 범위 대조 능력의 대조군이 아니다.

## 최소 호출 순서와 고정 요소

1. **Qwen think=true 1회.** 기존 request의 messages/schema/reference_map/evidence_reference_map/10블록/c13·c46·c47을 그대로 사용한다. 모델 digest, temperature 0, context 49152, 출력 8192, timeout 1800, 원문·후보·R05 저장 기록을 고정한다. 변경은 실행 recipe의 `think: false → true` 하나다. 기존 think=false는 재호출하지 않는다.
2. 출력 한도 때문에 실제 `truncated`가 확인된 경우에만 동일 요청의 출력 한도를 16384로 늘린 1회 복구를 허용한다. 첫 실패와 thinking/출력 사용 기록을 보존한다. 복구는 용량 비교이며 의미 품질 성과가 아니다. 더 큰 한도·재시도는 하지 않는다.
3. Qwen의 완결 출력이 의미 기준을 통과하지 못하면 실제 결과를 원문과 대조해 공유한 뒤, **같은 과제의 로컬 Gemma 1회**를 검토한다. 이는 과제 고정 상태에서 모델 적합성을 확인하는 질문이다. 두 모델 모두 thinking 지원이 확인됐으므로 Gemma도 think=true로 요청하여 직전 Qwen thinking 실행과 모델만 다르게 한다. 실제 내부 추론 방식·tokenizer·기본 모델 sampling 값까지 동일하다고 주장하지 않는다. 한도는 비교 대상 Qwen의 최종 한도와 맞춘다. Gemma가 실제 잘리면 동일한 한도 복구 원칙만 적용하며 의미 오판은 재시도하지 않는다.
4. 앞 단계가 의미 기준을 통과하면 불필요한 모델 조합은 호출하지 않는다. Qwen·Gemma의 동일 실패 뒤에 새 프롬프트·스키마·판정층·제한어 선택 과제를 즉시 추가하지 않는다. 외부 모델·채점, 추출, c116 재교정, LH는 제외한다.

각 실행은 이전 원본·실패를 보존한 별도 평가 결과로 저장한다. 제품 DB 구조나 새 검수층을 도입하지 않는다. 기존 호출·근거 복원 함수를 재사용한다.

## 완료·중단 기준

- c47: 실제 `raw.Event`의 일반 반납 확대를 특정하고, 원문 측에서 일반 번호판 변경의 **기존번호판 2매·봉인 구비**와 **지역 번호에 한정된 반납 후 변경**을 구분해야 한다. `unsupported_scope`는 제공 원문 미지지이며 외부 법적 거짓 확정이 아니다.
- c13/c46: 정상 후보를 오류화하지 않고, 후보가 실제 주장한 미방문 조건·문서 목록·날인 및 법인 대체조건을 실제 대응과 근거로 보존해야 한다. 특히 c46의 양도증명서 근거를 빼거나 ‘구비서류/구비한다’ 같은 넓은 이름만으로 세부를 확인했다고 하면 통과가 아니다. c13이 표현한 양도증명서 날인은 확인하되, c46이 주장하지 않은 원문의 날인 세부까지 새로 요구하지 않는다. 이 범위 해석은 Qwen 완료 전 조율 메시지와 `criterion_clarification.json`에 기록했으며 요청문은 바꾸지 않았다.
- 주소·스키마 통과, 정상 라벨, 보류 증가, thinking 내용의 길이는 의미 성공이 아니다. raw/복원 출력과 실제 원문 대응을 함께 검토한다. 근거 부족·미확정은 검출 성공으로 세지 않는다.
- 효과가 확인되면 기존 직접 검수의 대체 경로에 최소 연결하고 c47 실제 교정 → 저장 정상 의미 보존 재검수 → 원래 R05 → 그래프/검색 → 같은 QA를 확인한다. 부산 성립 전 기간/기관·버스 대조를 넓히지 않는다.
- 새 원인 변화 없는 의미 실패가 반복되면 해당 경로를 중단하고 기각 증거를 남긴다. 실제 완료되지 않은 #616/#617/#620은 열어 둔다.

## 실제 실행과 비용

로컬 Ollama 버전은 `0.35.0`이다. 두 모델 모두 `/api/show`의 thinking capability와 실제 응답 `message.thinking` 존재를 확인했다. 공통 호출부의 전달 코드와 실제 실행 recipe/receipt를 대조했다. 모델 내부 사고 내용은 평가 근거로 사용하지 않았다. 의미 평가는 최종 JSON 출력과 제공 원문으로만 수행했다. 과거 다른 과제의 Gemma think=true 실행이 있으므로 프로젝트 최초 추론 모드 시험은 아니다.

## 원문과 최종 출력 대조

c47의 실제 후보는 “번호판 변경 시 기존번호판 2매 및 봉인을 반납하여 번호를 변경한다.”다. 제공 원문 b32/e47은 “번호판변경시 기존번호판 2매 및 봉인(**지역 번호는** 반드시 기존번호판 2매 및 봉인 반납 후 번호 변경하여야 함)”이다. 구비서류 문맥의 일반 항목과 괄호 안 지역 한정 행위의 구분이 고정 평가 대상이다. 외부 법률상 진위나 비지역 번호의 반납 금지를 판단하는 과제가 아니다.

**Qwen think=true**는 c13의 부모·양도증명서 근거(e41/e46)를 선택하고 reason에서 날인 내용을 포함한 후보 관계를 실제로 대조했다. c46에는 이전에 빠진 양도증명서 e46이 추가돼 e41/e45/e46을 모두 선택했고, reason에 문서 목록과 법인 대체를 포함했다. c46이 주장하지 않은 날인 세부의 생략을 오류로 만들지 않았다. 양측 scope 필드는 여전히 넓은 이름이지만 reason과 근거의 세부 대응은 이전보다 충실하다. 이를 c47 검출 성공이나 전체 과제 통과로 확대하지 않는다.

c47에서는 양측 모두 `action='반납하여 번호 변경'`, `condition='번호판 변경'`, `form='obligation'`으로 만들고 `difference='none'`을 냈다. 최종 reason은 **“원문의 괄호 내 '지역 번호' 강조는 동일 행위의 특정 사례에 대한 재확인이지 별도 범위를 추가하는 것이 아니다.”**라고 단정했다. 이전 false 출력의 listed_item 분류를 obligation으로 바꿨지만, 지역 한정을 보존하지 않고 일반 반납 확대를 정당화한 핵심 오판은 유지됐다.

**Gemma think=true**는 c13의 양도증명서·날인·미방문 조건을 양측 scope에 구체적으로 적었다. c46도 실제 문서 목록, 법인 대체, 미방문 조건을 양측 scope에 적고 e41/e45/e46을 모두 선택했다. 정상 후보를 오류화하지 않았으며, 이 출력의 구체화는 부분 개선으로 보존한다. 다만 구비 목록의 form을 obligation으로 표현했고 이것만으로 모든 의미 구분의 안정성이 확인됐다고 말할 수 없다.

c47의 Gemma 원문 측은 다음과 같다.

```json
{"target":"기존번호판 2매 및 봉인","action":"반납 및 번호 변경","condition":"번호판 변경 시","form":"obligation"}
```

후보 측도 같은 일반 조건의 반납 후 변경이고 `difference='none'`이다. 원문 측의 지역 번호 제한이 빠졌으며 구비 항목과 조건부 반납 행위를 나누지 않았다. 두 새 호출 모두 정확한 전체 원문 인용이 복원돼 주소 오류로 이 의미 실패를 설명할 수 없다. Qwen의 설정 변경과 Gemma의 모델 변경은 이번 세 후보의 핵심 오류를 해결하지 못했다. 모델 내부 원인이나 다른 과제·설정의 일반 불가능은 확인 불가다.

## 별도 계약 결함과 검사 결과

Gemma는 `candidate_fields`에 c13은 `Tail`, c46/c47은 `Event`를 반환했다. 제공 후보의 실제 경로는 `raw.Tail`/`raw.Event`다. 문자열 목록인 JSON 스키마는 통과했지만 실제 후보 필드 존재 검사는 실패했다. 원래 검증기의 실패 로그를 보존했고, 별칭을 사후 추가하거나 경로를 사람이 고쳐 통과로 바꾸지 않았다. c47 의미 실패는 이 주소 경로 결함과 별개로 최종 scope/reason에서 확인된다. 따라서 경로 처리만 고쳐 후속 교정을 실행할 근거는 없다.

- 공통 통과: 동결 파일·런타임 해시, 원문/후보/요청문/스키마/참조 매핑 불변, 실제 모델 digest·요청/실행 한도, 단회 실제 호출·캐시 0, 원문 근거 복원, 원본·부모 DB 및 기존 claims/blocks/requirements/assessments/repairs/graph/concepts 불변.
- Qwen: 단일 think 변경 검사 및 실재 후보 필드 검사 통과. 의미 채택 기준 실패.
- Gemma: Qwen true와 동일 messages/schema/options/한도이며 review 모델만 바꾼 검사 통과. 정확한 원문 주소 복원 통과. 실재 후보 필드 검사 3개 실패. 의미 채택 기준도 실패.
- 원본 DB SHA는 `62f6eda378eb1258d84c6b85e6b2ce414a595fcbeef62260b6cdae22a7fecde3`로 유지됐다. 형식·무결성 통과와 의미 실패를 합쳐 성공으로 표현하지 않는다.

## 남은 병목과 다음 검토

거시적으로는 한 번 더 오래 생각하게 하거나 현재 다른 로컬 모델로 바꾸는 것만으로 원문 범위 검수의 채택 근거가 나오지 않았다. 미시적으로는 일반 구비 항목과 지역 한정 반납 행위의 연결을 모두 일반 반납으로 바꾸는 실패가 반복됐다. 한편 c13/c46의 근거·세부 대응에는 실제 부분 개선이 있었으므로 “모든 항목에 효과가 없었다”는 결론도 부정확하다.

이번 비용 증가나 thinking 내용의 존재는 판단 신뢰도의 증거가 아니다. 같은 입력의 단일 실행들이며 별도 일반화 평가도 없으므로 모델 전체 순위·실패 확률·안정성은 확정하지 않는다. Gemma의 후보 경로 결함은 연결 단계의 추가 위험이지만, 의미 오류의 원인은 아니다.

다음에 검토할 미확인 대안은 자유로운 재작성 대신 **원문 제한어와 해당 행위를 실제 위치에서 선택·대응시키는 과제**다. 기존 scope 필드를 더 늘리는 방향이 아니며, 선택지를 만드는 과정에서 사람이 정답을 주입하거나 서버가 잘못 범위를 확정하지 않는지 먼저 설계 검토가 필요하다. 이 대안은 미구현·미검증이며 이번 라운드에서 호출하지 않았다. 조율 세션에 결과를 전달하고 동일 실패 경로의 모델·프롬프트 반복은 중단한다.
