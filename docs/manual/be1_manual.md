## 1. 문서 목적

이 문서는 BE1(팀장)이 프로젝트 시작부터 최종 발표까지 무엇을 책임지고, 어떤 산출물을 언제까지 만들어야 하는지 명확히 정의한다.  
동시에 FE, BE2, BE3가 이 문서를 봤을 때 BE1이 어떤 일을 하는지 즉시 이해할 수 있도록 작성한다.

## 2. BE1 한 줄 정의

**BE1은 데이터 파이프라인과 구조화 품질을 책임지고, 최종 평가 리포트와 발표까지 끌고 가는 팀장 역할이다.**

## 3. BE1의 최종 책임 범위

### 주 책임
- 데이터 수집/정제 파이프라인 구축
- 4요소 구조화 전처리/후처리 설계 및 구현
- 구조화 품질 개선
- 평가 지표 산출 자동화
- KPI 리포트 정리
- PPT 준비 및 발표 총괄

### 협업 책임
- BE2가 검색/QA를 구현할 수 있도록 구조화 데이터 품질을 안정화
- BE3가 검증 로직을 설계할 수 있도록 구조화 필드 규칙 제공
- FE가 업로드/구조화 결과 화면을 만들 수 있도록 예시 데이터와 상태 정의 제공

### 하지 말아야 할 것
- 벡터DB 상세 구현을 주도하지 않음
- LLM 서빙 및 RAG API를 메인으로 맡지 않음
- 프론트 UI 세부 구현을 직접 담당하지 않음

## 4. BE1이 끝까지 만들어야 하는 산출물

- 데이터 입력 포맷 기준서
- CSV/JSON 로더 및 기본 정제 로직
- PII 마스킹 규칙 초안
- 4요소 구조화 전처리/후처리 규칙 문서
- 구조화 결과 샘플셋
- 구조화 품질 평가 스크립트
- KPI 집계 스크립트 또는 리포트 자동화 스크립트
- 발표용 정량 결과 표
- 최종 PPT 초안 및 발표 스토리라인

## 5. 주차별 상세 할 일

## M1 (1~2주)

### 이번 단계 목표
- 구조화 품질의 기준을 세운다.
- 입력 데이터와 평가 기준을 고정한다.

### 해야 할 일
- [v]민원 원문 입력 포맷 정의
- [v]CSV/JSON 컬럼 규칙 정리
- [v]정제 규칙 초안 작성
- [v]PII 마스킹 대상 패턴 정의
- [v]4요소 구조화 예시 20건 정도 수작업 정리
- [v]구조화 품질 평가 기준(F1 계산 방식) 정리
- [v]리포트 템플릿 초안 만들기

### 이 단계 산출물
- 구조화 예시 샘플
- 정제 규칙 문서
- 평가 기준 메모
- KPI 리포트 템플릿 초안

### 완료 기준
- 팀이 같은 입력 포맷을 사용한다.
- 4요소 정의가 모호하지 않다.
- 구조화 품질을 어떻게 측정할지 합의되어 있다.

## M2 (3~4주)

### 이번 단계 목표
- `ingest -> structure -> validate`가 실제로 돌아가게 만든다.

### 해야 할 일
- 데이터 로더 구현
- 텍스트 정제 로직 구현
- 중복 제거 기준 초안 작성
- 4요소 추출용 전처리/후처리 규칙 구현
- 구조화 결과 오류 케이스 수집
- 구조화 결과를 BE3 검증 로직에 넘길 수 있는 포맷으로 정리

### 이 단계 산출물
- 로더 코드
- 정제/후처리 코드
- 구조화 결과 샘플 파일
- 오류 사례 목록

### 완료 기준
- 샘플 50~100건에 대해 구조화 결과가 나온다.
- FE 화면에 보여줄 구조화 결과 예시가 안정적으로 나온다.

## M3 (5~6주)

### 이번 단계 목표
- 구조화 품질을 높이고 평가 자동화를 붙인다.

### 해야 할 일
- 전처리 노이즈 패턴 추가 수정
- 구조화 누락/오탐 케이스 분석
- 평가 스크립트 작성
- Precision/Recall/F1 자동 계산
- 평가 결과를 표 형태로 정리하는 자동화 스크립트 작성
- 발표용 그래프/표 초안 준비

### 이 단계 산출물
- 구조화 평가 스크립트
- 실패 사례 리포트
- KPI 중간 보고서

### 완료 기준
- 구조화 품질 수치가 측정 가능하다.
- 어떤 규칙이 품질을 올렸는지 설명 가능하다.

## M4 (7~8주)

### 이번 단계 목표
- 최종 평가 수치를 정리하고 발표 자료까지 마무리한다.

### 해야 할 일
- 최종 평가 리포트 정리
- KPI 표 및 실패 사례 표 완성
- 발표용 문제 정의/해결 흐름 정리
- 시스템 전체 스토리와 데모 흐름에 맞춰 발표 자료 작성
- 최종 발표 리허설 주도

### 이 단계 산출물
- 최종 KPI 리포트
- 발표 슬라이드 초안/최종본
- 실패 사례 및 개선 포인트 정리 문서

### 완료 기준
- 발표 자료만 봐도 구조화 품질과 프로젝트 가치가 설명된다.
- 팀원이 발표 질문을 받았을 때 구조화 파이프라인을 설명할 수 있다.

## 6. BE1이 받아야 할 것 / 넘겨줘야 할 것

### 받아야 할 것
- FE로부터 화면에서 필요한 구조화 결과 표시 요구사항
- BE2로부터 검색에 필요한 메타데이터 요구사항
- BE3로부터 검증 로직에 필요한 필드 제약사항

### 넘겨줘야 할 것
- 정제 완료된 입력 데이터
- 구조화 결과 샘플
- 평가셋/정답셋 초안
- KPI 중간 결과 및 최종 결과
- 발표용 정량 자료

## 8. 주간 체크리스트

- 이번 주 새로 발견한 전처리 노이즈는 무엇인가?
- 4요소 추출 실패 사례를 수집했는가?
- 평가 스크립트가 최신 출력 포맷을 반영하는가?
- 발표 자료에 들어갈 정량 수치를 누락 없이 확보했는가?
- 다른 멤버가 막히는 데이터/스키마 이슈를 해결했는가?

## 9. BE1이 놓치면 안 되는 리스크

### 리스크 1: 구조화 품질이 낮은데 후반까지 방치
- 징후: 검색은 되는데 답변 품질이 들쭉날쭉함
- 대응: 5~6주차 전에 반드시 구조화 실패 사례를 정리하고 규칙 보정

### 리스크 2: 평가 자동화가 늦어짐
- 징후: 성능이 좋아졌는지 감으로만 판단함
- 대응: M3 안에 최소한 F1/Recall용 리포트 자동 출력 확보

### 리스크 3: 발표 자료가 개발 끝나고 급하게 시작됨
- 징후: 슬라이드에 수치와 근거가 부족함
- 대응: M3부터 표와 그림을 계속 축적

## 10. 최종 완료 기준

- 데이터 수집/정제 파이프라인이 동작한다.
- 구조화 전처리/후처리 규칙이 문서화되어 있다.
- 평가 스크립트로 KPI를 재현할 수 있다.
- 발표 자료에 구조화 품질과 프로젝트 기여가 명확히 드러난다.
- 팀 전체가 BE1의 데이터/평가 산출물을 기반으로 후반 작업을 수행할 수 있다.
